# DSH / Codex 会话卡片时间与排序

## 行为

- DSH 卡片展示当前账号原生目录中未归档、非空白主会话的最新活动时间；不使用当前选中会话、同步收件时间或运行时心跳。
- Codex 卡片展示本人可见任务的最新来源事件时间；任务状态提示继续使用现有读取机制。排除空任务、排除项及已分类的后台任务。
- 两个入口与私聊、群聊、Bot、团队和通知使用同一排序链路。发给自己、Arko 的已有消息/离开后的草稿时间也复用该链路，避免固定入口位置破坏整体时间顺序。
- 置顶优先，同组按活动时间倒序；时间相同保持原顺序。没有可靠时间时留空，不填充当前时间。
- 刷新失败或不完整时保留同账号最后确认的数据；完整目录可以移除已删除的历史。切换账号清除旧账号展示。
- 不新增轮询或历史正文读取。Codex 复用原有元数据读取，DSH 复用原生活动桥。

## 时间口径与边界

DSH 此处沿用原生 Session Controller 的 `updatedAt`。当前安装依赖将其持久化为创建/最后用户消息时间，原生 `api-session/activity` 也由用户消息驱动；因此本次没有声称获得独立的 AI 回答完成时间。若需按每条 AI 回答更新时间，需在原生目录活动协议中统一补充，不能在前端拿接收时间推测。

Codex 的 `updatedAt` 来自源事件 `at`，覆盖用户消息、已同步的公开过程回复和回答结束事件；`checkedAt`、`captureHealth.checkedAt` 均不参与排序。
