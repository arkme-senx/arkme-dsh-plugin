## 已接通的能力

入口为左侧「探索 → 统计与分析」，日历提供「本月统计」。桌面页面读取真实账号数据，支持全部/按月、年份/月度热力图、日/周活动分布、耗时记录及原文详情。统计范围沿用移动端个人快记，不代表聊天、通话和全天录音的总量。

实际复用的 Record 接口：

| 接口 | 请求及含义 |
| --- | --- |
| `/api/v1/records/analytics/detail` | `from_stamp`、`to_stamp`（毫秒）、`timezone_offset_minutes`、`hide_record_pri_lock:true`；按月时附上 `pre_from_stamp/pre_to_stamp` |
| `/api/v1/records/analytics/active-time` | 同一统计范围；`w1` 到 `w7` 数组中的 `stamp`、`cost_sec` |
| `/api/v1/records/analytics/long-time-list` | 同一范围；`limit:20,offset`；响应 `items:[{record:{record_uid,title,text_content,send_at},cost_sec}]` |
| `/api/v1/calendar/buckets/query` | 复用已有日历服务按月取每日快记计数；按年展示时分月、最多 3 个并发 |
| `/api/v1/records/detail` | 通过已有 `record.app.detail` 读取原文，再次校验所有权和隐私锁 |

前端不将接口失败转成 0；缺失指标显示 —；月份切换取消旧请求。记录列表额外过滤隐私锁快记，分页偏移按服务端原始行数前进。

## 1. 关键词：需要确认可供新客户端使用的接口

后续已找回旧版词频实现及独立的 `jotmo-keyword` 服务，完整代码依据、统计口径与建议契约见 [关键词词频统计恢复-后端交接-20261016.md](./关键词词频统计恢复-后端交接-20261016.md)。以下为迁移初查记录；其中字段建议以专项交接为准：必须拆分 `occurrence_count`（出现次数）和 `record_count`（涉及快记数），不能混用。

确认的代码差异：旧移动端调用 `/summary/keywords`，返回全量 `summary`、`record_count`、按月 `durations`；本地新版移动端统计页面的 `_showKeywordSummaryCard` 为 false，新客户端只尝试解析统计详情内的 `summary/keywords`。新版统计服务适配器没有独立关键词查询方法。

3102 的真实全部、2026-09、2026-10 查询均未收到当前适配器可用的关键词字段，因此桌面显示「当前统计服务尚未提供关键词数据」，没有生成示例词云。该结论仅表示已查的 Record 统计详情不提供词云，不能据此认定所有后端都没有关键词服务。

请后端同事确认：
1. 新 Record 服务是否已有正式关键词接口？请给路径、鉴权方式及响应样例；不要让插件回退到依赖旧 Kernel 的端点。
2. 返回关键词是否明确属于请求的时间范围，是否过滤隐私锁？全部与按月要区分，不能把历史所有词放到本月。
3. 建议按词返回 `text`、`record_count`、`weight`，并附 `from_stamp/to_stamp`、统计更新时间和提取版本。缺少支持、尚未生成、生成中、成功但为空需要区分。
4. 建议支持关键词对应的精确 Record UID 分页列表，并执行权限过滤。普通全文搜索不等于 AI 语义关键词的来源关联。

桌面已保留词云呈现和相关记录抽屉。当前抽屉仅准备使用现有全文搜索并过滤个人来源及选定时间范围，尚无真实关键词返回可做端到端验收。后端提供精确关联接口后优先替换搜索降级，避免数量与来源不一致。

## 2. 历史记录用时：需要核对异常值及定义

实测「全部」的耗时记录和活跃时间分布出现单条 **165 小时 3 分**；另有 44 小时、43 小时、32 小时的历史条目。桌面按服务端 `cost_sec` 原样转换为小时，没有乘错毫秒，也没有在前端截断或改写历史统计。

这只能确认存在极端值，尚不能确认底层根因。请排查：
- `cost_sec` 是有效编辑时长、页面停留时长、创建至最终编辑跨度，还是多个行为的累计值？
- 是否把后台、睡眠、跨日闲置时段算入？同一快记多个设备/多个编辑会话是否重复累加？
- 单条异常是否同时污染 `record_min` 汇总和活跃图？是否需要清理历史数据，以及按同一版本重算？
- `stamp` 是一次独立编辑行为的时间还是快记创建时间？目前桌面沿用移动端显示方式，后端应明确这一点。
- 增加明确统计定义或指标版本，方便桌面后续调整说明，而非依赖猜测。

本交接不附用户原文、凭据或个人数据 JSON。请在经授权的账号/测试数据上排查。

## 3. 日期和记录口径的一致性

统计汇总携带本地时区偏移；热力图复用已有日历计数。后端需确认是否统一按自然日还是用户智能归属日，以及分享副本、导入快记、AI/DSH 输入来源是否一致纳入。

后续建议：统计接口回传 `timezone`、`belong_date_policy`、来源范围、更新时间；按月汇总与日历每日计数是否可相加对齐应有明确约定。当前没有在客户端强行用热力图相加覆盖服务端汇总。

## 验收建议

- 全部、历史完整月、当前未结束月、零记录月均有确定语义。
- 关键词统计数量与精确来源列表去重后相符。
- 隐私锁开启后，词云、计数、记录列表和原文权限同步生效。
- 快速切换月份/账号，不显示上一个范围或账号的旧数据。
- 历史极端用时能够解释或修正，并与汇总、活跃图采用同一算法。
