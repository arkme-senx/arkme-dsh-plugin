# 团队选人弹窗：缓存与群聊加载修复

## 根因与处理

1. 弹窗每次挂载都会清空联系人和群聊状态，重新调用目录接口，没有可同步显示的联系人列表快照。现在联系人使用按环境/账号隔离的共享内存资源，30 秒内复用已加载分页；过期读取保留旧列表直到新结果可用，失败保留展示，重试沿用失败页。Host 分页快照过期时从新首页恢复，不拼接两个不同快照。
2. `sources.list(localFirst: true)` 返回的是目录投影。其 `hasMore` 表示后台同步未完成，合法返回没有 `nextCursor`。原弹窗在显示已有群聊前将其误判为分页错误。现在直接订阅第二栏的 `arkmeChatDirectory`，采用同一可见性、排序与后续 Host 推送，不再自行分页读取本地投影。
3. 账号变化会取消旧读取并清理联系人缓存；本地 Provider 实例变化也清理内存中的旧引用，活动弹窗自动重读并清空旧选择。缓存不写入 localStorage。发起联系继续由 Host 校验账号、团队和目标，不以展示快照授予权限。
