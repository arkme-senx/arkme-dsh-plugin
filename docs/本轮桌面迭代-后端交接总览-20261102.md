## 每次编辑的记忆快照

### 现有路径与插件行为

- 编辑仍使用 `/api/v1/records/update`，没有为“即时发送”另造一个后端提交接口。乐观显示后，仍由现有 Host 保存任务确认成功、失败或结果不确定。
- 当前编辑请求增加 `edit_capture_context`，包括 `schema_version`、`captured_at`、设备／网络／电量等已有环境语义，以及有采集结果时的 `automatic_location`。未授权或未取得的内容不伪造。
- `edit_duration_millis` 使用既有累计编辑时长语义，本次输入时长加到基准值；历史页仅在相邻版本可比较时计算本次编辑增量，不把创建时长混入编辑时长。
- 背景音使用既有 `content_payload.media_refs` 的 `content_file_role: 4` 及波形；普通附件和语音正文保持各自语义，播放时只取该 revision 所属的背景音资产。
- 历史查询复用 `/api/v1/records/revisions/query`；聊天授权场景使用 `/api/v1/chats/records/revisions/query`。读取选定 revision，不用当前 Record 的设备、背景音或时长补历史空值。
- 地点补全调用现有 `/api/v1/records/location/context/get` 并携带 `record_uid` 与 `revision_uid`。历史编辑快照仅接受明确回显同一 record/revision 身份的补全；旧部署忽略 revision 参数时，保留历史快照本身的事实，不套用当前地点。

### 需联调核验

1. 确认更新接口对 `edit_capture_context` 的实际接收、验证和持久化；必须随本次新 revision 冻结，而不是覆盖原始创建快照。
2. 确认历史响应能返回当次编辑的采集环境、准确时长、背景音资产及编辑者头像／名称快照。缺失的旧历史应明确缺失，不能从当前用户资料反推当时资料。
3. 确认 `edit_duration_millis` 的累计定义、自动修订是否影响增量、并发 version 冲突语义；存在不同合同请提供实际合同后调整适配。
4. 位置补全需要明确 revision 身份，地点、天气、地址均属于所选版本；不应把当前版本或创建版本的地点误认作本次编辑地点。
5. 本人原始记录快照属于私有采集信息。聊天可读正文、收到的明确位置，不等于获准读取对方设备、背景音或自动采集位置；沿用当前记录与会话的权限校验。
6. 发送前后采集均不阻塞输入。此次只保留活动输入时的单点缓存，未做移动轨迹采集，也不要求为轨迹新增字段。

## 会话内位置：当前可用与后续优化

当前实现详见 `docs/conversation-locations.md`。插件本地 `search.conversation-locations` 适配已有个人 feed、未分类、主题记录及聊天时间线，按分页独立扫描；本人快照地点来自原始创建版本，收到的位置只来自当前聊天明确共享的正文。地图展示已检查进度，读完才声明完整，失败保留重试。

历史很大时，首次扫描仍受历史页数和旧记录快照读取速度影响。若已有统一索引，请提供支持以下范围的合同；没有时再评估新增：

- 发给自己全部／未分类／具体主题及有权查看的子主题；私聊／群聊固定当前会话。
- 本人消息的原始快照位置与正文明确发送的位置区分；收到的位置只用明确共享内容。
- 发送出现位置的稳定身份、消息发送／挂载时间、日期与时区、分页及完整性、当前用户权限过滤。
- 原始地点与后续编辑地点区分；删除、撤回、移出主题、隐私锁及撤权后，索引和游标及时失效。

不要仅从全局地图取点后在前端过滤来冒充精确会话范围，也不要因此开放他人的自动采集位置。

## 无需重复建设的部分

- 消息详情“已编辑”在全部与主题不一致，已从前端详情读取和投影链路统一处理。
- 原消息、详情、评论的局部引用展示，以及聊天延展超过 100 条的分页，已补前端／Host 消费。原文引用汇总仍需要上表所述合同。
- 重新编辑和详情延展已即时显示本地提交状态，后续确认成功、失败或结果不确定；结果不确定先核对，不盲目重复发送。不需要为 UI 变流畅重新建设发送接口。
- 附件菜单顺序已统一为本地文件、云端文件、即我文档、视图库，复用已有资源搜索和长文合同；执行端仍需按当前用户验证资产权限。
- 录音横向时间轴、全天说话人与统计已独立读取完整当天的紧凑概览，不再依赖转写正文滚动；播放／暂停和紧凑浮框是前端交互改动。
- 托管模型已有 `catalog_release_id / offering_revision_id / supplier_code`，插件已补消费，不应重复开发；这些字段不能替代实际模型运行版本。
