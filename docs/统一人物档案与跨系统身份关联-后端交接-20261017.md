# 统一人物档案与跨系统身份关联：后端交接

日期：2026-10-17。范围：Arkme 插件的关系人物、即我联系人、录音中手动标记的说话人。本文是待实现协议建议，不能当作线上已支持接口；本轮未修改、部署后端。

## 1. 目标与已完成前端

同一个现实中的人应有一个用户可理解的人物档案，汇总其联系人、录音身份和关系记录。一个人可以没有即我账号，也可以有多个录音身份、别名和导入身份。

第一期已在「探索 → 关系 → 人物」增加聚合目录：

- 三类资料独立读取，先到先显示；详情标题、概述先显示，相关原文分批加载、按来源去重。
- 仅以已保存的同一账号 ID 汇总。没有账号关联时，各实体/说话人单独保留，即便名称一样也不合并。
- 显示名优先联系人备注，再使用已标记的说话人名称，再回退联系人昵称/关系名称；其他称呼可搜索。
- 已关联身份可查看来源，打开私聊、最近出现的录音日期、定位原文。相关记录明确表示“提及或关联此人”，不冒充本人发言。
- 录音标记弹窗增加「从人物档案选择」，选择已有录音身份或已有即我联系人，回原弹窗确认范围后通过原标记接口保存。
- 仅有关系实体、未关联录音/联系人身份的人物暂不能直接选来标记。明确提示原因，不偷偷复制出同名说话人。
- 新增关联、解除关联、合并撤销尚未开放写入。现有聚合不修改后端实体，也不是声纹训练。

当前插件 `people.list` 是宿主读适配，不是后端新接口。返回的 `personKey` 是按环境、当前账号、本地密钥生成的 HMAC 读投影键；不稳定跨设备，不得持久化为服务器 person_id，也不能作写入授权凭证。

## 3. 建议数据模型

复用现有关系身份目录能力，补齐稳定的 owner-scoped person_id 和 identity binding。具体表名由后端确定，不要求新建与现有目录平行的另一套人库。

- Person：owner_user_id、person_id、display_name/用户备注、aliases、avatar、revision、created_at/updated_at、status。
- Binding：person_id、source_type、source_id、owner_user_id、status、evidence_kind、provenance、confirmed_by、confirmed_at、revision。
- source_type 至少区分 arkme_user、relation_entity、audio_speaker；未来再扩展带命名空间的 imported_contact。不同来源 ID 不可直接比较。
- 一个 Person 可绑定多个音频 speaker_id/实体。未注册人物同样有稳定 person_id。一个有效来源身份在同一 owner 下只能有一个当前归属。
- 外部账号 ID 相等只是该 owner 下的强关联证据。跨用户共享人物档案、自动公开关系、授权声纹使用不在此功能中。
- 区分用户明确确认、旧系统绑定、AI 推测、已否认。AI 推测只产生建议，不能覆盖人工决定。用户拆开后保留 cannot-link 证据，避免任务重跑再次合上。
- 同名/近音/声纹接近都不能单独触发跨系统人物合并。声纹一致性审查与手动标记保持独立。

## 4. 建议读接口（名称为建议，待后端约定）

1. 人物目录：游标分页、关键词及来源过滤，返回稳定 person_id、显示名来源、aliases、已绑定身份摘要、counts、revision；不能要求客户端拿完数万条再显示。
2. 人物详情：概述与身份关系优先返回。聊天/录音/被提及记录使用独立分页读取；每部分携带 loading/partial/error 或完整性信息。
3. 关联候选：返回候选身份、匹配依据与冲突。名称相似只能作为“可能是同一个人”的提示。
4. 能力声明：identity_link、unlink、merge_preview、undo、speaker_assignment_by_person 等独立能力；缺少能力应明确返回不支持。
5. 每条原文保留 source_ref、source_kind、原始时间、所属会话/录音日期与定位字段。读取原文时继续核验当前用户权限，失效/删除/无权限与网络错误分开。

## 5. 建议写接口及一致性

### 关联 / 解除

支持 relation_entity ↔ audio_speaker ↔ arkme_user ↔ person 的显式关联。先 preview，显示受影响身份和记录数量、冲突及显示名变化，再 commit。

请求包含 owner 认证、目标 person_id、具体 source_type/source_id、expected_revision、idempotency_key。不能信任客户端传 owner、昵称或 personKey 代替鉴权。解除关联只改变对应身份关系，保留原文及现有来源 ID；必要时创建独立人物承接身份。

### 合并 / 撤销

合并保留原人物/身份 ID 的可解析别名与操作日志，不物理删除原始消息/录音/实体。返回 operation_id、状态、revision、受影响范围与是否可撤销。撤销应恢复本次操作的边和字段，不能覆盖操作后用户的独立修改；存在冲突时返回可审查的冲突信息。

跨 relation/audio/chat 采用可重试的事务事件/outbox 或等价一致性机制。前端即时更新已确认返回的人物视图；后台处理未完成要显示同步状态。幂等重试不得创建重复人物或说话人。

### 录音标记

支持直接把片段/当天系统组标给 person_id，无账号人物也可复用一个正式 speaker 身份。绑定账号不等于声音来自该账号，更不等于本人认领或同意声纹训练。人工标记范围、声纹学习状态、学习是否成功分别返回。

## 6. 人物时间线口径

每条内容明确 role：author（线上作者）、speaker（录音发言者）、mentioned（被提及）、participant（通话等参与者）。例如甲在录音里说“周鹏明天来”，这条可出现在周鹏的“被提及”，不能算作周鹏的发言或声纹样本。

优先按事件发生时间排列，另外保留上传时间、识别完成时间。一次录音原文被同一人物提及多处，列表按原始来源/稳定记录键合成一张卡，保留各提及位置。播放媒体/环境声仍标明来源，不转为现实交流关系。

## 7. 历史回填

- 先 dry-run 输出总量、可精确绑定、冲突、待人工确认数量；不把个人样本 JSON 当成全量迁移数据。
- 仅同 owner 且已有相同有效 linked_user_id/ref_usr_id 的身份可精确候选；空值、同名、别名、近音一律不自动绑定。
- 校验旧绑定来源可信性与冲突；历史错误关联可留待人工审查，不以批量操作覆盖。
- 分批、幂等、可中断恢复；记录迁移版本和每次映射事实，支持回滚。
- 保留 entity_id、speaker_id 和原文定位引用。旧客户端仍可读，计数区分“人物数”“身份数”“匿名系统说话人数”。

## 8. 验收重点

- 备注/昵称/手动说话人名不同，但相同已绑定账号 → 一张人物档案；同名两个独立人 → 两张。
- 无即我账号的人也能连接关系实体和多个录音身份，不制造同名副本。
- 关联、解除、撤销后所有入口与刷新/换设备一致，旧来源跳转可用。
- 某个来源慢或失败，其余内容立即可用；游标稳定，记录不重复，不能把未加载当作 0。
- 重复提交、跨账号引用、旧 revision、已删除身份、冲突映射均有明确结果。
- 不自动发送消息、不增加原文可见范围、不隐式训练声纹；误认纠错后不能静默重新合并。

## 9. 当前实现边界

前端正式说话人目录使用 get-speaker-ls，不包含一万多个尚未命名的识别分组全量；后者继续使用现有“已识别说话人”入口。当前关系源复用现有 list 读取（limit=10000），需要后端提供真正按人物分页的聚合接口，以避免全量规模限制。联系人读取仍受既有目录/头像查询耗时影响，但不阻塞其他人物来源显示。
