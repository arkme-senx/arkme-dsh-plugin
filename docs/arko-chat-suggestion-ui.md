# 私聊 Arko 回复建议

旧 Flutter 桌面端的 `chat_thought_inline_widget.dart` 和 `chat_thought_dialog.dart` 使用紧凑摘要与独立建议弹窗。Browser UI 原先把完整建议直接铺在消息流中，并复用了普通消息详情，导致候选、分析和多个“填入输入框”同时出现，且把建议算作真实延展回复。

本次按已确认的交互收敛：消息下仅显示 `Arko有想法`、一句判断和一行建议；展开后展示一张候选卡片。“换一句”只切换已返回的候选，不触发生成；“填入输入框”沿用主输入框的草稿和焦点逻辑，不发送消息。分析默认折叠，私密提示显示一次。普通详情中的建议入口打开同一弹窗。

## 能力与资源边界

| 能力面 | 本次范围 |
| --- | --- |
| UI | 仅重组 scene 5 回复建议的展示和本地选择状态；保留真实 Arko 回复、续答和发给自己的入口 |
| Tools | N/A：未新增 Host 查询、写入或业务能力，继续使用现有已授权想法查询 |
| SDK | N/A：未新增公开业务能力或改变数据合同 |
| Host owner | 不变，沿用账号及消息签名绑定的 `chat.thoughts.query`；读取不会触发生成 |
| Client/Harness | 不修改桌面宿主或 DSH；通过现有 Browser module 和共享弹窗装配 |

每个 workspace 的 `RecordThoughtStore` 仍是唯一读取、批处理、轮询和重试 owner。弹窗增加的观察者共享同一结果，不创建第二个网络 owner。最多打开一个建议弹窗；账号、对话、启用状态改变或建议失效时立即关闭。候选队列来自 Host 已限制数量的结构化字段，去除空白及重复项；旧格式回退正文。相同结果的后台刷新保留候选、展开状态与焦点，新一代结果重置候选。

同一账号和稳定会话身份下，名称或备注造成签名引用更新时保留 Store 和展示状态，取消旧引用的读取，并使用新引用重校验。旧 Store 的读取闭包绑定自己的引用持有者，不跨账号或会话复用；没有稳定身份时按引用区分。缺失聊天引用时不发起查询，也不回退个人记录接口。自有快记仍可在主题间共享账号内缓存。

仅临时读取失败保留快照；明确不可重试、响应账号不符或其他非临时错误清除正文、流式暂存和待执行焦点意图，关闭建议。被拒绝后，旧流式片段也不能恢复正文，直到当前 owner 读取成功。请求取消与代次检查阻止旧引用的成功或失败结果晚到覆盖当前结果。仍使用原有批量上限、定时器和退避，不新增网络 owner。

建议不计入真实延展数，也不作为“回复 Arko”的目标。主输入框不可用、正在重新编辑或会话只读时，填入按钮禁用。共享弹窗的遮罩不再触发下层详情的外部点击关闭；焦点循环包含原生 summary，Esc 归最上层弹窗处理。关闭时通常恢复入口焦点，操作已主动转移到输入框等目标时尊重该目标，避免清理逻辑抢走焦点。

## 验证范围

回归覆盖摘要与详情共享入口、本地候选切换、重复和旧格式候选、刷新失败恢复、代际切换、账号及会话切换、显式失效、停用后重新启用、禁用填入、真实回复计数、遮罩层归属与键盘访问。

本地不可变包安装和真实页面验收记录保存在任务交付证据中；自动化通过不代表已安装客户端或生产端已升级。此次没有后端变更。
