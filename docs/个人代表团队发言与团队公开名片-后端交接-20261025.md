# 个人代表团队发言与团队公开名片：后端交接

日期：2026-10-25。此文更新“团队必须先入群才能选团队身份”的旧约束，以本文件为准。与 [双向团队私信](./双向团队私信-后端交接-20261025.md)、[团队内部群](./团队内部群与成员自动同步-后端交接-20261025.md)、[团队正式入群](./团队入群与发言身份-后端交接-20261025.md) 共用团队与实际操作者模型。

## 产品规则

本人已经在群里，并且真实创建或加入了一个团队，就应能从个人身份切到“我代表这个团队”。团队无须先成为群成员；无需额外管理员角色。仅申请中、已退出、已移除的团队不参与候选，不能用昵称、个人快记角色或自填团队名称代替真实成员关系。

这与团队正式加入群聊分开：

| 场景 | 可选身份 | 同事是否因此可读群 |
| --- | --- | --- |
| 本人入群，无所属团队 | 本人；不显示选择器 | 否 |
| 本人入群，真实属于团队；团队未入群 | 本人、代表所属团队 | 否 |
| 团队正式入群，本人也入群 | 本人、代表团队；访问仍按各自资格 | 已获授权同事按团队入群范围可读 |
| 团队正式入群，本人未个人入群但可代理访问 | 代表获授权团队，无个人发送选项 | 按团队代理权限 |
| 与团队名单绑定的内部群 | 本人，无身份切换 | 按内部群成员规则 |

不能因为当前群成员恰好都是同事而当作内部群。代表团队发言本身不向团队目录添加这个群，不邀请同事，不推送群历史给同事，也不自动归集群上下文到团队私信。

## 已完成的前端与当前限制

普通群输入框沿用个人快记角色选择器的交互：收起时“本人头像＋我＋下拉”；菜单为“我／个人身份”和“我 · 团队名／代表团队发言”，团队候选仍保留本人头像及团队角标。团队列表来自当前账号的真实 list-mine，进入群、打开菜单、窗口恢复焦点时核验，不增加高频轮询。刷新期间保留已有入口；旧团队选择暂不可点击。账号、群或成员资格变化后旧结果不再应用。

**真实团队发送尚未接通。** 点击团队先打开身份预览：本人头像、真实姓名、可点击团队标识；显示“后端接口开发中，开发完成后此功能完整可用。”以及“尚未切换，仍以个人身份发送；草稿已保留。”不会调用个人发送来冒充团队，也不会把普通消息本地伪装成团队消息。

预览的团队标识打开可复用的团队资料卡，显示真实公开名称、头像、即我号及“联系团队”。当前未取得公开简介，不编造简介。

- 本人所属团队：复用现有成员接口取得已开放通道的公开引用，联系按钮走既有团队入口；成员进入团队收件箱。仅浏览名片不打开会话、不发送消息。
- 外部查看者：公开发现接口可返回团队基本资料，但缺少公开通道定位字段，所以保留明确的开发中提示，不能冒用成员接口查询。
- 通道已关闭：明确提示“该团队暂未开放消息通道。”，不能与接口缺失混为一谈。
- 请求失败可重试，切账号／团队后晚到响应被忽略。

这次没有真实群消息代表身份落库、所有收件人可见的消息徽标、跨设备身份同步及内部群绑定能力。前端预览不代表这些功能已上线。

## 当前插件 Host 边界

| 操作 | 当前实现 | 后续接入 |
| --- | --- | --- |
| `team.app.group.context` | 校验账号及签名 group_chat 引用、读取 list-mine；返回 backend_pending、membershipPolicy:unknown、真实 teams | 补群绑定、个人群资格、团队成员版本、个人代表与团队代理访问能力；不能把 backend_pending 改成 ready 就算接通 |
| `team.app.public-card` | 请求 expectedAccountKey、jotmoId；公开字段投影，响应 name/jotmoId/avatar/contact | 外部可访问的公开团队资料和通道定位，返回真实业务状态 |

`public-card` 对所属团队先读 `/api/v1/team/list-mine`，再用可信 team_id 读取 `/api/v1/team/message-channel/get`；核对返回团队即我号。对外部团队只走现有 `/api/v1/team/discovery/search`，不调用成员专用通道配置接口。两者均仅投影必要公开字段，不返回团队成员列表、审批、内部设置或管理凭证。

当前 `contact` 是三个明确分支：`available + publicRef`、`disabled`、`backend_pending`。插件使用既有 `openTeamMessages({kind:'link',publicRef})` 导航。`/api/public/v1/team/message-channel/resolve` 要求已有 public_ref，不能由 jotmoId 猜出，因此不能替代待提供的公开定位能力。

## 后端协议需求

以下是能力建议，HTTP 路径由后端确定，前端没有调用不存在的上游路径。

### 个人代表身份与消息写入

1. 群上下文分别返回：`membership_policy`、当前用户个人群资格、有效团队及成员版本、团队是否已入群、代理访问资格。**个人代表身份不以 team_group_membership 存在为条件。** 团队代理访问是另一个能力。
2. 普通群消息发送支持 `represented_team` 与 `group_access_kind: personal_membership | team_delegation`；实际操作者来自认证态，不能信任客户端 actor id。个人路径重新检查本人在群内、真实团队成员资格、群禁言及正常发送权限；代理路径额外检查团队已入群、授权及历史边界。
3. `request_uid` 绑定账号、群、实际操作者、代表团队、内容／附件／引用；重复请求返回同一原消息，参数变化返回冲突。网络未知结果可查询，重试不降级成个人发送。
4. 消息保留实际操作者与代表团队两个事实。所有有权读取的群成员都收到同样的团队归属，个人头像名称依现有展示规则投影，私人备注按查看者解析，禁止外传。
5. 建议身份字段：`actual_actor_user_id`（服务端）、`represented_team_id`、`actor_team_membership_revision`、`group_access_kind`；只有代理路径才要求 `team_group_membership_uid/revision`。历史归属保存当时事实，退出团队或改名不改写原消息身份；当前团队资料另行读取。
6. 编辑、撤回、删除、发送信息、引用、转发、复制链接、导出、搜索和附件读取必须保持正确身份及原权限，不能只有主发送路径支持。

前端接入真实发送时：个人为默认；团队选择在当前账号、群及入口上下文内保存。两种身份各自保存草稿、附件、引用、上传和输入统计。切换不挪用个人草稿，权限失效拒绝发送并保留草稿，不自动换为个人。团队内部群始终按本人发送，不出现选择器。

### 消息上的团队标识及公开名片

消息使用实际发言人的头像与查看者备注优先的名称，另有团队标识；自己与别人都能看出是“这个人代表这个团队”。同团队其他成员消息仍按他人消息呈现。点击个人头像沿用个人资料；点击团队标识打开团队公开名片，两个目标不能混淆。

公开资料接口需允许有合法入口的外部用户访问，返回团队稳定标识、真实名称、头像、公开简介（若设置）和通道联系状态。不得返回成员名册、内部项目、私聊或配置。消息团队标识由服务端写入／签发，不信任消息正文里的自填标签。

公开联系定位需返回稳定 public_ref 或签名导航引用，并明确 `available / disabled / unavailable`，技术未接通与业务停用分开。匿名是否可读基本资料由后端定义；发起联系沿用登录、拉黑、接收规则和限流，不绕过现有权限。

点击“联系团队”复用 `(team, current_user)` 的既有团队通道；本人是该团队成员时进入团队收件箱。阅读名片不创建空会话、不发通知；点击联系只打开会话，首条消息仍由用户明确发送。团队解散、已关闭、被限制及不可访问要有真实错误状态，不能跳成个人私聊。

### 同步与群内容可见范围

个人代表团队发言仍属于原群的一条消息。团队未入群时：回复通知实际发言人，不自动出现 @团队 的群成员对象、不自动给同事发群提醒、不把原群上下文拷入团队通道。用户通过名片主动联系团队后，团队才在该通道共同处理其明确发来的内容。

团队正式入群后的共享、@团队、代理群窗口及来源引用归集按另一份入群文档执行。所有来源查看仍检查群权限；不能用“代表团队”作为向同事开放整个群的捷径。

后端提供团队成员变化推送后，客户端收到事件刷新上下文。发送时永远重新鉴权；跨设备同步原消息身份，避免只在发送设备显示团队角标。

## 优先级与验收

顺序：双向团队私信闭环 → 个人代表团队发言＋公开名片联系 → 团队内部群名册同步 → 团队正式入群＋代理访问 → 群互动引用归集。

重点验收：

- 团队未入群、本人已入群且是普通团队成员时可以代表发送；无团队、仅申请中、已移除不能伪造身份。
- 本人、其他群成员、其他设备看到同一真实操作者与团队；同事未入群不能因此读群。
- 内部群没有身份切换；一般群不会因成员碰巧相同被判内部群。
- 选择菜单紧凑，多个团队名称清楚；已选团队失效、禁言、上传期间切换、离线重试不串身份、草稿或附件。
- 外部查看者可从可信消息徽标看公开资料、联系同一个团队通道；没有成员配置权限也能完成，不泄露私有资料。
- 名片加载、重试、关闭、换账号／目标、通道关闭、团队解散、无简介和无头像均有正确状态。
- 当前 backend_pending 前端不得显示团队发送成功、跨设备已同步或假造消息徽标。
