# Codex 对话入口显示规则

## 产品规则与已实现范围

第二栏 Codex 入口默认隐藏，不因登录、加入团队、打开团队页、查看同事任务、生成/复制接入指令或开启上传而出现。

以下任一有效证据可激活当前账号的入口：

1. 本机团队接入实际收到有效 Hook 事件。仅写入配置、尚待信任或尚未收到事件，不算接入成功。
2. 当前账号通过现有云端 `tasks/list` 的 `view: self` 查询到本人任务。换电脑只读无需重新配置采集或开启上传。

已确认的入口状态按账号存入环境隔离的本机日志数据库，只记布尔资格和确认时间，不保存对话正文。暂停、离线或断开采集不隐藏已有入口。切换账号/退出登录立即隔离，迟到响应不能激活另一个账号。入口状态只控制导航，不能替代任务读取权限或上传授权。

## 实现

- 新增插件本机只读桥接操作 `team.codex.entry-availability`，入参 `expectedUserId`，返回 `{userId,visible,checked}`。
- 新用户未知/失败时隐藏，不把网络失败解释为绑定成功。
- 本机已确认状态直接读取；未确认时云端使用现有 `POST /api/v1/team-codex/tasks/list`，请求 `{view:"self",page:1,limit:1}`，严格核对 owner/source/task/team 标识。
- 云端空结果或失败检查间隔至少 30 秒；页面可见且对话列表激活时每 5 秒检查本机状态，返回对话页立即检查。不会额外开启采集、读取历史事件或上传。

## 后端剩余缺口（不是已上线接口）

当前合同没有独立的账号级「已绑定 Codex」读取接口。**设备 A 已接入但尚未产生任何云端任务，首次登录的设备 B 无法仅凭现有接口确认该绑定**；本轮不伪造绑定状态，设备 B 会在首条本人云端任务可查询后显示入口。

建议后端增加轻量的账号级接入状态，路径由后端确认，语义至少为：

```json
{
  "owner_ref": "当前鉴权用户 ID",
  "has_connected_codex": true,
  "first_connected_at": 1790790000000
}
```

- 绑定成功由真实接入确认/来源登记驱动，不能只凭客户端生成邀请或开启上传置为 true。
- 必须按登录账号及环境返回；无需客户端指定其他成员或团队。
- 暂停/离线保持历史接入标记，上传开关仍独立。
- 若要在无任何任务时支持跨设备显示，需要配套的来源接入确认，而不只是新增读取接口；不能自动上传正文来制造可见证据。
- 后续接入此状态时保留已有本机确认标记，避免已使用账号在升级或暂时离线时入口消失。
