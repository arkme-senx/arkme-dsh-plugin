# 团队消息交互统一与后端缺口

日期：2026-10-18。范围：Arkme 插件团队消息通道，包含团队成员视角与外部用户视角。

## 本轮前端与本机适配

- 团队消息使用普通对话的 `ArkmeMessageContent`、`ArkmeMessageTextSelectionToolbar`、`ArkmeMessageContextMenu` 和复制方法。
- 选区优先于整条消息操作；松开鼠标即出现「复制 / 全选 / 标记」，全选仅作用于当前消息正文。
- 文字标记沿用 `MessageUnderlineSession`、原文锚点及高亮层。重复点击已标记部分可取消自己的标记。
- 存储复用插件 SQLite `LocalMessageMarkStore`，按环境、当前账号、团队会话与查看身份隔离。刷新和重启后保留；不会同步给其他团队成员或外部用户，界面明确标注「仅本机」。
- 三个 `team.app.local-mark.*` 操作是插件 Host 本机接口，不是生产 Team 后端接口。它们只接受插件从已授权团队消息生成的加密快照引用，校验账号、会话、身份、原文摘要、版本和选区；不接收或生成普通 Chat 的 actionRef。
- 本机标记依附于读取时的授权内容快照。原文修改后不猜测迁移位置，而显示未定位标记；删除或失去访问权限后移除对应正文及标记展示。本机保存本身不发起云端修改。
- 无选区时，团队消息菜单按实际权限显示复制、编辑、删除、阅读状态。共享的交互代码不绕过 Team 的访问与媒体授权。

## 后端尚需闭环的能力

### 1. 整条引用和部分引用回复

当前插件 `TeamAppService` 的旧 `team.app.send` 路径存在 `replyToRef → reply_to` 转换，但实际使用的持久发送队列 `TeamSendInput` 未包含引用字段；`TeamMessage` 也未投影原消息/选区引用。因此不能仅添加按钮就视为支持完成。

建议 Team 协议提供：

- 被引用的 `conversation_uid + message_uid`，可选选区锚点。
- 选区沿用 `version=1, projection=arkme-text-v1, sourceDigest, recordVersion, start, end, text, prefix, suffix`。偏移为规范文本 UTF-16 偏移，不是 Markdown 源码偏移。
- 服务端校验引用属于当前会话、双方当前可访问、版本/摘要/选区吻合；身份由服务端确定。
- 消息投影返回引用状态：原文可访问、已修改、已删除/不可访问；不能向无权限方返回历史快照。
- 引用字段贯穿排队、持久化、恢复、幂等、重试、发送结果及消息列表；不可在上传或恢复过程中丢失。
- 点击引用可分页定位原消息。上线前同时验证成员视角、外部视角、消息修改/删除和权限撤销。

### 2. 多方共享标记

目前仅本机，不能把本地结果当成已同步。后端需明确共享范围：内部成员可见的标记与允许外部用户看到的标记是否分开。第一版应显式指定范围，不默认暴露内部标记。

建议提供能力查询、完整快照、增加/取消标记与变更通知。快照包含 revision、accessible、annotation uid、作者、锚点及原文状态；写入含 operation id 支持幂等，只能取消自己有权取消的标记。重试、乱序事件和多个窗口不得恢复已取消标记。原文修改不得静默把标记挪到近似文字。

现有本机标记不会自动上传；迁移到共享需要用户明确操作及后端重新校验来源与可见范围。

### 3. 转发、消息链接等操作

Team 消息和普通私聊/群聊的身份与权限协议不同。转发、分享链接、多选批量云端操作必须由 Team 后端明确支持目标权限、来源可见性、附件访问、幂等和结果核对后再开放。不能把团队签名引用直接交给 Chat 接口，也不能把无法授权访问的附件地址直接复制给目标用户。

## 前端回归重点

1. 选中一部分文字后立即出现工具条，复制仅得到选区；右键不会切换成整条复制。
2. 全选不包含昵称、时间、阅读状态及附件按钮；Markdown 选区不混入源码标记。
3. 未选中文字时菜单只显示有权限的操作，外部视角不暴露内部阅读者名单。
4. 标记后刷新仍在，点击可取消，取消后刷新不复活；普通私聊/群聊不受影响。
5. 切换会话、账号和原文版本后旧选区失效；等价后台快照不打断选区。

本轮不修改或部署生产后端，不自动合并 dev/master。

## 本轮验证记录

- 12 个相关测试文件通过：218 项通过、1 项既有跳过；类型检查、打包及打包后 worker 校验通过。
- 3102 使用当前登录账号，在真实团队内部会话验证了选区自动工具条、右键选区优先、剪贴板仅含选区、整条消息菜单、标记和取消。
- 整页刷新并重新进入原会话后，已保存标记仍可点击并取消；取消后再次整页刷新，选区恢复为「标记」状态。临时标记已清理，没有发送、编辑或删除真实消息。
- 现场发现并补齐回归：父组件的等价刷新替换消息展示对象后，旧对象引用判断会拦住标记。改为验证消息身份、权限引用、版本和原文内容，新增测试覆盖。内容真正变化时仍拒绝旧选区。
- 本轮实机页面验证的是团队成员视角；外部视角权限边界由组件和适配层测试覆盖，未切换外部账号做端到端验证。
