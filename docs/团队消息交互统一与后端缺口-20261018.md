# 团队消息交互统一与后端缺口

日期：2026-10-18。范围：Arkme 插件团队消息通道，包含团队成员视角与外部用户视角。

## 本轮前端与本机适配

- 团队消息使用普通对话的 `ArkmeMessageContent`、`ArkmeMessageTextSelectionToolbar`、`ArkmeMessageContextMenu` 和复制方法。
- 选区优先于整条消息操作；松开鼠标即出现「复制 / 全选 / 标记」，全选仅作用于当前消息正文。
- 文字标记沿用 `MessageUnderlineSession`、原文锚点及高亮层。重复点击已标记部分可取消自己的标记。
- 存储复用插件 SQLite `LocalMessageMarkStore`，按环境、当前账号、团队会话与查看身份隔离。刷新和重启后保留；不会同步给其他团队成员或外部用户，界面明确标注「仅本机」。
- 三个 `team.app.local-mark.*` 操作是插件 Host 本机接口，不是生产 Team 后端接口。它们只接受插件从已授权团队消息生成的加密快照引用，校验账号、会话、身份、原文摘要、版本和选区；不接收或生成普通 Chat 的 actionRef。
- 本机标记依附于读取时的授权内容快照。原文修改后不猜测迁移位置，而显示未定位标记；删除或失去访问权限后移除对应正文及标记展示。本机保存本身不发起云端修改。
- 无选区时，团队消息菜单复用普通对话的统一命令顺序、文案和图标；多选、复制、重新编辑、消息详情及权限允许的批量删除可用，内部成员继续保留阅读状态入口。缺少完整团队协议的操作置灰并显示原因，不绕过 Team 的访问与媒体授权。

## 后端尚需闭环的能力

### 1. 整条引用和部分引用回复

当前插件 `TeamAppService` 的旧 `team.app.send` 路径存在 `replyToRef → reply_to` 转换，但实际使用的持久发送队列 `TeamSendInput` 未包含引用字段；`TeamMessage` 也未投影原消息/选区引用。因此不能仅添加按钮就视为支持完成。

建议 Team 协议提供：

- 被引用的 `conversation_uid + message_uid`，可选选区锚点。
- 选区沿用 `version=1, projection=arkme-text-v1, sourceDigest, recordVersion, start, end, text, prefix, suffix`。偏移为规范文本 UTF-16 偏移，不是 Markdown 源码偏移。
- 服务端校验引用属于当前会话、双方当前可访问、版本/摘要/选区吻合；身份由服务端确定。
- 消息投影返回引用状态：原文可访问、已修改、已删除/不可访问；不能向无权限方返回历史快照。
- 引用字段贯穿排队、持久化、恢复、幂等、重试、发送结果及消息列表；不可在上传或恢复过程中丢失。
- 点击引用可分页定位原消息。上线前同时验证成员视角、外部视角、消息修改/删除和权限撤销。

### 2. 多方共享标记

目前仅本机，不能把本地结果当成已同步。后端需明确共享范围：内部成员可见的标记与允许外部用户看到的标记是否分开。第一版应显式指定范围，不默认暴露内部标记。

建议提供能力查询、完整快照、增加/取消标记与变更通知。快照包含 revision、accessible、annotation uid、作者、锚点及原文状态；写入含 operation id 支持幂等，只能取消自己有权取消的标记。重试、乱序事件和多个窗口不得恢复已取消标记。原文修改不得静默把标记挪到近似文字。

现有本机标记不会自动上传；迁移到共享需要用户明确操作及后端重新校验来源与可见范围。

### 3. 转发、消息链接等操作

Team 消息和普通私聊/群聊的身份与权限协议不同。转发、分享链接、多选批量云端操作必须由 Team 后端明确支持目标权限、来源可见性、附件访问、幂等和结果核对后再开放。不能把团队签名引用直接交给 Chat 接口，也不能把无法授权访问的附件地址直接复制给目标用户。

## 前端回归重点

1. 选中一部分文字后立即出现工具条，复制仅得到选区；右键不会切换成整条复制。
2. 全选不包含昵称、时间、阅读状态及附件按钮；Markdown 选区不混入源码标记。
3. 未选中文字时菜单只显示有权限的操作，外部视角不暴露内部阅读者名单。
4. 标记后刷新仍在，点击可取消，取消后刷新不复活；普通私聊/群聊不受影响。
5. 切换会话、账号和原文版本后旧选区失效；等价后台快照不打断选区。

本轮不修改或部署生产后端，不自动合并 dev/master。

- 整页刷新并重新进入原会话后，已保存标记仍可点击并取消；取消后再次整页刷新，选区恢复为「标记」状态。临时标记已清理，没有发送、编辑或删除真实消息。
- 现场发现并补齐回归：父组件的等价刷新替换消息展示对象后，旧对象引用判断会拦住标记。改为验证消息身份、权限引用、版本和原文内容，新增测试覆盖。内容真正变化时仍拒绝旧选区。
- 本轮实机页面验证的是团队成员视角；外部视角权限边界由组件和适配层测试覆盖，未切换外部账号做端到端验证。


## 2026-10-18 后续：整条消息菜单和多选统一

### 已完成的插件改动

- 普通群聊/私聊与团队通道共同调用 `conversationMessageMenu`；图标定义移出 Sidebar，后续统一在一处维护。
- 批量操作栏共用 `ArkmeMessageSelectionBar`，勾选控件共用 `ArkmeMessageSelectionControl`，框选共用 `RegionMarquee`，详情复用 `ArkmeDetailShell` 与团队授权的正文/附件组件。
- 团队消息右键「多选」后勾选当前消息，支持逐条选择、取消和空白区框选。账号/会话切换时销毁状态；等价授权引用刷新、接收新消息和加载历史不会改变已有选择。删除或丢失访问权限的消息会移出选择。
- 多选期间隐藏但保留输入草稿，退出多选或按 Esc 后恢复。部分文字选区仍优先，不能意外触发整条复制或打开详情。
- 单条复制文本与群聊规则一致；批量复制链接、转发、问 DSH 当前不可用。批量删除仅允许 1–100 条全部有权删除的消息，不能只处理其中一部分而不告知用户。
- 批量删除复用现有 `team.app.delete`，每条携带 Team messageRef、版本和当前账号，串行限制请求量。确认后先播放共享碎片动画、从列表移除；后台逐条同步。失败或结果不明的条目恢复，显示成功/未确认数量与「刷新核对」。已经确认的删除不会被旧快照恢复；新版本的恢复内容可重新显示。
- 确认弹窗期间内容或删除权限变化会停止提交，要求重新选择，不会自动删除更新后的内容。退出会话/账号停止尚未发出的请求；已发出请求的结果由下次重新读取核对。
- 单击正文或右键「消息详情」打开同款侧栏，支持选区工具、标记、Esc 和点击外部收起；媒体读取继续走团队鉴权路径。

### 需要后端同事核对/补齐的完整能力

下面是**当前插件已接入协议的缺口**，不能据此推断其他后端分支绝对没有实现。若服务已有对应能力，请提供正式接口、权限定义和验收样例，再接通；不猜测 URL 或复用不兼容的 Chat 引用。

| 操作 | 当前状态 | 需要闭环的协议 |
| --- | --- | --- |
| 多选、复制文本、详情、编辑、删除、阅读状态 | 插件已支持，现有 Team API | 批量删除可继续复用单条接口；建议补结果查询/批次结果，便于断网、重启后的精确核对 |
| 整条/部分延展 | 入口暂不可用 | 原消息引用、选区锚点、队列持久化、幂等恢复、历史投影与点击定位；旧 send 的 reply_to 不能代表整条链路完成 |
| 表态 | 入口暂不可用 | 可见范围、表态快照/版本、增删操作、作者身份、实时通知；明确内部与外部可见性 |
| 复制链接 | 入口暂不可用 | 可分享的消息快照/访问规则，收件人重新鉴权，失效/删除后的行为；不能把本机签名引用作为公共链接 |
| 转发 | 入口暂不可用 | Team 到个人/私聊/群聊/其他团队的目标授权、文本及附件原件投影、幂等请求与部分失败结果；不能直接转用来源附件 URL |
| 问 DSH | 入口暂不可用 | 带权限校验的正文/原件导出，保留作者/来源信息；插件复用 DSH 输入准备器，但不得伪造 Chat actionRef |
| 举报 | 入口暂不可用 | Team 所属关系、可举报范围、原因/证据版本、去重、结果 |
| 撤回 | 入口暂不可用 | 已发布消息的撤回权限、期限、终态、双方占位与事件通知；`team.app.cancel` 仅为待发送取消，不能冒充撤回 |

建议消息投影返回逐操作能力（allowed + reason），并提供协议版本或能力查询。角色、是否本人、频道暂停、会话屏蔽、消息状态/版本变化都应重新计算。团队管理员是否能撤回他人消息不能照搬群管理权限。

### 接口验收重点

1. 内部人员和外部用户双向验证，不泄漏内部阅读者、内部标记或原件。
2. Team 加密引用仅交 Team；不把 messageRef/localMarkRef 传给 Chat 的转发、链接、举报等入口。
3. 消息内容更新、删除、撤回、人员移出团队、账号切换后，旧授权引用不能继续访问或操作。
4. 并发编辑/删除必须按版本拒绝，不静默操作新内容；断网重试与结果核对不能重复发送/转发。
5. 引用回复和转发必须覆盖纯文字、Markdown、图片、文件、语音及混排；原文不可访问时不显示私有历史快照。
6. 所有能力补齐前保持暂不可用，不能只新增按钮就宣称与群聊功能完全一致。
