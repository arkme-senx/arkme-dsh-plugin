# 团队成员身份与消息详情统一：后端补充交接

日期：2026-10-19。收件人：华焱。本文补充同日已发送的《团队消息通道后端协作汇总》，聚焦团队内部成员操作、个人备注、消息详情、相关快记及延展回复。

## 结论与本轮边界

插件已完成内部成员头像的用户卡片、发起个人私聊、右键查看该成员在当前团队对话中的快记；名称优先使用当前查看者给此人的私聊备注。消息详情已复用普通对话的作者信息及可拖宽侧栏，移除可见的“消息详情”标题，显示所在团队对话并可定位原消息。

**相关快记与延展回复尚未完成端到端接通。** 当前插件 Team 协议没有完整的受权限约束的来源映射、关联快记与引用返回结构，持久发送队列也没有贯穿引用信息。后端是否已有可复用实现，请先确认实际接口与字段；不能仅凭插件缺口认定生产完全没有该能力。前端目前明确显示“相关快记与延展回复暂未接通”，没有将普通发送伪装为延展。

本轮仅修改插件及其 Host 适配，没有修改或部署服务端，没有合入 dev/master。下文 `team.app.*` 均为插件内部操作名，不是需要后端新增的 HTTP 路由。

## 1. 成员身份与个人备注：已有能力复用

### 已完成

- 时间线发送者通过 `actor_user_id`、阅读名单通过 `members[].user_id` 关联到同一即我账号。头像和昵称不能作为身份键。
- 插件向界面提供按当前账号隔离的稳定 `personKey` 和受保护的 `personRef`；引用绑定查看者及原团队会话。
- `team.app.person.private.open` 先重新验证当前团队会话可访问，再调用现有 `ChatService.openPrivateChatFromUser`；不接受界面任意指定用户 ID，不开放外部侧内部成员私聊入口。
- `team.app.people.remarks` 批量复用 `SourceService.privateRemarksByUserIds`，每批最多 50 人。备注属于当前查看者，不写入团队共享昵称；加载失败不阻塞消息、不覆盖已知备注。
- 名称顺序：当前查看者的非空备注 → 公开昵称 → 原有兜底。备注清除后回到公开昵称；切账号时不复用另一账号的备注。时间线、人物卡片、详情、阅读名单使用同一映射。
- 当前账号自己的头像显示个人卡片及“看我的快记”，不出现向自己发起私聊的按钮。

### 请后端确认的稳定契约

1. `actor_user_id` 始终是实际发送成员的即我账号，而非团队 ID、会话 ID 或机器人代理账号。机器人、系统消息、已注销成员的身份要有可辨认类型；无法确认身份时前端仅展示，不猜测个人私聊目标。
2. `read-receipts/query` 的 `members[].user_id` 与 Chat 用户身份使用同一命名空间；资料变更不应改变身份键。
3. 外部访客稳定身份继续采用主交接文档的 `external_user_id` 方案。不要依赖最后一条外部消息一直存在。
4. 已退出团队、账号切换、会话删除、被屏蔽等情况仍需实时校验权限。旧页面拿到的引用不能绕过后续撤权。
5. 个人备注只返回给其拥有者；不得把内部成员对访客的备注展示给访客或其他同事。

若现有身份字段已满足，以上不需要新接口。返回名称时也不必让 Team 服务复制维护一套私人备注。

## 2. “看TA的快记”的范围

当前功能只展示**这个人发在当前团队会话中的消息**，标题有“当前团队对话”范围说明。内部成员按稳定人物键筛选，外部访客按会话外部发送侧筛选；不是该人全部私人快记。

现阶段沿用 `POST /api/v1/team/conversations/timeline/page` 分页后筛选。建议后端支持受会话权限约束的发送者筛选，返回筛选后的游标、`has_more`；不要让客户端为查看少量成员消息遍历全部历史。需要同时保留按原消息 UID 定位前后上下文的能力。原消息被删或失权应显示明确状态。

若要额外展示公开个人快记，请另行复用公开资料权限契约，明确区分“当前团队对话”与“向我公开的快记”，不能读取对方全部账号记录。

## 3. 消息详情与相关快记

### 前端已统一

- `ArkmeDetailShell`：普通对话与团队共用可拖宽侧栏、关闭及外部点击行为。
- `ArkmeMessageDetailAuthor`：共用头像、备注名、时间布局。
- 正文继续使用 Team 授权数据，支持现有文字选择、复制、标记等交互；附件仍走 Team 媒体权限。
- 来源标签显示“团队 · 对话对象”，点击收起详情并定位原消息。

### 需要补齐或确认的协议

普通 Chat 详情的动作引用不能直接套在 Team `message_uid` 上。请确认是否已有稳定的 Team 消息到快记来源映射；若没有，应提供明确协议，至少覆盖：

| 能力 | 最小返回/请求信息 |
| --- | --- |
| 详情能力声明 | 当前查看者可查看、关联、回复的能力；不可用原因 |
| 原消息来源 | Team 会话与消息稳定身份、版本、可见侧、来源类型；如可映射 Chat 快记，返回服务端验证的引用 |
| 相关快记分页 | 关联身份、关系类型、作者、创建时间、可访问摘要、可定位来源、游标及更多标识 |
| 单条读取/定位 | 在读取时再次校验权限；删除、失权、临时错误分开表达 |
| 关联更新 | 关联/取消权限、幂等操作 ID、版本冲突、结果核对；若本期只读则明确声明 |

“没有相关快记”“不支持此能力”“无权查看”“网络失败”不能都返回空列表。团队内部资料、外部可见消息、个人私密记录的可见范围由服务端决定，返回关联也不能顺带泄露不可见标题、正文或附件 URL。

## 4. 整条及部分延展回复：需要贯穿持久发送链路

现有插件 `team.app.send` 支持旧的 `replyToRef → reply_to`，但当前实际使用的 `TeamSendInput` 和 `TeamSendQueue.enqueue` 只保存会话、clientUid、expectedReplySeq、content、fileRefs；没有保存引用关系。仅修改一个发送接口不足以让用户重启、重试后仍得到真实延展。

建议优先确认后端已有引用模型，再补齐以下闭环，路由和最终字段名由后端与插件一起确定：

1. **发送目标和父消息**：会话身份、父消息 UID、父消息版本、整条/部分引用类型。只允许引用当前用户有权访问且适用于目标会话的消息；不能把 Team 引用当作普通 Chat 引用。
2. **部分引用**：沿用当前选区锚点 `version=1, projection=arkme-text-v1, sourceDigest, recordVersion, start, end, text, prefix, suffix`。偏移按规范文本 UTF-16 定义，不是 Markdown 源码偏移。服务端校验范围及摘要；不得无提示改成对另一次同词的引用。
3. **持久发送**：引用字段贯穿入队、落盘、恢复、上传附件、提交、重试及状态核对。网络超时后使用同一幂等 ID 查询结果，不能再次创建另一条延展。
4. **返回投影**：发送结果、时间线、详情、更新事件都返回已确认引用及其状态；客户端才能展示引用卡片、相关快记和原文定位。
5. **读取与分页**：原消息下面的延展列表提供稳定游标和可见范围。双方视图不同，不能将内部讨论默认发送给外部联系人。
6. **变更与撤权**：父消息编辑后标明引用已变化，删除/失权后保留适当状态而不泄露原文；不要静默将用户选区迁到语义近似内容。明确能否保留历史引文，以及保留规则。
7. **错误与回退**：返回版本冲突、原文失效、无权引用、发送失败等可区分状态。失败保留草稿及引用；不能悄悄降级为普通消息发送。

还需明确：这里的延展是否就是团队消息回复线程，还是需要额外创建快记关联。若已有产品语义，请给出一个真实但脱敏的请求/响应例子，避免前后端各自实现不同概念。

## 5. 联调验收清单

| 场景 | 预期 |
| --- | --- |
| 两名同事同昵称 | 头像私聊与当前团队快记准确区分，不按昵称归并 |
| 我为某同事设有备注 | 团队正文、详情、用户卡片、阅读名单同名；其他人仍看自己的名称 |
| 清除备注、换账号 | 回到公开昵称；不显示前一账号的私人备注 |
| 成员退出/会话撤权 | 旧引用不可继续获取私密消息或发起未经授权动作 |
| 详情拖宽、点头像、点外部 | 布局沿用普通对话；子卡片操作不误关闭底层详情；输入草稿保留 |
| 相关内容空/失权/失败 | 分别呈现，失败可重试，不将失败冒充无数据 |
| 整条或选中文字延展 | 发送后、重新进入及重启后都保留父子关系和精确定位 |
| 超时重试与客户端重启 | 同一幂等发送只产生一条消息，引用不丢失 |
| 原消息编辑/删除 | 引用状态准确，不静默重新定位到另一段文字 |
| 内部关联与外部视图 | 只返回各自可见内容，内部讨论和私人快记不外泄 |

请优先反馈现有接口/字段、权限说明和上线版本；已有能力直接接入，确实缺失再新增。会员状态、阅读时间、入口偏好同步及共享标记仍以同日主交接文档为准，本补充没有宣布它们已上线。
