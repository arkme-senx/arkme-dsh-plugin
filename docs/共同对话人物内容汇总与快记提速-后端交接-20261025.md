# 共同对话人物内容汇总与快记提速：后端交接

日期：2026-10-25

## 2026-10-26 状态更新：现有接口组合先行

此功能不再等待新的后端聚合接口才可用。插件新增本地 Host 会话发现操作 `source.person-records.sources`，组合现有 `/api/v1/chats/common-group/query`、`/api/v1/chats/list`、`/api/v1/chats/members/list` 和 `/api/v1/chats/members/records/page`。这不是新增的云端接口。

- 先展示入口对话的真实消息，再逐批发现并读取共同群聊及已有私聊。群聊入口也能发现已有私聊；没有私聊时跳过，不创建会话。
- 消息读取最多两路并发；每个会话保留独立 before_seq，不把不同会话的序号混为统一游标。首批其他来源取 3 条，继续阅读时按来源时间边界优先取更早内容。当前展示是已加载的部分历史，不称为完整历史或精确总数。
- 按真实发送时间混排，按来源与稳定发送事件去重；不同会话、同一 record 再次发送不合并。正文相同不构成去重依据。
- 每条保留自身会话引用；媒体、来源跳转均使用该条的原始来源，不能套用入口群引用。
- 共同会话发现游标绑定环境、账号、入口和目标人并签名。发现时校验入口成员，每个会话的消息分页仍走既有权限；关闭、换人、换范围或账号变化会取消请求。
- 只在侧栏打开时读取，无后台定时轮询；失败保留成功内容并支持重试，明确撤权移除对应来源内容。
- “仅看此对话”继续沿用已有单会话分页和缓存，不改变自己的快记或 @TA 消息模式。

后端聚合接口仍有价值，但用途调整为减少逐群请求、提供统一稳定分页和更大规模下的性能优化。请沿用下方正式合同设计；上线后替换插件的聚合层，保留用户入口与交互。

本次 3102 验证：同一目标从私聊入口发现 19 个共同群聊，首批覆盖 20 个会话并显示 39 条内容；打开“仅看此对话”后仅有私聊来源。切回共同范围后能从群消息来源跳回正确群聊。继续分页后增加至 157 条，未出现读取错误。上述条数为此账号本次实际已加载内容，不是完整历史总数或性能承诺。

以下保留 2026-10-25 的交接与验收记录，其中“共同范围待接口”的描述为当时状态，以本节更新为准。

## 用户需求与范围

群聊或私聊中，从他人头像打开「看TA的快记」，使用同一个人物内容侧栏。默认查看“共同对话中TA发的内容”；打开「仅看此对话」后，限定入口所在群聊/私聊。

共同范围只包括：当前用户有权读取的共同群聊，以及当前用户与目标人的私聊。筛选的是会话中的实际发送人，不是转发卡片里被引用的原作者。不包含TA的发给自己、TA与其他人的私聊或其他无权读取的数据。公开世界和团队通道不在本轮范围。

## 本轮插件已完成与尚未完成

- 群聊、私聊共用侧栏、人物标题、来源标记、调宽、关闭、滚动分页和「仅看此对话」开关。
- 默认共同范围；当前后端聚合协议未接入，明确显示“共同对话汇总接口开发中，开发完成后此功能完整可用”，提供“先看此对话”。不会用当前群的数据冒充共同范围，不会将未接通显示为“暂无快记”。
- 当前对话使用现有 `/api/v1/chats/members/records/page`。初次取 12 条、后续取 30 条，使用已有数字序号游标；正文不等待整批成员资料、私聊备注映射或头像装饰。首屏使用入口中已知人物资料，图片在现有头像通道异步读取。
- 修复本地 `source.member-records` 路由遗漏 AbortSignal 的问题。关闭、换人、换范围会取消旧请求并忽略迟到结果。
- 本机内存缓存按环境账号、稳定会话、成员引用、查询模式及范围隔离。最多 8 个窗口、每个最多 500 条、60 秒有效，不使用后台轮询；重开先恢复缓存和阅读位置，再重新验证已加载范围。刷新分批合并，最终以已验证覆盖范围替换，权限撤销则清空缓存。大窗口不截断后伪造游标，而是不缓存。
- 同一会话来源引用续签时保持原窗口和滚动位置。当前对话来源按钮沿用 timeline-around 定位，不将正文的相似文字作为定位依据。
- 原有「@TA的快记」仍是本会话互动筛选，自己的快记保持原行为，本轮不扩大这两种模式。

`source.person-records.capabilities` 是本地 Host 预留操作，校验账号/会话成员引用后返回 `{version:1, shared:false, reason:"backend-pending"}`，**不是已经上线的聚合云端接口**。共同范围的真实分页读取和行级来源适配仍待最终后端合同，不能只把 shared 翻成 true 就宣称接通。

## 根因证据

修改前在固定 3102 只读核验同一成员：首屏两次分别返回 29 条，耗时 2521ms、2570ms。该耗时是整个 Host 操作耗时，未声称都是某一条云端请求的耗时。

旧链路依次等待成员列表、整批成员公开资料/备注、成员快记页及消息头像等投影，前端整页完成后才展示；关闭后重开没有内容缓存。当前轻量模式只处理目标成员的基本快照，不再等待上述可选资料。成员身份和会话权限校验仍保留。

## 后端需要提供的能力

请提供按目标用户汇总当前查看者可读会话中其发送内容的正式协议（路由和最终字段由后端确定），避免前端枚举全部群聊和逐群拉历史。

### 请求与权限

- 由登录态确定 viewer，目标身份从有效成员引用转换；不接受客户端自行声称的 viewer 或“共同群列表”作为授权事实。
- 范围为 `shared` / `conversation`。conversation 必须携带并校验原会话；shared 的入口会话只用于核验目标身份，不能因此把结果限制在入口群。
- 支持小批量 limit（建议默认 20，上限 50）与不透明 cursor。允许快速返回正文和已有名称快照，可选头像、精确总数不阻塞首屏。
- 每页重新执行可见性校验。退群、入群前后历史边界、封禁、撤回、删除、会话访问撤销、账号变化等均遵循原会话读取权限；缓存和游标不构成额外权限。
- 同一目标从不同入口群/私聊打开，应能得到稳定的目标身份引用，供后续共享范围缓存和跨入口恢复使用。

### 返回建议

每个结果应包含：

| 字段语义 | 要求 |
| --- | --- |
| 稳定发送事件身份 | relation/occurrence ID；不能只给正文或 record_uid |
| 原会话来源 | kind、会话稳定身份、当前可用读取引用、查看者可见名称 |
| 原消息身份 | record_uid、record owner、relation_uid、seq、发送时间 |
| 实际发送者 | 稳定用户身份、显示快照、可选头像 |
| 正文与媒体 | 沿用原消息投影/权限，不为聚合视图重新放开附件 |
| 消息操作引用 | 绑定原会话，供详情、播放、复制链接、转发、引用等既有能力使用 |
| 分页状态 | has_more、下一页不透明游标、可选可见性/快照版本 |

当前侧栏的条目都来自同一个会话；共同范围接通后，必须逐条使用自己的来源，不能把入口群 sourceRef 套给其他群的消息。

### 排序、去重与失败

- 服务端统一按真实发送事件时间排序，并以稳定身份补齐同时间排序。初次进入最近内容，向上加载更早记录。
- 共同范围不能继续使用单个会话的 before_seq 比较所有群。游标须绑定 viewer、目标、范围及必要的可见性/排序版本。
- 群聊消息在私聊互动流中的 @ 投影，若本质是同一发送事件，仅显示一次。不同时间/不同会话的真实再次发送仍保留；禁止按相同文字或 record_uid 无条件合并。
- 不借用入口群的 recordCount 作为共同范围总数。没有精确统计时返回未知；部分成功须返回实际覆盖状态，不能称为全部。
- 区分接口未支持、确实为空、权限失效、游标失效和暂时失败。暂时失败可保留已读内容与重试，明确撤权必须移除对应内容。
- 使用既有消息变更/权限事件失效或合并缓存；本轮不要求增加高频轮询。分页不能为个人阅读改变原会话已读状态，若现有协议有这类副作用请明确说明。

## 联调验收

1. 同一人从群聊和私聊入口打开，共同范围结果一致；开启开关后分别只显示当前群/私聊。
2. 不同共同群、1:1 私聊按时间混排，每条可回原会话准确定位；详情和媒体使用原会话权限。
3. @ 互动投影不重复，真实重复发送不丢失；转发中的原作者不替代实际发送者筛选。
4. 同时间消息、分页过程中新消息、撤回/删除、退出群、切账号，不错页、不串人、不恢复无权内容。
5. 首批正文先展示，头像/统计延后不改变来源与排序；关闭重开、切换范围保留各自阅读位置。
6. 没有共同群或没有私聊时能正常返回其他可读范围；接口未接通时不显示虚假空结果。

后端交付请同时说明部署环境、版本、真实请求/响应、权限边界、游标与去重规则、错误码、预期规模下的首屏耗时，以及可供联调的账号与场景。


## 本轮插件验证结果

固定 3102、同一成员的只读对照：原完整投影返回 29 条耗时 3366ms；轻量投影同样返回 29 条耗时 278ms；轻量首批 12 条耗时 232ms。以上为单次 Host 端到端观测，不是服务端 SLA，也未据此声称所有账号均达到相同耗时。

- 576 项相关测试通过；源目录及保留安排改动的组合预览均构建通过。
- 3102 实际私聊验证默认共同范围显示开发中；开启「仅看此对话」后加载真实记录和媒体，来源显示“与TA的私聊 · 时间”。
- 关闭重开、切换范围后恢复同一条可视记录，纵向偏移差为 0；后台刷新补足到 30 条，未清空正在阅读的窗口。
- 从已加载记录点击来源，侧栏关闭后原消息进入主对话可视区，没有定位失败提示。轻量 DTO 补齐真实 record owner，并有普通和大整数用户 ID 回归覆盖。
- 此次验收没有发送、修改或删除任何云端消息；共同范围真实聚合仍待后端交付。
