# Codex 事件触发同步与过程回复后端交接

本次目标是让已授权的 Codex 对话及时出现在即我中。用户强调采用明确事件触发，不通过提高轮询频率换取速度。现有提问、最终回答和中断上传协议继续使用；处理中用户可见的进度回复需要新增云端协议。

## 已确认的问题

当前 Hook 仅有 `UserPromptSubmit`、`Stop`、`Interrupt`，没有过程消息。采集主机每秒消费本机收件箱，每五秒尝试云端上传，打开的对话每五秒刷新。较长的任务在最终回答之前没有新正文可同步，界面因而长时间停在提问处。

2026 年 10 月 23 日现场核验：上一轮最终回答于 20:06:15.880 产生，20:06:16.130 已写入采集记录，检查时云端已确认、待上传为零；19:37 至 20:06 的中间进度回复未被旧链路采集。实际采集和上传由正式桌面端承担，3102 预览读取云端副本。更新预览代码不等于正式采集端已更新。

## 本次插件实现

- 监听当前账号已授权收件箱的写入，合并短时重复通知，立即消费新提问、最终回答和中断；原一秒消费与五秒上传兜底周期不变。
- 新提问出现后，核对已绑定会话的近期轮次。对已收到提问但缺结束事件的轮次，从原生 `task_complete` 或 `turn_aborted` 恢复结果；不按正文出现“完成”或“当前时间”推测状态。
- 监听已绑定原生会话文件的追加，按持久化游标增量读取，只保留面向用户的 `assistant / commentary`。短时间写入合并处理；首次补查分块、限额并让出执行机会，不扫描整个历史目录。
- 中间回复单独存储，不伪装成 `Stop`，不进入旧版云端事件正文。本人同机可查看，界面注明“过程回复 · 仅本机”。
- 一次上传触发可连续发送最多四个得到有效确认的批次，每批仍遵守 100 事件、1 MiB 上限。无确认进展即停止；网络错误继续使用原有退避。重复上传保持事件身份和版本。
- 页面回到前台、网络恢复时立即刷新；后台更新保持阅读位置。没有提高现有前端轮询频率。
- 保持现有 Hook 命令和信任配置。暂停、排除、退出账号后停止监听和补查；不会补回暂停期间产生的内容。

本机过程回复只通过宿主的 `team.codex.events` 返回给有准确本人来源绑定的页面。其他电脑、其他团队成员暂时仍仅得到旧协议中的提问、最终回答和中断；不要把本机显示解释为云端过程同步已经完成。

## 建议扩展协议

现有 `/api/v1/team-codex/sync` 和 `/api/v1/team-codex/events/list` 仅按三类事件接入。建议增加经能力协商启用的 `Progress` 事件，旧客户端不能被强行返回无法识别的类型。以下字段为建议，尚未作为线上接口调用：

```json
{
  "event_id": "稳定事件标识",
  "turn_id": "现有脱敏轮次标识",
  "turn_seq": 12,
  "message_seq": 2,
  "kind": "Progress",
  "version": 1,
  "at": 1792757400000,
  "text": "已找到问题，正在验证修复。",
  "truncated": false
}
```

| 字段或行为 | 需要保证的语义 |
| --- | --- |
| 能力协商 | 客户端先确认支持过程事件；旧客户端继续只收到三类事件 |
| event_id | 同一条可见进度回复重试、重启、补传保持同一身份 |
| message_seq | 在同一轮中保持提问、各条进度、最终回答的稳定顺序，不能继续只按 `turn_seq × 3` 编排 |
| version | 同身份同版本重复提交幂等；只确认实际接收的版本，不提前确认更新版本 |
| at | 原消息时间，与上传时间、服务器接收时间分开 |
| 状态 | Progress 不结束任务；只有真实终止事件改变该轮状态；上一轮迟到事件不结束下一轮 |
| 分页 | 返回新增消息与已有消息的新版本时不漏、不重；提供稳定游标 |
| 权限 | 沿用现有账号、团队、来源、任务校验及上传授权；拒绝伪造来源、跨账号写入 |

只传递已完成的一条用户可见进度回复；不传内部推理、工具原始结果和子任务内部消息。图片保持单独的本人私有权限链路，不借过程消息或团队正文上传图片内容和本地地址。

## 接收端及时更新

优先复用现有实时消息通道推送轻量失效通知，例如“某任务有新事件 / 最新版本”。接收端得到通知后增量读取，不推送未经权限校验的全文。切回前台和重连时按最后确认的游标补查。暂时缺少推送时可保留现有轮询兜底，不增加频率。

后端应返回可解释的确认水位，区分“来源主机已采集”“服务器已接收”“当前查看端已更新”。来源心跳在线不能代表所有消息已经同步。

## 联调验收

1. 一轮任务产生多条过程回复后再结束：顺序一致、任务不中途变完成。
2. 新提问立即到达，而上一轮最终回答延迟：补齐上一轮，新轮仍在进行。
3. 断网、部分确认、重试与重启：同一条消息不重复，未确认的数据继续补传。
4. 旧客户端读取新任务：仍能正常读取提问和最终回答。
5. 多账号、暂停和排除任务：不越权采集或读取，暂停期间内容不自动补回。
6. 空闲期没有持续新增网络请求；有事件时触发，批量事件合并；记录采集、发送、确认、展示四个时点衡量端到端延迟。
7. 本人图片不随团队过程消息泄露，其他成员的接口响应不包含图片地址或原文件路径。
