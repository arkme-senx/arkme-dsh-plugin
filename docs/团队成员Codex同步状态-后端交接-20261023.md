# 团队成员 Codex 同步状态 · 后端交接

日期：2026-10-23。插件已实现下述可选字段的读取、状态展示与失败重试；**协议待后端确认和上线，不能将插件适配完成视为真实状态已接通**。

## 问题及目标

联系人 → 团队 → 成员列表过去无条件显示「查看对话」，仅以成员有无即我号控制是否可点击。未开通同步的成员也会出现这个入口，容易让用户误以为已有同步内容。

需要显示的是**该成员在当前团队的 Codex 同步状态，以及当前查看者能否进入其对话**。不能由是否存在某条任务、当前分页是否为空、成员角色、设备在线状态或即我号推算。

现有 `POST /api/v1/team-codex/connection/status` 是当前 JWT 所属账号的历史接入资格；请求为空对象，不适合用来逐个查询其他成员，也不能代表目前向某团队开启了同步。

## 最小接口扩展

复用 `POST /api/v1/team/members/list`，不新增逐成员请求。每个 `items[]` 增加可选 `codex_sync`：

```json
{
  "user_id": 11,
  "display_name": "成员甲",
  "codex_sync": {
    "version": 1,
    "state": "enabled",
    "has_conversations": false,
    "can_view_conversations": true
  }
}
```

| 字段 | 语义 |
| --- | --- |
| `version` | 本文契约版本，整数 `1` |
| `state` | `not_connected` / `enabled` / `paused` / `disabled` / `unavailable` |
| `has_conversations` | 当前查看者在这个团队有权查看的该成员对话是否至少有一条；独立于当前任务分页、设备在线或本轮工作状态 |
| `can_view_conversations` | 当前查看者是否可进入这个成员的 Codex 阅读区；只用于入口呈现，不替代后续任务/正文接口的权限检查 |

状态定义与客户端展示：

| 状态 | 确认条件 | 展示 |
| --- | --- | --- |
| `not_connected` | 后端明确确认成员尚未向此团队建立同步关系；两个布尔值必须均为 `false` | 灰色「未开通同步」，无按钮和箭头 |
| `enabled` | 成员已开启向此团队同步；不要求当前有设备在线或已产出首条任务 | 有读取权限则「查看对话」；无对话时同时显示「已开通·暂无对话」 |
| `paused` | 已建立同步关系但目前明确暂停；不能由长时间无事件推断 | 「已暂停同步」；若有读取权限保留「查看对话」 |
| `disabled` | 曾建立同步关系，后续明确关闭向此团队同步 | 「已关闭同步」；仍有权限读取历史时保留「查看对话」 |
| `unavailable` | 后端依赖暂时失败，无法可靠确认状态 | 「状态获取失败」及「重试」；该状态只需 `version`、`state` |

`enabled` 且 `can_view_conversations=false` 时不显示阅读入口；已有对话但不可查看时显示「暂无对话查看权限」。如果不能可靠判断启用/暂停/关闭，不要从最后上传时间拼造状态，应返回 `unavailable`。

## 多设备、权限与隐私

- 绑定当前查看者、当前团队、真实成员身份查询；不以昵称匹配，不能接受客户端直接指定他人 owner 身份绕过成员权限。
- 多来源聚合在后端完成：至少一个来源仍明确启用时为 `enabled`；没有启用但存在暂停来源时为 `paused`；已建立过关系且所有来源关闭时为 `disabled`。设备掉线不等于暂停或关闭。
- `has_conversations` 只统计当前查看者有权限查看的该团队记录，不披露私人任务或其他团队记录。
- 删除最后一条可见对话，不应把已开通状态改成未开通；暂停和关闭也不自动撤销已有历史阅读权限。实际 ACL 以产品规则和后端授权为准。
- 退组、撤销查看权限后，成员查询及后续对话读取都必须重新检查权限；不能只依赖前端入口隐藏。
- 当前只有来源确认与任务上传时，如后端尚没有「关闭/暂停向团队同步」的可靠记录，应先补齐状态写入及聚合依据，再声明相应状态可用。

## 兼容和性能

- 不提供 `codex_sync` 或返回 `null`：插件显示「同步状态暂不可用」，悬浮说明接口开发中，不伪装成未开通。
- 未知版本、错误类型、`not_connected` 与布尔值矛盾等：只降级该成员状态，不影响整个成员列表。
- 响应仅取白名单字段；不下发本机路径、排队正文或私有来源信息。
- 与成员分页同批查询，避免对每位成员逐个请求或扫描所有历史任务；状态存储/查询应有可聚合的元数据和索引。依赖失败可让成员基础资料照常返回，状态为 `unavailable`。
- 插件没有增加固定高频轮询。进入团队、原有列表刷新时重新读取；修改同步设置后重新进入团队可更新状态。状态失败可按成员手动重试原分页，仅更新其状态并保留已加载列表。
- 切换账号/团队时取消旧请求并丢弃迟到响应。成员身份缺失时，即使状态允许读取，也不使用昵称猜测跳转目标。

## 联调验收

1. 同一团队同时含已开通、未开通、首条对话尚未产生的成员；三种状态不混淆。
2. 当前任务第一页没有某成员的记录，仍正确返回其状态，不按空分页判未开通。
3. 开通后产生第一条对话、暂停、关闭、删除最后一条记录，状态与入口分别正确变化。
4. 多设备中一台离线或暂停，另一台仍启用，不错误降级整个成员。
5. 旧后端省略字段、单成员依赖失败、格式错误，成员列表仍可用；状态不冒充 `not_connected`。
6. 第 2 页成员重试不清空第 1 页、不改变滚动位置；切换账号/团队后旧响应不能覆盖新状态。
7. 无权限用户不能通过直接调用阅读接口绕过状态和 ACL；此功能不扩大任务可见范围。
