# 本地录音器：Windows 与 macOS

首批功能包括设备识别、容量显示、增量同步、本地播放、另存为 WAV 和导入即我。入口为“录音 → 本地设备”。设备识别与同步需要用户点击；打开页面只读取本机索引和枚举串口，不探测设备协议。充电盒、设备设置、校时、格式化与擦除不在此范围。

## 实现归属

- `src/local-recorder/protocol.ts`：AKRQ/AKRS v1，只暴露 INFO、GET_STORAGE_SPACE、GET_BAD_BLOCK_TABLE、READ、READ_STREAM。校验响应序号、地址、长度、头 CRC、数据 CRC 和流式尾标记；旧固件不支持 READ_STREAM 时回退分块 READ。
- `serial.ts`：Node SerialPort 13.0.0，在本机 Host 使用系统串口绑定。识别量产固件 SQS `2FE3:0002`，再通过 INFO 就绪及几何信息验证。Windows 保留 COM 名称，macOS 使用 `cu.usbmodem`。同一 USB 序列号的双 CDC 接口归为一台设备，有效握手后不再探测另一接口；不向普通 CP210x 充电盒发送录音器指令。macOS 在打开前以只读 `lsof` 检查整台设备的两个接口及 tty/cu 别名，其他客户端占用时提示等待其读取完成并退出；Windows 使用串口独占打开并提示占用/权限错误。初次打开清理主机输入队列，协议最多跳过一个完整流式区块及少量启动信息，兼容前一客户端中断读取的残留字节。
- `volume.ts`：V2 录音卷、坏块与块 CRC。检查至少两份一致的格式副本，以格式和首个数据页共同识别存储卷，兼容旧固件重复使用 Generation 1。逐块校验后原子保存，后续同步复核本地缓存、重读尾块并读取新增块。缓存损坏从缺失位置之前恢复，不跳过未完成区块。
- `catalog.ts`：恢复会话、实际缓存音频时长和设备时间锚点。时间无法恢复时返回 `null`，不使用连接时间或下载时间代替录音时间。
- `owner.ts`：账号及服务环境隔离、设备任务、离线缓存、流式 PCM16 WAV 生成和现有导入队列适配。不同存储卷的历史缓存保留；不复制或修改原 Swift 客户端的资料库。
- `routes.ts`：本机同源控制接口及账号绑定的 Range 音频流。前端只获得设备 ID、录音 ID 和音频引用，不获得串口路径、文件路径或凭据。

协议及编解码逻辑依据 `yingjian/ArkmeRecorderMac` 中的 RecorderProtocol、RecorderReader、RecorderAudioCodec 和 SerialPort 实现迁移。旧 Python 导出工具的 R/e 指令流程不用于当前设备。

## 账号和任务生命周期

缓存根目录为插件独立状态目录的 `local-recorders/`，按环境、音频服务地址和用户 ID 的摘要隔离，再按设备身份与存储卷隔离。账号切换或退出时停止任务、撤销媒体引用并中止正在传输的音频。关闭设备页面不会停止已启动同步；用户可以主动停止，后续继续读取。

设备同一串口只允许一个任务。音频准备同时最多两条；只在本机按区块处理，不把整段音频放入浏览器内存。列表每页 100 条并核对版本，旧分页结果不能拼入新列表。停止或断线只保留完整校验的块，未完成会话可以试听、导出，导入需等待完整结束页。

导入需要用户确认真实开始时间和“自己/他人”归属。导入使用现有 `acceptRecordingImport`，设备录音来源为 0；本机 WAV 保留，交给导入队列的是独立副本。持久保存 UUIDv7 提交身份，响应丢失及重复点击复用同一回执。沿用现有单文件 1 GiB、10 小时限制，超过限制明确提示，避免截断。

## SDK 与访问边界

公开 Browser SDK 提供 `localRecorders`、`discoverLocalRecorders`、`syncLocalRecorder`、`stopLocalRecorder`、`prepareLocalRecorderAudio`、`importLocalRecorderAudio`。所有 `recorders.local.*` 请求要求当前本机页面的同源 Origin，即使其他 Host API 允许非回环访问也不能远程操作录音器。

此版本评估后将设备访问限定为本机 UI/Browser SDK；没有新增模型自动探测设备、同步或上传工具。模型不得把物理连接等同于用户授权上传。后续若增加 Tools，需复用同一 owner、账号及本机权限合同，并分别声明读取设备、写本机缓存及上传云端的效果，不提供任意串口或任意文件路径入口。

## 分发与验收

桌面仓库的 Harness runtime 固定依赖 `serialport@13.0.0`。运行时制品检查包含串口包及对应系统的 N-API 二进制：Windows x64、macOS Intel/Apple Silicon（同一个 Universal 绑定）。插件也声明精确依赖及安装脚本许可；源码不依赖开发电脑的路径。

已有运行时缺少串口组件时，页面明确提示升级并保留缓存播放能力。发布时先提供包含串口组件的兼容运行时，再推广新插件；回滚时旧插件会忽略本机设备缓存，不需要修改设备或清除资料。

验证包括协议及故障样本、真实临时目录下的续读与离线 WAV、账号隔离、同源/Range HTTP、页面交互、现有导入队列回归，以及桌面多平台运行时制品检查。Web 验收使用安装版当前 Keychain 登录、独立状态目录和本对话固定端口 52016，不导出凭据、不执行真实云端导入。

Windows/macOS 真机验收由用户选择稍后进行。自动测试、原生模块加载和二进制存在性检查不替代真实设备连接、驱动、完整同步、播放、系统另存为或云端导入验收。本次不合并、不发布，也不触碰生产数据或录音器存储写命令。

## 原生端布局与渐进列表

本地设备面板采用可调宽度的双栏：左栏为设备选择、物理总容量/可录音区使用率、同步进度与录音列表，右栏为时间标题、时长/音频数据量/结束原因摘要、播放与导出/导入、录音信息。样式随 DSH 明暗主题变化。导入操作展开真实开始时间和归属表单，确认后才提交现有队列；部分录音保持禁止导入。

目录从已校验的页提取固件、电压、增益、VAD、结束原因和物理区块。旧索引缺失字段显示未知，后续同步复核缓存后补齐；未读到结束页时区分“待完整同步”和完整扫描后的“未完整关闭”。播放器使用当前已缓存的真实时长，同步期间新增音频不打断正在播放的版本，下次播放准备最新缓存。

每块只解析新内容或发生变化的尾块，以不保留音频载荷的摘要构建列表；设备快照发布限频，避免每块重扫全部音频。缓存块与卷索引仍逐块原子提交，停止或断线后的目录从最后完整校验块恢复。同步统计来自实际读取字节及耗时，读取性能明确标注为本次设备统计。可选新增字段兼容旧客户端/索引，不需要修改录音器或清空本机缓存。
