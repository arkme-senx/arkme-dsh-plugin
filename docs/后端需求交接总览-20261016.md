# Arkme 插件后端需求交接总览

更新时间：2026-10-16 晚间。用途：把近期已经整理的后端需求交给即我项目同事集中对接。插件本轮代码同步目标为 dev；实际合并 SHA 与 PR 链接随群消息提供。本文不代表后端已发布，也不要求同事另起一套服务。

## 先读这几条

- 优先复用已有 owner 服务、队列、鉴权、生成与分页能力；文档中的“建议路径/拟定协议”可由后端确定最终契约，定稿后再调整插件适配和测试。
- 前端入口、交互或测试样本通过，不等于生产结果可用。下表分别说明真实读取、前端准备及剩余工作。
- 个别专项文档保留编写时的“未合 dev/尚未开放”记录；代码状态以本次 PR 为准，能力状态以本表核验日期及线上返回为准。不能因为旧说明忽略同事新合入的实现。
- 本交接包只包含项目文档，不含个人录音、聊天原文、生产候选 JSON、登录信息或原始日志。个人回填清单不能当全用户迁移脚本输入。

## 晚间增量与状态边界

今日较早的 20 份专项文档已通过 Arkme 发到「即我大群（包含实习生）」。本次只补发更新总览与安排来源排查，既有专项设计仍参照群内原交接包和本仓库 docs，避免重复下发整包。

- **优先排查安排来源的误报。** 已确认原通话可正常读取，但保存的引用少了语气词或被改写时，逐字匹配失败会被错误归为“已删除或无权限”。前端已经补齐多条原始依据的依次核验；后端仍需区分来源访问权限和原句定位结果，详见更新后的《安排来源链路对接进展》。这是新缺陷，不是要求重做已上线的来源接口。
- **本轮其余交互没有新增必需后端接口。** 最新消息预览与表态提醒分离、离开对话才发布草稿并按离开时间排序、发给自己保留所选主题、编辑记录按相邻版本展示差异且原始消息直接展开，都复用现有服务或本地状态。
- **已有需求以已核验证据为基准。** 下表“未接通/下一步”表示前一次核验时仍需联调或确认的内容；本次没有重新审计所有生产服务，不代表同事截至此刻尚未实现。请先回传已完成项的服务版本、正式协议与验收入口，再补未完成项，避免重复开发。
- **历史回填数字是单账号抽样结果。** 45 条历史通话在此前核验时未保存来源，本次未执行生产回填、未扩大到全用户。候选 JSON 和个人原文不随群文档发送。
- 本次仅同步插件前端及文档到 dev，实际 PR 与合并提交以群消息为准；不修改后端、不发布生产。

## 建议交付顺序

1. 先完成数据与来源正确性：说话人学习/纠错、安排历史来源、真实存储与计量、实体及探索证据。
2. 可并行推进确定性统计：Chat 活跃分布、私聊群聊词频、旧关键词恢复；复用身份和来源协议，不互相阻塞上线。
3. 多源日回顾、原音词频与线下聊天关联基于稳定事实层推进；保留覆盖缺口，不通过提示词补造身份和来源。

## 每项回交给前端的最小内容

- 服务与部署版本、正式路径、请求/响应示例、错误和能力状态、时间/身份/计数定义。
- 所有入口的来源定位、当前权限校验、跨账号隔离、删除/纠错后失效规则。
- 写操作幂等键、结果核对、重试/撤销语义；任务断点恢复和历史迁移范围。
- 一组可复现测试数据及验收结论。个人生产数据另行授权、单独传递，不放公共源码或默认交接包。

本文不是后端实施/部署的授权书。本轮只同步插件代码与项目文档；后端代码、部署和生产回填由对应同事按团队流程负责。
