# 选中文字发给自己：跨来源引用云端交接

日期：2026-10-23

## 需求与本次边界

用户在 Codex、DeepSeek Harness、Arko、私聊、群聊、团队消息、发给自己、录音转写、通话转写中选择部分文字后，可以点击「发给自己」，在弹窗中写自己的思考。保存后的快记须清楚区分引用原文和用户新写的内容，沿用延展引用的视觉。

用户已确认过渡方案：**先支持本机引用视觉，文档交接云端结构同步**。本次没有新增云端协议，也没有将普通快记伪装成已有原文关联。

## 当前插件已实现

- 各来源复用选中文字工具栏和发送弹窗。原有复制、全选、标记、查找、回复/延展等能力保持各来源自己的权限与实现。
- 弹窗冻结选中文字、作者、来源名称和原时间；新笔记为单独输入框。引用长度沿用当前选区上限 2,000 UTF-16 单元，完整快记仍受现有服务端发送长度配置约束。
- Host 验证环境及账号，并自行解析当前账号的「发给自己」目标，调用现有文本发送链路。调用方不能指定其他收件人。
- 每次发送使用固定 UUID。首次发送后冻结正文，结果不明时使用同一 UUID、同一内容重试；收到匹配 UUID 且 synced 的结果才提示成功。
- **先把引用结构落到插件 Host SQLite，再发快记**。表为 `self_note_quotes`，主键为 `(环境:账号, record_uid)`，不依赖页面端口或 localStorage，不按缓存过期时间清理。
- 云端暂存完整可读文本：来源与原时间、引用原文、分隔后的「我的笔记」与新内容。本机按记录 UUID 和完整前缀精确校验后恢复引用视觉，原始 `textContent` 不变。
- 本机修改自己的笔记正文仍可保留引用结构；如果引用前缀被改动则退回完整文本，避免错配。不会根据文字相似度猜测历史快记的引用关系。
- 本次仅保存个人阅读摘录，不创建不可见的中间快记，不伪造原记录 ID，也不将该摘录当成服务器核验过的延展关系。既有分享、转发安全审核不被该入口替代。

插件新增的 `self-note.quote.send` 是 **本地 Host 操作名，不是已上线云端接口**。

## 云端需要补齐的结构（建议，待后端确定最终字段）

建议在快记上分开保存 `body` 与一个有版本的 `quote_snapshot`：

| 字段 | 含义 |
| --- | --- |
| schema_version | 引用协议版本 |
| quote_text | 用户确认的选中文字快照，保留换行 |
| source_kind | record / team_message / arko_message / dsh_message / codex_event / recording_segment / call_segment 等来源 |
| source_identity | 各来源自己的稳定标识，禁止用显示名称或临时 sourceRef 代替 |
| source_version、source_digest | 引用时的原文版本和规范化文本摘要 |
| selection_anchor | start / end / selected_text；明确使用 UTF-16 与现有 `message-quote` 相同的规范化规则 |
| source_label、author_snapshot、source_at | 展示来源、作者和原时间；与新笔记的创建时间分开 |
| verification | 服务端核验通过 / 仅用户摘录快照 / 来源不可用；不得由前端自行声称已核验 |
| availability | 可跳转 / 原文已删除 / 权限已失效 / 来源仅本机等明确状态 |

本次本机最小快照只有来源显示名、作者显示名、时间和选中文字。它**没有保存可用于核验或跳转的完整原文身份及 anchor**。后续云端新建流程需从各来源适配器传入真实身份和选区；历史本机数据只能迁移为用户摘录快照，不能升级成已核验的原文链接。

### 写入、读回和权限

1. 新建笔记的正文和引用必须原子写入，沿用客户端 record_uid / 幂等键；同键不同内容应返回冲突。
2. 创建回执明确返回正文与引用均已保存，不能仅确认普通文字发送成功。
3. 自己的时间线、详情、搜索和跨设备同步统一返回结构；旧客户端仍有完整可读的兼容文本。
4. 有来源身份时服务端校验原文读取权限、作者归属、版本与选区，不接受任意客户端伪造的群聊/私聊关联。
5. 来源只在本机时允许保存「个人摘录」，但须与可验证引用区分；来源跳转仅在服务端确认身份和权限后启用。
6. 原文后来删除或撤回、团队退出、权限改变后，是保留已摘录快照还是清除内容，须制定一致政策并返回明确状态；禁止通过快照重新获得原文访问权限。
7. 公开分享或转发这条快记时继续使用现有统一安全与敏感检查。引用关联不代表获得公开原文/媒体的授权。

### 编辑、删除与迁移

- 编辑自己的 `body` 不应重写引用；替换选区时校验版本，避免覆盖其他设备的改动。
- 快记软删除、恢复、彻底删除及账号数据删除应同步管理引用结构。此过渡表当前不作缓存清理，后续需对接确定的彻底删除事件。
- 跨设备写入冲突沿用快记版本规则，不能让旧设备的纯文本写回默默丢掉引用结构。
- 本机迁移按环境、账号、record_uid 精确定位，并核对云端仍包含本机记录的完整引用前缀；收到服务端结构保存成功回执后才标记迁移完成。禁止批量正则猜测普通文字里的「引用」。
- 导出、复制、搜索须定义是否包含引用，并保持可读的来源说明；UI 中「自己的笔记」不能与摘录混为一个作者发言。

## 代码入口

- `src/selected-text-note.ts`：快照、兼容文本与投影校验。
- `src/local-self-note-quotes.ts`：SQLite 持久化与账号隔离。
- `src/services/selected-text-self-note.ts`、`src/arkme-service.ts`：存储前置、收件人解析、幂等发送与确认。
- `src/client/SelectedTextSelfNote.tsx`：共用发送弹窗。
- `src/client/SelectedTextSelfNoteContent.tsx`、`src/client/ArkmeRichContent.tsx`：引用/笔记分区呈现。
- `src/client/ArkmeMessageTextSelection.tsx`：各来源共享入口。

## 验收用例

1. 各来源部分选中后打开「发给自己」，准确显示所选内容、作者和来源，自己输入的笔记独立显示。
2. 发送时切账号：不得发到新账号；失败与未知回执不能显示成功，重试不重复创建。
3. 重启 Host、客户端端口变化后本机引用样式仍在；不同账号和环境不能相互读取。
4. 引用中有换行、中文、emoji、URL 时，复制、全选、再次引用和替换自己的正文仍对应正确原文偏移。
5. 云端接通后另一台设备读回同样的引用视觉；旧版仍能读完整内容。
6. 原文已删除、权限已失效、设备不可达的情况不产生虚假原文跳转；历史本机迁移保持「用户摘录」身份。

本地自动测试覆盖重启持久化、账号隔离、前置存储失败、未知回执、固定 UUID 重试、选区偏移及共享工具栏。正式云端结构同步的端到端验收需后端实现后进行。
