# 明确团队联系与零消息目录

沿用团队内「联系用户」及名片「以团队联系」交互；公开 SDK `teamOutboundOpen`、`arkme_team_outbound_open` Tool 和 UI 共用 TeamAppService。

服务端 `conversations/open-by-member` 在现有 Team 授权事务中保留首次明确联系。`team_conversation.member_opened_at` 是内部毫秒时间，不返回访客；成员响应仅增加可缺省的 `member_initiated`。普通预览、公开入口和群来源投影不写入该事实。

成员目录资格为：真实消息存在，或已明确联系。团队成员共享联系事实，移除和置顶仍是个人入口偏好。首次真实发送继续按 `last_seq == 0` 检查当前接待资格；联系不产生消息、未读、阅读回执或客户通知。

重复打开保持首次联系时间及稳定会话 UID，已发布会话无额外写入。首条真实消息复用同一关系。F 工作区客户行以同一资格决定是否仅来自群来源；来源撤权不删除独立联系入口，也不保留已失权的群正文。

沿用实时活动排序与现有游标、个人偏好 CAS。新活动在头部刷新体现，临时选中行只是页面投影。浏览器或 Host 重启、移动端重建后以 Team 云目录恢复。

Team 增加一条仅覆盖零消息明确联系的 partial index，保留原消息活动和访客索引。无历史意图回填、集合、状态机、配置开关或业务双轨。索引由 Team 既有服务启动初始化自动创建并等待完成，部署不依赖人工建索引；本任务未执行生产发布。

实现与证据由 jotmo-meta 的 c20261105-team-contact-directory change 维护。F 团队群目录是依赖候选，不能把本地集成视作主干或生产已生效。
