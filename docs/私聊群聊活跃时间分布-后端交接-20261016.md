# 私聊、群聊活跃时间分布：后端交接

> 2026-10-16 交付更新：本文件随本轮插件 dev 同步交付，代码合并状态以 PR 回执为准。下文“未合 dev”等为编写时记录；生产能力与待办以 [后端交接总览](后端需求交接总览-20261016.md) 的本次核验栏为准，拟定接口不代表已经上线。

日期：2026-10-16。前端已实现，以下新增协议为对接草案；不代表生产已有这些路由。

## 产品目标

聊天顶部原「对话词频」入口改为「对话分析」，内含「词频」「活跃时间」。共用全部时间/按月/自定日期、全部人/本人/对方或群历史发言者筛选。默认统计整个会话全部可查看历史、全部人、所有消息类型。

活跃时间展示：消息总量、活跃天数、参与人数；一天内24小时柱状图；一周内7×24热力图；悬浮显示数量、占比、人数及系统通知量；点击时段查看消息，再精确定位原文。

它是时间戳与消息身份的确定性聚合，不依赖关键词、分词、正文长度或 AI 任务。

## 当前基础与缺口

- 插件已有 `/api/v1/chats/session/statistics`，由 `src/services/calendar-service.ts:chatStatistics` 调用。目前消费的是 `daily_data`，可用于聊天日历；每日总量不能推导小时分布或每小时参与人数。
- 个人统计 `/api/v1/records/analytics/active-time` 是个人快记的时间和记录用时，不等于当前私聊/群聊全体人员的发消息活动。
- 不能扫描当前加载的几页消息冒充全历史，不能复用词频中“有正文才可分析”的筛选。
- 新的活跃时间接口与词频独立支持，任何一项先上线，另一项不可用不应阻塞它。
- 后端可以基于现有会话 statistics 索引扩展聚合能力；下列路由是插件当前适配约定，如复用旧路由，请一起调整适配和测试，不能只修改路径而遗漏范围和数据口径。

## 统计口径

### 输入与去重

1. 当前用户有权限查看、属于该会话的原生消息，全部类型纳入：文字、图片、语音、视频、文件、混合内容、通话记录消息、卡片、自定义消息及系统通知。没有正文也计入。
2. 每个原始 message UID 计一次。一条消息里多张图、多附件、多段富文本不拆成多次；引用内容不再加一次。编辑是同一条消息的版本变化。
3. 私聊界面穿插显示的其他群消息、关联个人快记不能因为同屏出现就重复归到这个私聊。录音分享等卡片本身计一条，卡片内部所有转写不拆成聊天消息。如果后续要分析跨来源互动，可另设显式来源范围。
4. 通话结束卡片与同一通话对应的消息更新去重为一条；当前版本按该原生消息的发送时间分桶，不把通话时长转换成消息量。多处渲染同一消息也只能计一次。
5. 已撤回、已对当前用户删除或无权查看的消息，按现有 Chat 可见性规则排除。展示的总量和详情必须遵守同一权限口径。
6. 系统通知包含在全部人的消息总量中，用灰色区分，并单独返回 systemMessages；系统身份不算参与人数，单独选人时不归到他名下。
7. 参与人数是此范围内实际发过非系统消息的去重真人账号数。机器人消息仍计消息总量，机器人不算“人数”。后端若目前无法区分真人/机器人，先补齐此口径，不能拿消息作者数量冒充真人数量。后续可额外返回机器人数量。

### 时间、范围和数据完整性

- 按真实 `message.send_at` 统计，不按本次上传、同步、索引完成时间；补同步历史消息应落回历史时段。
- 请求 IANA 时区（如 Asia/Shanghai）；不能只按当前UTC offset套用全部历史，需正确处理夏令时。
- from_date/to_date 自然日均包含；内部采用 `[起始日00:00,结束日次日00:00)`。全部时间时二者均为null。
- 小时分布：同一筛选范围的所有日期，按0–23小时聚合。
- 每周分布：同一筛选范围，按周一=1…周日=7与0–23小时聚合，并非仅最近一周。
- 活跃天数是范围内至少一条计入消息的去重当地自然日数，不是区间长度。
- 消息数可相加；各桶参与人数不可相加得到总人数，必须独立COUNT DISTINCT。
- 所有桶含零值且完整返回24/168格；零是确认无消息，不能用0代替接口缺失。
- result必须是完整范围的已完成快照。索引未齐时 result=null+progress，或保留上一个完整快照并stale=true；禁止用部分历史当完整结果。

- `src/conversation-activity.ts`：完整桶、计数一致性、时区和来源范围校验。

## API v1草案

全部走现有Chat认证。公共请求/响应范围与词频类似，但scope不同：

```json
{
  "schema_version":1,
  "scope":"conversation_activity",
  "chat_session_uid":"example-session",
  "time_zone":"Asia/Shanghai",
  "from_date":null,
  "to_date":null,
  "sender":"all"
}
```

`sender`：all/self/peer（仅私聊），或历史发言者的不透明ref。**人员ref须与词频接口使用同一套会话内身份**，因为用户在两个页签之间会保留人员筛选；名字变化不能影响ref。绑定请求账号/会话并验证，禁止用昵称匹配。

后端逐次验证会话权限。每个响应必须回显公共范围；跨会话、日期、时区、人员的响应会被拒绝。以下示例省略公共字段，生产必须合并。响应外壳沿用现有 authenticatedChatPost 解包约定。

### capabilities

`POST /api/v1/chats/activity-time/capabilities`

请求 `{"schema_version":1,"scope":"conversation_activity"}`。

```json
{
  "schema_version":1,"scope":"conversation_activity","supported":true,
  "full_history":true,"all_message_types":true,"historical_senders":true,
  "sender_filter":true,"source_navigation":true
}
```

不存在返回404/501或supported:false；鉴权、网络、5xx保留为错误。全部能力准备好后再返回true。

### query

`POST /api/v1/chats/activity-time/query`，请求公共范围，只读。

```json
{
  "stale":false,
  "progress":null,
  "result":{
    "id":"immutable-snapshot-id",
    "corpus":"authorized_conversation_messages",
    "time_basis":"message_sent_at",
    "message_types":"all",
    "deduplication":"message_uid",
    "updatedAt":1792108800000,
    "fromAt":1791939600000,
    "toAt":1792065600000,
    "totalMessages":100,
    "systemMessages":5,
    "activeDays":2,
    "participants":3,
    "hourly":[],
    "weekly":[]
  }
}
```

注意：示例的空数组仅省略展示，非有效非空结果。实际hourly必须24格，weekly必须168格，每格：

```json
{"hour":9,"weekday":null,"messages":20,"systemMessages":1,"participants":3}
```

weekly格的weekday为1…7，hourly固定null。不得重复格或省略零格。消息总量=24小时消息数总和=168格消息数总和；每个小时也须等于对应7天该小时之和。系统通知同样满足总和关系。人数满足去重集合的上下界，不得简单相加。

全零结果仍必须返回完整零桶，fromAt/toAt都为null，activeDays/participants/systemMessages为0。非空结果的fromAt/toAt为本范围真实最早/最晚消息时间；所有时间均毫秒。

尚在索引：`result:null, progress:{"completed":2000,"total":10000}, stale:false`。如展示旧完整快照则result非null、stale:true；新结果使用新id，不修改旧id含义。complete状态progress=null。query不应触发AI或额外付费任务。

### participants

`POST /api/v1/chats/activity-time/participants`

公共范围（sender=all）+ `{"search":"","cursor":null,"limit":50}`。

```json
{"search":"","items":[{"ref":"opaque-person-ref","name":"备注优先名","isSelf":false,"former":true}],"next_cursor":null}
```

基于当前时间范围的全部类型消息作者，不要求有文本，不仅取active成员；历史离开成员保留。搜索备注/昵称，私有备注只对当前查看者使用。与词频共用身份ref；search回显去首尾空格后的原字符串。稳定分页、不重复、不循环。

### messages

`POST /api/v1/chats/activity-time/messages`

公共范围 + `{"result_id":"...","hour":9,"weekday":null,"cursor":null,"limit":50}`。

weekday=null表示所有星期的该小时；1…7表示该星期的该小时。请求的日期/人员范围仍然生效。

```json
{
  "result_id":"immutable-snapshot-id","hour":9,"weekday":null,
  "items":[{
    "key":"stable-message-key","sourceRef":"opaque-source-ref",
    "senderName":"周鹏","preview":"","sentAt":1791939600000,"kind":"image"
  }],
  "total":20,"next_cursor":null
}
```

kind：text/image/voice/video/file/call/mixed/card/system/other。preview可空，前端会显示类型占位，不因此剔除图片、语音等消息。按发送时间+消息ID稳定分页。total为当前仍可查看的去重消息数；已失权数据不能返回旧正文。返回时段必须与发送时间的请求时区匹配，前端会校验。

### source

`POST /api/v1/chats/activity-time/source`

公共范围 + `{"result_id":"...","source_ref":"...","hour":9,"weekday":null}`。

```json
{
  "result_id":"immutable-snapshot-id","source_ref":"opaque-source-ref",
  "hour":9,"weekday":null,"available":true,
  "message_uid":"actual-message-uid","send_at":1791939600000
}
```

每次重新校验账号、会话、快照、人员、时段和原消息权限。前端以当前会话+message_uid+send_at定位。不匹配/不可查看返回available:false或明确404/409，不能跳到相似的另一条消息。

## 后端实现建议

- 从Chat消息事实表/索引做授权、会话、时间、作者过滤；消息类型不能先筛成text。
- 每条消息UID只保留当前可见版本，时间以原始send_at为准。建立会话/日期/作者聚合索引，旧数据后台分批回填，新增/编辑/撤回/删除增量更新。
- 对大范围统计优先读聚合索引；涉及账号可见性差异的删除、入群权限或私密内容必须应用到聚合与详情两端，禁止共享缓存越权。
- 索引版本、算法/口径版本、会话范围及查看者可见性版本共同决定快照。保留更新时间和过期状态，禁止结果半更新。
- 不需要把完整聊天正文发送给大模型，不需要借用录音AI或词频创建任务。

## 验收

1. 双方及多人混合发言，全部默认包含他人；单人筛选不混入其他人和系统通知。
2. 图片/语音/视频/文件/混合消息无正文仍计入；一条多图仅1条；回复引用不多计。
3. 所有小时、周小时、总数一致；跨时段同人去重；系统通知独立展示。
4. 从多年前到今天的全历史，超出客户端已加载范围也计入；未完成索引明确进度。
5. 补同步按原发送时间回到历史；时区/跨天/夏令时正确；星期分布基于筛选范围全部日期。
6. 已离开成员可筛选其可见历史；同名成员不误合并；切页签保留兼容人员ref。
7. 点击小时/周小时列表准确，纯附件可定位；撤回/删后不能显示不可见正文。
8. 快速切换账号、会话、人员、时间及页签，旧请求不能污染新结果；词频不可用不阻塞活跃分析。
