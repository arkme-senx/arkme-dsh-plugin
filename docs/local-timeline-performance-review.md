## 本轮修复

- 完整校准删除正文后，旧请求可能在其他窗口重建已删除事件。补充持久化会话 ticket 围栏；Host 明确拒绝过期提交，不能用网络降级结果重新发布旧正文。
- 共享 canonical 正文中的 token 可能污染其他窗口。读回与 gap 保留现在使用窗口引用自己的 coverage token，同时保持共享正文更新。
- 历史锚点原先通过正文 JSON 扫描查找，改为稳定事件身份索引查询；兼容身份只扫描一次 canonical 内容。
- 重叠窗口 gap 保留重复解析同一正文，改为 SQL 事件去重后解析，跨 token 重复事件也不会再次解析。
- 文本选择结束但没有新滚动时，可见块可能不更新。补充 selectionchange 恢复与卸载清理，布局排序前每候选只读取一次几何位置。
- Worker 排队字节预算原先只统计正文，遗漏刷新 token 等命令参数。现在 admission 统计完整命令，超大参数在 structuredClone 前拒绝，不能绕过队列预算。
- 块身份原先包含末条消息 ID，追加一条消息会重挂整个末块。改为稳定首行身份，1,999→2,000 条追加测试从重挂 40 行降为仅挂载新行，已有 39 行无需释放和重建媒体/反应 owner。

上述场景均先以失败回归复现，再修复通过。另覆盖真实 Host 并发网络结果晚于完整删除校准的拒绝路径。

## 2026-10-12 实时刷新修复

真实测试客户端在列表底部连续收消息时发现两层竞争：UI 在读取进行中直接丢弃刷新需求，失败路径不补读；Host 又把普通 sessions-delta 与内容撤回共用提交失效围栏，密集到达时整个读取窗口反复作废。第一轮仅修 UI 的真实 100 条测试确认了后者：网络读取峰值为 1，但连续发送期间出现 12 次 stale 拒绝，发送结束后才追上。该轮不作为实时验收通过证据。

- 每个当前会话只保留一个待刷新标记、一个 250ms 尾随定时器，所有分页读取共享读者计数。读取成功或失败后均能补读，相同版本的通知复用当前请求；账号、会话和导航作用域切换会取消旧任务。定时器不会被后续到达无限推迟，同一版本的 stale 重试最多两次。
- sessions-delta 仅要求后续追赶，允许已确认窗口提交并显示；已观察到的删除、撤回、编辑、成员变化、账号切换仍严格拒绝旧结果。SQL 的硬围栏及完整校准事务不变。
- SQLite 新增有界 refresh_hints 元数据（最多 1,024 个作用域），将“窗口还需追赶”与“结果已被撤销”分开持久化。读取仍返回真实 committed/stale 状态；重启不会把未追平窗口误报为最新。
- 冷加载期间不消费或保存空列表的 viewport。真实页面刷新暴露了空占位提前覆盖历史锚点的问题；完整 Surface 延迟缓存回归先失败，修复后通过。真实客户端切换对话、同源页面刷新后的消息锚点及 -3.125px 偏移完全一致。
- 不新增 Host 路由或 SDK/Tool 能力；UI、现有 SDK 和 Tool 仍共用同一 UnifiedChatTimelineService。客户端与 DSH 源码未修改，插件版本与根 README 未修改。

回归覆盖：100 次读取中到达通知的成功/失败收尾、底部跟随及历史位置；1,000 次通知的固定资源上限；切换会话后的迟到结果；四轮各 100 次到达期间持续提交；硬失效覆盖软刷新；SQLite 重启后的 stale/撤销状态；真实 ArkmeService 的通知路由。

### 实现与一致性边界

- 底部追新使用现有 Host 统一时间线的完整最新页（常规 40 条），同步成本不再随以前浏览过的历史增长。读取前后都检查追新意图；期间上翻、定位、around 窗口或来源不完整时，保留原来的完整窗口校准与阅读位置。旧消息可继续通过正确的 older cursor 加载。
- SQLite、Worker、账号作用域、ticket、删除/权限硬失效及提交后读回保持原 owner。UI 不从推送提示伪造正文、不把未持久化结果标记成已缓存。缩小的是底部活跃显示窗口，不执行数据库清库。
- 滑动窗口裁剪和前插时保留幸存行的分块归属；观察器只在分块身份变化时重建。可见预算改为 200 行加最多 40 行强制锚点，删除造成短分块时也能填满视口。
- 同一滚动区域只有一个动画帧 owner；到达底部后停止帧任务，但保留追新意图以应对异步高度变化。滚轮、触摸、指针或键盘操作立即取消，作用域退出释放监听；显式阅读恢复仍即时按锚点定位。动画中的临时距离不会被保存为历史阅读，也不会闪现“回到底部”。
- CPU 采样定位到侧边栏 `conversationTimeLabel`：25 秒采样里自耗时合计约 8.93 秒。现在只保留当前语言的三个日期格式化器，时间戳不进缓存；按每个日期的本地偏移处理系统时区变化与夏令时。另一轮 25 秒实测中该函数自耗时约 0.26 秒。两轮阅读动作不完全相同，函数采样用于定位热点，不作为整机统一基准。

## 2026-10-12 连续正文投影与前台未读语义复核

用户继续实测发现消息按批弹出，当前对话的未读随批次增加后消失。本轮基线为 `8a971d1e`，沿用同一隔离任务分支。修复 owner 为 Plugin Host 与 Browser UI；客户端和 DSH 源码不变，不调整请求协调器并发上限。

### 已确认原因与修复

1. 实时事件已有经过 Host 校验的消息正文，但 unified 窗口仍等第二次网络读取才显示。新增 mounted-conversation live tail：仅在完整最新窗口、原生序号严格连续且身份完整时立即呈现；缺号、历史窗口、不完整来源仍走原有权威校准。live tail 不拥有分页覆盖证明，也不直接写 SQLite，明确标记 `network/deferred/stale`；随后由原有单个校准 owner 提交持久化窗口。校准以读取开始时的 revision 为边界，保留与读取并发的新消息，删除和权威遗漏不得复活。
2. 当前对话只有离散的打开已读动作，目录先到而正文/ACK 后到时产生角标闪烁。目录发布前投影连续阅读意图，只有前台可见、窗口在最新端且没有阻断覆盖层时生效；真实 ACK 仍等待正文显示，且只推进实际显示的原生序号。离开/隐藏恢复尚未显示的未读，已经显示的游标继续有界排空；失败恢复服务器未读，历史模式不吞掉新消息。
3. ACK 的剩余未读可能对应更靠后的服务器序号，旧实现把剩余数量放到较旧目录序号上。Host 返回经过校验的 `latestSequence`，Host/Browser 均将剩余未读与该服务器前沿一起投影，并保留较新的目录和已读水位。部分 ACK 更新未见消息的备份数量，乱序旧 ACK 不得反向增加该数量。
4. 原 `sourceRef` 含会话活动时间和最新序号，每条消息都会改变引用，误触发成员页、文件任务和重编辑恢复的初始化读取。新增账号签名的 `conversationRef`，仅去掉目录活动证据；会话 kind/owner/name/subject/bot 绑定与原授权校验保留。目录隐藏/恢复继续使用原始动态 `sourceRef`；正文消费者使用稳定引用，旧 Host 无该字段时保持旧路径。
5. 本机已读写入及其事件回声原来重复触发正文投影。成功 ACK 不再拉取正文，自己已确认或正在提交的游标回声只做有界去重；不确定写入、其他设备推进和未被覆盖的游标仍触发目录校准。跟踪器不能切换账号 owner，晚到的旧账号完成回调不得污染新账号。日历自动失效读取使用已有后台请求通道，初次打开与显式重试保持前台语义。

### 资源与兼容边界

- live tail 与当前账号/会话同寿命，沿用 2,000 事件窗口上限；不生成新的 coverage token，不改变 500 token 上限。没有人为逐条播放队列、延迟动画或新增轮询连接。
- 权威窗口刷新仍单飞；实时正文立即显示，持久校准在空闲时采用 1 秒的固定合并期限，连续事件不会重置计时；已有读取在途时等待其结束，紧急失效仍可提前。
- 已读 ACK 为一个在途请求加一个最新待提交游标，两次启动至少间隔 1 秒；离开只立即排空已经观察到的游标，账号变化后旧请求结果丢弃。Timer 在排空后清理。
- Host 本机回声跟踪最多 512 会话，每会话最多 128 个并发 ticket；容量不足回退普通目录校准，不丢写。账号切换、订阅释放和 dispose 均清理。
- 默认关闭的诊断只增加阶段耗时、数量和协调器统计，无正文与凭据；关闭时不采集统计。临时逐帧、网络和长任务监听仅在本地验收脚本中，未进入发布包。
