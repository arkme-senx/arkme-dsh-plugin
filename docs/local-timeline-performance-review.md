## 本轮修复

- 完整校准删除正文后，旧请求可能在其他窗口重建已删除事件。补充持久化会话 ticket 围栏；Host 明确拒绝过期提交，不能用网络降级结果重新发布旧正文。
- 共享 canonical 正文中的 token 可能污染其他窗口。读回与 gap 保留现在使用窗口引用自己的 coverage token，同时保持共享正文更新。
- 历史锚点原先通过正文 JSON 扫描查找，改为稳定事件身份索引查询；兼容身份只扫描一次 canonical 内容。
- 重叠窗口 gap 保留重复解析同一正文，改为 SQL 事件去重后解析，跨 token 重复事件也不会再次解析。
- 文本选择结束但没有新滚动时，可见块可能不更新。补充 selectionchange 恢复与卸载清理，布局排序前每候选只读取一次几何位置。
- Worker 排队字节预算原先只统计正文，遗漏刷新 token 等命令参数。现在 admission 统计完整命令，超大参数在 structuredClone 前拒绝，不能绕过队列预算。
- 块身份原先包含末条消息 ID，追加一条消息会重挂整个末块。改为稳定首行身份，1,999→2,000 条追加测试从重挂 40 行降为仅挂载新行，已有 39 行无需释放和重建媒体/反应 owner。

上述场景均先以失败回归复现，再修复通过。另覆盖真实 Host 并发网络结果晚于完整删除校准的拒绝路径。

## 性能证据

macOS、Node 25.5.0，本机同一 worktree、相同 SQLite/WAL 配置。每组 256 窗口 × 40 事件，每事件正文约 1 KiB，20 次操作；审查前后都用单 worker 的 Vitest 执行。数字是本地样本，不是跨平台 SLO。

| 操作 | 审查前 p50 / p95 (ms) | 修复后 p50 / p95 (ms) |
| --- | --- | --- |
| 未变化窗口写入 | 0.298 / 0.852 | 0.226 / 0.357 |
| 历史稳定锚点读取 | 13.059 / 19.082 | 0.150 / 0.220 |
| 40 条正文变化写入 | 1.713 / 3.904 | 1.956 / 7.912 |
| 满容量写入与淘汰 | 1.655 / 3.888 | 1.553 / 3.853 |

正文变化写入尾延迟有抖动，不能据此宣称所有路径提升；该路径未新增随缓存窗口数量重复解析正文的操作。锚点路径的扫描已从热路径移除。确定性测试还确认：

- 256 个重叠窗口、40 条共享事件：gap 保留的 JSON 解析次数从 10,240 降为 40，正文不丢失。
- 256 个满容量窗口继续写入：窗口数保持 256、没有孤立正文、引用计数与窗口事件数一致。
- 未变化窗口连续写 10 次：无整页 metadata 更新。
- 120 条失效通知合并为 20 次写入，峰值并发 1；等待可取消。
- Worker admission、窗口/字节/页数上限、卸载释放、长列表最多 240 行、阅读位置持久化均有回归。

SQL、数据库清理和大部分持久化 JSON 工作在唯一存储 Worker；UI 仍需进行有界投影和内存预算估算，整个进程 RSS 不等于正文预算。

另以隔离编译的真实 Worker 连续进行 20 次 2,000 事件窗口的变更提交与读回（序列化 2,376,339 字节）：功能校验全部通过，p50 82.84 ms、p95 103.09 ms。调用方事件循环监测分辨率 10 ms，观察 p95 11.12 ms、最大 16.65 ms，期间 1 ms timer 获调 1,357 次。该轮与完整测试同时运行，没有对应旧版同负载曲线，仅证明所测窗口的功能、异步存储和主线程存活，不声明全局延迟提升。

最终浏览器 fixture 复验 2,000 条消息：10 次 A→B→A、正文刷新、重载后均保留 `A:1002` / `-15px`。选择文本后跳滚，取消选择即恢复目标可见块，观察最多 120 行，未超过结构上限 240。
