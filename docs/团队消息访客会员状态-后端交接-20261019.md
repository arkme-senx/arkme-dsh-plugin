# 团队消息访客会员状态后端交接

日期：2026-10-19

目标：团队成员查看外部访客时，在昵称旁看到与私聊一致的 VIP / SVIP 星标。展示的是当前会员权益，不代表历史付费、订单金额或充值记录。

## 当前核验结果

2026-10-19 对生产环境进行只读抽查，没有发送消息、修改已读或会员数据：

| 接口 | 抽查范围 | 返回情况 |
| --- | --- | --- |
| `https://team.jotmo.cc/api/v1/team/conversations/list` | `side=team`，返回 3 个会话，`has_more=false` | 3 个 `visitor` 都只有 `nickname`、`avatar_url` |
| `/api/v1/team/conversations/timeline/page` | 上述其中 2 个会话 | `conversation.visitor` 和消息 `sender` 同样不含会员类型 |

会话响应也不含可供前端调用公开资料查询的访客用户 ID。不能根据昵称、头像或某条消息发送者猜测访客身份，更不能拿当前操作团队成员的会员状态代替。前端目前无法判断这些访客是否为会员；缺字段不等于非会员。

私聊已通过 Chat 对方资料中的 `member_type` 调用 `arkmePeerMemberType`，使用 `ArkmeMembershipBadge` 展示 13px 星标。本次团队显示复用该组件和类型转换，不新增支付数据接口、不逐条消息查询会员。

## 建议后端补充的最小协议

以下是待后端实现并确认的协议，尚未宣称生产已支持。

在团队会话的 `visitor` 对象中增加 `member_type`，推荐字符串枚举：

```json
{
  "visitor": {
    "nickname": "访客昵称",
    "avatar_url": "原有头像地址",
    "member_type": "svip"
  }
}
```

| 值 | 含义 | 插件展示 |
| --- | --- | --- |
| `vip` | 当前 VIP 权益有效 | 私聊同款紫色星标；悬浮提示「VIP 会员」 |
| `svip` | 当前 SVIP 权益有效 | 私聊同款金色星标；悬浮提示「SVIP 会员」 |
| `free` | 已核实当前没有有效会员权益 | 不显示会员星标 |
| `unknown` / `null` / 缺失 | 状态不可用或尚未提供 | 不显示星标，内部保留未知；不当成非会员 |

兼容现有 Chat 枚举时，插件也接受 `0=free`、`1=vip`、`2=svip`。如后端采用不同字段或枚举，请先对齐协议，不能直接套用数字。

需要覆盖所有返回会话对象的入口，至少包括：

- `conversations/list`：团队收纳中的访客列表。
- `conversations/timeline/page`：会话标题、聊天预览标题，包含翻页响应。
- `conversations/open`：从联系人或其他入口打开会话的首屏资料。
- 如果发送或其他操作返回完整会话对象，也应使用同一个访客资料投影，避免新响应遗漏字段覆盖已有状态。

消息 `sender.member_type` 可按同一规范返回；本次不在每个消息气泡重复加星标。团队名称、团队成员身份、当前登录用户权益都不作为访客会员状态的回退来源。

## 状态与权限要求

1. 由服务端根据已鉴权会话的真实外部访客 ID 查询当前会员权益，前端不需要获知底层用户 ID 或订单数据。
2. 只有本来有权读取该团队会话的成员能随会话读取该资料；不增加按任意身份枚举付费状态的公开接口。
3. 分页目录建议批量查询会员权益，避免逐访客或逐消息串行调用阻塞消息列表。会员依赖失败时返回 `unknown`，消息仍正常可用。
4. 明确按权益有效期判断到期、退款后失效、升级和降级。不要使用「曾经买过」或旧消息发送时的会员快照。
5. 目录、打开会话、时间线共用同一投影；定义短期缓存及失效方式。会员变化可发会话资料失效事件；至少下次目录刷新、窗口聚焦或重新打开会话时返回最新权益。
6. 不依赖消息 `revision` 才更新会员信息：会员到期可能发生在没有新消息的时候。

## 联调验收

1. 使用已知 VIP、SVIP、非会员各一个账号给同一团队发消息（由测试人员授权操作），检查第二栏、第三栏、预览中的星标类型一致。
2. 非会员与未知均不画会员星标，但服务端与适配层应能区分二者，未知不能计入非会员统计。
3. 外部身份查看「团队」时，不把访客自己的星标贴到团队名称上。
4. 当天到期、升级、降级后，重新读取会话与目录能更新；最新响应为 `free` 或 `unknown` 时清除旧星标。
5. 同名访客、团队成员自身为会员、不同团队和切换账号时均不串身份。
6. 长昵称窄窗口不遮挡星标、时间和关闭按钮；现有消息、未读与权限行为不受影响。
7. 预览只读，不因查询会员或预览消息而提交已读。

自动化测试覆盖访客与发送者区分、数字/字符串协议、未知值、到期后清除、各展示位置及预览只读行为。4 个相关测试文件共 180 项通过、1 项原有测试跳过，类型检查和插件构建通过。
