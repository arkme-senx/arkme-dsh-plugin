# Arkme 联系人目录设计

## 目标

在 Arkme 产品导航的“对话”下方新增一个同级“联系人”Tab，不改动对话列表的结构、状态和交互。点击“对话”继续展示原有对话列表与聊天内容；点击“联系人”才将中间列切换为联系人目录。目录包含群聊、Bot、未标记说话人、团队和联系人五个可折叠分组；联系人按首字母分组。右侧在未选择条目时展示 Arkme Logo，选择联系人后展示联系人资料与世界内容，选择未标记说话人后展示移动端既有的推测、试听和标记流程。

## 已确认的交互范围

- 五个分组按以下顺序展示：群聊、Bot、未标记说话人、团队、联系人。
- 每个分组可展开或折叠，并在标题右侧展示数量。
- 联系人按排序名称的首字母归入 A–Z；不能映射到拉丁首字母的名称归入 `#`。
- 未选择任何联系人或说话人时，右侧展示 Arkme Logo。
- 联系人右侧上栏展示头像、昵称、备注和“发消息”；下栏展示该联系人的世界内容，没有公开内容时展示空状态。
- 未标记说话人右侧复用现有移动端 Web 页面交互：推测说话人、去听声音、选择说话人、确认标记全部片段。
- 团队只展示列表和数量。团队行没有点击、键盘激活、选中或详情交互。
- 群聊和 Bot 沿用现有会话入口，不在联系人详情区域重复实现业务详情。

## 当前事实与复用边界

- 真实宿主通过 `ArkmeProductNavigation`、`ArkmePersistentSidebar` 和 `ArkmePersistentWorkspace` 分别承担产品 Tab、中间列和主内容；`ArkmeRootFrame` 只是兼容表面，不得作为生产接入点。
- 插件已有 `user.card`、`chat.private.open` 和世界内容读取能力，可复用联系人资料、私聊打开和用户世界数据。
- 即我联系人列表接口为 `/api/v1/chats/contacts/list`；移动端已有联系人排序和首字母目录投影。
- 团队列表接口为 `/api/v1/team/list-mine`。本次只消费列表，不引入团队详情能力。
- 现有未标记说话人 Web 页面使用以下服务端能力：
  - `/api/v1/audio/unmarked-speakers/list`
  - `/api/v1/audio/unmarked-speakers/mark-options`
  - `/api/v1/audio/unmarked-speakers/speaker-inference/retry`
  - `/api/v1/audio/unmarked-speakers/segments`
  - `/api/v1/audio/unmarked-speakers/mark`
- 未标记说话人候选、推测、声音片段和标记结果均以服务端为 owner；插件不得根据录音内容自行合并、推测或构造候选。
- 声音播放继续通过受控媒体签发链路完成，浏览器不直接获得登录凭证、存储凭证或任意对象读取权限。

## 方案选择

### 采用：插件内原生联系人目录

插件 Host 新增目录与未标记说话人服务，浏览器 UI 使用安全投影和不透明引用渲染桌面布局。该方案能与现有 Arkme 外壳、主题、键盘交互和右侧状态路由一致，同时保留移动端业务语义。

### 未采用：嵌入现有 Web 页面

直接嵌入 `/unmarked-speakers` 能减少服务适配，但会形成桌面外壳内的第二套路由、鉴权、主题和返回行为，联系人右侧也无法统一管理选中状态，因此不采用。

### 未采用：在 `ArkmeRootFrame` 中直接调用所有接口

该方式改动入口少，但会把网络契约、数据投影、播放和写操作继续堆叠到已较大的根组件中，难以独立测试和维护，因此不采用。

## 架构与组件边界

### Host 服务

新增联系人目录服务作为五类数据的统一入口，但不复制各业务 owner 的数据：

- 聚合群聊、Bot、团队、联系人和未标记说话人列表。
- 将原始接口字段转换为稳定、最小化的 UI 投影。
- 对浏览器可选择的联系人、会话、候选、声音片段和手动说话人签发账号绑定的不透明引用。
- 提供分页、重试、详情、声音读取和标记方法。
- 在认证用户变化时清理账号级缓存和未完成请求。

未标记说话人能力单独封装，负责严格验证候选列表、mark options、segments、retry 和 mark 契约。它不负责联系人世界、团队或现有对话。

### Client 组件

在 `src/client/redesign` 下建立独立联系人目录模块，至少拆分为以下职责：

- `ContactDirectorySurface`：协调目录加载、折叠状态和当前选择。
- `CollapsibleDirectorySection`：通用分组标题、数量、加载、空状态、错误和列表容器。
- `AlphabeticalContactList`：联系人首字母分组和稳定排序展示。
- `DirectoryDetailPane`：在 Logo、联系人详情和未标记说话人流程之间切换。
- `ContactProfileDetail`：资料卡、私聊动作、世界列表及世界空/错状态。
- `UnmarkedSpeakerDetail`：候选摘要、推测、声音和选择说话人子状态。

`ArkmeProductNavigation` 只新增同级“联系人”Tab 及模式切换。`ArkmePersistentSidebar` 在对话模式下必须保留原有 `ArkmeNavigation` 分支不变，仅在联系人模式下改为挂载 `ContactDirectorySurface`；`ArkmePersistentWorkspace` 同理仅在联系人模式下挂载详情。业务字段转换和未标记说话人写逻辑不得进入这些外壳组件。

### 选择状态

右侧选择使用显式判别联合，不复用字符串路由猜测条目类型：

- `none`
- `contact`
- `unmarked-speaker`

群聊和 Bot 点击后直接调用现有会话打开能力，不进入该详情联合。团队没有选择状态。

## 数据投影与排序

### 联系人

联系人排序名称按以下优先级生成：

1. 非空备注；
2. 非空昵称；
3. 服务端允许展示的账号名；
4. 安全兜底文案。

中文名称使用项目已有拼音/目录投影语义得到拉丁首字母，拉丁字母统一转为大写。数字、符号、Emoji、空白和无法映射的字符进入 `#`。分组按 A–Z、`#` 排序；组内使用中文 locale 的稳定比较，并以安全引用作为最终稳定次序，避免刷新时跳动。

### 未标记说话人

候选名称复用现有 Web 页面口径：

- 跨天候选显示为“说话人 {token}”。
- 单日候选显示为“{日期} · 当天说话人 {token}”。
- 副文案展示出现天数和最近时间。

目录不得把“手动说话人”或“已识别人”混入未标记候选。

### 团队

团队仅投影名称、可公开标识和头像兜底。团队数据不生成详情引用，也不注册点击处理器。

## 加载与交互数据流

### 初次加载

- 保留现有任务/对话加载流程。
- 联系人默认展开并优先加载。
- 群聊、Bot、未标记说话人和团队先加载数量；首次展开时加载列表。
- 每个分组拥有独立请求与独立状态，一个分组失败不影响其他分组或现有对话。
- 折叠状态在当前插件会话内保留，不新增跨设备设置。

### 联系人详情

1. 用户选择联系人。
2. 取消上一详情请求，并记录新的联系人安全引用。
3. 并行读取用户资料和世界内容。
4. 资料成功后立即展示上栏；世界内容在下栏独立进入 loading、ready、empty 或 error。
5. 点击“发消息”调用现有 `chat.private.open`，打开或创建对应私聊并切回该对话。

世界空结果和世界读取失败必须区分：只有成功返回零条公开内容时才展示空状态。

### 未标记说话人详情

1. 首次展开分组时读取候选第一页；后续按游标加载并按候选身份去重。
2. 选择候选后读取 `mark-options`，展示出现天数、有效声音时长、相关片段、最近时间、推测说话人和对话摘要。
3. 推测处于 pending 时按现有退避规则轮询；长时间等待或失败不阻塞人工试听和选择。
4. “去听声音”读取 `segments`，展示日期、会话、时间、时长和转写，并按需签发可播放媒体引用。
5. “选择说话人”展示现有手动说话人、服务端推荐项和“新建手动说话人”。
6. 确认时提交候选引用、`candidate_version` 以及选中的手动说话人或新名称。
7. 标记成功后展示成功状态，刷新候选与数量；用户可返回目录或查看已标记说话人的相关录音。

## 声音播放

- 同一时间只允许一个片段播放。
- 播放其他片段前先暂停并释放前一个片段。
- 离开候选、折叠目录、切换账号或卸载组件时停止播放并撤销临时媒体 URL。
- 播放失败只更新当前片段的错误状态，不使整个说话人详情失败。
- Client 只持有短时媒体引用；Host 校验当前账号、候选和片段归属后才解析真实对象并返回受控媒体。

## 错误、空状态与并发

### 通用分组状态

每个分组独立维护 `idle / loading / ready / empty / error`。错误状态在分组内部显示重试；已有旧数据时保留旧数据并显示非阻塞提示。

### 请求竞争

- 每次详情选择创建新的 `AbortController` 或等价请求代次。
- 响应提交 UI 前同时校验请求代次和当前安全引用。
- 旧响应、已取消响应和前一账号响应不得覆盖当前详情。
- 当前选中项被刷新结果移除时，停止相关媒体、清除选择并恢复 Arkme Logo。

### 未标记说话人投影状态

- `building`：没有已发布数据时显示“正在建立说话人列表”，按服务端 `retry_after_ms` 重试。
- `stale`：保留已发布列表并提示后台更新。
- `failed`：有旧数据时继续展示旧数据；没有旧数据时显示错误与重试。
- 游标失效：丢弃增量页，从第一页重新载入并去重。

### 推测状态

- `pending`：显示正在分析，可继续试听或人工选择。
- `failed` 且允许重试：显示上次可用推测（若有）和“重新分析”。
- `unavailable`：不编造推测，仍保留试听和选择入口。

### 标记结果

- `marked`：刷新候选、数量和手动说话人数据，展示成功状态。
- `stale`：提示录音分析已变化，重新读取候选详情。
- `conflict`：提示部分片段已被其他操作标记，不修改本地列表，刷新候选。
- `candidate_not_found`：清除当前候选并刷新目录。
- `speaker_not_found`：保留候选，刷新选择说话人列表。

所有非 `marked` 结果都禁止乐观移除候选。

### 鉴权

登录失效交给插件现有鉴权恢复流程。恢复后重新加载当前展开分组，不把未认证期间的数据归属给新账号，也不持久化敏感响应。

## 可访问性与视觉约束

- 折叠标题使用原生 `button`，维护正确的 `aria-expanded` 和关联内容。
- 列表使用原生可聚焦操作；选中项有视觉状态和语义状态。
- 团队行使用非交互元素，不伪装为禁用按钮。
- 所有可执行动作支持键盘触发并保留可见焦点。
- 目录和右侧详情支持浅色、深色和窄窗口；不得出现水平溢出。
- 右侧空白、资料、世界空状态和说话人子流程遵循已确认低保真原型，不引入未确认的搜索、筛选或团队详情。

## 测试方案

### 服务契约测试

- 五类列表的成功、空、分页和失败契约。
- 未标记说话人 list、mark-options、retry、segments 和 mark 的严格字段校验。
- 安全引用的账号绑定、类型绑定、过期、篡改和跨账号拒绝。
- `candidate_version`、游标失效和全部标记结果映射。
- 媒体签发仅允许当前账号可访问的候选片段。

### 数据投影测试

- 备注优先、昵称兜底和安全名称兜底。
- 中文、英文、数字、符号、Emoji 和空名称的 A–Z / `#` 分组。
- 稳定排序、分页合并、重复项去重和刷新保持。
- 未标记说话人跨天/单日显示口径。

### Client 组件测试

- 五个分组的数量、展开、折叠、懒加载、空状态、错误和重试。
- 团队行不可点击、不可键盘激活且没有选中状态。
- Logo、联系人资料、世界列表、世界空状态和世界错误状态。
- 推测详情、去听声音、选择/新建手动说话人和成功状态。
- 快速切换、取消请求、选中项失效和账号切换。
- 单实例声音播放与播放失败恢复。

### 回归与构建门禁

- 现有对话列表、新建任务、群聊/Bot 入口和私聊打开能力保持不变。
- `pnpm test` 通过。
- `pnpm typecheck` 通过。
- `pnpm build` 通过。
- `git diff --check` 通过。
- 对桌面常规宽度、窄窗口、浅色和深色主题做截图或浏览器视觉验收。

## 不在本次范围

- 团队详情、团队成员管理、创建、加入或退出团队。
- 修改服务端联系人、团队或未标记说话人业务算法。
- 在插件侧自行进行说话人聚类、身份推测或声纹比对。
- 将未标记说话人误当作联系人或自动发送消息。
- 新增联系人搜索、通讯录管理、语音通话或视频通话。
- 修改移动端/Web 端页面视觉或交互。
- 提交、推送、创建 PR 或部署。

## 验收标准

1. 产品导航在“对话”下方展示同级“联系人”Tab；默认对话视图的列表、会话选中、缓存、未读和新任务交互与原版一致。只有点击“联系人”后，中间列才按顺序展示群聊、Bot、未标记说话人、团队和联系人五个折叠分组及数量。
2. 联系人按 A–Z / `#` 分组，备注、昵称和排序口径符合本设计。
3. 未选择时右侧展示 Arkme Logo。
4. 联系人详情上栏展示头像、昵称、备注和“发消息”，下栏展示世界列表、真实空状态或独立错误状态。
5. “发消息”打开正确私聊，现有对话不回归。
6. 未标记说话人展示与现有移动端一致的候选统计、推测说话人、去听声音和选择说话人流程。
7. 用户能试听声音、选择推荐或其他手动说话人、创建手动说话人并以 `candidate_version` 确认标记全部片段。
8. 标记成功及所有冲突结果符合本设计，失败时不误删候选。
9. 团队列表可展开查看，但团队行完全没有点击交互。
10. 分组失败、世界失败、推测失败和声音失败互不扩大为整页失败。
11. 快速切换和账号切换不会显示前一选择或前一账号的数据。
12. UI 不出现 Token、存储凭证、真实对象 key、内部路径或其他账号身份。
13. 自动化测试、类型检查、生产构建和差异检查全部通过，桌面与窄窗口无水平溢出。
