# Arko 对话统一：前端交付与后端对接

更新：2026-10-18。范围：Arkme 插件的 Arko Agent 对话。本文不含用户的实际对话内容、令牌或账号数据。

## 本次已完成

- AI 回复及消息详情复用 `ArkmeMarkdownBody`：标题、列表、强调、表格、代码、链接；用户输入保持原文，不强行将其解释成 Markdown。
- 顶部复用对话的日历、搜索和更多菜单；更多包含导出、清除上下文、能力快捷提问。
- 气泡、头像、日期分隔、消息右下角时间、输入框和发送按钮与普通对话保持一致；模型选择、停止任务、恢复待确认请求保留。
- 单击消息打开共用详情面板，作者与时间在面板头部。选择文字、点击链接不误开详情。
- 搜索按页展示读取进度，匹配提问和回复，点击结果定位原消息；日历点击日期定位该日首条消息。定位使用原 `sessionId + messageId`，不伪造快记 ID，不切换正在进行的 Agent 会话。
- 历史定位只呈现附近的 50 条消息，可向前/向后查看并返回最新消息。后台回复更新不会强制打断历史阅读。
- 完整读取成功后才生成 Markdown 导出；失败、取消、分页异常、读取期间首页身份变化均不导出一份冒充完整的文件。切换账号或离开 Arko 会中止工具发起的读取。

当前前端工具暂用已有 `arko.history` 完整消息投影，按 offset 顺序读取。只有用户打开搜索、日历或导出时才触发工具读取，不在主界面初始化时全量扫描。每页最多 50 条；进度和部分结果先出现。很长的历史仍需服务端检索优化，见下文。

## 需要后端配合的重点

### P1：关键词查询与原消息上下文定位

在现有活动查询能力上扩展，或提供等价的统一消息查询；路由可由后端定，以下字段是建议协议，不是声称已经上线的 API。

1. 支持 `keyword`、可选角色 `user / assistant`、可选 `start_at / end_at` 和稳定游标。默认搜索两种角色的正文；思考过程不默认参与搜索。
2. 返回 `session_id + message_id`、角色、时间、命中片段，以及同一快照的 `has_more / next_cursor / source_version`。明确是原文匹配还是语义搜索，第一期原文搜索即可。
3. 支持按原消息身份读取上下文，例如 `anchor_message_id + before_limit + after_limit`。需支持旧助手与 Agent 会话，不能只查当前 session。
4. 被删除、无权限、不存在、仍在生成要明确区分；不可返回空文本却让前端误认为成功定位。

这样前端可以搜索时直接显示命中，点日期通过现有活动接口取锚点，再按身份加载附近消息，避免为了一个旧日期扫描全部历史。

### P1：活动投影到完整消息的桥接

当前线上活动条目已验证的字段是：`entry_id / source_kind / occurred_at / role / content / source_ref`。`source_ref` 保存原始消息和会话身份。

现有 `arko.history` 除正文外还会投影执行状态、运行身份、关联快记和插件消息操作引用。活动接口的精简条目不能直接替换完整消息：否则旧消息定位后可能丢失状态、来源和已有操作。

建议复用现有消息序列化，提供按消息身份批量读取完整消息的能力，或让活动查询可请求完整投影。所需事实字段包括：

- `message_id / session_id / role / content / created_at`，保留原始 Markdown。
- `order_at` 与 `created_at` 的含义、单位明确；日期索引目前按 order_at，消息时间使用 created_at，需要确认产品口径及二者差异。不要静默互换。
- 消息/执行状态、运行身份，以及原先可见的关联快记和来源引用。
- 可用操作的能力信息。插件可继续从服务端事实生成自己的不透明操作引用，不要求后端返回插件内部引用字符串。
- 文本格式建议显式提供 `plain / markdown`，兼容旧 AI 回复默认 Markdown、用户消息默认原文。附件不在此次增加范围内。

### P2：完整导出的快照一致性

活动接口已有版本校验，优先复用。需要把它覆盖到完整消息投影的批量读取/导出：固定查询范围与 `source_version`，分页期间发生编辑、删除或新增时明确要求重读，或保持服务端快照。

当前前端用 offset 去重并在结束时重读首页，可发现首页消息身份变化；**不能证明历史中间的编辑/删除一定会被发现，也不能解决 offset 读取期间所有并发变更**。这不是已完成的严格快照保证。若历史很大，可提供后台导出任务，显示进度并获取有权限校验的短期下载链接。

## 建议对接顺序

1. 后端确认完整消息按身份读取的可用接口和字段，若已存在直接告知并给一份脱敏样例。
2. 前端将日历改为现有按月 buckets + 日期活动查询 + 原消息上下文，避免扫描全部历史。这部分主要是前端接线，不要求重做日期接口。
3. 接上服务端关键词查询和稳定完整导出，保留当前客户端检索作为有明确边界的兼容路径。

## 验收

- 超过一页的历史可命中旧消息；用户提问、AI 回复都可搜；同关键词同一消息不会重复。
- 日历每日条数包含可见双方消息，时区、跨日、夏令时与消息时间口径一致；无记录与加载失败区分。
- 点击旧结果定位精确消息并展示上下文，继续输入仍发到当前 Agent 会话；不误创建会话或发送消息。
- 读取过程中新增/编辑/删除不静默漏消息；游标过期和版本变化可重试；取消或换账号后不能继续导出旧账号数据。
- 无权限、删除消息不会通过搜索、详情或导出泄露；普通账号不能访问他人历史。
- Markdown 安全渲染，链接点击、文字选择不触发详情；右键局部复制与快捷键一致。
