# 录音说话人纠错一期：后端交接

日期：2026-10-14；前端仓库：arkme-dsh-plugin；当前分支：`codex/ts1014-10-录音实体识别`。

## 交付状态与目标

前端已实现纠错入口、单条明确排除人物、声音来源选择、附近片段试听/手动勾选、拆出原分组、成功反馈和撤销，以及插件 Host 的接口适配和账号/范围校验。未合并 dev，未修改或部署后端。

本文件中的新 API 是**待后端实现的 v1 对接协议**，不是已经上线的接口声明。接口未开放时，3102 可以预览选择/试听，提交按钮禁用，明确显示“当前选择尚未保存”。不会调用旧取消标记接口伪装成纠错成功，也不把本机 localStorage 当成跨端纠错数据。

目标案例：真实人物 A 的发言与手机播放的其他人物声音被归为同一说话人。用户指出某句“不是 A”后，该句应立即恢复为独立待确认身份，后续读回、自动归属、聚类重跑不得又回到 A。用户不必知道真正是谁。

**示例人物、ID、数字均为虚构协议示例，不需要另索取用户个人的 candidates JSON。**

## 现有问题证据

- 插件 `src/services/recording-service.ts` 的 `recordingSpeakerRecommendation` 走 `similar-session-speaker`，按 `session_id + num` 推荐，不能表达某一句对人的明确否定。
- 本地 jotmo-audio 的 `audioSimilarSessionSpeakerHandler` 从 SessionSpk 取声纹，按正式人物的历史声纹匹配。需上线同事核对生产版本。
- `BatchRestoreChildAsrSpeakerIfMatches` 只撤销 Q / 设置 QU 忽略当前继承标记，不创建永久排除关系、不拆聚类。
- 部分 Session 级人工绑定会保存 `SpeakerVoiceprintVector`。若绑定的声音簇已混杂，取消展示标记不会自动清理错误参考样本。具体用户是否受污染需查来源，不能根据现象直接断言。

## 产品语义（请保持一致）

| 操作 | 必须保存的事实 | 不能发生的行为 |
| --- | --- | --- |
| 原有“取消标记” | 恢复系统身份，沿用已有接口 | 不等同于明确否定某个人 |
| “不是 A” | 所选声音片段明确排除 A，并拆离错误归属 | 只删标签，下一次又推荐/自动标成 A |
| 声音来源 | `unknown` / `in_person` / `playback` | 把所有播放内容合并成同一个人物 |
| 拆出原分组 | 所选片段与原分组的分离约束、独立待确认身份 | 根据旧 num 扩大范围；把所有选中片段强行合成同一人 |
| 撤销 | 撤销指定 correction 的效力并恢复它影响的事实 | 用旧快照覆盖之后他人的修改 |

“播放内容”独立于人物身份：真实 A 的视频也可能是 A。仅修改来源不得清除人物；排除 A 不要求用户填写新的姓名。保留原录音和转写。摘要/人物统计需要识别播放来源，不能继续把播放内容当成现场人物的亲口发言。

## 前端交互和范围

1. 点头像，保留原有“取消标记”，另有“不是 A”和“声音来源 / 纠错”。若未标记且有推荐人物，可以明确否定这个推荐。
2. 能力已读取且可用时，“不是 A”对当前一条直接保存排除与拆分，提供撤销。没有能力时只打开预览，不保存；面板后来恢复能力也不会未经再次操作自动提交。
3. “核对附近片段”是当前日期、当前转写来源、前后 10 分钟内最多 100 条的**时间邻近列表**，不是声纹相似检索结果。可试听；默认只选当前条，无“全选同一说话人”。
4. 多条必须用户逐条勾选。每条保留原时间、姓名、原文；提交只传明确的片段集合。后续若提供声学候选检索，需另行约定证据和评分协议。
5. `playback` 在转写气泡内显示小型“播放内容”标签；默认不增加一整行。
6. 提交不自动重试。失败/未知结果保留选择，先重新读取状态；有提交回执但转写读回失败时明确告知“已保存，但暂未刷新”。
7. 关闭面板会放弃未保存的选择；不会后台排队写入。账号切换/组件退出后忽略晚到响应。

## HTTP 约定

服务：jotmo-audio，当前用户 Bearer 鉴权；用户 ID 从鉴权获得，不接受客户端指定 owner。

三个新增路由均 POST，沿用 Audio 业务响应封装 `{ "code": 200, "data": ... }`。以下示例仅展示 `data` 或请求 JSON。成功必须同时检查 HTTP 和业务 code。

Host 端解封 `itemRef` 后构造真实音频定位；浏览器不直接提供 child/session/person ID。建议上线顺序：先返回 supported:false，所有写入、读回、推荐约束和撤销验收后再开放 supported:true。

### 1. POST /api/v1/audio/speaker-corrections/context

请求：

```json
{
  "date_stamp": 1791907200000,
  "item": {
    "session_id": "session-example",
    "child_id": "child-example",
    "item_index": 12,
    "transcript_source": "system",
    "start_at": 12000,
    "end_at": 18000
  }
}
```

`date_stamp` 为客户端所选自然日的起始毫秒时间戳；服务端须使用账户录音日期规则校验，不能把请求日期当权限依据。`start_at/end_at` 是 Child ASR 相对时间（毫秒），必须与当前 ASR 内容校验，防止重转写后索引对应到另一句话。`system/doubao` 是不同来源。

未开放返回 `{"supported":false}`。前端也把此路由 HTTP 404/501 作为未开放；401/403、超时、5xx 和畸形响应是错误，不能伪装为不支持。

开放后的响应：

```json
{
  "supported": true,
  "schema_version": 1,
  "version": "owner-day-revision-17",
  "max_items": 100,
  "sound_source": "unknown",
  "excluded_speakers": [{"speaker_id":"person-example","label":"人物 A"}],
  "last_correction": {"id":"correction-example","can_undo":true}
}
```

- `version` 是覆盖所选自然日相关纠错事实的版本；必须随归属/排除/来源/拆分/撤销等相关事实变化。不是某条候选的临时编号。
- `max_items` 为 1–100；前端遵守上限。
- `excluded_speakers` 必须返回真实持久化排除事实。前端将 ID 映射为候选 optionKey，过滤被排除者的推荐标记。
- `last_correction` 可省略；可撤销记录必须属于当前用户和当前锚点片段。Host 会封装账号、日期、锚点绑定的 undoRef，浏览器不能改 correction_id。

### 2. POST /api/v1/audio/speaker-corrections/apply

```json
{
  "item": {"session_id":"session-example","child_id":"child-example","item_index":12,"transcript_source":"system","start_at":12000,"end_at":18000},
  "items": [
    {"session_id":"session-example","child_id":"child-example","item_index":12,"transcript_source":"system","start_at":12000,"end_at":18000},
    {"session_id":"session-example","child_id":"child-example","item_index":14,"transcript_source":"system","start_at":24000,"end_at":29000}
  ],
  "date_stamp": 1791907200000,
  "expected_version": "owner-day-revision-17",
  "idempotency_key": "fa05b98c-c5ba-46b9-93cb-121f8b8de7a1",
  "rejected_speaker_id": "person-example",
  "sound_source": "playback",
  "detach": true
}
```

- `item` 是锚点，必须包含在 `items` 中。一期只能同日期、同转写来源、同授权窗口的显式片段，最多 100 条。
- `rejected_speaker_id` 可省略。出现时，排除该人，并让被纠错片段不再继承该人；本期前端同时传 detach:true。不能清除其他片段或其他正确人工人物归属。
- `sound_source` 可省略，表示不改；`unknown` 是显式设为不确定。
- `detach` 表示从原错误分组中分开，**不表示这些选中片段相互同人**。至少一项改动非空。
- 每条校验 owner、来源、有效时间范围、当前 ASR 版本；跨账号、过期引用、删除音频、范围变化一律拒绝。一个目标冲突，整批失败，不能悄悄部分成功。
- 用户主动选择“不是 A”的片段若已被另一人新近明确标为 B，须返回冲突让用户核对，不能顺手清除 B。
- 幂等按用户 + key + action 存储原请求 hash 和原响应；相同 key 不同 payload 拒绝。匹配到已成功的同请求幂等记录应先回放结果，再检查旧 expected_version，不能重复写入。

成功响应：

```json
{
  "schema_version": 1,
  "state": "applied",
  "correction_id": "correction-example",
  "version": "owner-day-revision-18",
  "affected_count": 2,
  "can_undo": true
}
```

`affected_count` 是本次确认的去重目标数（含已满足目标状态的条目），须与请求集合一致；不是仅统计物理 modified_count。响应必须在纠错事实持久化后返回。不能只接收异步任务就返回 applied。异步派生重算可以后续进行，但权威读模型必须立即覆盖这些片段的展示归属。

### 3. POST /api/v1/audio/speaker-corrections/undo

```json
{
  "item": {"session_id":"session-example","child_id":"child-example","item_index":12,"transcript_source":"system","start_at":12000,"end_at":18000},
  "correction_id": "correction-example",
  "expected_version": "owner-day-revision-18",
  "idempotency_key": "8d29b5fe-ac5b-45bd-865c-0d97900b91e7"
}
```

响应：`{"schema_version":1,"state":"undone","version":"owner-day-revision-19","affected_count":2}`。

撤销该 correction 的所有目标，保留其他纠错事实。如果之后有新的人工修改，返回 409，不允许旧快照覆盖新状态。撤销是追加补偿记录，保留审计，不物理删除历史。

## 必须同步补齐的读模型

`one-day-trans` 的每条 ASR 添加：

```json
{
  "speaker_identity_source": "system",
  "effective_spk_id": "",
  "speaker_partition_id": "partition-example",
  "speaker_display_number": 10081,
  "sound_source": "playback"
}
```

- 使用既有 system/effective_spk_id 语义解除旧人工归属。仅清除 Q 而仍继承 SessionSpk 不算完成。
- `speaker_partition_id` 是稳定的不透明纠错分区 ID，`speaker_display_number` 是可展示的正整数编号。前端已接入：无正式人物时优先使用分区身份/编号，不再按旧 num 合在一起。
- 对未纠错旧数据可不返回新增字段。声音来源只有用户/可靠流程明确确认后才填，不能从“不是 A”推导成播放内容。
- 同步更新说话人目录、出现统计、搜索、时间轴、人物引用和新的摘要输入；旧摘要标记待更新，不应偷偷重写用户编辑内容。
- 摘要中播放来源应作为录音捕获的媒体内容，而非现场某人观点；无需删掉原文。

## 推荐与样本纠错要求

1. 人工排除/人工指定的优先级高于声纹自动匹配，不能被后续任务覆盖。排除键必须锚定原音频时间范围，不能只挂在易变的 ASR 数组下标上。
2. 现有 `similar-session-speaker` 对整组的推荐不够。前端当前用 context 的 excluded_speakers 再过滤；后端自动归属和其他端也必须使用同一约束。建议增加具体片段定位参数或统一推荐入口，约定后再调整插件请求。
3. 必须处理同一 SessionSpk 内混人的情况。禁止只在整组 num 上记录“不是 A”，那会误伤组内真正 A；需要分区/片段级身份覆盖，必要时对选定音频重新提取特征。
4. 追踪 SpeakerVoiceprintVector 的源音频区间、人工确认来源、模型版本和状态。被证实混杂的向量应可隔离/停用并重建，不应整个人物所有声纹一并删除。
5. 若一个声纹向量来自混合片段，不能把它直接当整个人物的负样本或正样本。保留真实 A 的清晰确认样本，把错误/媒体样本从 A 的匹配资产中隔离。
6. 重新聚类遵守 cannot-link / 排除约束；本次选中片段不能全部强行合并。若拆出多个声音，可生成多个待确认身份。
7. 原有 assign 接口也必须尊重纠错：用户重新明确指定可原子撤销相应排除（或返回明确冲突要求先撤销），自动/整组批量标记不能静默绕过排除。
8. 一期不承诺全账号未来所有声音一次纠正后永不出错；确定性保证针对明确纠正的音频范围。未来相似声音应保守推荐；自动历史修复另行提供预览/审批，不在本次范围。

## 补充：人工否定后的匹配范围收紧

用户补充希望“明确不是同一个人”后，后续识别自动更谨慎。建议作为后端纠错配套设计，以下策略尚未实现或验证，不是直接修改生产阈值的指令。

### 已核对的本地代码

- `jotmo-audio/internal/audio/types.go:364` 定义 `DefaultThreshold = 0.3`；`IsSimilarSpk` 判断归一化向量的余弦距离 `d <= threshold`。0.3 是距离上限，不是向量某一维，也不是 30% 的置信度；数值降低才是收紧。
- `internal/audio/speaker_voiceprint_match.go:134` 以正式人物最近最多 3 条声纹的平均距离排序并检查阈值。`gin/api/audio.go:3491` 的推荐读取 Session 说话人向量，而非被纠错的单句向量。
- `gin/compound/pipeline_v3.go:1948` 有组间归并 `<= 0.30`；`:1970` 的 Session 映射另要求最佳与次佳距离相差至少 0.05。`jotmo-audio-sd/child_sd_ms_up.py:132` 默认归并 0.3、更新参考向量 0.25。它们是不同阶段，不能仅修改一个全局常量就认为全部纠错完成。
- 上述为本地工作副本读取结果，未核对当前生产镜像或实际任务路由；后端实施前核对部署版本、模型和各阶段有效参数。

### 建议顺序

1. **明确纠正的原片段必须硬排除。** 无论计算距离多近，都不得自动回到被否定人物；撤销或后续明确重新标记才可改变。不能用更严格阈值替代这条事实。
2. **先处理错误参考样本。** 保留纠错原音频与时间定位；只从可确认的单一声音片段提取该人物的负样本。混音、重叠或多声混合片段先隔离/重分段，不把整个混合簇直接作为负声纹。追溯并停用错误正样本，保留真正人物的清晰样本。
3. **对未来新片段做局部、可回退的保守匹配。** 按用户、人物、embedding 模型版本管理确认正样本和反例。除满足该人物距离上限，还应明显更接近其可靠正样本，而非反例或其他候选；证据冲突时保持待确认。一次否定不能推导“所有类似声音都永远不是 A”，更不能把不同反例合成一个新人。
4. **有足够独立正反例后才校准阈值。** 比较同人与异人分数分布，按误合并优先的产品目标评估，同时统计真正同人被拆开的代价。不要每点一次“不是 A”就机械减 0.01，也不预设 0.25/0.2 一定正确。样本不足或正反例重叠时采用待确认，避免持续缩小导致本人完全识别不到。
5. **自动归属与推荐区分。** 自动归属应更严格；不确定候选可请求人工确认，但明确已排除的片段不能继续推荐被否定者。播放来源不等于另一个身份；现场和播放的分布差异应纳入校准，不能凭来源硬判不同人。

校准要记录策略版本、证据和适用范围，并可回退。上线前离线回放独立录音，检查误合并、误拆分和待确认比例；不要以同一段音频切出的重复样本冒充充分证据。第一期优先完成原片段硬排除、样本追溯和待确认降级；自适应阈值可以在上述数据具备后启用。

### 可复用的基础与缺口

本地 `internal/audio/models.go:860` 的 `SpeakerVoiceprintVector` 已有 owner、正式人物、embedding 类型、来源 Session、来源说话人编号和状态；`:888` 的 `VoiceprintHitLedger` 已有精确 `voiceprint_ref_id`。应复用这些身份与归因，不另建一套互不相认的声纹 ID。

这些现有字段还不足以证明某一条参考向量由哪些原音频区间生成。建议补齐参考向量的**输入音频区间集合、模型具体版本、人工确认/否定记录、质量状态和派生父资产**。命中账本记录“本次认人用了谁的参考声纹”，不能等同于“这条参考声纹由本次音频训练而来”。一次误匹配也不能直接证明被命中的参考声纹是错的：确认样本内容混杂或归属错误才停用；来源不明则先标待审，不按命中次数删除。

另需区分“本次重新算距离”与“继承原有归属”。本地 `gin/compound/pipeline.go:1544` 对已绑定的 Session 说话人会跳过正式人物的自动匹配；只调整下一次匹配阈值，不会自动修复既有绑定。必须落实片段级覆盖和重跑时的人工事实优先级。

| 后续：校准和泛化 | 以独立正反例评估人物级/模型级匹配上限和候选间隔，版本化启用；校准过程不得修改人工原始事实 | 离线回放报告、误合并/误拆分/待确认比例、策略适用范围与回退步骤 |

阶段名称是交接拆分建议，以上后端任务尚未完成。`supported:true` 至少要求一期四项及前述 9 条验收通过；不能只实现 apply 写入就开放。自适应阈值尚未上线时，前端也不得声称已“自动学习”或以后永久不会认错。

同步保存与异步工作需要分开：apply 返回 applied 之前，人工事实及有效身份覆盖必须已经生效；已确认应隔离的资产也不能继续被新任务取作可信样本。重新提取、样本重建和统计刷新可以异步，但任务需携带纠错/模型版本。撤销或再次纠错后，旧任务产物必须失效，不能把过时结论重新写回。

### 诊断记录与定位顺序

后端为一次误识别提供一条受权限保护的诊断记录即可，不要求同事外发用户录音或完整声纹向量。建议记录：

- request/job/correction ID、owner、原音频定位与 ASR 版本。
- 实际阶段：Child 归并、Session 映射、正式人物匹配或已有归属继承；实际模型版本。
- 是否命中人工排除/指定，采用的 correction/策略版本；继承归属时记录继承来源，不伪造一个匹配距离。
- 实际参与比较的参考资产 ID、来源与有效状态；排名距离、最佳/次佳间隔、该阶段有效阈值。区分 Top-K 人物平均分与某一条参考声纹的距离。
- 决策原因：人工排除、正反例冲突、样本质量不足、超过阈值、正常匹配等，以及写回的身份/分区。

排查顺序：先确定错误发生阶段 → 查是否绕过人工事实 → 查参考资产来源和混杂情况 → 查分数与间隔 → 最后决定是否需要校准阈值。日志无 token、原始录音、完整转写或 embedding 数组。

### 纠错反馈专用验收用例

以下均为**虚构测试条件**，数字用于验证分支，不是生产调参建议。

| 用例 | 输入条件 | 预期 |
| --- | --- | --- |
| 明确否定优先 | 原片段已排除 A，重新计算到 A 的距离为 0.01 | 仍排除 A，不因非常相近而自动恢复 |
| 同组局部纠错 | 相同旧 num 中只有第 2、4 条被否定 | 只改 2、4；第 1、3 条真正 A 保持；2、4 不自动成为同一新人 |
| 收紧方向正确 | 单独测试距离上限 0.30 与 0.20，输入距离 0.25 | 仅在前者通过该阈值检查；通过阈值仍需过人工约束等其他条件 |
| 反例仍然更近 | 真 A 距离 0.22，已知异人样本到 A 距离 0.18 | 校准不能仅凭 0.20 排除真 A 却保留反例就判为改进；报告冲突/误差并保持待确认策略 |
| 相似不等于事实 | 未纠正新片段同时接近 A 正样本与 A 反例 | 待确认，不直接继承原片段的硬排除，也不自动标 A |
| 污染与误匹配区分 | A 的一条参考样本本身正确，但碰巧被 B 错误匹配 | 不自动删除该正确样本；反之，确认参考样本内含 B 时隔离并追溯派生资产 |
| 不足以学习 | 只有一句极短/重叠的否定片段，或同一录音切出的多条重复片段 | 保存硬排除，不冒充多个独立反例来自动收紧人物阈值 |
| 来源与身份正交 | 用户把 A 自己的视频标为播放内容 | 保持 A 身份，仅改来源；其他播放内容不合并为 A |
| 重跑与撤销竞态 | 纠错后启动重建；用户撤销；旧重建随后完成 | 旧任务不得重新启用已撤销纠错的排除、分区或样本策略 |
| 模型/账号隔离 | 同一向量维度但模型版本不同，或另一账号同名人物 | 不直接混算距离、共享人物阈值或沿用排除事实 |

## 并发、权限、错误

- correction 建议含 owner、稳定音频区间、ASR snapshot、操作前后事实、排除人物、source、分区、原声纹资产引用、创建时间、幂等键和撤销状态。
- 一次操作以事务或等价原子提交保证事实、版本、审计、可撤销性一致。派生任务的旧版本结果不得覆盖纠错。
- 409：版本/片段/人物变化，整批未写入；400：参数错误；401/403：登录或权限；429：限流；5xx：失败或结果待确认。错误须带可读 message，不回传 token/底层堆栈。
- unsupported 只能用于能力未开放，不能吞掉业务错误。首个接口 ready 但撤销/读回尚未实现时不要开启 supported:true。
- 前端不自动重试写入；服务器仍必须实现幂等，处理超时后用户重试或多端重复请求。
