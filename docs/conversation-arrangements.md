# 对话与安排双向关联

私聊、群聊的输入框左上方提供“相关安排”入口，参照移动端快捷入口使用图标、文字、细边框和圆角胶囊，沿用已有信息栏。输入框聚焦时隐藏入口，失焦后恢复；两种状态保留一致的行高，避免消息区域跳动。点击入口不会激活输入框，在会话右侧展示列表，可切换未完成、已完成，查看共享详情并定位原消息。

入口统计已读取的未完成事项。还有后续页时显示 `N+`，不把局部结果当成全量统计。读取中、读取失败与零事项分别显示。新增消息、安排更新、回到前台及每分钟的可见窗口轮询触发刷新；切换会话、账号或关闭页面会取消旧请求。

共享详情展示当前会话的识别快照和可读取的来源消息。个人补充、私人标题修改、个人提醒以及其他会话的依据不进入共享详情。安排持有者可点击“管理我的安排”，进入原有个人详情；修改、完成、删除仍由原有接口校验权限。

个人安排详情的聊天来源显示真实会话类型、名称、消息时间，并提供原消息定位入口。历史关联消息继续标注“关联对话”，不能仅凭一条可变关联关系就认定它是最初的识别依据。

## 接口与边界

- Provider / SDK：`arrangements.conversation.list`、`arrangements.conversation.detail`。
- Intelligent：`POST /api/v1/arrangements/conversation/list`、`POST /api/v1/arrangements/conversation/detail`。
- 来源读取的 `ready` 响应新增可选 `conversation`，旧消费者可继续只读取 `text`。
- 会话引用、共享事项引用均按当前账号校验；共享事项引用不能用于个人安排修改。
- 每次查看由 Chat owner 重新核验成员及原消息权限。来源消失、受限或版本变化时不回退展示旧快照。
- 网络错误保留为错误，不转换为无安排。后端尚未部署时也不伪装成零事项。

需要先部署配套后端 API 和 `coreRecordEvent`，再发布插件。后端回填方式、数据边界与回滚要求见后端同名文档。历史记录缺少会话定位时不能猜测归属，也不能只按标题匹配会话。
