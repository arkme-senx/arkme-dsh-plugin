# 对话与安排双向关联

私聊、群聊的输入框左上方提供“相关安排”入口，参照移动端快捷入口使用图标、文字、细边框和圆角胶囊，沿用已有信息栏。输入框聚焦时隐藏入口，失焦后恢复；两种状态保留一致的行高，避免消息区域跳动。点击入口不会激活输入框，在会话右侧展示列表，可切换未完成、已完成，查看自己的安排详情和来源消息。

入口统计已读取的未完成事项。还有后续页时显示 `N+`，不把局部结果当成全量统计。读取中、读取失败与零事项分别显示。新增消息、安排更新、回到前台及每分钟的可见窗口轮询触发刷新；切换会话、账号或关闭页面会取消旧请求。

相关安排只展示归属当前登录用户、且来自当前对话的安排。侧栏注明“仅显示我在此对话中的安排”，列表标题和“查看详情与来源”都进入现有个人安排详情。归属我的安排不等于按关键词猜测与我有关；当前使用既有安排 owner 事实，不引入新的 AI 相关性评分。

个人安排详情的聊天来源显示真实会话类型、名称、消息时间，并提供原消息定位入口。历史关联消息继续标注“关联对话”，不能仅凭一条可变关联关系就认定它是最初的识别依据。

## 接口与边界

- Provider / SDK：`arrangements.conversation.list`、`arrangements.conversation.detail`。
- Intelligent：复用 `POST /api/v1/arrangements/list`，新增可选 `chat_session_uid` 和 `conversation_cursor`；当前固定 `status=-1, limit=20`，与 offset、看板、日期、topic/record 筛选互斥。
- 响应必须含 `conversation_scope={kind:"personal",chat_session_uid,user_id}`。插件核对账号和会话；旧服务忽略新参数而返回个人全部安排时，明确报服务尚不支持，不展示错误范围或伪装为零事项。
- 每页最多 20 条，以固定 `_id` 上界和游标翻页；未完成/已完成按已加载数据切换，存在后页时不宣称全量统计。
- 后端由 Chat 当前成员合同校验会话访问，并通过 Subject 既有内部只读 `batch-basic` 解析精确旧主题 UID。查询始终交集当前 `user_id`，兼容旧 `topic_uid` 安排和新 `chat_refs` 投影；映射缺失、权限失效和网络错误都保留为错误。
- `arrangements.conversation.detail` 暂留 SDK 兼容，以同一个人范围查询重验引用；新界面直接打开原有个人详情。相关安排引用不能替代个人安排修改引用。
- 来源读取的 `ready` 响应继续支持可选 `conversation`；个人详情中的消息定位与权限检查沿用现有路径。

需要先部署支持该筛选契约的后端，再发布插件。旧主题已关联的个人安排可直接按精确 UID 读取；新识别由 `coreRecordEvent` 维护会话投影。后端回填方式、数据边界与回滚要求见后端同名文档。历史记录缺少会话定位时不能猜测归属，也不能只按标题匹配会话。

## 验证范围

自动化覆盖 Provider 引用隔离、分页、取消、切换账号、错误状态、来源展示、定位、直接进入个人详情、旧服务忽略参数、跨账号/会话游标及 SDK/服务边界。真实账号验收使用独立预览，读取真实账号/群聊消息；测试安排保存在隔离 Mongo 中，不向生产账号创建测试安排。

该验证属于本地新代码验证，不能据此声称已安装客户端或生产服务已经升级。实际构建哈希、点击证据与测试结果保存在本地忽略的 `.codex-artifacts/conversation-arrangements-20261103`，其中真实消息和会话引用不提交到仓库。
