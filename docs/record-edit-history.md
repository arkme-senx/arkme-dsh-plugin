# Ordinary edit history

Record owns accepted immutable revisions. Chat verifies active membership and the exact visible relation before forwarding a query. The plugin and mobile reuse the existing history cards and snapshot interaction.

`cursor_version: 0` starts a version-ordered page; a positive cursor selects strictly older versions. The continuation follows the last raw owner-page version, including when a rejected version or an entire page is filtered. `revision_uid` selects one revision of that record and is mutually exclusive with page cursors. Server version, not device time, orders history. Published timestamp pagination remains available to existing callers.

New human submissions freeze a stable revision identity and the editor's `{nickname, avatar}` before asynchronous work. Plugin recovery reads the formal write receipt for that identity, including when a later edit has already changed the current body. It never resends an uncertain write or decides success by comparing today's content. Existing pending operations lacking an identity retain their original recovery semantics.

`edit_duration_known` distinguishes a measured zero from an absent measurement. The published update duration remains cumulative; Record freezes the single-operation delta against the accepted base. An explicit edit plus AI polish counts human time only once, on the final accepted revision. Automatic processing remains separate. Incomplete cumulative coverage cannot become complete after a later known edit.

Only version 1 establishes creation facts. Missing historical capture is not filled from retained current metadata. Snapshot completion uses the human capture clock independently of server edit time. Location enrichment and its cache must explicitly identify the requested revision. Active chat members retain the original whole-Record historical body reader. Private capture, location, ambient sound and human timing are projected out for peers; memory snapshots remain author-only. Group versions without their own decision are reviewed independently through the existing moderation worker. Pending review is retryable; provider outages never become approval or permanent rejection. Historical review neither changes the current message verdict nor triggers delivery. A positive approved current version bounds history; it does not prove every smaller version passed. Private chat retains its existing moderation policy. Diffs compare the actual loaded visible snapshots and display the comparison baseline. A gap between Record version values alone does not prove a missing edit: upload status and lifecycle changes also advance Record versions.

The official DSH and standalone browser mechanism adapters supply synthetic reads without production credentials or writes. The cross-repository acceptance in `record-edit-history-acceptance.md` additionally connects the original edit/history UI and Host to real authenticated isolated Chat/Record/Mongo owners. Directory shell and profile identity remain synthetic; edit acceptance, revisions and visibility checks use the actual business owners. No collection, BSON field, index, product configuration or rollout switch is added. Historical review uses separate scheduling values in the existing stage field and reuses the existing stage/due index and audit collection. Old workers and old administrative outcome filters cannot mistake these tasks for current messages.
