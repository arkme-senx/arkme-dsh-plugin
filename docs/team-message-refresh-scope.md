# 团队消息延展详情刷新范围

普通发送、修改和撤回都会产生 `team.message.changed`。详情保留现有账号、会话和消息定位，复用 `teamChangeAffectsSource` / `invalidateTeamMessageRead`，不能把每条提示当作整页读取资格失效。

- 同会话新增消息：刷新延展窗口并保留已加载深度，原正文、独立回复和输入框保持挂载。
- 单个来源变化：仅移除相应正文或父预览；独立子回复仍可显示。来源待复验期间停用原操作入口，状态由既有 Host 读取裁决。
- 其他账号、其他会话、回执和免打扰等内容无关提示：不清理详情材料。
- 未知提示、重连和相关权限变化：立即清除原快照；明确拒绝或无效响应同样清除。明确的网络、依赖或限流错误只保留此前未受影响的材料。
- 新读取会中止旧读取；迟到响应不能恢复已失效内容。读取引用轮换不改变消息内容身份；版本变化仅撤下相关来源，账号替换清除当前展示。

沿用同事的详情壳、列表、占位、重试和输入交互，没有新增样式或业务状态机。

主会话保留已打开的 `revalidating` 来源详情，避免复验时销毁详情及独立回复；能否展示材料、延展或发送，仍由详情原有读取资格和操作门禁决定。

| 能力面 | 本次范围 | 证据 |
| --- | --- | --- |
| UI | 修复现有详情的刷新及读取生命周期 | `team-extension-detail.test.tsx` 覆盖发送、单源、独立回复、窗口重置、引用轮换、版本/账号替换、暂时失败及迟到响应；既有权限拒绝测试继续通过 |
| Host owner | Team 原有读取与授权 owner 保持 | 沿用 SDK `readTeamExtensions`，没有新增接口、命令、持久化或授权语义 |
| Tools | N/A：未新增 Host 业务能力或模型入口 | 原团队延展读取 Tool 保持，现有合同测试纳入回归 |
| SDK | N/A：未修改公开 SDK 能力与协议 | 原 SDK 延展读取接口保持，现有合同测试纳入回归 |

不新增配置、表、索引或部署步骤；插件版本和依赖保持基线。

验证：全量测试 14,652 通过、26 跳过；最终挂载条件修复后的八文件专项 177 通过、1 跳过；类型检查、构建及 `.tgz` 打包通过。不可变包安装到未修改的官方 DSH `0.2.1-rc.2` 全新临时 Profile，实际浏览器验证了上游 SSE → Host 定位转换 → 详情局部失效、父撤回保留独立回复、权限变化清材料，以及输入 DOM/草稿保持。验收上游为隔离合成 HTTPS 数据，没有向真实团队发送测试消息；安装后的 client 字节与打包产物一致。
