# 团队消息入口偏好同步后端交接

日期：2026-10-19

团队消息总入口、外部身份的直属入口，以及团队内单个对话，现在共用「预览、置顶/取消置顶、移除」右键菜单。当前实现将置顶与移除偏好按账号保存在本机，可跨页面刷新和客户端重启保留；跨设备同步需要后端补齐个人入口偏好协议。

## 已有能力与边界

- `team.app.conversations` 读取分页会话目录，返回 `lastSeq`、`updatedAt`、未读数和预览。
- `team.app.timeline` 读取某会话的分页消息。预览使用该接口及现有消息展示组件，不进入正式会话，不调用 `team.app.read`。
- `src/team-app-contract.ts` 当前没有团队入口的置顶、移除接口。`team.app.home.visibility` 管理消息的首页可见性，不能用于隐藏会话入口。
- 本机偏好在 `src/client/team-directory-preferences.ts`，只保存稳定标识、置顶值和移除时的消息序号，不保存正文、签名引用或媒体地址。
- 移除仅隐藏当前用户的入口，不删消息、不退出团队、不屏蔽对方、不修改已读。团队内可展开「已移除对话」并重新打开；团队总入口也可从联系人重新打开。

## 建议补齐的协议

以下字段和操作是待后端评审的建议，尚未宣称上线。

入口身份应区分「团队文件夹」与「具体会话」，并绑定当前登录用户。文件夹使用团队稳定 ID，具体会话使用稳定 conversation ID 和访问侧；禁止以昵称、可轮换签名引用或客户端传入的 viewer ID 作为权限依据。

| 能力 | 建议请求 | 服务端结果 |
| --- | --- | --- |
| 获取入口偏好 | 按当前用户分页读取；也可随会话目录返回 | entry_kind、entry_id、pinned、dismissed、version |
| 设置置顶 | 稳定入口身份、pinned、expected_version、幂等操作 ID | 最新偏好及版本；置顶同时恢复入口 |
| 移除入口 | 稳定入口身份、expected_version、幂等操作 ID | 服务端原子记录移除水位并返回最新偏好 |
| 显式恢复 | 稳定入口身份、expected_version、幂等操作 ID | 清除移除状态，不修改消息或已读 |
| 变更通知 | 当前用户的偏好版本/变更事件 | 所有设备立即同步；断线后可增量核对 |

文件夹移除水位必须覆盖尚未加载的会话及之后新出现的访客。推荐服务端提供团队内「实际新消息活动序号」，在移除事务内原子取得水位；不能依赖前端已加载会话集合。具体会话可以使用单调递增消息序号。

`updated_at` 可能随已读、编辑、权限或元数据变化，不应作为恢复入口的唯一证据。消息编辑、删除和已读回执不自动恢复入口；移除后的实际新消息才恢复。访问权限失效时应移除可见数据，并阻止旧响应重新显示。

建议独立提供 `last_message_at` 与 `last_message_seq`。本机当前对已知会话使用 `lastSeq`；对移除后才加载的未知访客，只有在检查真实最新消息的 `createdAt` 后才恢复，避免把历史分页误判为新消息。跨设备和时钟偏差由服务端水位解决，不沿用客户端时间作为最终依据。

## 前端接入与迁移

1. 通过能力标识确认服务端支持后，再切换到云端偏好；不盲发不存在的接口。
2. 采用即时本地反馈、后台提交和失败可重试机制，版本冲突后读取服务端事实。
3. 只迁移当前账号已有本机偏好，并带幂等操作 ID；禁止本机空值覆盖其他设备的云端设置。
4. 保留现有共享菜单、预览窗口和置顶角标，不新增另一套入口交互。
5. 预览保持独立只读加载，不能以请求 timeline 自动标为已读；遮挡正式会话期间暂停其自动已读意图。

## 验收场景

- 同一账号设备 A 置顶或移除后，设备 B 同步；其他账号、其他团队成员不受影响。
- 刷新、重启、离线重连、重复点击与接口重试均不丢失最终偏好。
- 移除后刷新目录、翻到旧访客、收到已读回执或编辑旧消息，入口不恢复。
- 移除后原访客或新访客发来实际新消息，入口恢复且未读准确。
- 同时发生移除与新消息时，以服务端原子水位判定；迟到响应不能覆盖更新的操作。
- 预览总入口或具体会话时，已读水位不变；点击「打开对话」后才进入正常阅读行为。
- 移除不删除消息、成员或通道；从联系人或已移除列表重新打开可恢复。

本次仅修改插件前端与本机偏好，没有修改或部署后端。实时消息恢复通过现有目录变更通知、窗口聚焦和周期刷新核对；客户端关闭期间收到的新消息会在下次读取目录时核对恢复。
