0.3 是余弦距离上限，越小越严格，不是 30% 置信度。会话聚类、长期认人和增强转写映射是不同阶段；不能仅改一个常量就认为所有阶段都完成纠错。

现有算法的反例（合成数据，不是用户账号数据）：只有一个距离 0.10 的样本时命中；增加距离 0.50、0.60 的样本后，前三平均为 0.40，变为不命中。因此“不断增加样本”必须配合质量、多样性和评测，不能承诺严格单调提升。

## 4. 第一阶段：先补齐学习和纠错闭环

### 4.1 所有标记入口提交同一种确认事实

- 本人、联系人、手工人物遵循一致规则；既有稳定人物 ID 作为归属，显示名相同不自动视为同一人。
- 区分两个范围：这次标记影响哪些转写片段；这次有哪些声音可进入人物识别样本。单段确认不能自动确认该说话人簇的所有声音。
- 单段、整轨、跨历史批量、未标记目录、system/doubao 入口统一触发样本生成或明确返回不能学习的原因。
- 以 owner + 稳定音频片段 + 人物 + 确认版本为幂等依据。ASR 数组下标只作定位提示，必须结合音频范围与转写版本校验；不能重转写后套用到另一句。
- 标记持久化成功后可立即返回；样本提取异步执行。任务创建和确认事实要有可靠的 outbox / 持久待处理标记，支持重试、超时恢复与对账，不能在响应后仅启动一次内存异步任务。
- 提取失败不回滚用户已经确认的人物归属，但不能返回“学习完成”；重复请求和任务重投不能增加重复样本。

### 4.2 从确认的原音区间取样

- 仅从明确被确认的声音区间取样，复用现有人声归档和可逆时间映射；需补上下文时不能纳入其他说话人作为训练音频。
- 太短、重叠、多声混合、低质量、缺原音等情况保留归属，样本进入待处理/跳过状态，并说明原因。
- 按质量与录音条件选择多个有代表性的样本，避免同一音频重复切片充当多个独立证据。批量样本数量和预算由后端明确，不能静默只取第一条。
- 播放来源与人物身份分开：标为播放内容的声音不自动进入现场声音参考集；如未来支持识别媒体中的已知人物，应使用单独质量/场景策略，不把所有播放内容当成一个人物。

### 4.3 样本必须可追溯、停用和重建

复用 `SpeakerVoiceprintVector` 与既有命中账本身份，补齐实际输入原音区间、模型标识及版本、人工确认事件、质量信息、来源模式、派生父资产和状态。现有 `source_session_id + source_spk_num` 无法完整证明一条向量到底包含哪些声音。

- 取消标记：撤销对应确认事实；若样本仅由该确认支撑，停止作为人工确认样本。若有独立有效确认，保留这些确认所支撑的部分；取消不自动创建“不是此人”的否定关系。
- 明确不是此人：建立作用于原音区间的排除约束，未来推荐、自动匹配、重跑均遵守；追溯误学样本，只有证实其输入归属错误/混杂才停用。一次错误命中本身不能证明被命中的参考样本是错的。
- 改绑 A → B：撤销该区间对 A 的确认，B 的清晰样本重新提取；不能让同一已否定样本同时作为 A、B 的正样本。
- 混合簇：按确认片段拆分并重新取样，不把整簇向量转送给 B，也不把整簇当作 A 的负样本。
- 纠错发生在提取任务运行中：任务提交前再次核验确认版本。晚到任务不得重新启用已撤销样本；缓存和索引按新版本失效。
- 撤销纠错应检查后续变化，不能用旧快照覆盖别人后来作出的确认。

## 5. 第二阶段：改善匹配决策

先复用现有模型与向量存储，优先解决数据和决策问题，不以更换模型替代闭环修复。

1. 同模型空间、有效质量、有效确认、未被排除的样本才参与匹配。
2. 同一人物保留多种录音条件的代表样本，比较不同聚合方式，避免样本从 1 增至 3 时被低质量样本拖低召回；不直接改成无约束“只取最近一条”。
3. 自动归属同时检查最佳距离、与次佳人物的差距、可用样本质量和人工约束。不确定时保持未确认，推荐可以比自动归属更宽松。
4. 阈值校准先离线验证，按人物对/声音场景有范围地收紧，并记录策略版本和回退依据。不要全局从 0.3 改到 0.2，也不要用同一段音频既校准又验收。
5. 已确认的人工归属优先于自动结果。后台自动命中只记录识别事实，不自动提升为人工确认正样本，避免自我强化错误。

## 6. 给前端的状态协议建议（待确认，不是现网接口）

建议在统一标记结果中，明确区分 `assignment` 与 `learning`。现有标记接口需要保持兼容；后端确定最终契约后再接入展示，旧响应缺字段时前端只显示“已标记”。

```json
{
  "assignment": { "state": "saved", "affected_count": 1, "revision": "opaque-revision" },
  "learning": {
    "state": "pending",
    "operation_ref": "opaque-operation-ref",
    "revision": "opaque-learning-revision"
  }
}
```

建议状态：`pending / processing / ready / skipped / failed / revoked`。`ready` 必须表示有效样本已进入当前匹配所用的存储/索引；不是单纯提取结束。`skipped` 要有稳定原因码，例如 `insufficient_clean_audio / overlapping_speakers / source_unavailable / duplicate_sample / unsupported_model`。

异步读取方式需后端确认，可复用现有状态通知或新增有鉴权的 operation 查询。查询返回最新版本及建议重试间隔；账号切换丢弃晚到结果，避免永久轮询。标记提交超时属于结果不明，先按幂等键核对，不生成新键重复写入。

人物级可增加：有效样本数、待处理/失败数、最后学习时间、模型/策略版本。不要把命中账本次数、转写片段数、原始说话人簇数当成有效样本数。不要向浏览器返回向量、内部音频地址或其他用户的数据。

## 7. 历史修复与迁移

- 先 dry-run：统计各入口人工标记、有无有效样本、未知模型类型、同源多人物冲突、原音可用性。输出汇总与受控审计引用，不外发个人录音/向量。
- 能准确证明原音范围、人工归属和模型来源的历史确认，才补提样本；无法证明的保留标签并标待核对，不能把全部 ASR.Q 无差别当作人工确认（部分 Q 可能来自自动继承）。
- 旧“我的声纹”缺模型类型：追溯原模型/来源，或重新提取；不要仅凭向量维度猜类型。
- 历史同一人多个档案：按稳定用户身份和人工确认映射处理，不凭同名或近音合并；保留别名、样本来源、授权边界和回退记录。
- 新样本生效后，可对明确范围内的未确认历史片段重认。自动结果不覆盖人工确认；大规模任务要有预算、进度、断点和取消。
- 执行迁移前由后端负责人与用户确定账号/日期范围，持久备份原状态，dry-run 审阅后再写入。

| 场景 | 必须验收的结果 |
| --- | --- |

| 取消 / A 改 B / 明确不是 A | 确认和排除语义准确，错误样本不会继续参与 A 匹配。 |
| 纠错与提取并发、重投、超时 | 旧版本不能复活，幂等不重复入库，可恢复和核对。 |
| 人物 A 与 B 很相似 | 达绝对阈值但差距不足时不强认；明确排除的 A 不再推荐。 |
| 媒体播放与真人交替 | 不把手机声音混入现场人物正样本；来源与身份分别保留。 |

质量评测使用跨日期、与入库材料不重叠的测试录音，分别统计本人/其他人、近讲/远讲、现场/播放的误认率、漏认率和待确认比例。当前只有代码证据，没有证明改动能提高多少百分点，不能用一次正确识别代替稳定性评测。

### 10.1 数量不是所有向量两两距离大于 0.3 的证明

`0.3` 是余弦**距离**上限，即 `1 - cosine_similarity`；对应相似度至少 0.7。目录按正式人物身份或匿名候选身份去重，不对最终所有条目做两两互斥校验。

- `internal/audio/speaker_directory.go:234–263,315–327`：正式人物使用 `speaker:<id>` 或关联用户身份；匿名项使用 `candidate:<id>`。同一真实人的未认回片段可以仍落在匿名项中，和已标记人物同时存在。
- `internal/audio/unmarked_speaker_readonly_cluster.go:277–311`：临时跨日聚类先排除模型不同或日期集合重叠的候选，再要求最佳距离不大于 0.3、次佳距离与最佳距离之差至少 0.05。两个候选都很近但有歧义时，仍保留独立候选；同日两个已有分组即使距离为 0，也会被这一层排除。这是此层的保守规则，不代表前面的日内聚类从不合并同日片段。
- 同文件 `83–99,225–234`：已有 InnerSpeaker 候选直接保留，没有在本轮把所有已有 InnerSpeaker 两两重新合并。临时聚类按时间顺序增量更新质心，也没有最终全量重新聚类。
- 原仓库测试明确覆盖“跨月可合并”“同日相近声音保持分开”“歧义时保持单日”：`internal/audio/unmarked_speaker_candidates_test.go:304,509,561`。

### 10.2 日期确实影响一部分自动归并，但不是统一过期规则

| 层次 | 实际比较范围与规则 | 源码位置（audio/master，另注除外） |
| --- | --- | --- |
| 单次录音内分离 | 当前 Session 的既有声纹传给 SD；窗口/Child 之间复用，其他 Session 不直接进入这份上下文。链接距离 0.3，EMA 更新另有更严格条件。 | `gin/compound/pipeline.go:304–317`；sd/master `child_sd_ms_up.py:129–263,359–375` |
| 当天匿名身份 | 同一录音日期内读取已完成录音，补齐日内身份；已有 DaySpkId 一般保留，不自动全量重分。 | `internal/audio/inner_agg.go:322–475` |
| 已有跨日匿名身份 | 读取当前账号全部正常 InnerSpeaker，没有录音日期截止条件；使用距离 0.3。 | `internal/audio/repository.go:1181–1202`；`inner_agg.go:555,677,777` |
| 新建跨日匿名身份 | 未命中既有 InnerSpeaker 时，只查询当前录音日期**之前 3 天**的 DaySpeaker，并要求距离不大于 **0.2**，再生成长期匿名身份。 | `inner_agg.go:17–18,591–601,684–719,796–815` |
| 正式人物自动认回 | 读取当前账号正常人物和同模型声纹资产，没有日期或 import_batch 限制；按每个人物距离最近的最多 3 条样本的平均距离排名，第一名不大于 0.3。这里“最近”指向量距离，不是创建时间。 | `repository.go:2743–2815`；`speaker_voiceprint_match.go:134–194` |
| 目录展示层补合并 | 可读取跨历史日期候选做只读合并，受前述日期重叠、模型和歧义规则限制；不回写长期身份。 | `speaker_directory.go:387–456`；`unmarked_speaker_readonly_cluster.go:40–48` |

因此，仅有 10 月 1 日和 10 月 10 日两个匿名日内身份、又没有既存 InnerSpeaker 时，10 月 10 日的“新建长期匿名身份”流程不会把 10 月 1 日作为历史证据；目录的只读合并仍可能把它们呈现为一个候选。不能把只读展示合并视为全局身份已经持久化。

另有恢复范围限制：`task/cron/audio.go:31–40` 的匿名身份聚合实际只在整点运行，扫描近 **30 天创建**的 Session；不是近 30 天录音，也不是所有历史录音每次重新识别。audio/develop 保留了前三天与 0.2 规则（`inner_agg.go:17–18,539–549`），也保留近 30 天创建窗口（`task/cron/audio.go:31–40`、`repository.go:1787–1795`）。

### 10.3 “上传批次”不等于全账号声纹上下文

插件 `src/services/recording-import-gateway.ts:554–582` 为每个文件任务创建/恢复 Session，`import_batch` 是批次协调信息。SD 的 `spk_context` 来自该 Session，不是整个导入批次、更不是账号全部历史匿名声音。新 Session 因此会先产生新的局部分组，再依靠后续日内、跨日及正式人物匹配统一身份。

audio/develop 已把 SD 改为 Job 编排，但 `internal/audio/recording_speaker_context.go:20–45` 仍只读取传入 Session 的 `SpkLs`；模型类型、维度及历史编号保护更严格，并没有变成账号全部历史声纹库输入。这个分层本身并非错误，缺口在后续统一身份和人工学习是否完整接通。

### 10.4 昨天标记了、今天又匿名：优先查学习事实

1. **单段标记未入库**：插件单段调用 `/assign-asr-item-to-spk`（`src/services/recording-service.ts:874–885`）；audio/master `gin/api/audio.go:3035–3116` 与 develop `2921–3002` 均只写人物覆盖、会话标记与命中账本刷新，没有提取/新增声纹资产。因此手工标对一句话，不能等同于已学会此人的声音。前端默认单段是为了避免混合簇误伤，不能通过偷偷扩大范围来绕开后端缺口。
2. **批量不等于多场景学习**：普通批量标记以及未标记目录绑定只保留第一条可用 `targetVector`；其余声音只更新归属。master `gin/api/audio.go:3311–3373`、`audio_unmarked_speaker_mark.go:969–1014`。
3. **部分增强转写只改标签**：v3 synthetic 绑定走 Q 覆盖并提前返回/继续，不增加正式声纹（`audio.go:3320–3325,3367,3483–3490`）。v3 声纹先映射本 Session 的正式轨道（`gin/compound/pipeline_v3.go:1961–1976`），不能直接当成又一次全账号正式人物库识别。
4. **新证据不自动重认已完成录音**：`TryAggregateSession` 遇到 `HasDoneChild` 返回；新标记后的命中账本刷新不等于历史录音重新认人。master `pipeline.go:1580–1586`；develop `pipeline.go:382–387`。
5. **有样本仍可能漏认**：模型类型/维度不同会过滤；样本少、质量差或原轨混入多人可能导致距离不达标。前三距离平均算法也不保证“新增样本后必然更准”：合成距离由单条 0.10 增加到 0.10/0.50/0.60 后，平均变成 0.40，反而不命中。此项证明算法性质，不证明该账号真实发生了这些距离。

### 10.5 develop 已有改善，不能按旧实现重复修复

develop 的 `speaker_aggregation_match.go:50–117` 已把日内匹配改为同模型、最近距离和稳定 tie-break；`inner_agg.go:93` 使用用户级锁序列化跨日归并；`pipeline.go:448` 使用 `SelectClosestInnerSpeaker`，替代 master 的第一个过线即命中。已有模型录入修复见第 1 节。这些改善不等于单段学习、全历史匿名身份统一和纠错闭环已完成；需后端核对实际部署 SHA。

### 10.6 本次验证与下一步排查

本次没有修改后端工作目录、接口、阈值、真实人物归属或生产数据。完整 `internal/audio` 测试包因缺少本地 `config.yaml` 无法启动，包初始化还依赖 Mongo/Redis；没有借用生产配置补跑。

另将 master 的相关纯计算函数逐字提取到独立测试模块，保留函数来源、行号及 SHA-256，以内存结构代替持久化类型，运行 **7 项隔离算法验证，全部通过**：同日完全相同向量被此层排除、相隔一年仍可匹配、近邻歧义不合并、模型不同不匹配、0.25 达到 0.3 却不能通过历史晋升的 0.2、新样本使前三平均越过门限、正式人物匹配没有次佳差距限制。它们不是完整服务或账号数据验收。

后端建议先对一组“昨天已确认、今天漏认”的真实片段做只读诊断，回传下列事实，而非立即全局改阈值：

- 实际部署提交、Session/轨道标识、人工确认时间、确认入口和范围、识别执行时间；核对标记是否早于后续匹配。
- 对应正式人物 ID、可用样本数、各样本来源/有效状态/模型类型；明确人工标记有没有生成样本。
- 目标声音模型与版本、有效时长/质量；候选人物是否进入搜索、最近三条距离与均值、第二候选及未命中原因。
- 匿名 Day/Inner 身份来源、前三天候选覆盖、目录只读聚类成员、日期重叠或 margin 拒绝原因、聚合/目录版本。
- 单段学习和样本撤回闭环优先补齐；长期匿名候选检索覆盖全历史，近三天可以作为优先检索层，但不应成为唯一长期身份创建依据。用可靠证据持久化身份关联，提供进度、幂等、撤销，不能把所有相近声音一次性自动合并。

对外只返回必要的诊断值与受控引用，不下发原始声纹向量。当前无法凭源码统计该账号一万多个条目的真实重复比例；这项必须由账号级只读数据审计回答。

## 11. 只读核对结论及最小排查工单

已验证其他人物确有本地识别声纹、历史声纹和跨日期的局部分组关联，因此不能概括成“其他人的标记完全没有学习”。个案中的人物姓名、编号、声纹条数、日期和命中快照保留在本机核验材料，不随本项目交接分发。

当前 master `internal/audio/repository.go:3092–3132` 的命中数是精确声纹身份账本的 `segment_count`，不是准确率或训练次数；`gin/compound/pipeline.go:2014–2075` 同时处理自动匹配与人工纠正。历史缺少匹配引用、恢复与纠错也影响账本，不能把零命中直接解释为无效样本。授权播放项按接口规则命中为 0，不能和本地训练样本混算。

`gin/api/voiceprint_recognized_speaker_voiceprints.go:41–47` 当前 DTO 缺少模型及版本、维度、样本质量、确认来源、候选过滤原因、最佳和次佳距离、当时声纹库版本及命中覆盖率。只读列表不足以复算某一段漏认，更不能据此删除样本或全局调整 0.3。

后端最小工单：
1. 在获得授权的测试账号选“已确认片段 → 后续同一真人的匿名片段”，按第 10.6 节追踪；手机播放混入的误标案例不能作为正样本。
2. 核对单段确认是否生成兼容模型的合格样本，明确新录音处理时是否召回；已处理历史不会因为后来标记就自动认回。
3. 优先完成“人工确认 → 合格样本入库 → 后续识别使用 → 错标可撤回”，再处理历史近邻和拆分。组内一致性与组间相似独立展示。
4. 返回受控诊断：无新增样本、模型不兼容、候选未召回、距离不达标、候选歧义、历史未重认、账本待恢复。不需将原始向量下发插件。
