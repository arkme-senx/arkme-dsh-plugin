目标：无论本人还是其他人，用户明确标记的清晰声音都能成为后续自动识别的可靠参考；明确纠错能够停止错误传播。标记次数不能冒充有效声纹样本数，识别成功也不能自动成为人工确认样本。

0.3 是余弦距离上限，越小越严格，不是 30% 置信度。会话聚类、长期认人和增强转写映射是不同阶段；不能仅改一个常量就认为所有阶段都完成纠错。

现有算法的反例（合成数据，不是用户账号数据）：只有一个距离 0.10 的样本时命中；增加距离 0.50、0.60 的样本后，前三平均为 0.40，变为不命中。因此“不断增加样本”必须配合质量、多样性和评测，不能承诺严格单调提升。

## 3. 前后端职责

前端本轮方案：保留头像弹窗，提供当前片段试听；明确“仅此片段 / 当天同组 N 处”的应用范围，从全天入口也可切回单段；区分取消标记、明确不是此人和声音来源。成功显示标记结果，不根据 HTTP 成功、标记条数或人物命中次数宣称“已经学会”。交互方案确认、实现和验证状态以本次 PR 为准。

后端负责：持久化确认与否定事实、原音区间提取、质量筛选、声纹资产生命周期、自动认人、历史修复、异步恢复和跨端一致性。前端不能用旧的整轨绑定接口偷偷扩大用户选择范围来换取声纹入库。

现有纠错协议见 [录音说话人纠错一期-后端交接-20261014.md](./录音说话人纠错一期-后端交接-20261014.md)。该文档早期“未合 dev”描述是当时状态；本文补充持续学习链路，并不宣称其中后端建议已上线。`speaker-corrections/context/apply/undo` 在本次核查的 audio master/develop 路由中仍未找到，需同事确认其他部署分支；前端继续按真实能力控制写入。

## 4. 第一阶段：先补齐学习和纠错闭环

### 4.1 所有标记入口提交同一种确认事实

- 本人、联系人、手工人物遵循一致规则；既有稳定人物 ID 作为归属，显示名相同不自动视为同一人。
- 区分两个范围：这次标记影响哪些转写片段；这次有哪些声音可进入人物识别样本。单段确认不能自动确认该说话人簇的所有声音。
- 单段、整轨、跨历史批量、未标记目录、system/doubao 入口统一触发样本生成或明确返回不能学习的原因。
- 以 owner + 稳定音频片段 + 人物 + 确认版本为幂等依据。ASR 数组下标只作定位提示，必须结合音频范围与转写版本校验；不能重转写后套用到另一句。
- 标记持久化成功后可立即返回；样本提取异步执行。任务创建和确认事实要有可靠的 outbox / 持久待处理标记，支持重试、超时恢复与对账，不能在响应后仅启动一次内存异步任务。
- 提取失败不回滚用户已经确认的人物归属，但不能返回“学习完成”；重复请求和任务重投不能增加重复样本。

### 4.2 从确认的原音区间取样

- 仅从明确被确认的声音区间取样，复用现有人声归档和可逆时间映射；需补上下文时不能纳入其他说话人作为训练音频。
- 太短、重叠、多声混合、低质量、缺原音等情况保留归属，样本进入待处理/跳过状态，并说明原因。
- 按质量与录音条件选择多个有代表性的样本，避免同一音频重复切片充当多个独立证据。批量样本数量和预算由后端明确，不能静默只取第一条。
- 播放来源与人物身份分开：标为播放内容的声音不自动进入现场声音参考集；如未来支持识别媒体中的已知人物，应使用单独质量/场景策略，不把所有播放内容当成一个人物。

### 4.3 样本必须可追溯、停用和重建

复用 `SpeakerVoiceprintVector` 与既有命中账本身份，补齐实际输入原音区间、模型标识及版本、人工确认事件、质量信息、来源模式、派生父资产和状态。现有 `source_session_id + source_spk_num` 无法完整证明一条向量到底包含哪些声音。

- 取消标记：撤销对应确认事实；若样本仅由该确认支撑，停止作为人工确认样本。若有独立有效确认，保留这些确认所支撑的部分；取消不自动创建“不是此人”的否定关系。
- 明确不是此人：建立作用于原音区间的排除约束，未来推荐、自动匹配、重跑均遵守；追溯误学样本，只有证实其输入归属错误/混杂才停用。一次错误命中本身不能证明被命中的参考样本是错的。
- 改绑 A → B：撤销该区间对 A 的确认，B 的清晰样本重新提取；不能让同一已否定样本同时作为 A、B 的正样本。
- 混合簇：按确认片段拆分并重新取样，不把整簇向量转送给 B，也不把整簇当作 A 的负样本。
- 纠错发生在提取任务运行中：任务提交前再次核验确认版本。晚到任务不得重新启用已撤销样本；缓存和索引按新版本失效。
- 撤销纠错应检查后续变化，不能用旧快照覆盖别人后来作出的确认。

## 5. 第二阶段：改善匹配决策

先复用现有模型与向量存储，优先解决数据和决策问题，不以更换模型替代闭环修复。

1. 同模型空间、有效质量、有效确认、未被排除的样本才参与匹配。
2. 同一人物保留多种录音条件的代表样本，比较不同聚合方式，避免样本从 1 增至 3 时被低质量样本拖低召回；不直接改成无约束“只取最近一条”。
3. 自动归属同时检查最佳距离、与次佳人物的差距、可用样本质量和人工约束。不确定时保持未确认，推荐可以比自动归属更宽松。
4. 阈值校准先离线验证，按人物对/声音场景有范围地收紧，并记录策略版本和回退依据。不要全局从 0.3 改到 0.2，也不要用同一段音频既校准又验收。
5. 已确认的人工归属优先于自动结果。后台自动命中只记录识别事实，不自动提升为人工确认正样本，避免自我强化错误。

## 6. 给前端的状态协议建议（待确认，不是现网接口）

建议在统一标记结果中，明确区分 `assignment` 与 `learning`。现有标记接口需要保持兼容；后端确定最终契约后再接入展示，旧响应缺字段时前端只显示“已标记”。

```json
{
  "assignment": { "state": "saved", "affected_count": 1, "revision": "opaque-revision" },
  "learning": {
    "state": "pending",
    "operation_ref": "opaque-operation-ref",
    "revision": "opaque-learning-revision"
  }
}
```

建议状态：`pending / processing / ready / skipped / failed / revoked`。`ready` 必须表示有效样本已进入当前匹配所用的存储/索引；不是单纯提取结束。`skipped` 要有稳定原因码，例如 `insufficient_clean_audio / overlapping_speakers / source_unavailable / duplicate_sample / unsupported_model`。

异步读取方式需后端确认，可复用现有状态通知或新增有鉴权的 operation 查询。查询返回最新版本及建议重试间隔；账号切换丢弃晚到结果，避免永久轮询。标记提交超时属于结果不明，先按幂等键核对，不生成新键重复写入。

人物级可增加：有效样本数、待处理/失败数、最后学习时间、模型/策略版本。不要把命中账本次数、转写片段数、原始说话人簇数当成有效样本数。不要向浏览器返回向量、内部音频地址或其他用户的数据。

## 7. 历史修复与迁移

- 先 dry-run：统计各入口人工标记、有无有效样本、未知模型类型、同源多人物冲突、原音可用性。输出汇总与受控审计引用，不外发个人录音/向量。
- 能准确证明原音范围、人工归属和模型来源的历史确认，才补提样本；无法证明的保留标签并标待核对，不能把全部 ASR.Q 无差别当作人工确认（部分 Q 可能来自自动继承）。
- 旧“我的声纹”缺模型类型：追溯原模型/来源，或重新提取；不要仅凭向量维度猜类型。
- 历史同一人多个档案：按稳定用户身份和人工确认映射处理，不凭同名或近音合并；保留别名、样本来源、授权边界和回退记录。
- 新样本生效后，可对明确范围内的未确认历史片段重认。自动结果不覆盖人工确认；大规模任务要有预算、进度、断点和取消。
- 执行迁移前由后端负责人与用户确定账号/日期范围，持久备份原状态，dry-run 审阅后再写入。

## 8. 验收清单

| 场景 | 必须验收的结果 |
| --- | --- |
| 本人和其他人各标一个清晰片段 | 人物即时正确；后台产生正确归属、正确模型的样本，并参与后续不同日期录音匹配。 |
| 单段标记来自混合簇 | 未选中的其他声音不进入样本，不跟随整簇修改。 |
| system / doubao 各入口 | 归属、学习状态一致；无可靠材料时明确跳过，不伪成功。 |
| 批量跨多个日期/场景 | 样本选择有解释、有去重，不只因排序取第一条。 |
| 取消 / A 改 B / 明确不是 A | 确认和排除语义准确，错误样本不会继续参与 A 匹配。 |
| 纠错与提取并发、重投、超时 | 旧版本不能复活，幂等不重复入库，可恢复和核对。 |
| 人物 A 与 B 很相似 | 达绝对阈值但差距不足时不强认；明确排除的 A 不再推荐。 |
| 媒体播放与真人交替 | 不把手机声音混入现场人物正样本；来源与身份分别保留。 |
| 旧样本未知模型、混合模型 | 不进入不兼容匹配空间；有可解释的修复/跳过结果。 |
| 跨端刷新与重新处理 | 标记、排除、样本状态持久一致，重处理不覆盖人工事实。 |
| 历史回填重复执行 | 不重复、不跨账号、不覆写人工结果，有完整回退和审计。 |

质量评测使用跨日期、与入库材料不重叠的测试录音，分别统计本人/其他人、近讲/远讲、现场/播放的误认率、漏认率和待确认比例。当前只有代码证据，没有证明改动能提高多少百分点，不能用一次正确识别代替稳定性评测。
