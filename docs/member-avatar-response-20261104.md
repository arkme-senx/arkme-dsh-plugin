# 群聊消息头像即时响应（2026-11-04）

## 原因与结果

原先消息已有姓名、头像和签发的 `memberRef`，但头像只接受完整成员对象。渲染时先在另行加载的成员分页结果中查找；查不到即渲染无点击、无悬浮事件的静态 `span`。成员页到达后才变成按钮，因而同屏不同用户可在不同时间恢复响应。已通过原函数隔离运行复现该条件；这不是对用户某次生产请求的现场复现。

本次将消息身份与完整成员资料拆开：

- `MessageAvatar` 成为独立组件。带成员引用的可见人类消息立即绑定悬浮、点击、键盘和右键事件；不等待成员分页、公开资料、头像下载或统计。
- `MemberActionTarget` 仅保留消息可证明的身份与展示信息，不伪造角色、在群状态、所有者标记、统计或 @ 凭据。
- 正在打开的浮框/资料卡按需读取一个成员，关闭、换人或切换账号时取消。晚到结果按身份键隔离。整群分页仅补充资料。
- 缺少身份引用的旧消息仍可立即打开提示浮框或卡片，不按昵称猜人，不制造收件人引用。
- @ 需要真实引用、公开显示名和可用输入框；不满足时显示加载或不可用状态，失败可重试。统计未知时保持未知。
- 资料卡先显示消息中的姓名、头像；公开账号信息独立更新。进入世界直接走单人身份校验，不等待装饰资料。私聊失败在卡片中显示，进行中仍可关闭；关闭会取消本地等待并抑制晚到导航。

## 服务端 Host 解耦与审查

`memberWorldTarget` 与 `openPrivateChatFromMember` 改为复用一个私有校验器，以现有 `/api/v1/chats/members/by-user-ids` 查询一个目标，`active_only: true`、`include_stats: false`，不再读取全群名单。RPC/SDK 的公开输入输出没有改动，也没有数据库迁移。

最终 diff 复核内容：

- 先验证成员引用绑定的账号、会话与签名，再查询；响应只允许同一会话下的唯一指定在群成员。空结果、异人、重复、失效状态和异常字段明确失败。
- 校验使用新鲜交互请求，不用头像、统计或成员缓存代替授权；查询后再次检查账号。创建私聊前继续传递预期账号，避免跨账号接续操作。
- 请求前、响应后和账号校验后检查取消；前端不同账号/会话/成员使用独立状态键。单人查询不涉及分页或跨页快照合并。
- 只有打开的交互读取目标成员，关闭/换人后取消，避免为所有可见消息逐个预取。整群缓存与原有分页流程保留；移除成员等管理操作仍需权威成员信息与现有服务端校验。
- 保留 int64 成员引用的区分；当前世界界面无法处理的大标识明确提示，不将其转换为不安全数字。
- 现有部署已在成员资料流程使用 by-user-ids；本改动不新增服务端协议。缺少该接口或被拒绝的环境会明确失败，不回退扫描整群。回滚功能提交即可恢复原行为。
