## 3. 旧版实际链路与统计口径

```text
Flutter 关键词模块
  → 本地 Kernel POST /summary/keywords
  → 读取本地个人快记 / 过滤锁定主题与隐私锁记录
  → 按月份汇总，以每批 100 条文本上传到 jotmo-keyword
  → 每批提取 Top 50，再按月聚合候选 Top 50
  → 拉回候选结果，内核根据当前可见快记重新计数
  → 返回全部 Top 50 + 各月关键词
```

旧版最终返回示意（非账号真实数据）：

```json
{
  "summary": [{"text": "录音", "count": 128}],
  "record_count": 42,
  "durations": [{
    "year": 2026,
    "month": 9,
    "record_count": 12,
    "items": [{"text": "录音", "count": 36}]
  }]
}
```

- `items[].count` / `summary[].count`：关键词在正文中的出现次数。一条快记出现 5 次就应贡献 5 次。
- `record_count`：该范围内命中候选关键词的去重快记条数，不是词频，也不是该范围全部快记数。旧聚合的全局 `record_count` 在最终 Top 50 截取之前计算，未必恰好等于最终显示的 50 个词对应记录的并集。
- 云端 `weight`：TF-IDF 提取重要性，用于候选筛选；不是次数、概率或置信度。内核最终列表按重算后的 `count` 降序排列，同频按文本稳定排序。
- 英文统一小写，纯 ASCII 英文词采用边界匹配，例如 `ai` 不计入 `myai`、`ai2`；中文沿用子串计数。它不是实体别名归并，也不是大模型语义概括。
- 候选来自每批/月 Top 50，因此不是完整词表。全部统计聚合的是各月保留的候选，一个词在未入选该月候选时的出现次数可能未纳入全局总数。需明确候选覆盖，不能宣称旧算法提供全历史精确全词频。
- 旧词云字号按排名递减，不按真实次数等比例绘制；桌面可以保留视觉呈现，但必须以明确数字作为次数依据。
- 旧来源弹窗采用关键词搜索再按时间筛选，并没有返回精确的关键词—Record UID 关联。搜索分词、时间口径与统计匹配规则不一致时，列表数量可能不一致。

## 4. 推荐接法

由拥有快记数据的 Record 服务提供正式统计查询，内部复用 jotmo-keyword 的分词、词项提取及计数逻辑。不要要求插件启动手机 Kernel，也不要把读取统计设计成插件全量下载、重新上传历史快记。

如果生产已经有适用的新端接口，请优先提供现有路径与真实契约，前端按现有接口接入。否则可采用下面的建议契约；路径最终由后端确定。

### 4.1 关键词汇总（建议）

`POST /api/v1/records/analytics/keywords`

请求复用现有统计时间范围：`from_stamp`、`to_stamp`（毫秒）、`timezone_offset_minutes`、`hide_record_pri_lock:true`；明确范围端点是否包含，并回传 `effective_range` 与 `date_policy`。全部/按月由明确请求范围决定，不能无条件返回全局词云给月份页面。

建议响应字段：

| 字段 | 定义 |
| --- | --- |
| `status` | `ready / processing / not_generated / unsupported`；请求失败仍按错误协议返回，不能伪装成空结果 |
| `snapshot_id`、`updated_at`、`algorithm_version` | 结果身份、计算时间和匹配口径版本，供来源列表对齐 |
| `source_scope`、`effective_range`、`date_policy` | 本期个人快记；明确包含正文/标题等哪些字段，以及自然日或智能归属日 |
| `coverage` | 是否覆盖所请求的所有可见记录；候选提取上限、返回数量上限、未完成月份等 |
| `items[].keyword_id`、`text` | 稳定词项 ID 与完整显示文本 |
| `items[].occurrence_count` | 该词在请求范围内的出现次数，不能混用记录数 |
| `items[].record_count` | 含该词的去重可见快记条数；没有准确值时用 null，而不是回填 occurrence_count |
| `items[].weight` | 可选提取权重，仅用于重要性排序；不代替词频 |
| `matched_record_count` | 可选：明确针对返回词集的来源记录并集，避免旧全局 record_count 含义模糊 |
| `next_cursor` | 如返回更多关键词，按稳定排序分页；若只支持 Top 50，明确限制即可 |

推荐第一期先保留候选提取的性能优势，对最终展示的候选在完整请求范围内重算次数。若暂时只能提供旧版各月 Top 50 累计值，请明确标注覆盖范围和估计性质，不把它当作精确全历史次数。

### 4.2 来源记录（建议）

`POST /api/v1/records/analytics/keyword-records`

请求：`keyword_id`、`snapshot_id`、同一时间范围、`cursor/limit`。返回去重 `record_uid`、该条 `occurrence_count`、原文片段/命中位置、有效日期和下一页游标。沿用 Record 原文读取权限校验。

统计和来源必须用同一归一化、词边界、日期、可见性规则。快记已删除、改为隐私锁或权限收回时，以当前权限为准并明确快照已过期；不能为了维持旧快照数字继续暴露原文。普通搜索可作为显式的「搜索相关记录」，不能伪装成精确统计来源。

## 5. 后端需要确认或补齐的事项

1. **生产可用性与入口**：jotmo-keyword 是否仍部署；新 Record 是否已有适用聚合接口；给出鉴权、路径、字段、错误/状态码及脱敏响应样例。本文只查代码，不以本地 HEAD 代替部署版本。
2. **增量更新与历史数据**：旧接口注释明确删除快记不会同步更新远端计数，依靠内核本地重算。新端需要覆盖新增、正文修改、删除、恢复、月份迁移、隐私锁/主题锁变化，且跨设备一致。缓存不能只用剩余记录的最大更新时间判断删除是否发生。
3. **权限与隐私**：词项自身、次数、来源列表、词云全部需要同一过滤结果。不能直接展示旧远端按月缓存，让已锁定/已删除的词继续出现。
4. **统计字段区分**：每词出现次数与涉及记录数分开返回；权重不能当词频。插件本次已拆分 `occurrenceCount` 与 `recordCount`；旧 `count` 仅映射为出现次数，绝不再用 `record_count` 填充出现次数。后端需要保持这两个字段的明确语义。
5. **覆盖与精度**：旧分批 Top 50 可能遗漏全局高频词或漏计部分月份；明确候选覆盖与计算方式。计数建议逐条记录计算后求和，避免跨记录拼接形成并不存在的短语命中。
6. **日期规则**：旧内核 `gin/api/summary.go:1187` 调用 `tmpTime.AddDate(...)` 后未接收返回值，该处归属日位移没有应用到月份分组；新实现应按统一日期策略正确处理月初凌晨边界，并与统计详情及来源列表对齐。
7. **关键词来源链路**：旧存储只有按用户/月/词项聚合，没有 Record UID 级来源关系。后端可在查询时使用同一匹配规则重建，或维护词项索引；不要求照搬旧搜索弹窗的数量偏差。
8. **生成状态**：查询不能长时间阻塞整个统计页；计算异步化、幂等去重，并提供状态与最后成功结果。失败结果不覆盖最近成功快照；最近成功结果必须标明更新时间和权限变化后的失效情况。

## 6. 已确认并实现的桌面交互

入口沿用「探索 → 统计与分析」，不增加第一栏图标。首页优先展示词云，最多预览 18 个收到的关键词；「查看词频」打开右侧完整词频列表。使用顶部全部/按月范围；列表显示 `词语 + N 次`，有可靠记录数时附 `涉及 M 条快记`。词云和列表均可点击词语，展开相关快记搜索结果并打开原文；从列表进入后可返回词频列表。

当前前端已区分接口未接通、请求加载中、请求错误、真正空结果；缺失次数不按 0 显示。词云字号使用出现次数，权重不代替词频；全部列表仅表示当前接口返回的词集，不暗示完整词典。按月时只取对应月份的旧 `durations`，不会把全局 `summary` 显示成本月结果。生成中/尚未生成、覆盖范围等服务器状态需等待正式契约后继续接入。

## 7. 验收用例

- 同一快记含「录音」5 次：词频贡献 5，涉及记录数贡献 1；两条分别 5/2 次则为 7 次、2 条。
- `AI / ai / Ai` 合并，`myai / ai2` 不命中；中文及中英混排沿用声明的算法版本。
- 全部与月份范围不串用；月初、跨年、时区及归属日边界与原文日期一致。
- 前端切换月份/账号后，旧请求不能覆盖新结果；错误不被显示为空或 0。
- 删除、编辑、加锁/解锁后，词项、次数、记录数和来源同时更新；历史回填可重跑而不重复累计。
- 单词、多词、长词、Top 50 限制、零记录月、生成中/失败状态均可解释；词云不截断原词作为查询键。
- 对最终展示词项，精确来源分页无重复；当前有效快照下，各条命中次数之和等于词项出现次数。
- 使用测试账号验证，不需要用户提供私人快记 JSON；交接附件不包含账号原文或访问凭据。
