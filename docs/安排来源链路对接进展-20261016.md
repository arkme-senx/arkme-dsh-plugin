# 安排来源链路对接进展

核验日期：2026-10-16。本文为项目交接，不包含个人安排清单、原文、凭据或 candidates JSON。

## 10 月 16 日晚补充：通话仍存在，但依据匹配失败

来源接口已接入，不代表所有来源都可定位。晚间在 3102 的首条通话安排复现了缺陷：同一通话的三段依据返回 `unavailable / unavailable / ready`；以当前用户读取通话详情成功，原通话有 294 段转写，第三段依据可打开并定位。前两段保存的引用与当前转写存在省略或改写，其中一段仅省略了开头的重复词和中间一个语气词，就无法通过逐字子串校验。

这不是历史来源尚未回填：该安排已经保存 `source_provenance.version=1` 和 `room_id`。也不能据此认定通话被删除或用户无权限。

### 已定位的代码原因

核查 Intelligent 最新远端 master `06b7b6197f823ea4b2604cf25348a802a78d3fdd`（2026-10-16 晚拉取；不代表生产部署 SHA），相关来源代码较此前 `057e201c` 无差异。

1. `gin/compound/arrangement_call_utterance.go:320–339`，创建安排时保存模型返回的来源文字。仅在唯一逐字匹配时保存 `start_ms/end_ms/speaker_ref`；未匹配也会保存来源，但没有语句位置。
2. 同文件 `ReadCallArrangementSource:468–490`，读取时又要求 `strings.Contains(utterance.Text, strings.TrimSpace(evidence.Text))`。通话可读但引用文字不匹配，也返回 `false`。
3. `gin/api/arrangement_source.go:127–135`，所有 `false` 统一变成 `state=unavailable, reason=原通话已删除或当前无权查看`，混淆了访问权限与语句定位。
4. 插件 `ArkmeArrangementSources` 收起时原先固定选第一段依据，其他可用依据未被尝试。这放大了后端缺陷：同一安排明明存在可用原文，直接点击却失败。

### 插件本轮修复范围

- 收起卡片的「查看原文」依次核验初始来源；一条明确不可用时继续尝试下一条，找到可用来源就打开。不会把后加资料当作首次识别依据。
- 再次打开时优先使用上次成功的来源，但仍重新经过服务端权限校验，不缓存授权结论。
- 展开后点击具体依据只打开该依据，不暗中换到其他语句。
- 将旧通话接口的含混原因显示为「这条通话依据暂未通过核验」，提供重新核验；不再断言通话已被删除。
- 登录、账号切换、网络及来源身份错误不会触发盲目替代；保留错误和重试。切换安排会取消旧请求。

这只能解决「同一安排还有其他可用来源」的入口问题。全部引用均无法匹配时，仍需要后端修复；插件不会擅自用相似文本充当已确认的定位。

本轮验证：来源 UI、读取、打开三个测试文件共 48 项通过，类型检查及完整构建通过。3102 使用真实账号，从收起卡片直接打开后续可用依据并确认原转写高亮；展开显示两条「暂未通过核验」及重新核验入口，第三条显示真实引用；关闭后再次打开成功。未修改云端安排或来源数据。

### 后端需要调整

1. **拆开授权与定位结果。** 建议在现有 `source/read` 协议中独立返回来源访问状态和引用定位状态，例如 `access_state=readable/forbidden/missing`、`quote_state=exact/unlocated/ambiguous/version_changed`。这些是待协商字段，不是当前已上线协议。网络/服务异常返回可重试错误；转写处理中独立表达 pending。只有确定删除/拒绝权限时才能给出对应原因。
2. **通话可读但句子未定位时，允许打开原通话。** 必须先用当前账号核验通话权限，再返回合法的通话入口；显示「原句待定位」，不能把模型改写的引用冒充原文或伪造高亮位置。
3. **新识别使用稳定来源定位。** 输入给模型的每段转写携带稳定 `utterance_id` 和转写版本，模型返回引用 ID 或 ID 列表；后端从已提供、已授权的语句中取回原文、时间范围和说话人，不依赖模型重新抄写。跨句依据允许多段引用。拒绝越界 ID；同文多段不能任选一处。
4. **历史修复单独预览和审计。** 已有房间定位的安排先核验权限，再基于确定的语句身份/版本证据补齐锚点。相似文本仅作为待核对候选，不能直接当作准确回填；保留旧引用、处理版本、审计及回执，不能覆盖安排标题或状态。
5. **补齐验收场景。** 精确引用、少语气词、改写、跨语句、同文重复、转写版本更新、无转写、无权限、已删除及服务超时分别覆盖。真实复核应包含三条来源中只有最后一条可读、以及全部未定位的安排。访问状态与定位状态必须与真实情况一致。

原始响应和逐字比对保存在用户本机 `.codex-artifacts/arrangement-first-source-20261016/`，未放入公共交接包。后端同事如需真实安排 UID、room ID 或完整原文，请由数据所有者单独提供。本轮不修改后端、不执行云端回填；用户已授权将插件修复同步 dev，实际 PR 与合并 SHA 随群消息提供。
