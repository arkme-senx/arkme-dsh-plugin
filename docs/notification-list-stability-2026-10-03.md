# 通知列表刷新与排序

基线：`origin/dev` / `58e579677e931111785d50954755cfc901d85b4a`。本任务在独立 worktree 开发，原 checkout 的录音与频道改动保留。

## 范围与能力边界

用户确认的行为：点击通知只切换内容区；同账号刷新保留已有通知行与内容；通知按最新一条事件的时间参与普通会话排序，保留置顶规则。已读与刷新不生成新的排序时间。

随后确认移除通知标题栏的返回箭头及占位，保留铃铛、标题与全部已读操作；通过会话列表直接切换对话。

跨板块返回统一恢复离开前的会话：补齐通知与 Arko 的 `lastConversationDestination` 记录，复用普通会话、Bot、Harness、Codex 和发给自己的恢复机制。记忆仍由现有 UI controller 持有，仅保存当前运行期间的一个目标，退出登录或账号替换时清除；不增加持久化、网络请求或后台资源。

| 能力面 | 范围 | 验证 |
| --- | --- | --- |
| UI | 通知缓存展示、账号隔离、目录排序、选中状态与跨板块恢复 | 慢请求、失败、账号切换、目录排序、会话恢复及真实登录态 Web 验收 |
| Host owner | 复用既有通知查询与已读 API，不改变请求合同或权限 | 无 Host 修改 |
| Tools / SDK | N/A：仅修复 Browser 展示状态，不新增业务能力、路由或持久化 | 既有入口保持不变 |
| Client / Harness | 无客户端、原生桥或运行环境修改 | 仅部署独立 Web 预览 |

## 请求与资源边界

入口为已有通知行和通知中心的挂载；缓存 owner 仍为单例通知 store。同账号并发刷新共用现有 in-flight 请求，账号变化取消旧请求并清除旧账号投影；不新增轮询、定时器或后台进程。通知行移动不拥有新的数据请求生命周期。

既有查询上限保持：安排 50 条、世界最近 10 条记录各取最多 50 条互动、AI 来信 20 条。失败保留已有的有界快照，成功结果替换对应快照，不累计历史。目录新增一个合成通知项，继续使用现有分块渲染。

表态仍复用现有未读收件箱，不新增已读表态历史存储；排序取当前通知投影中最新事件的原始时间，不使用点击、已读操作或请求完成时间。
