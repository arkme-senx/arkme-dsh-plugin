# DSH 嵌入右侧栏边界修复

## 原因与范围

即我将原生 DSH iframe 保持为整个浏览器大小，以便任务菜单越过对话区域显示；实际对话通过 AppFrame 定位和 iframe clip-path 限定在第三栏。

原生右侧栏在 AppFrame 宽度小于 768px 时切到 `position: fixed; inset: 0; width: 100%` 的全屏模式，其定位仍相对于整个 iframe。1100px 窗口中第三栏从 x=344 开始、宽 756px，原生面板却从 x=0 开始、宽 1100px。文件列表因此被外层裁掉，造成空白、会话消失的观感；会话实际没有卸载。

本次只在嵌入适配器内限制原生 fullscreen 面板的边界：横向与第三栏一致，纵向位于当前任务标题下方。标题变化通过尺寸观察同步，不写死高度。宽屏 push 并排布局不变，不替换上游面板、消息、输入框或状态存储。

## 极窄窗口补充修复（已确认并完成）

420px 窗口下第三栏仅 236px。打开面板前 header.scrollWidth 为 276px，外层会话容器 scrollWidth 为 501px；点击右侧按钮后该容器 scrollLeft 变为 144px，导致顶部标题离开可见区域。此问题与 fullscreen 面板坐标越界不同。

用户确认后，仅在标题内容区域宽度不超过 360px 时将工具按钮另排一行；上方保留对话名与当前任务。使用标题自身的容器查询而非窗口媒体查询，适配左侧目录和侧栏对实际宽度的影响。原生 React 节点和事件绑定不移动、不重建，常规桌面布局不变。

420px 复测中标题保持 x=184，外层 scrollLeft=0；标题高度由 73px 自适应为 109px，侧栏自动从 y=109 开始，不遮盖工具栏。放大回 1440px 后恢复 73px 单行布局。
