# 团队消息右键操作：已接通能力与剩余协议

日期：2026-10-20。接收人：华焱。范围：Arkme 插件团队通道；本轮不修改、不部署后端，不合并 dev/master。

## 1. 发现与结论

用户反馈右键的表态、复制链接、延展、转发、问 DSH、举报全部半透明。直接原因是插件 TeamConversationMessage 把这些菜单项统一写成 disabled:true 和空回调；多选栏同样存在。此前共享的是菜单样式，不能称为功能完整复用。

本轮已拉取只读的 jotmo-team master：`21cfe2019ae23b6f00c64c1bed0003c27812029b`。这是源代码核验，不代表生产部署版本已经核实。没有探测或调用猜测的线上写接口。

## 2. 前端与插件 Host 本轮接通

### 整条延展：已有后端能力，无需为基础回复另造接口

后端证据：

- `gin/api/team_messages.go`：已有 `conversations/messages/send` 和 `conversations/timeline/page`。
- `internal/teammessaging/models.go`：SendInput.ReplyTo、MessageView.ReplyTo 均通过 `reply_to` 收发，Message.ReplyTo 持久保存。
- `internal/teammessaging/service.go` Send：校验原消息属于同一会话且为 Published，保存 ReplyTo；messageView 返回关联。
- `internal/teammessaging/identity.go`：幂等指纹包含 ReplyTo。

插件新增整条延展：右键或详情中的延展回复 → 同款输入框引用预览 → 原关联进入持久发送队列 → 正式 `reply_to` 提交 → 时间线返回后映射为账号内稳定键 → 点击引用分页定位原文。草稿重载保留，取消延展保留正文；重试不生成第二条消息，不丢弃引用；改变父消息而复用发送 UID 会拒绝。

Host 校验 Team 引用的账号、会话和访问侧；不把 Team 引用传给 Chat。引用原文加载不全时显示“查看原消息”，读取失败明确报错，不伪造历史引用正文。发送队列重启、丢失应答、引用轮换和越会话拒绝有测试。

当前为整条关联，原文按最新可读版本展示，**并非保存当时某段文字的不可变引用快照**。部分选区延展和反向“相关快记”仍需下面的协议支持。

### 问 DSH：已有本机桥接和团队原件读取能力

单条右键和多选“问 DSH”接通同一 DSH 草稿准备器。先通过 Team timeline 重新校验所选消息的可见性、版本和正文；保留界面备注名、作者、时间和所在团队。附件通过现有 Team `/conversations/messages/media` 对应的本机鉴权读取路由取原件，不导出临时授权链接，不通过 Chat 快照接口读取 Team 引用。

只准备所选消息和附件，不自动发送问题给模型；切换会话/账号取消未完成准备；消息变更、撤权、附件失败均停止并明确提示，不默默丢附件。没有增加后端接口。

## 3. 仍需核对或补齐的服务能力

| 操作 | 当前代码证据与需求 |
| --- | --- |
| 表态 | 核对的 Team App 路由没有表态快照/增删入口。请提供或补齐消息级表态读写、作者、去重/幂等、增量事件；明确团队成员、发送者、外部用户分别可见哪些信息。前端复用普通群聊选择器和展示。 |
| 复制消息链接 | 当前 channel.link 仅是团队消息入口，不能定位一条消息。需消息分享/定位协议、访问校验、有效范围、删除/失权后的状态。不能用团队入口或插件本机加密引用冒充跨设备可打开的消息链接。 |
| 转发 | Team SendInput 已有 record_ref/source，RecordClient.AuthorizeReference 已有授权复用基础，请优先核对这条已有能力，不直接新建重复接口。仍需明确 Team→私聊/群聊/发给自己和 Team→Team 的可用目标、原件授权、发送结果查询及删除/变更语义；当前插件 Chat 转发不能直接接收 Team messageRef。请分别反馈已支持的方向和正式调用示例。 |
| 举报 | 核对的 Team App 路由没有消息举报入口。需要可举报范围、原因、提交时正文版本/证据、去重、处理结果。身份应由服务端消息关系解析，不由前端昵称匹配。 |
| 撤回 | 当前 cancel 用于取消发送中的操作；delete 是删除 Record，并不是消息撤回。需要单独确认撤回权限、时限、占位与实时事件，不能把上述两个操作换个名字就开放。 |

缺口指核对到的 master 及插件已接协议。若另一个仓库/分支已有实现，请反馈接口与部署版本，我这边接入；不要重复开发已有能力。

## 4. 延展后续增强（不阻塞本轮整条回复）

1. 按 message_uid 定位并返回原消息所在分页/seq，避免很久以前的引用需要客户端逐页查找。
2. 原消息摘要投影：作者、时间、当前可见状态、正文/附件预览；删除或撤权时明确不可读。需要区分当前正文与引用时快照。
3. 部分内容延展：原消息/版本、规范化文本位置、选中文字和前后文锚点；发送幂等、读取投影、编辑失配/删除状态。不能把部分引用伪装为整条回复。
4. 反向延展列表与相关快记：分页、关系权限、排序和数量；前端不能仅用当前已加载页面推断“全部相关内容”。
