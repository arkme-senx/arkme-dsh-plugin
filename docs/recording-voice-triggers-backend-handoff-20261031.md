# 录音语音触发：原音口令检测、本人优先与确认保存

状态：前端、Host 适配器及本机规则配置已开发；下述 Audio owner 接口是待确认的 v1 合同，当前仓库未发现对应后端实现。没有接入原音检测前，不宣称功能已开始检测，也不以转写文字包含口令作为等价实现。

## 1. 产品范围与验收结果

第一期口令“帮我记一下”，动作是将后续口述内容保存到“发给自己”。支持用户增加不同口令和别名，动作暂限 `save-self`。一个账号最多 20 条规则，每条最多 5 个别名。所有新上传的历史音频、App/桌面端长录音、全天候录音均进入同一处理 owner；从 DSH、网页、客户端导入不应改变处理结果。这里“历史音频”指新上传的旧文件；已存云端录音不因启用规则而自动回扫。

声纹用于身份判断与优先展示，不能作为扫描入口的过滤条件。**所有声学命中均保留**，包括未识别和被误判为其他人的声音。可靠本人 + 明确指令语境 + 内容完整时允许自动保存；其他命中待用户确认，不对外发送。保存记事与说话人标记是两个独立动作。

入口：录音日历工具栏“更多 → 语音触发”。管理规则、查看识别记录（本人优先）、播放原音、忽略、确认保存。保存成功后可选择具体原音片段，复用原有编辑说话人组件（本人/已有身份/手动创建）。更大范围标记沿用原有明确范围确认，不自动修改整场录音。

## 2. 音频管线

```
canonical audio ingestion / source-ready event
  → 授权与账号规则快照
  → 原音 KWS 候选检测（所有说话人）
  → 与时间轴、声纹、正文 ASR 对齐
  → 指令语境与内容边界判定
  → 候选事实持久化
  → 自动保存或用户确认
  → Record owner 创建快记及来源关联
```

- 口令判断必须直接使用保留的原始音频/人声音频及声学分数。可评估 sherpa-onnx 自定义中文 KWS，使用与模型匹配的拼音/音素建模单元。用户设置口令不等于为每个用户训练一套 ASR。模型选择和阈值需实测，不能仅根据文档宣称准确。
- 可把 ASR 文本、近音匹配作为候选补充，但必须回到原音验证；不能只对文字先命中的位置做 KWS，否则转写完全漏词时仍会漏检。现有 `hasOfflineResultText` 跳过空转写的步骤不能先把声学候选丢弃。
- 检测与正文转写分开；命中口令不表示正文转写无误。口令本身不进入正文，原话与原音保留。不要把模型整理/补全的内容伪装成原话。
- 同一逻辑录音跨技术分片连续处理，维护 pre-roll、口令尾部、候选 capture 状态及原始时间映射。口令和正文位于相邻文件时仍为同一个候选。不能按分片末尾直接判定记事结束，也不能使用压缩场景内时间代替真实时间。
- 结束边界可综合“记好了”、足够长停顿、后续口令及语境；阈值需用真实口述验证。长停顿不可靠、重叠说话、身份不明等情况保留候选，不能无限吞入后续聊天。达到上限也应保留已有内容并待确认，不能静默截断丢失。
- 普通提及、引用、否定、播放录音/电视以及“刚才不记了”等需纳入负例或取消逻辑。声纹不可靠时不能强行判定为本人。
- 首期是上传后处理，没有设备实时反馈承诺，不修改录音器固件。
- 执行由 source-ready/ASR-ready 等事件驱动，队列限并发、支持恢复；不靠每 5 秒全量扫描，不为每个用户每条规则重新加载同一个模型。后台不能引起用户录音页刷新或滚动跳动。

## 3. v1 接口合同（待后端确认，路径可协商）

统一前缀 `/api/v1/audio/voice-triggers/`，所有接口 POST，沿用 Audio 身份验证与标准 envelope，**每个 data 返回 `user_id`**，且必须等于当前认证用户。客户端传入的账号不构成授权依据。接口不可用返回 HTTP 404/501；网络错误、401/403/5xx 仍作为错误显示，不能映射为空列表或“无命中”。

### capabilities

请求 `{}`。返回：

```json
{"user_id":11,"version":1,"detector":"audio-kws","ready":true,"sources":["upload","long-recording","all-day"]}
```

只有原音检测和三类录音统一接入后才发布 `ready:true`。前端没有后台轮询，打开/返回焦点/手动刷新时读取。页面关闭后前端不会继续扫描。

### rules/query、rules/set

query 请求 `{}`；set 请求 `{ "expected_revision": 3, "rules": [...] }`。均返回 `{ "user_id":11, "revision":4, "rules":[...] }`。规则示例：

```json
{"id":"note-to-self","phrase":"帮我记一下","aliases":[],"enabled":true,"autoSaveSelf":true,"action":"save-self"}
```

CAS 冲突返回 409；设置时后端验证规则总数、口令长度、重复别名、动作白名单，并给启用规则确定生效时间/版本。扫描任务保存执行时规则快照。修改口令不能把已忽略/已保存的旧命中重新执行。历史回扫将来必须是显式、独立、有范围的能力。

接口未就绪时 Host 把规则写入稳定账号目录中的 state.json（按环境+账号隔离，CAS，本机重启不丢）。界面明确显示“后端接口开发中，开发完成后此功能完整可用”。云端就绪后本机配置通过显式“应用此前保存在本机的配置”提交，不静默覆盖云端设置；本机配置不代表自动检测已运行。

### candidates/query

请求 `{ "limit":30, "order":"self-first", "cursor":"可选上页游标" }`。返回 `{ "user_id":11, "items":[...], "next_cursor":"可选" }`。最多 30 条，游标覆盖完整结果；全局本人优先、组内最新在前。后续声纹更新不改变候选业务 ID，不能让待确认记录丢失。游标需绑定账号、排序及分页快照，防止身份更新造成翻页漏项。

```json
{
  "id":"stable-candidate-id",
  "revision":1,
  "phrase":"帮我记一下",
  "text":"明天和宏顺确认接口",
  "start_at":1793410200000,
  "end_at":1793410210000,
  "speaker":"unknown",
  "speaker_label":"未识别说话人",
  "status":"pending",
  "boundary":"complete",
  "evidence":{"kind":"audio-kws","model":"calibrated-model-version","score":0.86}
}
```

枚举：speaker=`self|unknown|other`；status=`pending|saved|ignored`；boundary=`complete|open|uncertain`。时间为原始绝对毫秒，start/end 包含口令与后续内容的回听范围。text 不含触发口令。evidence 必须是原音声学判定结果，不接受 `transcript-match` 冒充。分数用于证据而非向用户宣称精确概率。

### candidates/detail

请求 `{ "id":"stable-candidate-id" }`；返回 `{ "user_id":11, "id":"...", "revision":1, "anchors":[...] }`。

每个 anchor 为 `{ "date_stamp":当天当地零点毫秒, "at_millis":原始片段内绝对时间, "transcript_source":"system|doubao" }`，最多 100 条；依序完整覆盖口令和正文原音，按实际说话段去重，不能超过上限时静默截掉后续原音。Host 按日期与转写来源复用附近片段读取，重新核验权限与当前转写条目，映射为密封 itemRef，复用原音播放与说话人标记。前端不接受任意 CDN URL 或原始数据库 ID。

后端需要保证 anchor 对应唯一原始片段；若多来源存在重叠、原件/转写发生重切分，需增加 canonical source locator 再对接，不能任取重叠记录中的第一条。原音已删除、身份无权、来源失效应明确返回错误，不能播放其他人的相近时间音频。需要精确子区间时沿用播放 owner 的范围授权。

### candidates/decide

请求 `{ "id":"...", "expected_revision":1, "decision":"save|ignore" }`；返回 `{ "user_id":11, "candidate":完整最新候选 }`。

- save 成功前候选不能显示 saved。必须在 Record owner 真正提交后返回 saved，并保留可核验的快记 UID/来源关联（UID 留在服务端，不作为前端授权引用）。原音丢失不能伪装已保存；正文不完整的 open 候选拒绝保存。uncertain 在用户明确试听确认后允许保存当前范围。
- 通过原生 Record owner 创建属于当前用户的私密快记，保留录音、口令、正文时间范围及触发规则版本的来源。复用已有多端快记同步/设备位置权限规则；不能编造地理位置，也不能保存到团队或公开世界。
- 幂等键应基于账号+规范源录音+稳定口令发生位置+动作，而不是 ASR 文本、请求重试次数或临时分片ID。自动保存与手动保存共用同一个提交 owner 和幂等键。重试、重复导入、重切分或晚到声纹都不能生成第二条快记。
- 相同决定重复提交返回已提交事实；相反决定或其他变更冲突返回 409。网络结果不明后前端可刷新核对，禁止生成新的写入身份绕过原请求。
- ignore 只标记不执行，不删除录音或快记。忽略后的候选不能因后补本人声纹被自动保存。
- **decide 不修改说话人、也不训练声纹。**保存后用户可单独标记实际原音片段，沿用已有说话人 mutation 与明确范围确认。

## 4. 当前插件边界

Host 操作：只读 `recordings.voice-triggers`（settings/page/detail）；写 `recordings.voice-triggers.rules.set` 与 `recordings.voice-triggers.decide`，写操作要求受信任页面 Origin。前端调用时附带 accountKey；Host 再绑定当前账号，响应前复核登录代次，防止切换账号串数据。候选及游标经过按账号和环境隔离的密封引用，UI 仅持稳定 opaque key。暂为内置 UI 能力，未扩展到公开 SDK/Tools。

列表懒加载、失败保留已有内容、无定时扫描。声纹补充或确认后原地更新，正在编辑时不因窗口焦点刷新覆盖输入。保存内容与标记声音分开；原音读取只在点击播放/标记时进行，不为显示列表拉全日转写。

## 5. 后端必测与接入顺序

1. 同一组真实佩戴录音比较文字匹配与原音 KWS：轻声、口音、噪声、近音、漏转写、负例，报告漏检及每录音小时误触发数，不能只报告截取样本准确率。
2. 三类录音和各上传入口一致；跨片口令/正文/结束词、跨午夜、重叠说话、无声纹及误归他人均保留可确认命中。
3. 从未启用到启用、规则修改、晚到声纹、用户先忽略、自动/手动保存竞争、录音重传与任务重试、写入成功但应答丢失，均验证不漏、不重复、不跨账号。
4. 完成 KWS 与候选只读 → 接通确认保存与来源 → 校验说话人标记 → 真实录音观察验证 → 才启用可靠本人自动保存。不要先返回 ready:true 再补检测实现。

本次未部署 Audio 服务、未验证模型效果，也没有修改录音器固件。此文档供后端确认实际路由和响应后联调。
