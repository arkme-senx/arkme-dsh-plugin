# 选中文字转发：引用结构云端补充交接

日期：2026-10-25

本文是《选中文字发给自己-跨来源引用云端交接-20261023》的增量更新。入口已从「发给自己」升级为「转发」；此前文档中“仅发给自己、必须输入笔记”的行为以本文为准。

## 插件本次行为

- 私聊、群聊、发给自己、Bot、Arko、Codex、DSH、团队消息及录音/通话转写沿用同一个选中文字工具栏。
- 点击「转发」复用普通消息的「转发给」选择器。发给自己排在第一项，默认不选收件人，可多选现有支持发送的目标；不新增不具备发送协议的目标。
- 冻结用户选中的文字、来源标题、作者显示名和原时间。只发送这份阅读摘录，不附带整条原消息、附件、原媒体地址和访问凭据，也不为原消息伪造延展关系。
- 附言可空。选择器内分开展示引用原文与附言。多目标发送沿用原有权限检查与部分成功重试流程，成功目标不会重复发送；失败目标使用原 UUID、原目标与原附言重试。
- 新增 `selected-text.forward` 是本地插件 Host 操作，**不是新云端接口**。它校验当前环境、账号及目标权限，先将引用结构保存至 Host SQLite，再调用既有文本发送链路。普通发送链路现有的审核规则继续适用；不生成公开分享链接。
- 同一 record_uid 冻结引用、附言、目标与 relation_uid；刷新目标访问引用不能改变原发送内容。账号切换或取消时中止本轮请求；只有匹配 UUID 且 synced 的回执才确认成功。
- 本机本人已发记录使用引用块与附言分区样式，发给自己和本人已发送的私聊/群聊均适用。旧的“我的笔记”记录保持兼容。

## 当前跨设备/接收端限制

云端当前保存完整可读文本，例如：

```text
引用 · 群聊名称
原作者 · 原时间
只选中的文字

附言
我的新想法
```

无附言时不生成空的“附言”段。接收方和其他设备可读到这些明确分段的文字，但尚无服务端结构来恢复同样的引用块视觉。不会声称云端已保存结构；选择器内有提示。引用结构仅通过本机已保存的 record_uid 与完整文本精确匹配恢复，不通过正文关键词猜测引用关系。

## 后端需要支持

请沿用前一份交接中的 `quote_snapshot` 建议，将其从“个人笔记”扩展为所有允许转发的会话消息：

1. quote_text、source_label、sender_display_name、source_at、version 与可空 comment 分开保存；标记这是用户摘录快照，不是假定服务器已验证的原文关联。
2. 写入支持 private_chat、group_chat、send_to_self 等现有目标；权限、禁言、接收限制、审核和幂等与普通发送一致，不因引用元数据绕过任何检查。
3. 读取在本人和有权查看该消息的接收方设备上返回结构，包含历史分页、详情、搜索与重连增量；旧版仍能看到可读文本。
4. 仅在明确权限与合法原文身份核验后返回可跳转来源。显示名称和来源说明本身不是访问授权。
5. comment 允许空；引用与附言不同作者归属，渲染、复制、编辑、标记偏移须一致。引用被更改时不得沿用旧结构；只编辑附言不应损坏引用。
6. 后续转发这条摘录、删除/恢复/彻底删除、跨设备冲突与旧数据迁移，沿用前文约定，不能把原完整消息或私有图片偷偷补回。
7. 本地迁移以环境、账号、record_uid 和精确文本校验为依据；收到结构化保存成功回执后再确认迁移完成，不扫描普通文本猜引用。

## 代码与验收入口

- `src/client/ArkmeMessageTextSelection.tsx`、`selected-text-forward.ts`：所有现有部分选中文字入口、不可变快照。
- `src/client/local-snapshot-forward.ts`、`ArkmeSidebar.tsx`：共用选择器、可见 DSH frame 身份校验、来源预览、可选附言。
- `src/services/selected-text-forward.ts`、`src/arkme-service.ts`：账号、目标、存储前置与原发送链路。
- `src/local-self-note-quotes.ts`、`src/selected-text-note.ts`、`src/client/SelectedTextSelfNoteContent.tsx`：本机持久化、旧记录兼容、精确投影。

联调重点：空附言、多接收人部分失败、重试不重复、切账号、权限失效、选中内容中有换行/emoji/URL、无整条原文或附件泄漏、跨设备引用视觉与旧版兼容。
