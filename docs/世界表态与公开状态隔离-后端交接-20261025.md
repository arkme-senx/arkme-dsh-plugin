# 世界表态与公开状态隔离

日期：2026-10-25。产品方案已确认。世界表态现在先提供完整的**本机交互**；本文所列 `/reactions/world/*` 是已预接但未启用的**待后端实现合同**，并非已上线接口。本机表态不会发送公开表态、云端写入或对方通知。

## 一、当前事实与阻断点

- 世界卡片现已复用统一表情、手势、自定义短语、表态列表及表态者组件，默认数据仅保存在本机。既有评论仍走原有接口。
- 已只读核对 jotmo-record 最新 master `8f6758f8b7d929e2ea28af7ef14969f365e22427`：`internal/reaction/service.go:Query` 明确将公开视图视为所有来源的汇总；`internal/reaction/repository.go:Query` 的 public 分支按 `record_anchor` 聚合同一快记各来源表态，`targetFilter` 对公开目标也返回 anchorFilter。集成测试中有 `public union failed to deduplicate actor` 的断言。
- `internal/reaction/access.go` 对世界表态仅作者可见 actor；世界撤回后 Writable=false；`Service.Set` 无论新增或撤回都要求 Writable，因此原表态者无法仅撤回自己的历史态度。
- jotmo-world 的 `public_records` 以 `record_uid` 保留公开事实、审核及 is_public；单纯重复公开沿用 UID，不足以表达“内容修改后不继承旧评价”。

**不能把现有 `{record_uid}` 的旧公开表态接口直接挂到世界。**否则群内/私聊/自己的私密表态可能变成公开统计。不能靠客户端减数、过滤演员或复制数据来修复。

## 二、已确认产品规则

1. 同一条内容在群聊、私聊、发给自己、世界中的表态互相独立。公开内容只发布正文和允许发布的附件；不迁移原场景的表态、人数、成员或群信息。原群也不自动显示世界读者的表态。
2. 取消公开是收回访问权，不删除世界表态。作者在原快记详情的独立“世界表态 · 已取消公开”区只读查看历史；不混入普通消息下的表态行。
3. 他人失去原文与表态者列表访问权；其个人操作历史可以保留“该内容已取消公开”及自己的表态操作事实，不能保留可访问原文/图片/其他成员的快照。仍可撤回自己的表态，不能新增。
4. 同一内容未改变，重新公开恢复该世界版本仍有效的表态；不复活已经撤回的态度，不补发旧通知。
5. 正文或附件实际改变后，后端生成新的公开内容版本。旧表态归档到旧版本，不计入当前版本。内容版本由 owner 按确定的正文/附件变化规则生成，不能由前端猜测或用更新时间替代；外观布局、昵称更新等不产生新正文版本。
6. 公开表态者使用公开资料；不带出群昵称、群名、私聊备注。每人可对同条内容选择多个不同表态；相同表态计人数。支持给自己表态，但不给自己产生互动通知或未读。
7. 列表、个人公开主页及公开详情指向同一世界内容版本；一次操作各入口一致，不重复建立状态。

## 三、已完成的客户端部分

- 世界卡片常驻“表态”和原有评论入口；点击即可打开与私聊相同的 ArkmeReactionPreview / ArkmeReactionSelections / ArkmeReactionPhrases，支持新增、取消、多种表情与自定义短语。
- 默认走独立的 `world.reactions.local` Host 操作，保存在插件稳定目录的 SQLite，按环境和账号隔离。刷新、退出重开不依赖页面端口；自定义短语同样只存本机。聊天表态和聊天云端短语库保持原合同。
- 世界表态弹窗底部以小号灰字显示“仅本机保存 · 未云同步”，动态卡片不重复展示提示。本机状态只呈现自己的表态，不伪造其他用户、公共人数、通知或已同步状态；保存失败保留原数据并提示失败。
- 本机目标随世界列表投影返回，不等待 prepare 或后端能力探测才打开面板。目标按内容 UID 和本次可见正文/附件摘要区分；签名 URL 续签、昵称变化不更换目标。该摘要只用于本机注释归属，**不是后端权威公开版本**。
- 云端适配保留独立 transport 和合同检查，但当前界面未启用。后续联调时启用后端 prepare/query/set 等合同，禁止降级读取旧 union 接口。
- 本机数据不是待发送队列。云端能力上线后**不自动上传、补发通知或合并本机表态**；迁移策略需要独立确认。本机取消公开、历史归档、重新公开的状态不能替代后端事实，完整流程仍待后端联通。

## 四、前端已预接的 Record 合同

所有接口均为认证 POST JSON，用户与账号取当前会话，不能信任客户端传 owner_user_id。成功统一为既有 record envelope `code=0`，data 中必须包含 `contract: "world-reactions-v1"`。下列均为新命名空间，**禁止 fallback** 到原 `/api/v1/reactions/query`、actors、groups、received 或 set。

### 1. POST /api/v1/reactions/world/prepare

请求：`{"record_uids":["record-uid"]}`，1–50个去重 UID。

响应 data：

```json
{
  "contract": "world-reactions-v1",
  "items": [{
    "record_uid": "record-uid",
    "readable": true,
    "context_uid": "stable-world-context",
    "content_revision": "authoritative-content-revision",
    "visibility": "published"
  }]
}
```

- 与请求一一对应。不可读只返回 `{record_uid, readable:false}`，不返回正文、身份或历史快照。
- visibility 目前客户端接受 published/unpublished；unpublished 只准作者读取。不准把审核中或被拒绝内容标成 published。
- context_uid 是稳定的世界发布上下文，content_revision 是实际公开内容版本。取消公开再公开未修改内容时二者不变；真实内容变化时 revision 变化。
- Host 将 record_uid/context_uid/content_revision 封入按环境和账号绑定、15分钟有效的不透明引用；浏览器不接触原始 UID。此引用只定位目标，后端每次仍须重新鉴权。

### 2. POST /api/v1/reactions/world/query

请求：`{"targets":[{"record_uid":"record-uid","world_context_uid":"stable-world-context","content_revision":"authoritative-content-revision"}]}`。

响应 data 为 `{contract, items:[{target,mine,groups,has_more,actors_visible,private}]}`，字段与现有 reaction Snapshot 一致。target 必须逐字段回显以上三项。mine 为 `{revision,selections:[{key,expression,at}]}`；groups 为 `{key,expression,count,actor_user_ids:[最多3人]}`。

- 只统计这个 world context+revision 的状态，不使用 record anchor union。
- 当前公开时 private=false；作者读取已取消公开的版本 private=true 且只读。他人不再可读时从 items 中省略该目标，客户端据此收回卡片可见性。
- 内容变更后旧版本不作为当前公开内容返回；作者查旧版本必须走明确的 owner 历史入口。
- query/actors/groups 在 IO 后再次校验权限；不能仅凭缓存公开标识或客户端 opaque 引用授予权限。

### 3. POST /api/v1/reactions/world/set

请求与现有 set 一致，target 为以上三个世界字段：`{target,expression,active,expected_revision,request_id}`。

响应 data `{contract,outcome,state}`。outcome 使用 updated/unchanged/idempotent/revision_conflict；state 为当前用户确认后的 revision/selections。

- 新增须世界当前公开且目标版本仍为当前版本；全局停用、审核不通过、删快记等也须重新判断。
- active=false 可允许操作者仅移除其已有世界表态，即使该版本已取消公开；不得由此授予读原文或其他身份的权限。历史入口还需向客户端提供可撤回的目标引用。
- request_id 绑定用户+目标+版本+表达式+active。超时重试不可重复新增或重复通知。
- 防止读写竞态：取消公开/版本切换与 set 的最终写入须有 owner 版本或可证明的原子校验。返回 world-reactions-context-expired 表示上下文须重读；不要悄悄将旧版本操作写入新版本。

### 4. POST /api/v1/reactions/world/actors/query 与 /groups/query

请求沿用现有 `{target,key,after_user_id,limit}` / `{target,after_key,limit}`，target 为世界三元组；响应 data 分别 `{contract,user_ids,has_more}` / `{contract,items,has_more}`。人数、列表、分页必须全部按同一 world scope+revision 过滤。公开时可查看公开资料；取消公开时只准作者看归档。

## 五、还需后端给出的合同与联调项

优先级 P0：独立世界作用域、当前内容版本、prepare/query/set/actors/groups、全链路权限与不向原聊天迁移；上面的前端适配可以直接联调。

优先级 P1：原快记 owner 查询世界版本与归档、操作者历史撤回目标、取消公开提示中的真实互动人数、世界表态通知定位。请明确字段和入口后补齐原快记详情/历史/通知的前端联动，不能将现有 world_only received 当作已隔离的世界历史。

兼容性要求：旧公开 query/actors/groups 的 anchor union 也必须收紧或停用，避免旧端继续扩散聊天表态。已有数据保留：只有可证明原来直接发生在世界的状态才可迁移为世界历史；不从聊天或 owned/self 状态复制到世界，也不把无法确认内容版本的旧表态强挂到当前版本。

## 六、联合验收矩阵

- A在群内发消息，B表态；A公开，世界人数为0。C在世界表态，群内仍只有B。
- A对自己的世界内容表态正常，无自通知；多个用户相同表达式按人去重。
- A取消公开：A能查归档，B/C旧公开链接/图片/表态者查询失效；C个人历史不露原文但能撤回自己的表态。
- 未修改重新公开：恢复未撤回的世界表态；修改正文/附件重新公开：新版本0表态，旧版本只进入归档；无旧通知重放。
- pending/rejected/deleted、离线缓存、跨账号引用、token过期、伪造context、query与撤回竞态、set与内容变更竞态、重复request_id均有验证。
- 当前本机模式：点击立即打开；新增、取消、自定义短语持久化；刷新及 Host 重启可恢复；跨账号不可读写；失败不伪装成功；没有任何云端表态/短语写入和对方通知。
- 未来启用云端后：新接口404/不含contract时显示真实待开发提示，不调用旧公开union接口，不进行高频探测，不影响世界正文加载或原有评论；不会悄悄上传既有本机数据。
