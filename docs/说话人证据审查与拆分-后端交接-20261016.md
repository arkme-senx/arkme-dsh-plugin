# 说话人证据审查与拆分：后端交接

> 2026-10-16 交付更新：本文件随本轮插件 dev 同步交付，代码合并状态以 PR 回执为准。下文“未合 dev”等为编写时记录；生产能力与待办以 [后端交接总览](后端需求交接总览-20261016.md) 的本次核验栏为准，拟定接口不代表已经上线。

日期：2026-10-16。接续《说话人标记与持续识别学习-后端交接-20261016.md》和《录音说话人纠错一期-后端交接-20261014.md》。本文不包含个人录音、生产向量、账号凭据或真实距离样本。数值示例都是协议示例。

## 1. 目标与本轮边界

解决不同真实声音被系统归为同一说话人的问题。用户先查看每个说话人的整体一致性，再查看组内各片段的偏离情况，必要时用甲乙参照进一步核对，最后手动选择误归并的片段并拆出；纠错需要影响后续推荐及学习，不能只改显示名。

本轮只改插件，不改或部署后端，不合 dev。插件新增“声音一致性”侧面板：

- 全天说话人图例及头像弹窗直接显示一致性指标，点击进入整体一致性 → 片段偏离列表；不要求先选择甲乙参照。
- 顶部显示 0–100 分、已分析／完整组片段数、待复核数量。部分覆盖标注“局部”；没有真实数值显示“待计算”，单段或质量不足显示“证据不足”，读取错误显示失败与重试。
- 下方逐段展示真实偏离距离，可按本页偏离较大优先或时间查看。当前不是全组异常排序，不会暗示第一页包含全日所有异常。
- 甲乙对比默认收起在“进一步核对”里。

- 从录音转写头像弹窗进入，也可从全天说话人编辑入口进入。
- 按稳定 speakerKey 展示已加载同组片段，或查看前后十分钟已加载片段。明确显示已加载数量，不能称作已扫描全天。
- 用户明确设置甲乙参照，各最多三段；默认不信任当前人物标签。同一片段不能同时作为甲乙参照。
- 真实录音试听；“交替试听”每点击一次切换到甲或乙的首个参照片段，不是自动播放队列。
- 每页最多 50 段，跨页选择最多 100 段。参照甲从待拆出选择中排除。参照自身不显示距离或参与判断。
- 接入下述拟定的只读证据接口。没有证据显示空值；404/501 或 supported:false 才视作未开放，网络错误显示重试。
- 展示距甲、距乙、两者绝对差，及有效语音时长、模型、计算方法和证据版本。阈值只控制前端高亮，不修改系统算法，不自动勾选。
- “拆出，身份待确认”复用现有 speaker-corrections 能力，第二步明确确认来源、排除人物和范围；只有接口支持才允许保存。
- “拆出并归到已有／新人物”当前只有前端预览，保存不可用。不能用逐条改名接口模拟原子拆分，也不能假称已经学习。

## 3. 插件已接入的拟定证据协议 v1

### 3.1 首屏核心：整体一致性与片段偏离

`POST /api/v1/audio/speaker-evidence/consistency`

只读查询，不自动修改归属、训练模型或启动全历史重算。全天图例按每批最多 100 组查询摘要，打开详情时请求 1 组及本页最多 50 段的偏离证据；遇到不支持停止后续批次。前端不读取原始声纹向量。

请求例：

```json
{
  "schema_version": 1,
  "date_stamp": 1791907200000,
  "groups": [
    {"client_index": 0, "session_id": "session-example", "child_id": "child-example", "item_index": 7, "transcript_source": "system", "start_at": 12000, "end_at": 18000}
  ],
  "items": [
    {"client_index": 0, "session_id": "session-example", "child_id": "child-example", "item_index": 8, "transcript_source": "system", "start_at": 18000, "end_at": 23000}
  ]
}
```

- groups 1–100 个精确片段锚点；items 0–50。items 非空时只允许查询一个组。
- **锚点只是定位完整组，不是计算一致性的唯一参照。** 服务端按当前录音日和该片段的稳定分组身份确定完整成员集合，与 one-day-trans 的 speakerIdentity / speakerKey 口径一致；不能只按显示名，也不能只取锚点所在文件。已人工统一到同一人物的多个子组应纳入对应人物当日组，仍保留原分组信息供排查。
- 必须核对账号、日期、精确区间、当前人物归属、源转写版本。若已被重新标记／拆分，返回冲突并要求刷新，不以旧组计算新结果。
- items 允许包含附近其他组片段，用于观察其对当前组的偏离；这些片段不能因此被纳入当前组总数或一致性计算。
- 指标必须基于后台完整成员集合，不能把当前页 50 段当成完整组。分页之间可复用相同证据快照。

响应例（纯合成数值）：

```json
{
  "supported": true,
  "schema_version": 1,
  "metric": "cosine_distance",
  "groups": [{
    "client_index": 0,
    "version": "group-snapshot-example",
    "model_version": "embedding-model-example",
    "score_definition": "cohesion-calibrated-v1",
    "reference_method": "robust-dominant-cluster-v1",
    "state": "partial",
    "score": 86,
    "analyzed_count": 800,
    "total_count": 927,
    "review_count": 32,
    "suspected_voices": 2,
    "items": [{"client_index": 0, "status": "ready", "deviation": 0.34}]
  }]
}
```

- 一致性分数表示“这一组声音内部是否一致”的概览，越高越一致，**不是人物身份正确率，也不是识别置信度**。完全一致的一组也可能被标成错误人物。
- score 只接受有限 0–100。ready 要求 analyzed_count = total_count 且至少 2 段；partial 要求至少 2 段、已分析少于总数，前端标“局部”。不足或准备中分别返回 insufficient / building，score 必须为 null。不能单段即 100 分。
- analyzed_count、total_count 是非负整数，已分析不得大于总数。review_count 为 null 或不大于已分析数的整数；null 表示未知，0 表示确实无待复核项。可选 suspected_voices 为正整数且不大于已分析数，仅提示可能存在多种声音。
- version、model_version、score_definition、reference_method 必填。前端详情展示，方便定位分数变化与模型口径。
- 每个 groups/client_index 和 items/client_index 恰好返回一次。行 status=ready 时 deviation 是有限余弦距离 0–2；insufficient 时必须为 null，可用 reason 解释。没有 items 时返回空数组。
- 偏离距离必须明确是相对哪个可信参照或稳健组原型计算；不能未经定义将“平均两两距离”等不同指标塞入同一字段。组本身多峰时，主簇代表不足的风险也必须反映在整体一致性中。
- 缺失数据不能换算为零距离或 100 分；前端不会用片段文本、昵称、已加载比例或甲乙对比分数推算整体一致性。
- 不支持：404/501 或 `{ "supported": false }`；超时、鉴权、格式错误必须按真实错误处理。

### 3.2 进一步核对：甲乙参照对比

`POST /api/v1/audio/speaker-evidence/compare`

只读、账号内对比。不得因读取证据自动改归属、收紧阈值、添加训练样本或开始重跑历史识别。若需要异步提取缺失向量，应另设计明确启动操作和成本策略；此接口可返回 building，不自动启动无限计算任务。

请求：

```json
{
  "schema_version": 1,
  "date_stamp": 1791907200000,
  "items": [
    {"client_index": 0, "session_id": "session-example", "child_id": "child-example", "item_index": 7, "transcript_source": "system", "start_at": 12000, "end_at": 18000}
  ],
  "reference_a": [
    {"session_id": "session-example", "child_id": "child-example", "item_index": 1, "transcript_source": "system", "start_at": 1000, "end_at": 6000}
  ],
  "reference_b": []
}
```

- items 为 1–50 段，reference_a 为 1–3 段，reference_b 为 0–3 段。
- 日期使用既有录音 date_stamp 口径；start_at/end_at 与现有 correctionLocator 的 child ASR 区间一致，不能自行解释为 Unix 绝对时间。
- 插件解封账号绑定 itemRef 后传递定位，服务端仍必须校验归属、日期、转写版本、精确音频区间和数据版本。client_index 只用于把结果映射回请求顺序，不是 ASR item_index。
- 不同模型版本、不同维度的向量不能直接比较。不要为一整组的每个片段复制同一个聚合距离；没有片段级向量就返回证据不足。
- 原始生物特征向量留在后端；插件不需要下载、存储或日志打印向量。

响应（现有 authenticatedAudioPost 的 data 内容）：

```json
{
  "supported": true,
  "schema_version": 1,
  "version": "evidence-snapshot-example",
  "model_version": "embedding-model-example",
  "metric": "cosine_distance",
  "aggregation": "mean_reference",
  "state": "ready",
  "items": [
    {"client_index": 0, "status": "ready", "distance_a": 0.18, "distance_b": null, "effective_speech_ms": 4100}
  ]
}
```

- metric 当前仅接受 cosine_distance，合法有限数值范围 0–2，越小越近，绝非正确率。
- aggregation 接受 nearest_reference / mean_reference / centroid，必须准确说明实际方法。不要用最近一个样本距离冒充 Top-K 平均决策分数。
- 可选 review_threshold（0–2）、ambiguity_margin（0–2）。若提供，必须有真实模型／策略依据，不能默认全链路都是 0.30。前端审查线仅本次视图生效。
- state 为 ready / building。每次都返回 items 中所有 client_index，恰好一次；building 时没有完成的行也明确返回 insufficient 和 null，不能靠漏行暗示“无问题”。
- 行 status 为 ready / insufficient。ready 必须有 distance_a；请求包含乙参照时必须有 distance_b；没有乙参照必须为 null。insufficient 的两个距离均为 null。
- effective_speech_ms 是真实有效语音时长，不能用整段文件时长替代；reason 可解释语音过短、重叠、噪声、向量缺失、模型不兼容。
- 不支持返回 `{ "supported": false }`；断网、鉴权错误、格式错误不能伪装成不支持。
- 当前比较只针对用户选定的参照，不代表完整候选库中的“第一／第二候选”。正式识别候选证据应另提供决策快照，前端再增加对应展示，不能混淆两个概念。

## 4. 需要后端完成的核心能力

### P0：整体一致性是第一层，不延后为可选项

1. 基于完整分组提供经过版本化定义和校准的整体一致性。这里先给出工程约束，不随意指定未经验证的加权公式或把距离线性映射成“准确率”。
2. 统计组内距离分布、离群比例、可信子簇之间的分离情况及各簇有效语音占比；“两个人各占一半”的组即使到污染中心距离都接近，也不应被判为高度一致。使用稳健参照与多簇检测，避免只检查所有向量平均中心。
3. 短语音、噪声、重叠、跨模型不兼容等证据先标不足。质量和有效时长可以用于校准权重，但不得把“未分析”算成一致。保留成员数、覆盖时长和模型版本供审计，必要时扩展响应字段。
4. 同一人远近距离、设备和房间变化可能形成声学子簇；分数只作为复核线索，不能自动当成多个真人拆分。用人工确认的同人／异人案例评估误报和漏报后再发布分数口径。
5. 缓存按账号、日期、完整组版本、模型／算法版本区分，人工标记或拆分后失效重算；不同模型分数未经校准不可直接横比。给前端稳定成员分页及服务端偏离排序后，才能支持“全组最可疑优先”。

### P0：精确区间证据和可靠拆分

1. 保存或按需提取精确 speech span 的 embedding、模型版本、音频来源及有效时长。混入多人的单条转写需要可进一步划分区间，而非只能整行改名。
2. 将上述 compare 接口与真实模型输出对齐。保留“识别当时的判定依据”与“当前重算对比”两份语义，不能用今天模型冒充历史决策。
3. 实现先前 speaker-corrections/context、apply、undo 协议：仅所选区间、版本冲突检查、幂等、明确结果和撤销。不能扩大为 session/num 或当天所有相同名字。
4. 拆出时取消所选片段对错误人物样本库的贡献，清理受污染聚合向量；保留可审计关联以供撤销。不能只把 Q 或昵称清空。
5. 人工“甲与乙不是同一人”作为有来源、有范围的负证据。默认限制到明确片段和相关人物，不因一次纠错全局降低阈值。
6. 如果用户只确定“不是周鹏”，拆出后保持未知；多个被拆出的片段不能自动全部合成同一个新 B。声音来源 playback 与人物身份分别维护。

### P1：完整审查与原子归属

1. 提供同组完整成员的稳定分页快照及证据覆盖率。当前前端只显示已加载内容，不应靠下载整天转写来长期代替专门接口。
2. 以用户确认的甲／乙多个参照检索相近片段，返回候选及理由，不自动修改。跨天扩展必须单独明确范围。
3. 提供 split preview / commit：已有人物、新人物、保持未知；预览绑定区间集合、目标、数据版本、证据版本和过期时间。commit 原子写入拆分＋归属＋样本撤回／新增＋负证据＋审计。不要客户端串行多个 assign 调用。
4. 提供操作状态查询和撤销：超时后先查同一幂等操作，不重建请求盲目重发。撤销不能覆盖其他设备后续改动。
5. 后续识别使用受控、可撤回的人工参照。明确的错误样本先隔离，人物特定阈值、候选间隔及负证据的组合应有离线误合并／误拆分评估；低质量、极短、多人重叠音频允许“无法判断”。

## 5. 验收场景

- 不选任何参照也能看到整体一致性、完整覆盖数和各片段偏离；甲乙对比不阻挡第一层审查。
- 两种声音各占近半的混合组、少量外来声音、同人换麦、只分析小部分等情况均有可解释的分数／覆盖差异；不凭空给固定分数。
- 真人周鹏与手机视频同组：必要时选可信甲、可信乙，能够找到不同声音；视频中多个声音不被强行合为一个人。
- 只选两段：提交后其余分组、原文、音频和时间位置保持不变。刷新及另一端能读到相同拆分结果。
- 参考甲是可信样本：不得对自己产生高置信度自证或被自动加入拆出集合。
- 没有乙人物档案时仍可先比较乙片段；没有第二候选不代表第一名可靠。
- 多段选择跨前端分页、超过十分钟：只发送实际选择，不能隐含包含最初打开面板的片段。
- 新甲乙参照、页码、账号或数据版本变化：旧证据不可继续展示为当前结果。
- 短语音、重叠、旧模型向量缺失：明确证据不足，不显示 0 距离或 100% 一致。
- 保存断网、超时、部分成功、撤销冲突：不假报成功，不重复提交，不误覆盖其他设备更新。
- 更新后新录音不再把明确排除的声音自动学回原人物；可追溯学习状态与受影响样本。
