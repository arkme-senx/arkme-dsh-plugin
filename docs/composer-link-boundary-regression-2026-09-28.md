# 输入框链接与后续正文边界修复

## 根因与范围

共用 Markdown 编辑器开启自动链接后，底层 Link mark 为 inclusive。粘贴链接后在末尾输入空格会继续继承链接格式，导致后续说明被序列化进同一个链接标题。即我分享链接在消息区会显示统一标题，因此还可能遮蔽被误包含的说明。

本次在共用 Markdown 扩展中处理链接右边界新增的空白字符，仅移除新增空白及后续文本继承的 link mark，保留正文、其他格式与同一撤销事件。不修改链接中间的编辑、显式粘贴的带空格链接标题、恢复的草稿或已发送的历史消息。不需要后端接口变更。

## 验证

- 修复前：新增的 13 个边界测试中 10 个失败，复现 URL、多个空格及中文说明被存进同一个链接标题。
- 修复后：链接边界测试扩展为 16 项并通过；涵盖普通/连续/全角/不换行空格、制表符、原生/IME 文本事务、纯文本粘贴、自定义链接标题、编辑链接内部、其他格式、换行、第二个 URL、撤销/重做。
- Markdown 输入框、正文渲染、标签、粘贴/聚焦与长文链接等 8 个文件共 170 项通过。
- 消息发送与边界回归共 365 项通过，其中 16 项与上组重复；合计 9 个文件、519 项不同测试通过。
- 类型检查、完整构建、最终重新打包与差异空白检查通过。
- 独立 Web 3100 已更新。实页只读检查确认锚点文本仅包含 URL，空格及后续中文位于链接之外；用户正在输入，未代替用户发送消息。
- 未改动已安装桌面客户端，未提交或推送代码。

## 已有草稿

修复作用于新输入的链接边界，不自动重写旧草稿中已经包含的链接标题，也不批量修改云端历史。重贴链接后再输入空格即可按新规则输入普通正文。
