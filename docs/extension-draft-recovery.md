# 延展草稿父消息恢复

聊天输入区的延展父消息与正文属于同一份账号、会话草稿。会话引用轮换、切换后返回、组件重建或页面刷新时，两者一起恢复；取消延展只移除父消息，提交时一起消费，失败时仅在没有更新草稿的情况下恢复原父消息。发送仍由既有 `source.message-extension.extend` 校验权限和父消息有效性。

| 能力面 | 范围与验证 |
| --- | --- |
| UI | 父消息预览、引用轮换、重建、刷新、取消、失败恢复与双窗口同步 |
| Tools | N/A：未增加 Host 业务能力；模型不消费用户尚未提交的输入框草稿 |
| SDK | N/A：未增加 Host 接口；外部插件不读取内置输入框的未提交草稿 |
| Host owner | 不变；继续通过现有延展接口授权和发送，不自动重发 |
| Client/Harness | 沿用已有草稿快照同步与 Browser module 装配；不改变原生桥、Profile 或运行环境发布 |

## 状态与兼容边界

- 只保存有界预览和既有不透明操作引用：正文预览 2,000 字符、标题 500 字符、最多 3 个媒体预览。不保存整个时间线对象或媒体字节。
- 操作引用包含 Host 签名的原文，长度与短预览不同。恢复时允许最大 1 MiB 引用，覆盖 Host `maxTextLength` 可配置到 100,000 字符的场景；损坏的父引用不会被悄悄转换成普通发送。
- 只有用户在当前窗口明确选择父消息时，才初始化群聊默认 @。刷新、回到会话和收到其他窗口草稿时保留用户已经删除或改写的 @，避免窗口间重复改写。
- 仅有父消息、尚无正文的草稿也会同步。取消、消费及账号清理通过同一个草稿 owner 广播，保留原有 40 ms 合并窗口。
- 重试身份使用稳定会话草稿键和父消息标识，避免会话引用轮换使同一草稿重新生成记录、关系编号。
- 沿用已有浏览器持久化、账号清理和存储失败退化，不新增请求、轮询或订阅。兼容最新发送时长采集：采集仍先于草稿消费，失败时保留原来的恢复顺序。
