# Harness 会话下拉入口

已确认的交互：Arkme 登录状态下，把 DSH 常驻会话侧栏收进对话标题下拉菜单。标题使用圆角描边按钮，文字与箭头之间有分隔线；菜单直接显示原有会话和工作区，底部同一行显示新会话、视图选项和添加工作区。菜单内不再显示重复的搜索入口，搜索仍可从 Arkme 第二栏使用。空白会话也有入口，点击会话、外部区域或 Escape 收起菜单。未登录和独立 Harness 页面继续使用官方侧栏。

## 官方升级边界

`harness-session-dropdown.ts` 是可撤销的展示适配层。官方 SidebarRoot、WorkspaceBrowser、会话树、右键/更多菜单、工作区目录选择器和所有数据操作继续由当前宿主提供。没有复制官方组件源码，没有重挂载会话内容，没有新增会话数据缓存，也没有移动 React 所拥有的 DOM 节点。

目前官方没有替换标题和把侧栏列宽设为零的公共插槽。因此用已有的 `data-slot`、语义按钮和三列布局结构识别适配位置，仅添加自己的标题按钮和 CSS 标记。菜单是原侧栏的浮层展示，原“新会话”按钮通过 CSS 排序放到底部。原生侧栏折叠时，首次展开菜单通过原按钮请求展开；没有直接改布局存储。

第一列归零；右侧详情列的宽度从官方当前布局读取并跟随变化，其他官方组件和样式继续使用升级后的版本。若升级改变了已识别的侧栏或布局结构，适配自动撤销，恢复官方侧栏，避免失去导航。未知结构需要重新适配；不能保证任意未来版本的私有 DOM 结构都兼容。

模块卸载或账号退出会移除按钮、样式及标记，并恢复原侧栏折叠状态（仅当适配层主动展开过它时）。插件的登录态设置入口规则继续单独使用官方 `sidebar.settings` 插槽。

工具栏紧凑布局仅在识别到官方搜索、视图选项、目录选择插槽及已知操作集合时启用；出现未知操作时保留原工具栏。隐藏的是标题与搜索区域，整个工具栏容器使用 `display: contents`，目录选择插槽继续挂载。视图选项和添加工作区仅通过 CSS 定位到底部，原按钮及其回调、原生菜单和目录选择流程都不变。撤销适配时恢复全部区域。

底部操作行上方不额外绘制分隔线，以现有留白区分会话列表和操作区；新会话按钮自身的边框和三个操作的布局保持不变。

## 第二栏卡片悬停入口

登录后，鼠标在第二栏 DSH 卡片停留 200ms，原生会话菜单出现在卡片右侧；离开卡片和菜单 300ms 后收起，经过两者间隙时允许移入菜单继续操作。原卡片点击入口保留，键盘聚焦卡片后可用向右键进入菜单，Escape 返回卡片。标题下拉与悬停入口共享同一菜单，互斥展开。

`harness-session-hover.ts` 通过同源文档事件请求 `harness-session-dropdown.ts` 改变浮层位置，没有复制列表、重挂载 iframe 或转移 React 节点。私聊、群聊继续显示；仅在菜单及其原生子菜单区域展示和接收 iframe 输入，其他区域仍可操作原聊天。退出浮层时移除临时样式和监听器。点击会话或新会话时，先执行原生操作，再激活 Arkme 的 DSH 页面。

悬停不改变 `data-arkme-visible` / `data-arkme-follow-session`，不会把当前 DSH 会话标为已查看；账号范围不匹配、原生布局未识别、页面切换或 iframe 重载时撤销浮层。触屏不触发悬停，继续使用点击卡片和标题下拉入口。底部原有操作及排序偏好继续归官方管理。

验证：6 个相关测试文件、65 项检查通过，类型检查和完整打包通过。真实页面覆盖 DSH、私聊、群聊的会话选择，悬停保持原聊天与未读状态、跨菜单间隙、二级菜单外部关闭、创建空白会话、标题入口互斥、键盘向右键/Escape 和窄窗口边界；页面无 JavaScript 错误。证据保存在独立 profile 的 `session-hover-verification.json` 与 `session-hover-*.png`。

第二栏所有会话卡片统一使用悬停底色：普通卡片显示主题的浅色悬停背景，选中卡片在原底色上轻微加深；DSH 菜单展开期间通过 `aria-expanded` 保持来源卡片高亮。规则仅覆盖 Arkme 会话树，包含插件贡献入口和虚拟列表中的私聊/群聊/Bot，不影响原生 DSH 菜单或联系人目录。浅深色主题均适配，底色过渡为 120ms，系统减少动态效果时关闭过渡；禁用卡片不增加可点击提示。

第二栏卡片不再设置浏览器原生 `title` 提示，避免“打开：会话名”等文字浮框遮挡菜单。卡片名称、摘要、状态角标、读屏标签、高亮、点击与悬停菜单均保留。

浏览器本地只新增一个“已应用默认分组”的标记，不保存第二份视图偏好。之后分组与排序由官方继续保存，刷新或重新挂载不会强制改回单列表；其记忆范围与官方一致，即当前浏览器和站点。官方改变存储键或增加其他字段时无需复制或覆盖。共享存储仅在两端插槽都为 root、且原官方分组动作存在时启用。

## 标题下方的模式与对话次数

后续确认的布局：标题独占第一行，模式标签与“n 次对话”并列在第二行。标题取消 360px 固定上限，使用右侧官方操作按钮以外的可用宽度，超长时省略并通过原生 title 提示显示全文。

模式标签仍由官方 `agent-preset` 贡献提供，没有复制名称、图标或交互。只识别原生标题行、标题容器和 `conversation.session.header.actions` 的关系，通过 CSS 纵向排列；原节点及 React 归属不变，卸载、退出账号或未知布局时撤销标记。

次数作为独立条目注册到公开的 `conversation.session.header.actions` 会话级列表插槽，使用框架 `useProjection('sessionStats')` 读取官方整段会话的 `turns`。不统计当前屏幕消息，不复制官方计算逻辑、不缓存第二份次数；分页、折叠、历史压缩及实时推送继续由官方负责。失败、取消及轮次何时增长也沿用宿主统计口径，与官方底部“n 轮”保持一致。数据缺失或格式不兼容时不显示次数，不用 0 代替未知值。文案通过官方 locale 接口提供中英文。

验证：8 个相关文件、59 项检查通过，包含次数更新、工具步骤不重复计数、会话数据切换、缺失值、卸载清理以及原生节点身份保留。类型检查和完整打包通过。真实页面对比顶部次数与官方底部轮次，验证宽/窄窗口、超长标题、会话切换、新会话和轨迹往返。当前两行标题区高度 77px；第二行是实际信息，并非原 tab 留白。测试用长标题仅在浏览器临时 DOM 中模拟，没有修改服务端会话标题。
