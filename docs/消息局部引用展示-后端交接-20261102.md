# 消息局部引用展示：前端进展与后端对接

日期：2026-11-02。接收：华焱（群内 mention 名 Lucis）。范围：私聊、群聊，复用既有延展关系。

## 用户要求与本地效果

- 原消息中被局部引用的文字常驻细下划线，右下角显示评论角标与数量。
- 点击角标，打开原消息详情并定位下方评论；详情正文同样显示下划线。
- 每条局部引用回复在评论正文上方显示当时引用的文字块；引文作为普通文字展示，不触发 mention。
- 不新增评论树，不通过公开分享链接读取私聊或群聊内容。

插件本地前端已实现上述展示链路，并使用既有群聊记录进行只读验证。代码未发布。

## 已确认的前端问题，已修复

`src/services/chat-service.ts` 的 `chatExtensionTreeItemFromData` 原来没有保留延展树边上的 `quote_reply / quote_reply_state`，导致回复卡片能显示引文，详情评论却没有引文。

2026-11-02 实际接口验证：`/api/v1/chats/extensions/tree/page` 对目标回复已返回可用引文、状态以及子消息 relation/sequence。插件现已保留并消费这些字段。**这部分不需要后端重新实现。**

插件同时补上原文反向关联、常驻下划线、评论角标、详情评论引文，以及相关快记晚到后的滚动定位修正。选区只在正文散列及 UTF-16 锚点精确匹配时标记；不使用全文搜索猜测重复句子的第一次出现位置。

## 需要后端确认或补齐：原文的引用汇总

目前插件已消费的聊天时间线合同只携带“本消息引用了谁”的 `extension_edge`，没有“本消息被哪些回复引用”的可用汇总。当前本地版通过已加载的时间线回复和已打开详情的延展树反向建立关联。因此，仅加载原文、引用回复还在未加载历史页时，原文不能保证立即出现完整角标和全部下划线。

请先确认线上是否已有对应字段或批量查询接口；如已有，请提供真实路由、字段、权限约束和脱敏响应，前端直接对接，不再新增重复接口。未找到可用合同前，本地效果不能宣称历史覆盖完整。

如需新增，建议在时间线/around/单条结果中附带轻量汇总，或提供一个按原文身份批量读取的接口，避免前端对每个消息逐条拉取完整延展树。

建议返回语义（字段名是待确认提案，并非已经存在的接口）：

| 字段 | 含义 |
| --- | --- |
| 原文身份 | 当前会话、原文 record owner + record UID + relation UID + sequence，区分同一记录的不同发送位置 |
| comment_count | 当前用户有权看到的评论数量；明确是否包括嵌套延展 |
| quote_count | 包含有效局部引用的评论数量，和普通整条回复区分 |
| 引用项 | 稳定 edge ID、回复 owner/record/relation/sequence、原文出现位置、`quote_reply`、`quote_reply_state` |
| 完整性 | `has_more`、不透明 cursor 或明确 complete 状态，不能将首屏样本当作全部 |
| 版本 | 汇总 revision 或可用于失效的事件版本 |

沿用已有 `arkme-text-v1`：原文散列、规范展示文字的 UTF-16 左闭右开偏移、前后文和不可变引文快照。不要只返回一个字符串，让客户端在当前正文里模糊搜索。

## 状态与刷新

- 新增、编辑、删除回复，以及原文编辑、撤回、权限变化，都应能使该原文汇总失效或返回新版本。
- `edited` 保留当时引文，客户端不把旧锚点套到新正文；`unavailable` 不返回旧引文正文。
- 跨设备与重新进入会话应一致，不依赖当前客户端是否滚动加载过回复消息。
- 按当前查看者权限计算内容和数量；不能跨会话、跨账号或通过转发出现位置串联引文。

现有延展树已含分页信号。22:27 首次交接时，插件详情只读取首批 100 条，这是前端消费缺口。随后本地前端已补齐：首批立即显示，后续页后台追加；保留引用元数据、按消息身份去重、失败处重试、取消旧请求；Host 对游标绑定账号、会话和原消息。默认完整上下文读取也会继续翻页。125 条评论、重叠页、异常游标和取消流程已通过自动测试，未对生产群新增测试消息。此进展不改变原文引用汇总仍需对接的结论。对接汇总时仍需明确总数、直接子项和嵌套项的口径，以及并发变更时的快照一致性。

## 联调验收

1. 原文在当前页、回复在未加载的历史页：不滚动历史也能拿到完整数量和引用锚点。
2. 同一句话出现两次：只标记被选中的那次；Markdown、换行、emoji 的位置保持一致。
3. 同一记录被多次发送或转发：按会话和发送出现位置隔离，不错挂评论。
4. 原文编辑后不误画下划线；撤回/撤权后原文、评论、引用预览和缓存都不复活旧引文。
5. 超过 100 条评论、嵌套评论、分页过程中新增或删除回复：稳定去重，数量和完整性明确。
6. 请提供已部署环境、可用合同和脱敏响应；完成以上场景后再标记历史覆盖完整。
