# 世界作者会员标识后端交接

世界动态、右侧详情和评论需要在作者名称右侧显示现有 VIP 或 SVIP 星形标识，悬浮说明具体等级。插件已完成展示及数据接线，当前账号可复用现有会员接口。他人等级需要公开用户资料补充 `member_type`，否则客户端保持未知，不显示会员图标。

## 现有接口与缺口

已核对 `jotmo-backend origin/master` 提交 `ba46e6f`（2026 年 10 月 23 日）：`gin/api/auth_contact.go` 的 `publicUserIdentityItem` 包含 user_id、jotmo_id、nick_name、head_img、identity_ready，尚未声明 member_type。`/api/v1/auth/get-public-users-by-ids` 和公开身份 query 共用该投影。

私聊的 private_counterpart、团队通道的 visitor 已有独立会员投影，不能据此认为上述公开资料接口也有该字段。客户端不能调用 `/internal/.../premium/batch-member-type`；内部接口继续仅供后端服务使用。

## 最小对接方案

沿用认证 POST `/api/v1/auth/get-public-users-by-ids`，在每个 items 元素增加可选 `member_type`：

```json
{
  "code": 200,
  "data": {
    "items": [
      {"user_id": 123, "nick_name": "示例用户", "member_type": 1}
    ]
  }
}
```

- 0 为普通用户，1 为 VIP，2 为 SVIP。0 必须明确返回，不能因 omitempty 丢失。
- 字段缺失或 null 表示无法确认，不能当成 0；会员依赖读取失败时保留公开名称、头像等资料，不让整批资料失败。
- 等级使用会员服务计算的当前有效权益，统一考虑有效期及已有赠送、付费权益规则。不得复用动态发布时的历史等级或客户端昵称、图标推断。
- 去重后的 user_ids 维持现有最多 50 个限制，后端通过已有会员批量能力补齐，避免逐人 RPC。
- 只新增等级字段，不返回订单、金额、支付信息或其他私人账户资料。不得改变当前资料读取权限。

若采用独立接口而非本方案，请回传正式路径、认证、批量上限、缺失项语义和部署环境；当前预接代码读取的是上述公开用户资料字段。

## 插件已完成的接线

- `ArkmeWorldFeedItem`、`ArkmeWorldInteractionItem`、`ArkmeWorldAuthorLabel` 增加归一化 memberType，值为 free、vip、svip 或 unknown。
- 沿用 `world.author-labels` Host 操作。浏览器只传已展示内容的不透明引用，Host 校验环境、当前账号和引用后取得作者 ID；外部调用方不能任意提交一批用户 ID。
- 正文先展示，作者资料随后按最多 20 个引用分批加载。相同用户请求去重并合并进行中的批次，按账号缓存有效等级 60 秒、未知状态 5 秒；没有新增定时轮询。
- 当前账号通过已有 `/api/v1/premium/get/member` 读取真实权益。他人通过 `/api/v1/auth/get-public-users-by-ids` 读取 member_type；后端补齐该字段后即可展示，不需要重新安排前端入口。
- 资料读取进入交互读取队列，不占用消息写入队列。会员依赖最长等待 4 秒，失败后保持未知；切换账号后丢弃旧响应。
- 复用私聊的 ArkmeMembershipBadge 和悬浮提示。动态、详情、评论及精选评论统一展示；普通和未知用户没有占位图标。备注名称继续优先。

## 联调验收

1. 普通、VIP、SVIP 和状态未知四类作者，在动态、详情、根评论、回复及精选评论处呈现一致；自己发布的内容也显示真实等级。
2. 鼠标悬浮或键盘聚焦星形标识，明确显示 VIP 会员或 SVIP 会员。
3. 同一作者重复出现只按批次读取。会员服务慢或失败时，正文及公开资料仍可正常展示；缺失等级不能误显示免费或付费。
4. VIP 升级、降级和到期后，重新进入或手动刷新在缓存有效期结束后取得新状态；客户端不依赖后台轮询。
5. 切换账号、退出后旧请求不能把上个账号的状态带回来。备注名称、评论草稿、文字选择、图片预览和详情开关保持原行为。
6. 后端完成后请回传已部署环境与版本，以及含 0、1、2 和未知值的真实接口示例。前端模拟验收不能代替线上会员字段联调。
