# 搜索快速查找：位置

入口为全局搜索 → 快速查找 → 位置。桌面采用百度地图与相关记录并排布局，窄窗口上下排列。四类来源默认开启：快记的位置、我发送的位置、发给我的位置、群聊中的位置。

## 接口与边界

复用 Flutter 的现有只读接口，无新增云端接口或数据库迁移：

- `POST /api/v1/records/location/query`：历史位置记录，游标分页。
- `POST /api/v1/records/location/viewport-clusters/query`：当前视野的聚合点。
- `POST /api/v1/records/location/clusters/records/query`：指定聚合点关联的记录。
- 自己的精简记录投影通过已有 `records/detail` 补齐正文；通过 `records/location/context/get` 补齐相同坐标对应的地址。每页 20 条，最多 4 路读取。

收到的位置保留聊天投影和原始记录归属，不通过个人接口读取发送者的私有设备位置。已锁定、无权限、删除的记录不补齐。坐标统一采用 WGS84 查询，显示前转换为百度坐标；视野反向转换与 Flutter 使用的坐标算法一致。

点击聚合点时保留该点对应的查询视野，后续分页不会误用移动地图后的新网格。快速切换地点会取消上一次读取。来源筛选不重新挂载地图，分页失败保留当前结果。

初次查询的全球范围可能返回空聚合，但区域查询仍有数据；此时按最近的可读位置初始化区域，之后随拖动、缩放读取历史位置。不会请求浏览器的实时定位权限。位置列表支持继续翻页，不把首批记录作为全部历史。

关闭搜索后仅在内存中保留同一账号的地图范围和来源选择，不落盘保存位置记录。原记录沿用已有聊天导航或个人快记详情入口。

## 百度配置

复用 `baiduMapBrowserAk`。仓库 `cordis.patch.yml` 已在 `9ff81a21`（PR #779）配置浏览器端 AK。独立 Web 预览使用自己的 patch，需要同步这项配置；浏览器来源仍应符合公司百度控制台的域名授权。不得拿移动端 AK 或服务端 SK 替换。

若缺少配置或地图加载失败，显示明确提示，记录列表仍可阅读。测试环境的 patch、登录引导 URL 和本地状态不提交到仓库。

## 验证范围

覆盖查询参数校验、记录隐私过滤、归属 ID 保留、地址坐标匹配、过期响应取消、聚合分页视野、来源切换、分页失败保留结果、全球空聚合后的区域初始化，以及坐标转换。

真实账号的百度底图、地点标记、地点名称及记录正文在独立 3101 Web 环境验证。该预览借用客户端既有登录态，不修改客户端安装文件或客户端状态。
