# 私聊拒收能力

Chat 服务持有方向性拒收事实，并在新消息建立接收方可见关系前最终校验。插件只通过账号绑定的 sourceRef 访问它，不复用员工封禁、群成员限制或通知静音。读取历史、重新编辑、撤回与删除不受拒收影响。

## 能力矩阵与验收状态

| 能力面 | 入口与合同 | 验收证据 |
| --- | --- | --- |
| Tools | 查询及设置自己的拒收；business/hybrid，写操作要求 explicit-user-write 和目标/版本确认；沿用正式注册/grant 链 | 官方 ToolRuntime 注册、可见性、grant、确认和执行测试通过；已登录的真实 DSH 会话调用仍待验收 |
| SDK | 公开类型、能力探测、账号绑定 sourceRef、AbortSignal；不持久化状态 | 独立 tgz Consumer 可编译，查询/设置/不支持版本处理通过；请求使用模拟 Host 响应，不代表上游联调 |
| UI | 私聊设置入口；查询/变更中禁发，拒收时禁用新消息编辑，保留草稿；失败与刷新可见 | React 交互、extension 输入与终态附件测试通过；隔离官方 DSH 已验证插件页面激活与测试环境登录入口，双账号真实私聊仍待验收 |
| Host owner | 独立 DirectMessageAdmissionService；三个适配器共用；新消息 Gateway 解释业务响应 | owner/适配器一致性、账号隔离、终态错误与安全投影测试通过 |

## 边界与恢复

- 不新增全局业务错误码。上游通用权限失败仍为 1004；业务 Handler 验证响应体后只输出无内部 ID 的准入投影，且不可重试。2002 仅表示拒收设置的版本冲突，需刷新后由用户重新决定。
- 仅 Chat 明确的真人 Direct 适用，不从 private_chat 展示分类推断 PendingPrivate 或 Bot 会话的准入。
- 现有 projection.invalidated.v1 只负责失效通知。浏览器重查当前账号当前会话；断线重连/恢复焦点也重新查询，不共享跨账号状态，不以事件内容当作业务事实。
- DSH 只使用公开 dsh-tools 与 Host Web Server 扩展点；不修改 DSH，不影响常驻实例。验收须区分单测、构建、tgz 安装和真实环境行为。
- 后端先发布；Subject 旧直写客户端按产品决定排除，不新增其维护逻辑。拒收采用最终一致性，允许操作时在途消息的并发窗口，不以分布式锁串行化正常发送。
- Chat 的 `direct_message_refusal_creation_enabled` 默认关闭。投影的 `refusalCreationEnabled=false` 只禁用新增拒收入口，不关闭正常消息发送，不阻止解除既有拒收，也不绕过已有 active 事实。
- 新准入契约要求完整的布尔权限字段；缺失字段不推断为已开放。设置请求防止同一帧重复提交；失败后重新查询权威状态，恢复响应丢失或请求期间收到失效通知的情况，不自动重放设置或发送。
- 终态发送失败不自动重试、不允许附件手动重试，也不会在解除拒收或重启后自动复活。重新编辑已有记录与 World 公开复制链接延展不属于私聊新消息，不混用该限制。
- 多目标转发独立校验每个收件人；选中后某个收件人拒收，不中止其他正常目标，沿用原有部分成功反馈。

## 本地验证

本次完整 `pnpm typecheck`、`pnpm test`、`pnpm build` 的执行结果记录在跨仓任务验收文档；新增批量转发部分拒收回归。打包保持仓库版本不变，使用官方 DSH 0.1.0-rc.8、全新隔离 Profile 和独立凭据命名空间验收；未修改 DSH 或替换常驻实例。Chat 侧真实 Mongo/Redis/RabbitMQ/IM 的本地 E2E 覆盖本人两个设备与对方设备的 SSE 失效通知、回查及幂等无通知。

此状态不等于发布放行：仍缺已授权双测试账号的真实 DSH Tool/私聊 UI 场景，以及 Windows/Linux 实际目标环境验收。不能据 macOS 本机测试宣称所有平台和历史客户端均已覆盖。
