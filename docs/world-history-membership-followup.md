# 世界表态历史、通知与会员标识补齐

基于 MR1 合并后的 dev（61767c83）。保持现有数据管理、时间轴、通知会话及世界卡片布局。

- 表态操作记录分别读取聊天 `reactions` 和 `world.reactions`，浏览器按时间归并；两路各自保留游标和至多 100 条待合并记录。世界事件 ID 带来源命名空间；失败明确显示，不回退为聊天完整结果。撤权记录只展示动作事实，不补查原文或媒体。
- 世界表态通知进入现有表态分类，使用独立 ID、版本及 `notifications-read`。点击走公开世界 thread 的当前权限校验，不进入聊天定位。已读期间到达的旧响应不会恢复同版本未读，也不会丢弃新版本。
- World 通知提供可选 `recordRef`（公开导航），与版本绑定的 `target.worldRecordRef`（表态命令）用途严格分开。Host 统一生成签名引用，Tools/SDK 原样获得同一投影，不新增路由或存储。
- 会员沿用现有 VIP/SVIP 星标。补齐通知打开动态后的等级读取；详情独立读取当前等级，不被旧列表等级覆盖，同时保留列表异步更新。普通/未知不显示星标，团队身份不读取个人会员。切换、关闭及刷新取消旧请求，不新增轮询。

| 消费面 | 本次范围与验证 |
| --- | --- |
| UI | 原有列表、通知和详情接线；分页、失败、撤权信息最小化、已读并发、账号切换和会员回归 |
| Host | 现有 World 通知 owner 增补签名导航字段；不扩大原文/媒体权限 |
| Tools | 现有 world reactions read/write；补充导航字段语义，使用已授权的同一 owner |
| SDK | 既有 worldReactions 泛型结果公开字段，无新增消费者入口 |
| Client/Harness | 无源码或协议变更；独立不可变包安装验证，不替换常驻客户端 |

通知仍沿用基线数组界面，读取上限为 100 页 × 50 条，超限明确报不完整；分页界面留待第二期。本 PR 不包含团队主页/共同反馈等第二期 UI、后端 Bot 错误分类修复、部署或生产写入。
