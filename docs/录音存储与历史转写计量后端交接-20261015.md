# 录音云端存储与历史转写输入时长：后端交接

日期：2026-10-15。状态：插件前端口径修正，后端只读排查；未修改、推送或部署后端，未执行生产回填或重新转写。

## 需要解决的两个问题

1. 用户需要当前账号上传的录音经处理后实际占用的 OSS 存储量，包含所有说话人的音频。不能按 `belong_usr`（记忆归属）或说话人身份过滤；上传账号为 `session.user_id`。日期按录音发生日，不按补传日期。每日和所有录音累计应使用同一上传账号范围。
2. 部分历史日期已完成转写，但系统 ASR 输入时长全部缺失。需要明确历史数据能否恢复；有证据的回填真实值，不能恢复的保持缺失，能够重建的估算必须说明依据及覆盖边界。

## 只读核验方法

接口：`POST https://audio.jotmo.cc/api/v1/audio/one-day-trans`，业务成功码 200。

选择一个历史完成日期和一个新完成日期，按当前用户授权读取：

- 校验 session 上传账号、child 完成状态和跨午夜情况。
- 对唯一 child 累加 `archive_size` 和 `size`，分别核对主档与播放切片。
- `source_size` 不证明原件此刻仍存在，禁止直接加入当前存储。
- 检查每个 child 的 `asr_input_metrics`。历史完成数据可能返回如下缺失状态，而新数据具备 `ready` 计量：

```json
{"state":"unavailable","duration_ms":null,"spans":null}
```

具体账号、录音日期、数量和个人统计快照只保留在本地交接明细，不随源码公开提交。个案不能作为全库回填数据。

## 源码证据与边界

已只读 fetch 后核对：`jotmo-audio origin/master 205e272`；`jotmo-audio-asr origin/master 447f1ff`。没有切换或修改同事工作区。

- 插件旧 `src/recording-daily-metrics.ts` 只加 `archive_size`，按 `belong_usr` 过滤。界面原先叫“人声存储”，不是 OSS 所有存储产物总量。
- audio `gin/api/audio.go` 的 `one-day-trans` 返回 `user_id`、`archive_size`、`size`、`source_size` 和 `asr_input_metrics`。
- ASR `asr/deal_asr_task.go`：`splitClips` 以文件实际大小累计 `TotalSize`，并单独生成、上传 VAD 人声主档，回传 `ArchiveSize`。audio 将两者分别写入 child 的 `Size`、`ArchiveSize`。
- audio `gin/compound/recording_entitlement.go:recordingRetainedBytes` 会对仍存在的输入对象取真实对象大小，再加 `Size + ArchiveSize`。它提供可复用的服务端方向，但需要核实适用管线、历史覆盖、删除状态，不能直接假设现有日接口已返回了这些事实。
- audio `gin/compound/pipeline.go` 存在处理完成后删除原件，以及旁路处理期间保留原件的分支。因此 `source_size` 是历史上传事实，不能作为当前仍存储的证据。
- audio `internal/audio/asr_input.go:ProjectAsrInputMetricsAt` 只读取已保存的执行回执；无有效执行回执时返回 unavailable，不从文本、VAD 或完整音频时长倒推。该能力合入记录为 `ebf4ba9`，2026-10-09（这是代码合入时间，不冒称生产部署时间）。

## 插件已完成的部分

- 新增独立 `storage` 投影，按上传账号统计 `archive_size + size`，child ID 去重，不依赖说话人和记忆归属标记。
- 显示“云端录音存储 …（已记录）”；部分数据标“部分已记录”。悬浮显示主档和播放切片明细，并说明仍需云端核对原件留存和对象清理。
- 不将原 `archiveBytes` 字段悄悄改成另一种含义；旧主档字段保留兼容，新界面只读取新 `storage` 字段。旧 host 缺新字段时不把旧主档冒充合计。
- 全部录音累计复用现有分页列表和日接口，最多两路后台读取；累计按 session 开始日分桶，每个完整 child 计一次。缓存版本升至 v2，旧主档口径缓存不再使用。
- 每日跨午夜的物理文件缺按日字节分配事实，保留不可确认状态；全部累计仍完整计一次。后端若提供按产物归属日明细，可进一步补齐每日统计。
- ASR 同步改为上传账号范围；输入窗口按自然日裁剪，真实重叠窗口和重试保留。已完成但 API 未提供历史输入记录的 child 单独计数，界面显示“历史计量缺失”，不显示假零，不说还在转写。

## 后端需要交付

### A. 真正的 OSS 当前占用

请优先复用已有权益/存储账本与对象元数据，返回当前可见录音的真实留存大小和组成：人声主档、播放切片、仍保留原件，以及若存在其他持久音频产物的大小。

要求：

- 按上传账号校验权限；共享/记忆归属不得改变上传账号资源范围。
- 基于 bucket + object key 去重。同一录音多种实际存在的文件分别占空间；同一对象的重复引用只算一次。
- 明确原件清理、重处理替换、旁路产物、回收站和永久删除后的口径。对象不存在时不能继续按旧数据库大小累计；核验失败也不能当 0。
- 状态区分已核对、部分已知、处理中、缺数据，提供快照时间和核验依据。界面收到真实留存值后才能去掉“已记录”的限定。
- 提供跨午夜归属方案：完整文件按唯一录音归属日计一次，或提供确有依据的切片日明细；不得按录音时长比例假装精确分摊字节。
- 总量应覆盖所有日期，不随日历月份变化；避免每次读日历无界扫描 OSS。

### B. 历史 ASR 输入时长

请从授权用户提供的历史日期定位 session 和 child，核查：

1. MongoDB `asr_input_executions` 是否缺失、损坏、执行 attempt 不匹配，还是回执曾投递失败。
2. 若执行回执实际存在，修复读取/投影问题；若回执缺失，查可保留的 worker 调用日志、任务消息或计量账本是否含真实输入窗口。恢复需保留 execution ID，避免重投重复计算。
3. 若只有旧 VAD/SD 段和历史模型切窗规则，可评估重建“估算输入量”，但必须返回 `basis=estimated`，说明无法覆盖的重试、静音/合并窗口差异；不能把结果表述为真实消耗。
4. 若证据无法恢复，返回明确原因（如历史未采集），保留 unavailable。仅为了一个统计数字不应重新跑全部历史 ASR。
5. 建议返回历史缺失原因与覆盖范围；新录音持续记录真实输入，处理中与终态缺失分开。

## 验收

- 历史日期：存储展示去重后的现有处理产物记录合计；如 OSS 实存不同，提供差异明细和清理/留存依据。
- 修改说话人标记、取消标记或改变记忆归属后，上传账号的资源统计不变。
- 历史时长恢复后刷新 3102 即可更新；若为估算，显示“约…（含估算）”；不能用转写句子的起止合计冒充模型输入。
- 新录音、明确静音、缺计量、部分完成、跨日、重复 child/执行、删除、重处理、切账号都有可解释结果。
- 对日期和全量采用同一范围；前端缓存更新不能继续保留修复前的数据超过约定刷新周期。

请先提供方案和只读核查结果，再确定回填范围；本文不授权批量重处理或生产数据修改。
