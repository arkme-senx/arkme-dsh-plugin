# 团队消息通道后端协作汇总

日期：2026-10-19。收件人：华焱。范围：Arkme 插件近期团队消息通道功能。

## 结论与优先级

外部用户头像打开人物卡片、发起个人私聊、查看其在当前团队会话内的快记和定位原消息，插件已实现并在 3102 用真实会话验证。基础能力不需要等待新接口。但访客身份目前依赖一条外部消息解析，建议后端提供稳定契约，消除删除消息等边界影响。

以下区分已接通、生产抽查缺字段与待评审建议。`team.app.*` 是插件 Host 操作名，不是生产 Team HTTP 接口；本文中建议增加的字段/能力不代表已经上线。

| 优先级 | 事项 | 当前状态 | 后端需要配合 |
| --- | --- | --- | --- |
| P1 | 访客身份与发起私聊 | 已可用，存在消息依赖的兼容路径 | 提供已鉴权会话的稳定外部用户身份，明确是否允许发起个人私聊 |
| P1 | 访客 VIP / SVIP | 展示已接，10 月 19 日生产样本缺字段 | 会话 visitor 统一返回当前 member_type |
| P1 | 入口置顶、移除偏好 | 本机保存，刷新和重启保留 | 当前账号的偏好跨设备同步、原子新消息水位 |
| P1 | 已读时间与接收者统计 | 名单与侧边状态已接通 | 确认 read_at、接收者集合；补外部联系人阅读时间 |
| P2 | 访客快记检索性能 | 当前团队内逐页过滤外部消息 | 可选增加受权限约束的发送方筛选及按消息定位 |
| P2 | 引用回复、共享标记、转发/链接 | 引用链路未闭环；标记仅本机；部分菜单不可用 | 补齐下文能力，前后端共同联调 |

P1 / P2 是建议排期，不表示生产故障等级。后端本轮未由我修改或部署；最新头像功能本地提交为 `af524519`，尚未合入 dev/master。其他团队改动也有本地待合内容，不能以本文判断发布版本已经包含。

## 1. 访客稳定身份与个人私聊

### 已核实的现状

插件使用：

- `POST /api/v1/team/conversations/list`
- `POST /api/v1/team/conversations/timeline/page`
- 插件 `team.app.visitor.private.open` → 现有 ChatService `openPrivateChatFromUser`。

10 月 19 日生产只读抽查的两个会话：会话没有 `external_user_id`，`visitor` 只有 `nickname/avatar_url`；会话有 `latest_external_seq`，时间线消息有 `actor_user_id`。

当前兼容路径：重新请求已授权会话 → 若有 `external_user_id` 则使用 → 否则按服务端 `latest_external_seq` 精确取该条消息 → 校验会话、`side=external`、序号一致 → 使用其 `actor_user_id` 打开私聊。不会取任意最近一条消息的发送者，也不会按昵称、头像或客户端任意传入的 ID 匹配。

此路径已在真实账号成功打开个人私聊，没有发送测试消息。如果最后一条外部消息已不可读取、序号缺失或身份不可确认，则明确失败并允许重试，不猜测身份。

### 建议的最小后端补充

推荐在**内部团队侧、已通过成员权限校验的会话对象**统一返回 `external_user_id`（数值为有效安全整数；例中的 `123456` 仅为示意）：

```json
{
  "conversation_uid": "example-conversation",
  "side": "team",
  "external_user_id": 123456,
  "visitor": {
    "nickname": "示例用户",
    "avatar_url": "...",
    "member_type": "svip"
  }
}
```

- 由会话归属关系确定用户，不能依赖最近消息是否被删除。目录、打开会话、时间线等共用同一投影。
- 当前插件已读取 `conversation.external_user_id`；采用此字段可直接减少一次兼容查询。原始 ID 仅在插件 Host 内解析，不需要向渲染界面暴露。
- 如后端不希望提供原始 ID，可改为受权限约束的“解析私聊目标”能力，返回可被 Chat 验证的目标引用。此方案需额外对齐前端，不能只返回一个客户端无法验证的新引用。
- 明确是否允许团队成员向该访客发起个人私聊，以及拉黑、账号注销、成员退出等结果。私聊仍走 Chat 原有权限判断；浏览团队消息不自动获得额外发送权限。
- 不把内部成员名单或身份投影额外暴露给外部视图。

验收：同名用户不串人；最新消息为内部成员回复时仍打开正确访客；最新外部消息删除后仍可解析有效访客；成员权限撤销、切账号、用户失效时拒绝旧请求。

## 2. 访客会员状态

当前插件已复用私聊的会员星标及即时悬浮提示，覆盖访客列表、标题与预览。生产样本缺 `member_type`，所以不能宣称真实 VIP / SVIP 联调已经完成，也不能把缺字段当成非会员。

请在会话 `visitor.member_type` 统一返回：

| 值 | 含义 |
| --- | --- |
| `vip` | 当前 VIP 权益有效 |
| `svip` | 当前 SVIP 权益有效 |
| `free` | 已核实当前无有效会员权益 |
| `unknown` / `null` / 缺失 | 当前状态不可用 |

插件兼容已有 Chat 数值 `0/1/2`，分别为 free/vip/svip；若后台实际枚举不同，请先对齐。这里展示权益状态，不是历史付费、订单或充值数据。

- 覆盖 `conversations/list`、`conversations/open`、`conversations/timeline/page`，包括翻页及刷新返回的会话对象。
- 服务端按真实访客身份批量查询权益，避免逐条消息串行查会员而阻塞会话。
- 会员依赖异常时返回 unknown，仍返回消息；到期、升级、退款失效等按当前权益处理。
- 状态变化应独立于消息 revision 失效；至少重新打开/刷新目录时返回最新权益。

验收：VIP、SVIP、非会员各一例；到期/升级后多个展示位置一致；不同账号与同名访客不串会员。无需分享订单数据。

## 3. 团队入口置顶与移除偏好跨设备同步

当前团队总入口、团队内单个外部对话等已可预览、置顶/取消置顶、移除。本机按账号保存。移除仅隐藏当前用户入口，不删消息、不退出团队、不改已读；可以从联系人或已移除列表恢复。

建议增加个人偏好协议（接口名由后端定）：

- 读取偏好：`entry_kind + entry_id + pinned + dismissed + version`。
- 设置置顶/取消、移除、恢复：携带稳定入口身份、`expected_version` 和幂等操作 ID，返回最新偏好。
- 入口类型区分团队文件夹和具体会话；具体会话还要区分访问侧。身份绑定当前登录用户，不能用昵称或可轮换签名串作持久主键。
- 变更事件与增量补偿：设备 A 操作后设备 B 更新，断线重连可核对版本。
- 移除团队总入口时由后端原子保存“实际新消息活动水位”，覆盖尚未加载的会话及未来新访客。不能依赖前端当前加载了哪些对话。
- 编辑、删除、已读回执或资料更新时间不能触发入口恢复；只有移除之后的新消息才恢复。建议提供独立 `last_message_seq/last_message_at`，不直接拿 `updated_at` 判定。

前端后续通过能力协商启用云端偏好。已有本机偏好迁移必须幂等，不能让本机空值覆盖另一设备云端设置。预览继续只读，不推进阅读水位。

## 4. 阅读状态：已有能力与待确认口径

已使用 `POST /api/v1/team/conversations/read-receipts/query`，读取 `members[].user_id/identity/read/read_at`、`visitor_read`、`has_more/next_cursor`。

**当前界面已更新，以下描述覆盖 10 月 18 日旧交接里的界面说明：**

- 不再有全部/已读/未读三个 tab。已读成员在上方，按返回的阅读时间倒序；未读在下方用点和半透明样式。未知不当未读。
- 内部发出的消息在气泡侧边显示圆圈和团队已读人数；外部联系人未读为灰色、已读为浅蓝色。本人消息在左侧，外部来信在右侧，不占气泡下方一行。
- 外部视图只保留聚合状态，不能查看内部阅读者名单。

请后端确认/补充：

1. `read_at` 是最后阅读游标更新时间，还是本条消息首次阅读时间？明确单位与语义。当前前端按返回值展示，不应被解释成未被服务端证明的“本条首次阅读时刻”。
2. 外部联系人目前只有 `visitor_read` 布尔值，插件没有对应时间字段。建议补独立的外部联系人最近阅读时间，并明确语义（如采用 `visitor_read_at`，属于待对齐的新字段）。未知时间留空，不用消息时间或当前时间冒充。
3. 接收者集合是发送当时成员还是当前成员？新加入/退出/停用成员如何计数？发送者必须排除，未知状态独立计数。
4. 多页提供稳定快照/游标，避免成员变化导致漏人；可以去重但不能靠前端推断漏掉的人。
5. 大团队建议提供批量/聚合回执，包含接收总数、已读数、未知数。现有前端仅查询可见消息、限制并发并缓存；不要强迫每条消息拉全成员才算一个数字。
6. 阅读变更事件应只失效阅读缓存，不要求重载整段时间线。现有 15 秒轮询是兜底，不能据此声称毫秒级实时同步。

验收需真实多人配合：外部来信仅部分内部成员阅读；内部回复外部未读/已读切换；全员已读后入口仍保留；加载/刷新不改变滚动、输入焦点和草稿。

## 5. “看TA的快记”的范围与性能

当前实现明确标注“当前团队对话”，只展示该会话中 `side=external`、已发布、正文可访问的消息，分页、去重并可定位原消息。**这不等于获得访客全账号的个人快记，也不查询其私人自用内容。**

当前无需新接口，但内部回复很多时，需要逐页过滤，首次拿到外部内容可能偏慢。建议在现有时间线接口支持服务端发送侧筛选（字段名待定），或提供受同一会话权限约束的外部消息分页能力：

- 返回明确的过滤后游标、has_more；不可把未筛选分页的总数当成外部消息数。
- 可选提供按 `message_uid` 获取前后上下文的定位能力；校验当前会话与可见性，避免定位历史消息时前端扫描大量页。
- 删除、编辑、权限撤销的结果需可辨认；附件继续走 Team 媒体授权。
- 如后续产品要看“该用户向当前查看者公开的个人快记”，应单独接已有公开资料授权能力，清楚区分“当前团队”与“公开快记”。不能直接放开全账号记录读取。

## 6. 之前团队消息功能仍需闭环的协议

### 整条/部分引用回复

插件旧 `team.app.send` 有 `replyToRef → reply_to`，但当前持久发送队列 `TeamSendInput` 尚无引用字段，消息投影也未提供完整引用信息。因此按钮或单个旧接口存在不代表功能已闭环。

需要贯穿：原会话/消息 ID、可选选区锚点 → 排队/持久化/恢复/重试/幂等 → 服务端校验 → 返回投影 → 原消息定位。选区采用已约定的 `version=1, projection=arkme-text-v1, sourceDigest, recordVersion, start, end, text, prefix, suffix`，偏移是规范文本 UTF-16，不是 Markdown 源码偏移。原文修改/删除/失权后明确引用状态，不泄露历史正文。

### 多方共享文字标记

目前标记按账号/团队会话保存在插件本机，刷新和重启保留，**不跨设备、不共享给其他成员或访客**。需后端提供能力协商、快照/增量、增加/取消、幂等和版本控制；明确内部可见与允许外部可见的范围。取消权限归作者或明确授权角色。原文变更不静默挪到近似文字；现有本机标记不默认上传为共享数据。

### 转发、消息链接、部分批量操作

需明确 Team 与 Chat 的目标权限、来源可见性、附件授权及结果核对，再开放对应菜单。Team 引用不能直接作为 Chat 引用使用，也不能把私有附件地址直接发给无权限目标。批量操作要返回逐条结果；超时/重试不能重复发送或把部分成功显示为全部成功。现有可用操作继续保留，缺完整协议的操作明确暂不可用。
