# 跨群人物公共资料缓存（2026-11-04）

## 行为

A 群加载甲的公开资料后，B 群查看甲时可以复用同一份本机缓存，不再为公开账号等展示信息重复等待上游服务。

缓存保存在现有 Host SQLite 数据库的新表 `public_person_cache`，按环境、当前登录账号、目标用户标识隔离；同一个人不会因为群不同而存为不同身份。公开资料加载器统一写入缓存，所以 A 群的成员资料加载也能为之后的 B 群卡片提供数据。正常保留登录态的应用重启后仍可使用。

- 公开昵称、即我号和头像展示信息可跨群复用。私人备注、群昵称、角色、在群状态、统计和 @ 凭据不写入公共缓存。
- 卡片先打开，再进行纯本地缓存探测。缓存新鲜时不发起上游资料请求；过期时先显示已有数据，再后台更新。B 群自己的姓名/群昵称始终优先，通用资料不会替换它。
- 默认新鲜期 60 秒，保留期 14 天；每个环境/账号最多 4096 个目标，每条载荷最多 8 KiB。失效、损坏或过期记录按缓存未命中处理。
- 手动刷新绕过公共资料的新鲜期；刷新中和临时失败时保留已有展示。上游明确返回用户不存在时删除对应公共缓存。
- 分享链接仍使用原有的强制查询与身份匹配，避免将旧账号名称复制成另一个人的链接。世界、私聊、团队联系等真实操作继续执行各自的当前权限校验。
- 图片字节继续使用原有头像缓存机制；公共资料缓存不表示缺失的图片字节或需要授权的群操作也能离线完成。

## 实现与兼容

`identity.person.read` 增加可选 `cacheOnly` / `forceRefresh` 控制。只在缓存探测时允许返回 null；原有三参数调用仍保留非空返回的类型契约，老调用者无需修改。旧 Host 不支持探测时，前端兼容普通读取结果，避免重复请求。参数类型及冲突选项由 Host 校验。

群成员缓存探测只在本地验证 `sourceRef`、`memberRef` 的签名、当前账号与所属会话，映射到稳定目标用户标识后读取已经获取过的公开资料；它不向云端请求群名单，也不返回或授予群权限。实际操作仍走原有新鲜成员校验。

公共资料响应的批次写入使用 SQLite 事务；按请求顺序时间戳拒绝较旧结果覆盖较新缓存。单个服务实例使用单调递增读时间戳，失效代次改变或已取消的读取不能重新污染缓存。确定不存在的旧结果也不能删除更新的记录。缓存持久化失败不会阻断正常资料读取。

只新增本地表和索引，不修改云端协议或现有记录表。回滚功能提交可恢复旧逻辑，旧版本会忽略新增缓存表；无需删除用户聊天、录音或账号数据。
