# 长文库共享分类后端交接

日期：2026-10-26

## 已完成的前端与现有能力

- 快速查找的「长文」改为独立大弹窗，不再进入搜索页面顶部的内容类型 tab。
- 顶部分类固定为「最近」「我共享的」「共享给我的」。按需读取，保留各分类的列表和滚动位置。
- 「最近」沿用当前长文场景查询及服务端分页顺序。
- 「新建长文」通过 `sources.self-target` 取得当前账号签名的发给自己入口，复用现有长文编辑器、发布、草稿及编辑能力。新建成功立即补入最近列表。
- 本次没有修改或新增云端服务代码；只修改插件及其 Host 适配层。

## 当前缺口和真实状态

当前插件的 `search.scene` 调用 `/api/v1/search/records/scene/query`，长文为 `scene_kind=5`。现有接入参数仅支持场景、搜索范围、来源和 cursor；当前映射没有可确认的共享方向或共享关系。

因此，两个共享分类不能用作者 ID、文档归属或当前页结果猜测。自己创建但从未共享的长文不能进入「我共享的」；作者是别人也不能直接证明这篇文档是共享给当前用户的。

当前前端两个 tab 均可切换，Host 收到共享分类请求后立即返回：

```json
{
  "code": "long-article-sharing-unavailable",
  "message": "后端接口开发中，开发完成后此功能完整可用。",
  "retryable": false
}
```

前端显示这段说明，没有伪造列表或「暂无共享长文」的空状态，也不把无效参数发给旧接口。

## 建议补充的查询协议

可扩展既有场景查询，也可提供独立长文库查询，最终字段请后端确认。以下字段为建议，不是当前已上线接口。

```json
{
  "scene_kind": 5,
  "article_scope": "shared_by_me",
  "limit": 30,
  "cursor": "opaque-account-and-scope-bound-cursor"
}
```

`article_scope`：

| 值 | 含义 |
| --- | --- |
| `recent` | 当前账号可访问的长文，按服务端定义的最近活动时间倒序 |
| `shared_by_me` | 当前账号实际发起共享且共享仍有效的长文 |
| `shared_with_me` | 他人向当前账号或其当前所属共同空间共享、当前仍有权访问的长文 |

共享覆盖哪些形式需要明确区分：发送原始长文引用、共享主题中的原文、独立共享链接、转发的只读副本。建议只读副本作为独立记录，不能反推原文访问权限；仅生成或复制链接也不能证明已有接收方。

返回沿用当前搜索记录结构，并补充以下事实：

- `applied_article_scope` 或等价的明确筛选生效回执，避免旧接口忽略筛选参数后返回全部长文。
- 原文稳定身份：`record_uid` + 精确的 `record_owner_user_id`，以及当前可访问的来源定位。
- 最新相关活动时间及其语义：创建、更新、共享或接收；同时间使用稳定 ID 排序。
- 共享关系：共享者、共享时间、当前可见共享对象摘要。仅返回当前用户有权获知的对象信息。
- `has_more` 与绑定账号、分类的 opaque cursor；不能把「我共享的」cursor 用于另一个分类。
- 当前是否可读、可编辑；详情和更新仍由原文权限接口裁决。

## 权限与去重

1. 单篇长文共享到多个对话，列表按原文身份去重；共享关系可汇总多个对象，排序取与当前分类有关的最新有效活动。
2. 取消共享、退出群聊、移出主题、删除和隐私锁定后，重新查询及读取详情都应按当前权限处理。
3. 不能因参与过某个群、知道原作者 ID 或持有旧 cursor 而读取原文。
4. 同一 `record_uid` 可能涉及不同 owner；所有 ID 按字符串或已有无损 ID 契约处理。
5. 请求账号切换后，客户端会中止旧读取并关闭长文库；服务端也需要验证账号和 cursor 绑定。

## 联调验收

- 私有新建长文出现在最近，未共享时不出现在我共享的。
- 自己共享、他人共享、同一篇共享到多个位置的情况正确分类和去重。
- 撤销权限后列表和详情均不继续暴露内容。
- 各分类分页无重复、无漏项，切换分类时晚到响应不会串入另一列表。
- 原始长文和转发只读副本权限、归属、编辑能力分别正确。
- 旧服务不支持筛选时明确报不支持，不能悄悄返回全部内容。
