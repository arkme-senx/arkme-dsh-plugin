# 桌面个人与群聊分享链接

消息继续保存普通 HTTPS 链接，复制和转发保持链接内容。桌面端识别个人主页链接及当前 `chat_v1_` 群邀请链接，点击后打开站内名片。查看名片是只读操作；明确点击发消息、加入群聊或申请加入后才执行相应动作。

## 入口与接收流程

- 个人资料菜单：复制我的链接。
- 联系人资料、个人世界、找人聊聊详情、聊天成员和世界作者卡片：复制个人链接。
- 私聊右上角菜单：复制对方链接。
- 群资料与群设置：复制群聊链接，复用原生邀请生成与有效期。
- 收到个人名片：显示公开昵称、头像、即我号；可进入世界、复制链接、发消息或以团队身份联系。已有双方私聊由现有私聊接口复用。
- 收到群名片：显示群名、群主、加入方式及邀请有效期；已在群中直接打开，需要审批时显示申请和等待审批状态。可以复制原邀请链接继续转发，不改写邀请凭据或有效期。
- 失效、过期或无法读取时显示实际错误，保留浏览器打开入口；不将错误当作允许联系或加入。

链接不能携带发送者的联系人备注、手机号、账号凭据、本机 `sourceRef` 或联系人引用。发送者复制时验证公开即我号确实解析到所选用户；接收者用自己的账号解析和操作。发消息前再次核对实际用户与刚展示的名片，身份发生变化时要求刷新。

## 复用与边界

| 能力 | 复用方式 |
| --- | --- |
| 个人主页链接 | 生产环境使用 `https://jiwo.cc/{即我号}`；测试环境使用现有 `https://jotmo-app.senguo.me/{即我号}` |
| 公开资料 | 现有 Auth 按用户 ID 与即我号查询接口；缺少可验证公开标识时明确报错，不拼装假链接 |
| 群邀请链接 | 现有 `/api/v1/chats/governance/invite-preview`，原样保留服务器生成的 token、code、stamp 与有效期 |
| 群名片预览 | 现有 `/api/v1/subject/invite-preview-state`，包括当前查看者的已加入和申请状态 |
| 群加入 / 申请 | 现有 `/api/v1/subject/request-join`；沿用现有原生 Chat 桥接、邀请校验、群规则和容量限制 |
| 打开群 | 现有原生 Chat detail 校验有效成员后投影来源，不把旧共享主题 ID 当作新群身份 |
| 私聊 | 现有 `ChatService.openPrivateChatFromUser`，不搬运介绍人的聊天历史 |
| 手机号绑定 | 复用当前社交写入规则，仅加入群聊需要相同绑定校验；复制、查看、打开已有群保持只读路径 |

群邀请 token 的解码只用于定位群；不会在客户端复刻签名算法。服务器对完整邀请参数的校验和当前有效成员校验仍是最终依据。旧共享主题链接保持原有浏览器打开方式。

请求绑定账号与环境；切换账号或关闭名片会取消请求并丢弃旧响应。重复点击操作被拦截。加入结果未知后重试会先读取当前状态，已经加入或正在审批时不再重复提交。独立会话窗口沿用原来的新窗口导航策略。

## 统一人物资料卡

头像与个人链接均渲染 `ArkmeMemberProfileCard` / `ArkmePersonProfileDialog` 同一组件。聊天成员、世界作者、快记提及、表态用户、退群动态和团队人物卡沿用这一组件。采用 390 px 横排头像与身份信息、独立世界入口、个人与团队联系按钮、底部复制和更多操作；使用插件统一样式加载器，适配深浅色主题。

- 进入 TA 的世界与发消息为独立动作；自己的卡片显示进入我的世界、发给自己。
- 人物世界身份由现有成员引用、世界作者引用、成员动态或团队会话解析。公开即我号只用于资料装饰和分享；没有可分享标识时，已有授权的人物世界仍可进入。
- 新增桌面 Host 只读编排 `identity.person.read`，团队人物/访客解析也只读取已有会话，未新增云端接口。
- “以团队联系”复用现有团队选择与 `outbound.open` 流程；个人链接用已解析的公开用户 ID 固定联系人，服务器仍校验团队成员与外部用户状态。
- 链接卡片将刷新和浏览器打开收进“更多操作”。头像卡片同样支持刷新资料，复用关闭、Escape 与焦点约束。
- 独立会话窗口保留当前会话，世界入口打开对应公开主页；自己的链接卡在此窗口只提供世界入口与复制，避免切换固定会话。

## 人物链接名片加载优化

消息中的个人链接预览与人物弹窗共用 `IdentityPersonCardClient`：可见链接通过现有预览调度读取完整公开名片，点击时直接使用同一快照或加入同一在途请求。群邀请保持实时读取，不复用人物缓存。

- 快照按查看者账号、环境与公开即我号隔离；保留最多 64 张、60 秒内直接使用，10 分钟内的旧资料先展示并后台刷新。账号切换立即清空缓存并取消旧请求。
- 首次打开使用同一人物资料卡，先显示已有公开昵称或链接中的即我号。读取期间联系和世界按钮不可用，关闭、复制收到的链接与浏览器打开仍可使用，不再误显示加入群聊。
- 已有资料后台刷新时，世界入口和联系入口不因刷新整体锁定。发起私聊仍由原接口重新核对 `expectedUserId`；团队联系携带链接与所展示的用户 ID，在最终打开团队会话前重新解析核对。
- 明确失效或身份变更时撤销旧缓存；同时取消旧刷新，防止迟到结果把已撤销的名片重新写回。
- `ProfileService.shareIdentityByArkmeId` 从同一公开资料响应投影姓名、用户 ID 和头像引用，消除第二次相同资料查询及其后台排队。头像图片字节继续独立加载。

3104 真实生产 API 抽样：同一个“狗才”链接，优化前主体显示为 2.85 / 3.92 / 18.40 秒；优化后预览完成时三次打开约 57 / 46 / 217 毫秒，点击均没有新增资料请求。首次读取的卡片外框约 164 毫秒出现，资料随后原位补齐。数值为本机抽样，首次完整资料仍受网络影响。页面恢复中被取消的预览请求另行记录，不计作点击新增请求。

验证：17 个相关文件回归 1114 项通过、2 项跳过；最后的缓存撤销调整另有 42 项定向测试通过。`pnpm typecheck`、`pnpm build` 通过。实测只读取资料和打开/关闭人物卡，没有发送消息、建立私聊、发起团队会话或加入群聊。

## 复制、头像和状态反馈完善

- 收到的人物链接直接复制原 URL，保留收到的域名与路径，资料仍在读取或暂时不可用时也可以复制。不会为了转发原链接再查询或生成链接；头像、联系人等入口仍沿用所选用户当前链接的校验生成流程。
- 可见人物链接在取得公开资料后，异步预热头像。复用现有图片缓存、去重和并发队列，头像下载不阻塞名片文字和操作区。
- 人物卡底部显示更新中、更新失败及就地重试。刷新期间仅禁用刷新操作，已加载资料、世界入口和联系按钮保持可用；联系时的身份核对继续保留。瞬时网络错误保留已加载资料，明确失效则撤销旧快照。
- 群名片等待审批时每 10 秒读取一次状态；隐藏页面会取消在途读取并停止后续请求，返回可见时立即重新核对。通过审批后显示打开群聊，不自动打开或加入。
- 群邀请在到期时自动更新按钮状态，不需要点击后才发现失效；已经在群中的用户保持打开群聊。关闭卡片或切换账号会清理读取与计时器。
- 修正人物卡英文操作文案，避免将正文中的消息后缀译文用于独立按钮。

真实 3104 页面中，收到的个人链接复制由本次优化前约 30 秒降至约 46 毫秒，复制阶段没有 `identity.share.link` 请求；刷新开始后有明确提示，发消息仍可用。资料接口曾返回服务器繁忙，复制原链接不受其影响。

验证：14 个相关文件 804 项通过、1 项跳过；最终调整后的 6 个文件另有 107 项定向测试通过。`pnpm typecheck` 和 `pnpm build` 通过。受控组件浏览器覆盖浅色、深色、英文、920×680 桌面、刷新进度、失败重试及操作可用性。审批与到期通过可控时钟测试，未在真实账号提交申请或加入群聊。
