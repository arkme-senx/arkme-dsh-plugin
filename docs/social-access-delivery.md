# 社交 UI 展示控制

2026-09-24 用户将目标收敛为新版客户端主要 UI 展示，优先保持已绑定用户体验。此前跨服务强制准入已撤回。

## 当前实现
- 复用 `user.profile` 和既有资料缓存；缺少资料时才使用原 `user.profile.refresh`。不新增上游接口、Host 路由、SDK 或 Tool。
- 主导航、会话侧栏、快速添加、主要社交页面及转发目标读取一个展示快照。明确未绑定才隐藏；未知和首次失败保持正常展示，已有结果的失败保持原结果。
- 快照按账号/环境隔离。账号更新和窗口恢复读取既有资料缓存；隐藏页面不额外查询。
- 无整页等待、强制导航、独立窗口关闭、通话 SDK 拒接、消息投递或业务 Service 的资格守卫。
- 个人资料、记录、Bot、AI、登录流程与复杂跳转沿用基线。直接 Tools/SDK 调用继续原业务规则。

## 能力面
| 能力面 | 处理 |
| --- | --- |
| UI | 本次唯一生产改动面，绑定信息驱动显示 |
| Host owner | 复用既有 profile，不改数据/执行合同 |
| Tools | 无新增能力，原注册、授权和执行保持基线 |
| SDK | 无新增能力，原公开 API 保持基线 |

## 发布
无需后端配套部署、服务配置或数据迁移。插件版本不由此任务手动变更。单测、打包与官方运行时浏览器验收分别记录，不能将 UI 夹具验收等同于生产账号或供应商通话验证。
