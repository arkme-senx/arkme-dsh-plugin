# 社交展示与登录手机号要求

当前范围以 2026-09-30 的实现为准。社交能力只在新版客户端的主要入口和内容呈现层控制；此前跨服务的社交准入限制已经撤回。

## 社交展示

- 复用 `user.profile` 与既有资料缓存，不新增社交权限接口、Host 路由、SDK 或 Tool。明确未绑定才隐藏；未知和首次查询失败保持正常展示，已有结果的失败保持原结果。
- 主导航、会话侧栏、快速添加、主要社交页面及转发目标读取统一展示快照。快照按账号和环境隔离，资料更新后刷新。
- 不增加整页等待、强制导航、独立窗口关闭、通话 SDK 拒接、消息投递或业务 Service 的社交资格守卫。个人记录、Bot、AI 和免登录功能保持原有规则。
- 未绑定账号在个人资料区看到“绑定手机号后即可使用社交功能”，通过现有账号设置完成绑定。

## 登录要求

登录与社交展示分别处理。插件登录是否必须绑定手机号，由账号服务既有 `get-user-info.phone_binding_policy.mode` 决定，浏览器不再按“手机号为空”重复裁决。

启用后端既有强绑配置时，注册时间早于 `effective-at` 的未绑定账号返回 `none`，正常登录后由上述展示规则隐藏社交；注册时间不早于分界的未绑定账号返回 `required`。已绑定账号正常登录。`deadline-at` 保留既有响应及配置校验兼容，不再把分界日前的老账号转为强绑。配置关闭时登录不要求绑定，但客户端社交展示仍按真实绑定情况处理。

后端不可用或响应缺少策略不能被解释为“已绑定”。已绑定且存在既有资料缓存的账号保留原有离线启动路径。绑定成功后的确认检查真实手机号事实，而非仅检查登录是否允许。

## 能力面

| 能力面 | 处理 |
| --- | --- |
| UI | 统一展示快照和绑定指引，沿用既有登录与账号设置入口 |
| Host owner | Auth/Profile 消费账号服务的登录决定，账号切换沿用统一 session owner；无社交 API 拦截 |
| Tools | 无新增工具；原注册、授权与业务执行保持基线，登录状态复用 Host owner |
| SDK | 无新增方法；既有 auth/profile 返回值反映账号服务决定，不暴露凭据 |

## 发布

需要配套合并 `jotmo-backend` 的注册分界修正，以及 Flutter、插件和治理文档分支。建议先部署账号服务，再发布客户端。生产分界应核对既有 `phone-binding.effective-at` 为 2026-09-10，且 `enabled` 已开启；本任务没有新增配置项、表、集合、索引或数据迁移。

插件版本沿用基线，本任务不手动升版。正式包验收、真实测试服 UI 验收、短信供应商与各原生平台验收分别记录，不互相替代。
