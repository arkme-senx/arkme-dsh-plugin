# 所有录音累计统计：现状与最新口径

2026-10-15 晚间口径已调整。完整后端交接见 [录音存储与历史转写计量后端交接](录音存储与历史转写计量后端交接-20261015.md)。此前“仅本人记忆归属的人声主档”的口径及对应验证数字已被替代，不能用作新指标验收依据。

## 当前实现

- 现有 `get-session-ls` 完整分页 + `one-day-trans` 分桶读取；范围是 `session.user_id` 为当前账号的全部可见上传录音。
- 新 `storage` 为已记录的 `archive_size + size`，提供主档、播放切片明细；不把 `source_size` 直接加入，不声称已完成 OSS 实存核验。
- ASR 输入按同一上传账号范围读取真实执行窗口；历史缺失明确显示，估算单独标注。
- 累计按 session 开始日分桶并计完整 child，不受当前日/月筛选影响；跨午夜产物只计一次。
- 最多两路后台读取，缓存按账号、时区隔离；新存储口径启用 v2 缓存，旧 v1 无效。
- 索引完整后才移除已删除成员；处理中的日期及时更新，稳定历史缓存最多 24 小时。后端回填上线联调时需要主动刷新缓存或变更相应版本，不能等旧值自然失效来验收。

## 可选汇总协议

插件本地接口已可计算，不依赖新增生产汇总接口。以后若扩展月历的 `recording_totals`，必须明确全部日期和上传账号范围，不能被月份过滤。

本地解析预留的 **v2 建议合同**（不是已部署协议，数值仅示例）：

```json
{
  "version": 2,
  "scope": "all_uploaded_recordings",
  "as_of_ms": 1792051200000,
  "storage": {
    "state": "ready", "bytes": 300,
    "archive_bytes": 100, "clip_bytes": 200
  },
  "asr_input": {
    "state": "partial", "duration_ms": 3600000,
    "basis": "observed", "missing_history_count": 6
  }
}
```

这里 `storage` 仍然是记录的产物大小；不能把 OSS 原件和其他对象加入 `bytes` 却不扩展明细及核验依据。真正实存协议由同事确认后再适配。旧 `version=1 / all_owned_recordings / archive` 明确不作为新指标使用。

状态与数值独立：未知为 null，确定没有为 0；数值必须为非负安全整数。部分已知量保留，不能用缺失部分为零推导“全部完成”。
