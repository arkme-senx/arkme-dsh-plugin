# Arko 图片输入：后端对接与验收

更新：2026-10-18。本文接口字段为本次插件实现所约定的**待对接协议**，不表示生产已经支持；服务端若采用其他协议，请先对齐插件再开启能力。

## 交付边界

插件已实现图片选择、粘贴截图、拖入、缩略图、预览、移除和排序；支持文字加图片、纯图片的提交路径、历史和详情图片呈现、失败草稿保留及同一次请求重试。图片先进入插件本地暂存，不因选择图片立即上传到云端。当前前端限制每次最多 9 张、单张最多 20 MiB，并取本地文件策略和模型限额中更严格的值。

**真正调用模型看图仍需要后端补齐。** 本次未修改、部署后端，也未将本轮图片代码合入 dev。只有模型目录明确发布以下完整能力时，插件才允许上传及发送图片；否则显示“图片能力尚未接通”并保留图文草稿。仅更换模型名称不能开启。

当前明确限制：`waiting_user` 任务的续接图片先阻止提交，因为插件尚无该运行实际模型的图片能力证据。普通新一轮图文消息可走本协议。续接需要后端返回运行绑定能力后另行联调，不借用用户当前选中的模型冒充运行模型。

## 1. 模型目录能力

保持 `POST /api/v1/agent/model/list` 原有响应。支持图片的每个 `items[]` 增加：

```json
{
  "route_key": "deepseek/deepseek-flash",
  "image_input": {
    "enabled": true,
    "protocol_version": 1,
    "max_images": 9,
    "max_image_bytes": 20971520,
    "max_total_bytes": 41943040,
    "mime_types": ["image/jpeg", "image/png", "image/gif", "image/webp"]
  }
}
```

数字是协议示例，后端需根据真实模型/网关限制发布。所有限额为正整数、单位 byte。禁用时省略或 `enabled:false`。未知版本或缺字段视为未支持，不把任意模型自动设为支持图片。插件只接受上述四类 MIME；后端必须验证实际文件内容、大小、账号所有权及是否可读取，不能只信文件扩展名和客户端声明。

`image_input.enabled=true` 表示整条链路（接收、落库、历史、runtime、provider、预算）就绪。未就绪不得提前打开。模型切换也返回同样能力。

## 2. 新消息接口

保留 `POST /api/v1/qa/new-msg-v2` 现有字段和响应身份。图片请求新增：

```json
{
  "model": 2,
  "session_id": 88,
  "content": "这张图里是什么？",
  "extra": "{}",
  "client_turn_uid": "同一次发送及重试使用相同 UUID",
  "model_route_key": "deepseek/deepseek-flash",
  "client_capabilities": ["dsh.arko.v1", "dsh.arko.images.v1"],
  "attachments_protocol_version": 1,
  "attachments": [
    {
      "type": "image",
      "file_asset_uid": "云端文件资产 UID",
      "file_name": "示意图.png",
      "mime_type": "image/png",
      "size": 12345
    }
  ]
}
```

- `content` 可以为空，但必须有至少一张有效图片。文字与图片都空则拒绝。
- 数组顺序必须保持；用户会问“第一张和第二张有什么区别”。
- 插件先用现有文件上传路径得到 `file_asset_uid`，不会把本地路径、`arkme-file-v1` 或短期公网 URL 当作图片身份传给模型。
- `file_asset_uid` 是 Arkme 资产标识，**不等于 DeepSeek 的 Files API `file_id`**。如使用提供方文件接口，后端负责转换、生命周期及权限。
- 幂等键需绑定会话、文字、按序资产 UID 和模型；重试不得重复创建消息、执行任务或计费。同键不同载荷拒绝。
- 上传成功但 new-msg 响应丢失时，插件保留同一 `client_turn_uid` 和本地附件，上传层复用已上传资产；服务端需能恢复原来的消息和 run。
- 旧服务端必须明确拒绝图片协议，禁止忽略 attachments 后按文字执行。不要为图片格式/权限/限额错误创建运行或计费。
- 当前插件图片上传和运行提交展示整体状态，不展示编造的上传百分比；细分进度可以后续按真实 host 事件增加。

## 3. 持久化、历史与权限

`POST /api/v1/qa/message-list` 的对应用户消息增加同一 `attachments` 数组，可读取时返回权限校验后的展示 URL：

```json
{
  "id": 101,
  "session_id": 88,
  "role": 2,
  "content": "",
  "attachments": [
    {
      "type": "image",
      "file_asset_uid": "云端资产 UID",
      "file_name": "示意图.png",
      "mime_type": "image/png",
      "size": 12345,
      "preview_url": "短期授权预览地址",
      "download_url": "短期授权原图地址"
    }
  ]
}
```

插件 host 将 URL 转为本地 opaque mediaRef，页面通过已有媒体路由读取。永久记录保存资产身份，不能只存过期 URL。已删除、权限失效或原图暂不可用时仍返回附件元信息、不给 URL；插件显示图片不可用占位，不让整条纯图片消息消失。历史重新读取应刷新短期地址。

清除上下文只开启新会话，不删除旧图；后续追问必须能重新解析前文图片。消息详情、转发和导出需说明是否包含附件；当前 Markdown 导出保留图片附件名称提示，**不嵌入原图文件**。如服务端支持转发，应同样保留图片资产和权限，不仅复制正文。

## 4. Camellia 和 managed-ai

1. 在输入材料中保留类型、资产身份、顺序，经过 runtime 队列和恢复检查点仍完整。
2. 按当前运行绑定的模型能力准备图片内容，不使用会话 UI 最新选项替代旧运行模型。
3. 在提供方适配边界将用户消息组装为 content 数组，例如 text + image_url。真正的视觉输入必须送入模型；仅做 OCR 文本不是本功能验收通过。
4. URL 可达性、过期重签、图像格式和压缩由后端负责。若使用 base64，不进入日志和长期普通消息正文；凭据、授权 URL 不写普通日志。
5. token/上下文预算包括图片、历史图片及输出预留；模型不支持时给明确错误，不能静默丢图片或换成非视觉模型。
6. 确认 managed-ai 接受并透传图像 content blocks，图片用量/费用按实际返回记录；日志保留 run_uid、client_turn_uid、资产 UID、路由、图片数量及失败阶段，便于排查。

## 5. 联调验收

- 用不包含答案文字、文件名不泄露答案的合成图测试颜色、形状或布局，证明是原生看图；不使用用户私密照片作为测试材料。
- 纯图片、文字加图、两张图比较、重排图片、随后文字追问均正确；刷新后图片及上下文存在。
- 图片未完成本地准备时发送按钮等待；后端不支持/能力查询失败时不产生残缺消息。
- 上传失败、提交超时、已接收后 SSE 断开、重启后重试：不丢图、不重复运行、不重复计费。
- 模型切换到不支持图片、服务回滚、超过数量/单张/总量上限、伪造 MIME、他人资产、账号切换应有明确失败。
- 历史 URL 过期或图被删除有可理解的占位；不把图片错误显示为一条空白消息。
- 对旧文本请求保持兼容；仅打开图片支持的路由显示“支持图片”。

## 插件实现入口

- `src/arko-image-contract.ts`：能力协议与限制校验。
- `src/client/ArkoImageAttachments.tsx`：本地准备、附件条和图片预览。
- `src/client/ArkmeArkoSurface.tsx`：输入、发送、失败恢复、历史及详情。
- `src/client/arko-pending-turn-store.ts`：同一次发送身份与图片引用。
- `src/services/arko-service.ts`、`src/arkme-service.ts`、`src/host-api.ts`：能力检查、已有上传路径、图片请求和历史投影。
- `tests/services/arko-service.test.ts`、`tests/arko-emoji-dom.test.tsx`、`tests/arko-pending-turn-store.test.ts`：协议及交互边界测试。
