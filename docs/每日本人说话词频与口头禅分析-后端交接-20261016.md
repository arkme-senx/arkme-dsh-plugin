## 目标与入口

录音 → 当日转写 → 框内右上角「我的说话统计」。右侧面板默认口语习惯词云，支持全部词频、列表、出现详情、试听原音、定位原文。仅统计用户本人，不按录音上传者归属判断说话人。

现有个人快记关键词统计不可复用为结果：其分词、停用词、TF-IDF 会遗漏单字语气词，也不能从原音补回 ASR 已删除的表达。日总结的分层压缩同样不适合逐次计数。

## 推荐处理链

1. 按鉴权用户、所选自然日及 IANA 时区读取完整后台数据，不依赖页面已加载的转写条数。使用人工身份与当前有效身份版本；上传者不是说话人。排除明确 playback、非本人、重叠混音无法分离及身份不确定的区间，分别记录覆盖缺口。
2. 构建规范原音时间线：避免系统/豆包两套转写重复计数、VAD 窗口重叠计数；跨日片段按真实时间切分，同一词按约定的起始时间归日。压缩 scene 时间需还原成源音频绝对时间。
3. 对所有合格本人音频生成保留原始口语的逐字结果，不做语义顺滑，不压缩重复词，不使用普通关键词停用词表。合格的已有原音识别产物可缓存复用，但不能只校验当前转写中已有的关键词，否则遗漏的「嗯」「那个」仍然找不回来。
4. 对歧义、遗漏疑似或影响计数的片段做原音二次核验，结合上下文处理同音词。强制对齐只解决候选文本的时间位置，不证明候选文本识别正确。不得伪造音频置信度；无法确定的出现进入 pending。
5. 在逐次证据上确定性计数。短语需要明确词边界、重叠策略、词形归一规则版本；每个 occurrence 有稳定 ID。可以同时存在单词与短语统计，但不能把它们的次数简单相加当作总词数。
6. 对每次出现判断「口头衔接 / 实义表达 / 用法不确定」。例如「那个文件」不是必然属于口头禅。语音核验和用法分类是两套状态：确认说了某词，不等于确认它是口头衔接。
7. 发布不可变结果快照。保存音频、身份、ASR、分词/短语、用法分类、模型/参数版本。原音补齐、文本修正、说话人标记、来源类型更改需使旧结果 stale；保留旧结果供对比，不无声覆盖。

VAD 或清理已删掉的音频不能被模型恢复。没有原音时应标 missing，不用文本估计后冒充原音核验。自己身份可能有误，因此本功能不训练声纹；用户仍通过既有头像标记纠错。

## 统计口径

- `verifiedCount`：原音核验确认的该词/短语出现次数。
- `habitCount`：以上出现中，用法确认属于口头衔接的次数；必须 ≤ verifiedCount。
- `pendingCount`：词的出现本身待原音核验的次数，不计入前两项，不参与词云字号。
- 用法不确定但词已确认：计入 verifiedCount，不计入 habitCount；详情 verification=verified、use=uncertain。
- 默认词云按 habitCount 排序，全部词频按 verifiedCount 排序。待核验表达可从列表查看。
- 每 10 分钟频次 = 当前分类确定次数 ÷ analyzedMillis × 600000。分母为已分析、去重的本人有效语音时长，不是全天时长、录音墙钟时长或预计时长。
- 一天数据仅说明当天表现，不应宣称某词就是用户稳定口头禅。

## 接口提案 v1

以下均走现有鉴权 audio 服务；路径尚待后端确认。插件仅 capabilities 检查通过后才提交任务。`404/501` 或 `supported:false` 表示尚未支持；401/超时/5xx 显示错误，不当作不支持。禁止由浏览器传入任意 user_id 或把页面文本作为统计输入。

基础路径：`/api/v1/speech-statistics/`，全部 POST。

公共请求/响应信封（capabilities 仅需 schema_version/scope）：

```json
{"schema_version":1,"scope":"self_speech_day","date":"2026-10-16","time_zone":"Asia/Shanghai"}
```

### capabilities

```json
{"schema_version":1,"scope":"self_speech_day","supported":true,"audio_verbatim":true,"self_only":true,"source_navigation":true,"idempotent_create":true}
```

上述能力必须真实具备，不能先标 true 再用转写文本拼接实现。

### state / create

- state：读取当天已保存结果和活动任务，无自动生成副作用。
- create：公共信封 + `request_id`（UUID）。按用户/请求 ID 幂等，并按用户/日/输入版本去重活动任务。相同 request_id 重试返回同一任务，已完成后也不可新建或重复扣费。
- create 响应需回传原 `request_id`；其余与 state 相同。
- 所有字段大小写以本节及插件类型为准：外层使用 snake_case，result/coverage/terms 内按下方 camelCase。

```json
{
  "schema_version":1,"scope":"self_speech_day","date":"2026-10-16","time_zone":"Asia/Shanghai",
  "stale":false,
  "job":null,
  "result":{
    "id":"immutable-result-id","evidence_basis":"audio_verbatim","speaker_scope":"self",
    "generatedAtMillis":1792108800000,"identityVersion":"identity-v1","audioVersion":"audio-v1",
    "coverage":{"analyzedMillis":600000,"eligibleMillis":1200000,"pendingSegments":2,"missingAudioSegments":1,"uncertainSpeakerSegments":3},
    "terms":[{"key":"stable-term-id","text":"那个","verifiedCount":6,"habitCount":2,"pendingCount":3}]
  }
}
```

数字仅为协议示例，不是账号统计。首次未生成 result=null、job=null；零数据与未生成不可混同。terms 最大 5000 个，本期必须覆盖结果定义内的所有词，不能静默截断冒充全部。超大词表需要协商分页/总量后升级协议。

job 格式：`{"id":"job-id","stage":"recognizing","completed":3,"total":10}`。stage 为 queued/recognizing/verifying/counting/failed；阶段内进度，不冒充全流程百分比。插件打开面板时轮询，关闭停止轮询，后端任务继续运行；长任务需要持久化及恢复，失败原因在日志可追溯。

### occurrences

请求：公共信封 + `result_id`、`term_key`、`mode`（habit/all）、`cursor`（首次 null）、`limit:50`。

响应：公共信封 + 原 `result_id` / `term_key` / `mode`、`total`、`next_cursor`（末页 null）、items：

```json
[{"key":"occurrence-id","startAtMillis":1792108800000,"endAtMillis":1792108801000,
  "text":"那个……先看这里","originalText":"先看这里","verification":"verified","use":"habit","sourceRef":"opaque-source-ref"}]
```

- verification=verified/pending，use=habit/lexical/uncertain。habit 查询只返回 habit 或有待确定的相关出现，不能混入 lexical 记录。
- 时间为真实源音频时间，含每次发生的位置；text 为原音分析上下文，不是 AI 润色总结。originalText 为对应原转写，可为空（原转写遗漏），两者不一致时前端显示差异。
- total 是该筛选下所有可展示出现（含待核验）的数量，不是 verifiedCount，不能相互代替。
- sourceRef 为空表示无法定位，不伪造链接。分页快照不可变，cursor 绑定账号/结果/词/筛选，稳定排序按时间和 key。

### source

请求：公共信封 + `result_id` / `source_ref`。服务必须重查来源属于该结果、当前账号可访问、当前仍是本人且非明确播放内容，不能将 source_ref 当授权。

响应：公共信封 + `result_id` / `source_ref` / `available:true` / `original_quote` / `owner_ref`。

```json
{"provider":"audio","container_id":"session-id","child_id":"child-id","item_ordinal":0,"transcript_source":"system","start_at":1792108800000}
```

owner_ref 仅在插件宿主使用，不直接传浏览器；原音通过既有密封 itemRef 和媒体权限访问。original_quote 必须来自对应原转写，不是校正后文本，否则现有精确定位校验会失败。本期试听从锚定转写片段开始，带上下文；词级单独切片/播放截止若需要，应补充受鉴权约束的播放范围协议。

原 ASR 整段遗漏、来源删除、对应豆包片段无系统播放片段等情况下，返回 unavailable/明确错误，不能近似跳到其他段。若需要支持「整段无转写但有原音」的试听，需补充独立原音定位协议；本期不可用不隐藏。

## 联调验收

1. 本人 3 段、其他人 2 段、播放内容 1 段：仅符合条件的本人段进入统计；上传归属改变不改变说话身份。
2. 同音错字、语气词漏字、重复词、多人重叠、噪声、跨日、VAD 重叠场景：保留逐次证据并给出覆盖/待核验，不能静默编造正确文本。
3. 「那个文件」与「那个……」总词频均可计数，口头衔接仅计后者（需上下文判断）。短语重叠策略固定且可复现。
4. 每个确定次数能追溯到 occurrence；翻页无重漏；同一音频在系统/豆包两套转写中只计一次。
5. 原文错字和校正词不同仍可精确定位原 ASR；来源过期或人物取消标记后拒绝旧引用，提示更新。
6. 生成途中关面板/刷新、重复点击、提交超时后核对均不得重复任务或扣费；不同账号和日期结果隔离。
7. 旧快照 retained + stale；更新结果后按新身份和音频版本重新统计。
8. 分析大量历史音频前先验证小样本，人工逐音核验 precision/recall，特别检查语气词是否漏检；没有达到可用质量前不要以 supported:true 上线。
