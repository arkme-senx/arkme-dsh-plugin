# 本机旧实例历史与接管

当前任务延续同机接管机制。旧实例的账号容器结构是发现入口，电脑名称不是授权依据。默认自动发现，不要求用户输入开发目录。

## 行为与边界

- 当前 OS 用户的标准应用数据目录、已登记的实例优先；首次查不到目标历史时，按账号容器结构执行一次有界旧目录发现。只读取候选注册表和目标账号的来源索引，不扫描正文做搜索。
- 选中离线旧实例的会话时也先请求当前 Host 检查本机历史；不能用云端在线状态阻止本地发现。Host 确认不可用后暂停订阅，后续选择或来源更新再重试。
- 身份保持 environment/account/originRuntimeRef/sessionRef。多个不同日志副本不能按标题合并或任选一个接管。
- 查看使用官方 DSH persistence/query 的只读接口，不创建 Agent，不取得 writer，不把原文件复制成可执行新会话。
- 继续发送复用已有 Registry、Coordinator、原生 writer 锁与稳定地址。源实例忙碌时沿用原执行者；旧版不能配合释放时明确拒绝接管。
- 原始日志保留单一物理位置；不自动搬迁用户数据或启动旧实例，不复制登录凭据。工作目录、附件、格式或工具环境不满足时保留历史可读性并拒绝继续。
- 开发验证使用隔离 Profile 和原日志副本；正式应用替换、运行环境发布不在本轮授权内。

## 能力覆盖

| 面 | 入口与要求 |
| --- | --- |
| UI | 现有账号会话主区域自动读取验证后的本机历史，状态说明区分未找到、冲突与不能接管 |
| Tools | 沿用账号会话列表、读取与命令能力，使用相同 Host 来源和权限判断 |

## 资源与验收

旧目录发现只在历史缺失时触发并可取消；依次完成 4/7/10 层的有界发现，每层最多 25,000 个目录、256 个实例，注册表最多 4 MiB。先采用登记和标准目录，再采用较浅层结果，不保证穷举磁盘所有副本；同一阶段发现多个来源时拒绝任选。源码仓库只继续固定应用数据目录，不跟随符号链接、不进入依赖/缓存/备份目录。命中来源登记后后续直接定位。达到上限必须报告未完成，不能将部分结果伪装为完整扫描。

DSH 原生 follow 在快照后会尝试后台恢复 Agent；本扩展在 Registry 阻止旧会话通过此路径取得执行权，显式发送通过 Coordinator 才可恢复。原工作目录不存在或旧会话含附件时拒绝接管；附件存储尚未接入，当前仅保证文字历史可查阅。MAS 版暂不自动发现。

需要验证：带空格目录、标准/自定义应用数据根、跨账号与跨环境拒绝、路径逃逸、符号链接、损坏注册表、取消/容量上限、日志副本冲突、并发读取与唯一 writer、源实例忙碌/退出、原生历史还原和后续输入上下文。

### 2026-11-03 云端修复实现

- 既有远控/同步策略开启后，验证过的旧日志读取触发独立补传 owner。原 runtime/session 不变，使用当前账号 Host 身份上传，不取得旧会话执行权。
- 先协商 `/session-history/repair-capabilities`，旧后端不支持时保持本机查阅；每批最多 100 事件、4 MiB，单条 512 KiB。原始历史和标记来源一起写入，已有相同数据跳过；内容冲突停止且不覆盖。
- 当前账号容器只存队列元数据，不复制日志正文。最多 256 任务，完成回执可淘汰；单 worker、120 秒单次超时，网络错误 5 秒至 5 分钟退避。每批 ACK 后保存游标，重启重新计算日志 digest，匹配才续传。账号退出取消任务。
- UI 和 `arkme_dsh_session_read` / SDK `readDshAccountSession` 共用入口，返回 `historySync: {state,nextSeq,throughSeq}`。云端原始历史补齐后可独立读取，旧 Turns 未完成时工具使用 `cloud-raw` 游标。
- 标记来源尚未补齐时保留已有本机标记并显示待同步，复用已有 15 秒可见消息刷新，在云端确认后自动恢复。真正权限拒绝仍拒绝；冲突和不支持协议单独提示。
- 插件 14 个相关文件 198 项回归通过；后端 `internal/dshremote` 全包真实本地 Mongo 测试通过。跨仓真实 loopback HTTP + Mongo 副本集 + 官方 DSH persistence 验证了 203 事件三批修复、分页与标记来源读回、原 writer 排他保持。
- 本轮扩展尚未部署或装入已登录正式服的应用，因此当前用户真实日志仍未云端补传。应用旧版本保持运行；无生产写入、无模型调用。最终制品见任务验收报告。

## 会话访问与标记

旧实例来源经过账号验证后，Host 将裸 sessionRef 解析为原 runtime/session。目录的 localAvailable/localAccess 表示本机可读、可标记与执行路由；localTakeover 仅保留旧客户端兼容含义。阅读、来源标记和云端补传均不取得执行权。

NativeAnnotationsService 是 UI/Tools/SDK 的共同标记 owner。云端来源已就绪时正常读取；来源暂缺或网络离线时只读验证本机正文，沿用同一 messageRef 和 digest，并把新标记放入现有持久队列。队列同时保存来源，以便缓存淘汰、重启后重新校验并按原 operation ID 重试。真实权限拒绝和内容冲突不降级为成功。移除待同步新增标记时，先解析云端去重后的真实 ID，再持久化固定请求，避免不确定结果下改变重试目标。

显式发送仍由既有 Coordinator/Registry 交接并竞争原日志写锁；新执行者发布来源文字时使用 canonical runtime/session 和 execution proof。后端 source-context 使用与事件写入相同的 sessionRuntime 校验。该后端增量需要部署后才能完成新执行者新增来源的线上同步；本机历史阅读不依赖它。

附件使用官方 LocalAttachmentStore：原对象留在已验证的旧实例，新对象写到账号共享目录；接管时验证历史资源。缺失工作目录、缺失/损坏附件和不兼容引用保留历史并拒绝继续；不会静默丢弃上下文。自定义附件根保持显式保护。

## 标题与订阅状态

正文读取、执行能力和云端补传分别由各自结果驱动。原生正文采用 chat snapshot；只读云端正文采用同一个 ProjectedHistory 的 openState，卸载即撤销。正文可读时，不把后台原生 follow 的重连显示成首次加载。同步暂停保留独立说明，不阻止本机阅读。

本机 fallback 建立的订阅后续 pull/close 固定发给实际 reader；关闭旧 epoch 订阅仍校验账号，但不要求已失效的写入资格。失败或结束立即释放容量，避免旧实例退出后反复打开耗尽订阅。


### 2026-11-04 正式服升级后的恢复与首次加载

- 已登记的账号容器可以位于开发仓库的 `artifacts/.../app-data` 下；发现器继续识别这些运行产物目录，但不进入源码、依赖或备份树。目录仍受原有深度、数量、账号和环境校验约束，发现结果写入同一实例索引。扫描额度按实际检查目录计算，待检查队列独立有界；每批为应用目录和普通目录分别保留调度机会，避免大型目录树挤占所有额度。
- `session.native.channel` 只表示可使用账号通道，不能证明离线会话已经有可用 reader。离线且未验证本机来源时先显示云端正文，原生读取/接管发现独立进行；实际 Host 回复后恢复原生视图和操作。
- 明确指定云端的历史请求不查询执行者目录，也不等待实时连接。分页继续固定原云端格式和游标，账号授权保持不变。
- `unsupported` 补传任务保留在持久队列，由同一 worker 每五分钟重新协商服务端能力。能力没有变化时不重复读日志；服务端升级后自动继续原游标和格式迁移，无须重启客户端。账号退出仍取消计时器和正在进行的请求。

来源索引按账号和环境共享构建，最多缓存 4 个作用域、每作用域 10,000 个会话地址，30 秒失效；实例位置目录每 5 秒重新检查。索引只提供路径候选，命中后仍重新核验注册表账号和 runtime/session 归属。新增来源使索引失效，退出清理共享任务与索引。

原生正文就绪与执行能力分别记录：目录在线、控制流或模型查询成功不能隐藏云端正文；只有目标会话原生 snapshot/page 已收到才切换回原生视图。原生来源退回只读云端时清除正文就绪证明。跨会话、账号和订阅 epoch 的旧回复不能更新当前视图。

### 旧会话切换的请求隔离

原生只读调用与订阅复用账号作用域的 native-streams 通道，不占用正文 HTTP 连接池；通道只接受既有五类只读 endpoint，写入仍走原请求路径和授权。通道保持 64 个未完成请求、取消、断线失败和响应背压边界，不自动重放请求。

页面离开会话时取消其原生读取；同一页面的重复辅助查询复用 SharedReadGroup，单个调用者取消只解除自己的等待，最后一个调用者离开才取消底层请求。原生历史 page 保留各自游标与观察顺序。已发送写操作不受会话切换取消。离线来源仅有通道能力声明时不探测提醒存储；实际 reader 可用后沿用目录事件重新读取。历史加载期限保持 20 秒。

### 服务端身份归并与同步回执

Host 的 LocalSessionIdentity 只接受当前账号接口返回的 canonical_identity、runtime_ref 和 deduplicated_runtime_refs。会话目录批量观察这些关系，直接请求使用有界共享读取补充；最多保留 512 个会话，生命周期退出清理。发现器在同一来源库存中查询规范实例及其已验证旧实例，仍核验账号/环境/会话，保留原物理来源。多个物理副本仍拒绝任选；归并地址不改变 writer、epoch、conversationRef 或原日志。UI、Tools、SDK、标记及远控经过同一个 LocalSessionRuntime，不能通过浏览器提供别名扩大权限。

同步状态由补传 owner 的持久回执发布，经现有 native-streams 连接推送账号内的基线和增量，无新增轮询或 HTTP 长请求。Host 最多保留 256 个状态和 64 个观察者；断线、账号切换和卸载释放观察者。Browser 按连接内单调 revision 接收，切换会话读取对应状态，旧请求结果不再写入同步状态。重连重建基线，不把旧连接回执用于新生命周期。完成状态保存日志 revision，重启后未变化的已确认日志不重新进入 pending；未完成任务仍重新校验摘要再续传。

能力面沿用现有入口：Tools/SDK 的历史查询返回同一 Host 的 historySync，UI 额外使用已有只读连接订阅回执。制品重载、真实账号历史与远控结果以本轮验收记录为准。

### 目录身份、执行权与补传边界（2026-11-04）

`local` 仅表示当前 Runtime 的目录身份；`localAvailable/localAccess` 表示已验证的本机日志与操作能力。其他实例的日志即使在本机，也使用规范的账号路由 ID，不能假定裸 ID 已进入当前 Session Controller。原生 list 刷新或空闲 writer 释放不会删除可打开的账号入口；重命名与归档按本机能力授权。

实际取得 DSH 原生写锁后，Host 才发送 `local_recovery.writer_acquired`。后端仍核验账号及源版本，相同执行者、代次、epoch 的并发登记返回持久回执；不强夺其他实例持有的写锁。远控模型读取使用 session.follow 单会话投影，不枚举全账号目录。并发执行权登记共享在途请求，取消单个等待者不取消其他等待者。

补传选择经过官方转换器校验的最高可用物理日志版本，不要求已过时或损坏的更老版本必须成功。413 缩小本批前缀并按服务端 ACK 推进，单事件超限明确失败，不丢弃事件。历史等价比较以原始事件为身份；单方缺少可选工具展示投影不构成事件冲突，双方都有且不同仍拒绝，不改写云端原对象。

本轮后端已部署 TEST 并真实验证：执行权 MR319、展示身份 MR321，尚未作为正式服验收通过。没有可用新版日志且被官方 V0 解析器拒绝的数据仍需上游兼容支持，插件不改写原日志绕过校验。
