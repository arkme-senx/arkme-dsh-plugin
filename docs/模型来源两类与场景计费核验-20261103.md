# 模型来源两类与场景计费核验

日期：2026-11-03。本文更正《统一模型目录与积分-后端交接-20261102》中按供应商/渠道分组的语义，补充探索场景。接收：华焱（群内名称 Lucis）。

## 已确认的产品规则

所有选模型入口仅有两类：

1. **即我官方**：平台提供的模型与服务。百炼、DeepSeek、火山等是其背后的供应商，不能成为与官方并列的来源类别。
2. **用户自提供**：用户自行绑定的账户、API 凭据及其他服务，包括在 DeepSeek Harness 绑定的账户。使用该绑定账户的额度或结算方式。

来源、供应商、场景和计费方式是不同维度。同一模型名称可以对应官方和用户自提供的不同执行身份；不得按名称合并，也不能因供应商相同推断计费。

“即我官方”这一行显示即我积分、充值和用量入口。官方归属本身不能证明每个现有业务动作均已接入积分；用户自提供的账户额度不随即我充值增加。

## 本地前端修正

- DSH、Arko、录音、探索四个入口共用两类分组；探索包括个人档案、事件、目标、纪念日。
- 增加明确的模型来源字段，供应商保留为详情元数据；用户自提供条目显示绑定账户名称。
- 原生 Arko、录音和探索服务返回的目录归为官方；DSH 中 `arkme-managed` 为官方，其他已绑定 provider 为用户自提供。
- 按场景保存计费状态，精确路由合并时保留各自合同。一个路由在 Arko 中使用积分，不代表探索中的同路由也有相同收费规则。
- 已确认积分网关的场景显示“使用 Arkme 积分”；用户绑定账户显示“使用已绑定账户”；缺少合同的场景显示“此场景计费待确认”，不标为免费或默认收费，也不借用其他场景报价。
- 保留现有执行接口、授权、准入与扣费逻辑，不因本次界面调整增加收费。

## 代码核验事实与边界

本次检查的是本地 `jotmo-intelligent`，HEAD `b3b12ce5`，提交时间 2026-10-29。以下均为代码路径结论，未读取线上消费账本，不能代替部署验收。

| 路径 | 当前看到的实现 | 判断 |
| --- | --- | --- |
| DSH `arkme-managed`、Arko `managed-ai` | 既有托管积分网关与模型商品目录 | 官方来源；供应商可以是百炼等 |
| 已授权自动分析 | `gin/compound/automatic_ai.go` 的 `CompleteAutomatic` 调用 `managedaiclient`，供应商为 `aliyun-bailian` | 百炼已具有积分计费路径；不能将整个百炼标成不扣积分 |
| 个人档案 | `internal/personalprofile/paid_provider.go` 显式使用积分网关，并处理积分不足 | 已接入的代码路径 |
| 日历日总结 | `internal/dayreview/managed_model.go` 传用户、业务和 operation 身份到积分网关 | 已接入的代码路径 |
| 纪念日分析/核验 | `internal/anniversary/processor.go` 绑定 Token 归属；`verifier.go` 调用普通 provider；未发现本模块接入自动收费授权或积分客户端 | 存在官方供应商直连路径，需要确认是平台承担还是待迁移收费 |
| 普通 provider | `gin/compound/automatic_ai.go` 无自动授权 scope 时走 `direct`；`llm_provider_observe.go` 记录 Token 事实 | Token 遥测不是积分结算；需要按具体业务核验 |
| 事件、手动目标、录音总结等旧入口 | 有场景目录与执行路由，但目录没有返回清晰的场景计费合同 | 本轮不据供应商或模型名称推断收费；需继续逐业务核验 |

既有 `docs/ai-points-release.md` 也明确区分 Token 遥测、积分账本和平台承担的非收费后台业务。不能将所有直连一概视为扣费漏洞，也不能将所有官方业务一概展示成免费。

## 请后端协同确认

优先复用现有统一目录/业务合同，避免新增重复接口。需要明确：

- 每条执行身份的 `origin`（官方/用户自提供）、供应商和绑定账户身份，且不泄露凭据。
- **每个场景**的收费语义：积分、套餐内包含、平台承担、用户账户或未知；相应的准入、报价及有效版本。字段命名以已有合同为准。
- 纪念日等历史直连业务是否有意由平台承担；如应消耗积分，列明改造范围、授权与失败处理后单独推进。不能仅为补齐 UI 标签就开启新扣费。
- 检查已部署版本、当前生效费率/权益与实际账本。对同一测试任务关联业务 ID、operation ID、供应商 usage、预占、结算/释放记录；不能用成功返回或 Token 统计代替扣费证据。

## 验收

所有入口只有两类来源；官方百炼模型位于官方组；用户绑定账户位于用户自提供组。同名跨来源不串路由、不串计费。官方积分入口只在官方组标题中出现。缺少当前场景计费合同时明确待确认，切换、失败重试与账号切换不借用其他场景或账号的计费状态。
