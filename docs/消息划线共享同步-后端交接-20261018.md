# 消息划线与多人同步：后端交接

日期：2026-10-18。用户已确认交互；本次仅修改插件端，未修改或发布后端。以下均为待后端实现的 v1 合同，不能直接声明线上已有。

## 目标

选中一条消息中的片段后工具栏提供“复制 / 全选 / 划线 / 回复（个人为延展）”。自己和他人的消息都能划线。个人内容仅当前账号可见并跨设备同步；私聊群聊只在该会话内共享。

划线是附着在原消息上的独立标记，不改原文，不产生编辑记录或新聊天消息。多人重叠的片段只画一条线，查看时显示所有对应标记者，用户只能取消自己的标记。划线成功后无需额外确认弹窗。

## 插件已实现

- 共用局部引用的精确选区锚点（SHA256 + 版本 + UTF-16 范围 + 前后文），重复句子不会按第一次命中定位。
- 正文之外绘制细线，不插入 span 改写 Markdown/可复制文本，不挤占消息布局；支持对话、当前消息详情、明暗主题、折叠/滚动裁剪。
- 本地立即显示待同步细虚线；成功后实线。取消自己的标记不清掉他人的线；失败恢复之前状态，稳定 operation_uid 重试。
- 只在服务明确支持后写入。404/405/501 等未支持时显示“划线尚待服务端接通，暂未保存”。禁止本地假存、冒充多人共享。
- 仅批量读取当前可见消息，每批最多 40 条；滚动出现新消息、返回前台触发读取。服务启用后前台每 15 秒轻量核对，不刷新消息正文、滚动位置或文本选区。当前尚无 annotation 专用推送，15 秒核对是兜底，不等于秒级实时。
- 快照 revision 防止旧响应复活取消的标记；会话/账号切换中止请求，权限不可见投影清空标记。

## 1. 能力查询

全部为 POST，只读，不触发生成任务。

聊天：`/api/v1/chats/annotations/capabilities` 请求 `{chat_session_uid}`。
个人：`/api/v1/records/annotations/capabilities` 请求 `{}`。主题与全部视图共用同一条个人记录标记，不按主题复制数据。

返回 data：
```json
{"underline":{"enabled":true,"protocol_version":1,"projection":"arkme-text-v1","max_length":2000}}
```
只在存取、鉴权、撤销、历史读取和跨端同步都完成后开启。鉴权/网络错误不能按“不支持”吞掉。

## 2. 消息身份与选区

聊天目标包含 `chat_session_uid, record_owner_user_id, record_uid, relation_uid, sequence`，避免同一原记录转发或重复发送到不同群后互相串线。个人目标包含登录账号及 `record_uid`，不会把私人标记泄露给分享此记录的群聊。

插件 host 从签名 messageActionRef 解析身份，不接受前端随意拼接作者和目标 ID；服务端必须再次独立校验访问范围。

`anchor` 完全复用《消息局部引用回复-后端交接-20261018.md》中 quote_reply 的结构与规范化算法。最大 2000 UTF-16 单元。不要对 Markdown 源码偏移，不做近似字符串替换。前端签名快照不能替代服务端对原文当前版本的校验。

## 3. 批量读取

聊天 POST `/api/v1/chats/annotations/list`；个人 POST `/api/v1/records/annotations/list`。

请求示例（聊天有 chat_session_uid，个人没有）：
```json
{"chat_session_uid":"chat","messages":[{"target_index":0,"record_uid":"record","record_owner_user_id":42,"relation_uid":"relation","sequence":123}]}
```
`target_index` 仅用于本次请求匹配，必须逐一完整返回，不得漏掉空列表。个人 messages 不传 relation_uid/sequence。

返回 data：
```json
{"items":[{"target_index":0,"revision":7,"complete":true,"accessible":true,"annotations":[{"annotation_uid":"underline-id","actor_user_id":42,"actor_name":"当前查看者能看到的备注名","anchor":{"version":1,"projection":"arkme-text-v1","sourceDigest":"64位小写SHA256","start":0,"end":2,"text":"重点","prefix":"","suffix":""},"state":"available"}]}]}
```

- revision：每个消息出现位置的单调递增版本，新增、取消、编辑失效、撤权均推进。当前前端只接受完整快照，最多 500 条标记；达到限制要在创建时明确拒绝，不能截断列表还声称 complete。
- accessible=false：必须 annotations=[]，不能附带旧原文。缺权限与空标记是两种状态。
- actor_user_id 来自登录身份；actor_name 按当前查看者备注优先展示，再按群昵称/公开昵称回退。客户端自行比较 actorId 与当前账号判断是否自己的线。
- available：精确验证后的锚点。stale：原文已改变且无法可靠映射；显示未定位提示，不把旧位置强套到新内容。
- 撤回、全局删除、锁定、撤权：不可继续返回旧 anchor.text，需清理缓存与投影。客户端不会绕过未授权内容显示。

## 4. 新增与取消

聊天 `/api/v1/chats/annotations/create`、`/api/v1/chats/annotations/remove`。
个人 `/api/v1/records/annotations/create`、`/api/v1/records/annotations/remove`。

创建请求：消息身份 + `operation_uid` + `anchor`。
取消请求：消息身份 + `operation_uid` + `annotation_uid`。

- actor 从认证身份取得，不接受客户端指定 actor_user_id。
- 用户只能删除自己的 annotation；原消息作者、管理员也不能借此冒充他人操作，治理另走明确权限接口。
- 同一 actor + 消息出现位置 + 原文版本 + 选区精确去重；多人各自保留标记。
- operation_uid 作为幂等键；相同请求重试返回同一结果，相同键换参数应拒绝。操作幂等状态要覆盖断网、超时、返回丢失。
- 并发删除一个人的标记，不能用“替换整份列表”方式覆盖别人的新增。
- 返回 data 为完整快照，加 `operation_uid`，即上节 item 去掉 target_index。创建回执必须含当前用户精确 anchor，取消回执必须不含已删除 id。
- 缺失/不一致回执：插件按结果未知提示核对，沿用同一 operation_uid 重试，不能声称成功。
- 源消息已修改：返回冲突，用户重新选择；不要为了写入成功把锚点降级为模糊匹配。

## 5. 实时与跨端

服务端在事务提交后向有权查看该会话的在线设备发 `annotation_changed`（名称可讨论），载明会话、消息出现位置、revision。个人事件仅当前账号设备可见。事件可只携带无敏感内容的失效通知，客户端再按权限读取。

需和插件同事确认接入现有事件通道，当前前端 15 秒前台核对可先兼容，不能把轮询验收当成实时推送完成。离线重连、漏事件、乱序仍依靠单调 revision 和完整快照核对。新成员能否看加入前划线，沿用原消息历史可见权限，不能以“当前是成员”绕过历史边界。

移动端先实现读取展示、作者列表、取消自己的线，再补选区创建；旧端忽略划线仍能正常读原消息。划线不得触发 Bot、@提醒、未读消息数或修改原消息排序。

## 6. 验收

1. 自己/他人的消息分别划线；个人全部与主题视图、消息详情一致；切换设备/刷新后仍有。
2. 私聊双方、群聊至少三方同时划同一段和交叉片段；合并显示作者，撤销一方只移除该方。
3. 弱网先有即时线，失败恢复；服务已写入但客户端超时，再次重试不新增重复标记。
4. 源消息编辑、删除、撤回、成员退出/移除、个人隐私锁定，不能错划或泄露旧原文。
5. 重复词、Markdown、表情、跨段、长文折叠、滚动、窗口缩放、暗色模式、部分复制不带入作者/操作文案。
6. 阅读中收到他人划线更新，不能刷新整页、跳滚动或打断选区；不再可见的消息不持续轮询。

当前生产端没有经验证的划线能力接口；插件本地测试与真实浏览器的入口验证分别记录，不能代替多人云端验收。
