# 文件夹导出、原文件复用与额度规则（2026-11-04）

## 最终流程

数据管理 → 导出数据，直接显示「增量 / 按日期 / 全部」，默认增量。按日期右侧按钮打开日历浮框。选择本机文件夹后，Host 在其中创建账号、环境隔离的「即我备份」子目录，依次保存 Markdown、图片、语音和校验凭据；完成后自动确认保存，可打开文件夹。新界面不提供 ZIP、附件下载或「我已保存」。旧 ZIP Host/SDK 保留仅用于已发布调用方兼容。

文件夹路径只能由宿主原生 directoryPicker 取得，浏览器只持有密封引用，不能提交任意绝对路径。引用按账号/环境隔离，有效期 24 小时；操作时复查真实路径、设备号、inode 和目录类型。网页版缺少原生选择能力时明确提示，不回退到上传附件。

## 成本和本地数据

- 增量不调用旧 Premium check/pre/finish，不占用云端全量额度，也没有导出次数限制。首次必须在所选目录建立完整备份；不能凭另一目录或旧 ZIP 的设备进度假装已有基线；本地索引绑定环境/账号/设备/附件策略，不能只比较可能碰巧相同的版本号。
- 云端全部与按日期仍共用原有全量额度，避免分段日期绕过限制。
- 目录已有完整副本且与服务器备份链一致时，全部/日期先同步增量，再从本地筛选、排版，不再消耗全量次数；无网络时可以输出上次完整本地副本，并显示数据截止时间。权限类业务错误不触发离线降级。
- 正常使用时下载的受信任图片/语音原文件与导出共用 OriginalFileStore；按环境、账号、OSS 对象路径去重，签名轮换不改变身份，缩略图不能冒充原文件。缓存只有读到 EOF、长度和 SHA-256 校验、fsync 和原子重命名后才可复用。缓存可回收，上限每账号 64 GiB，不能当永久完整备份。
- 选定目录中的完整副本是独立文件，不受应用原文件缓存回收影响。增量只取变更正文和缺少的新原文件，重复完整导出可用本地原文件。未为旧缓存目录做无差别迁移，不声称旧客户端历史下载全都已纳入新索引。
- 这次实现的是原文件复用、持久备份副本和副本离线导出，没有把所有产品页面改为完整离线数据库。

目录包含账号身份清单、SQLite 本地索引、pic/voice 原文件、每次独立 Markdown 及 JSON 凭据。新导出不覆盖之前的 Markdown；文本删除/隐私锁等变化同步进当前副本，旧的用户导出文件不会被静默删除。保存目录需要和其中原文件一起保留，单独移动 Markdown 会导致相对链接失效。

## 写入和失败恢复

只在记录数量、分页、原文件、Markdown 和凭据全部校验后提交完整本地索引，再调用 finish/saved。日期导出不推进完整基线。取消或失败不推进增量进度，已完整下载的原文件保留用于重试；不将残缺数据标记成功。确认响应丢失时读取准确任务状态，复核 Markdown、凭据及原文件后恢复 saved，不盲目重复扣费。可重试的未知远端结果保持失败关闭。

副本计数按所选日期计算；同步尚未写入的变化不伪装成准确总数，界面标明先显示本地已保存数量。运行中固定确认时的统计，避免空白闪动。浅色/深色样式与日历窄窗口定位均纳入验收。

## 配套 Record 合同

既有 /api/v1/records/export/range 路由保持，能力增加 policy_version=3、attachment_reuse、incremental_no_quota、large_archive。新目录流程在 prepare/start/page/sign/finish/saved/status 请求携带 policy_version=3；旧节点严格解码会拒绝新流程，避免滚动部署误将增量按全量计费。旧调用方不主动开启附件复用，仍拿到独立 ZIP 所需的文件引用。

prepare 仅在 reuse_attachments=true 时增加 file_refs.backup_path、source_preview_uid、reuse。附件身份在已确认账本中保存；未变化原文件可复用，签名接口拒绝为标记 reuse 的文件重新签名。记录内容摘要不包含这类传输字段。服务端仍复核当前用户、隐私锁及实际文件范围。

后端快照按 100 条有界批次落库，使用索引和仅键游标编号，不在内存保留全账号正文。正文上限 256 MiB、单次最多十万条、制品身份上限 64 GiB；超限错误指出具体资源。每账号准备租约和执行租约分别控制并发，不与会员次数混用。准备状态先预留容量，部分失败使用独立上下文清理。
