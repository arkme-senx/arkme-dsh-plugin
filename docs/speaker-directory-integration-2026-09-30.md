## 当前行为

- 录音入口只读统一 summary，人数与新增数完全由后端提供。首次 building/null 显示整理中；有完整空快照才显示零。
- 目录以 `all/marked/unmarked + frequent/recent + query` 查询全局列表，每页 50 人，保持服务端顺序和本人置顶。查询按 300ms 防抖，不再扫描所有旧名单，不再用前端 2,000 人上限限制目录。
- 改变查询重新取首屏；翻页固定原 snapshot_version 和查询。重复人物去重，版本变化、循环游标拒绝追加，snapshot_expired 重取摘要及首屏。缓存按账号、查询和快照隔离，最多缓存 12 个查询。
- 仅“全部、无搜索”目录首屏实际渲染且页面可见时提交 list.through_cursor。完整空目录也可确认。预取、入口展示、搜索、筛选、未知快照、隐藏页面不确认。
- seen 成功后重新读取 summary，不自行清零新增数。离线待确认凭据仅保留于当前运行的原账号；失效凭据停止重试，重新展示首屏后才确认新凭据。跨端以 summary 同步。
- 可见期间约 30 秒检查摘要，building/stale/failed 遵从 retry_after_ms。后台停止；在线、重新可见和窗口激活时检查。并发请求合并；HTTP 429 同时尊重 Retry-After 和 retry_after_ms 的较长值，手动刷新不绕过等待。
- failed/stale 保留可用内容，disabled 保留入口、停止目录轮询和确认。未知状态不伪装为空；待处理诊断字段不加入人数。
- 列表 detail_ref 由 Host 封装为账号及环境绑定的引用。选中人物时再接入现有详情；未标记先通过既有 detail 获取候选信息，再复用 mark-options、候选版本、标记和签名音频链路。已标记保留 presence expected_version，不使用目录版本替代。失效候选和 stale presence 刷新目录引用后恢复。
- 已标记人物按当前页的稳定 speaker ID，通过既有说话人绑定及公开资料补齐头像；头像异步加载，不阻塞目录、排序或分页。未绑定头像时使用默认图，未标记人物保留编号头像，编号为零时不制造“说话人 0”。后端当前空 avatar_ref 不拼接为 URL。
- 本人引导只依据无搜索主目录的可用首屏；搜索页缺少本人不触发引导。声纹状态读取失败显示不可用。

新增 Host 操作：`speaker-directory.summary/list/seen/open/avatars`。沿用 ServiceRuntime 的当前环境地址、登录恢复和业务成功码 200 校验，不硬编码测试服务地址。seen 需要同源页面 Origin。
