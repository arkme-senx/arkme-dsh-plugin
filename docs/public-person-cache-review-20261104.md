## 复现与修复

以下均来自代码路径审查和可控回归复现，不代表已在用户真实群数据中复现：

| 问题 | 原因与影响 | 修正 |
| --- | --- | --- |
| 失效后恢复旧头像地址 | `invalidatePublicProfile` 只清内存，下一次读取从 SQLite 恢复旧地址 | 按环境、当前账号、目标用户同步失效内存与持久记录；后续读取等待该目标的失效完成 |
| 旧响应覆盖新头像 | 人物资料进行版本仲裁前就更新了独立头像地址缓存 | 先选择较新人物结果，再统一更新头像；较新的明确不存在也不会被旧响应复活 |
| 异常响应被当作用户不存在 | 只校验 `items` 是数组；错误标识、非对象行和重复行被跳过或覆盖 | 验证批次数量、行类型、请求标识、唯一性、字段类型和长度；整批无效时不写入缺失状态、不删除已有公开资料 |
| 损坏默认头像抛错 | `avatarFallback: null` 被直接读取属性 | 验证对象、标签和色号范围；损坏内容按缓存未命中处理 |
| 慢磁盘读取盖过新网络结果 | 磁盘读取完成后未重新检查内存中新到的结果 | 缓存探测与新鲜度恢复均在读取后重新仲裁，不返回或恢复较旧快照 |
| 连续强制刷新仍命中缓存 | 单调时间戳可能略大于同一毫秒的系统时钟，`maxAge=0` 的旧比较仍命中 | 显式无条件绕过新鲜度；读本地记录仅用于接续版本时间戳 |
| 重启后新资料未写回磁盘 | 重启前逻辑时间戳略领先系统时间，SQLite 正确拒绝了较小的新时间戳 | 读取持久快照后接续其逻辑时间戳，新请求排在已知快照之后 |
| 失效后的重试加入旧请求 | 请求协调器将读取归一化为 owner 路由键，独立清应用缓存不会解除旧请求复用 | 由 ServiceRuntime 统一失效主池和消息投影池对应路由；受影响的在途读取不能再填缓存，其他已发出的独立读取继续完成 |

同时将磁盘恢复到内存的入口纳入原有 4096 条容量限制。新增的在途读取与失效状态只保留到各自操作结束，不建立无限增长的永久目标版本表。

重启后从持久资料得到的头像地址也可能已过授权期。图片下载失败时，应用层最多发起一次公开资料强制读取并重试一次图片；取消、超大图片、格式错误等不会触发资料刷新与重复下载。测试分别记录成功、二次失败及终止错误的请求次数。

## 审查范围与环境

- 输入与响应契约：异常集合与行、重复/越界标识、超长字段、损坏缓存、时间边界。
- 隔离与授权：环境、当前账号、签名成员引用保持隔离；只缓存公开展示字段，群角色、备注和操作权限仍由原有路径判断。
- 顺序与并发：旧正结果/旧缺失结果、磁盘与网络交错、目标/账号/全局失效、取消消费者、相同目标请求复用；主池和消息投影池分别测试。JS 在单进程事件循环中执行，使用可控 Promise 门闩制造交错，不适用 Go 等语言的 race detector。
- 数据库：真实独立 SQLite 临时数据库，执行事务、版本条件更新与清理，验证每账号/环境 4096 条上限及相互隔离；缓存读写失败不阻断正常网络读取。测试只写临时目录。
- 资源：每批最多 50 人；新鲜 A/B 群复用仍为 0 次新增公开资料请求；头像恢复在资料接口正常响应的隔离场景中为 1 次资料 HTTP 和 2 次图片 HTTP，终止错误只有 1 次图片 HTTP。资料读取沿用 owner 既有的最多 3 次传输恢复尝试，因此遇到瞬时上游故障时，1 次应用读取不等于只有 1 次 HTTP 尝试。
- 兼容：保留现有 Host 调用与 SDK 接口；新增缓存接口为可选能力，不改变云端请求字段、成员分页或聊天数据模型。
