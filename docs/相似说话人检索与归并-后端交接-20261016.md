## 1. 用户目标和当前交付边界

账号中大量未标记声音分组可能属于同一真实人物。用户希望先看一个组是否内部一致，再找到其他接近的组，经试听核对后统一为一个人物；不知道姓名时也应允许保留一个匿名身份。

- 组内一致性：一组内部是否混入不同声音，用于发现需要拆分的组。
- 组间距离：不同组有多接近，用于找归并候选，不能转换为未经校准的身份概率。
- 正式人物归属：人工确认后写入、可撤销、跨设备一致；不能由相似候选自动推断完成。

插件本轮完成目录与详情的“找相似声音”、候选证据显示、跨页勾选、基准与候选片段对比及交替试听、统一标记／排除关系预览。已有／新人物／匿名身份三种目标可预览。**当前没有接入归并或排除写入；保存按钮明确禁用，显示尚未保存。** 不修改后端，不部署，不合 dev。

## 2. 可复用的已有代码与限制

核查参考：本地 origin/master `205e272ccae48b2533d2942ff2a809b2170d24f1`，以及本地工作目录相应实现。生产部署版本仍需后端核实，本轮未拉取或修改后端工作区。

1. `internal/audio/unmarked_speaker_readonly_cluster.go` 已有未标记 DaySpeaker 向 InnerSpeaker 和临时跨天簇的只读匹配。当前阈值使用 `DefaultThreshold = 0.3`，次近差距为 `0.05`。这些是这一分支的规则，不代表所有识别链路统一口径。
2. `findUnambiguousReadOnlyCluster` 跳过日期重叠的临时簇。这项保守限制能减少误归并，但同日被分成多个组的同一人也可能继续分开。**相似候选检索可以展示这类候选供人工核对，不应直接删除自动归并的安全限制。**
3. `/unmarked-speakers/mark-options` 源码已有正式人物推荐及部分 `match_distance`，插件目前只投影推荐人物，不显示这些距离。它不等同于匿名候选与匿名候选之间的检索。
4. `/unmarked-speakers/batch-mark` 已存在：最多 20 个候选，要求候选版本；当前目标为已有手工人物或新昵称，已有目标要求 `ref_usr_id == 0`。包含冲突检查及部分回滚逻辑，不能描述为完全没有保护。
5. 上述批量路径当前仍只选择第一条可用 `targetVector` 作为新增声纹；匿名身份归并、联系人／本人目标、片段子集、操作状态核对和完整撤销需要补齐。详见持续学习交接，不建议前端用多个单独 mark 请求模拟原子批量操作。

## 3. 已接入的拟定只读接口

以下为插件适配的建议协议，不能当成已上线 API。上线前请确认字段、路由和错误码，再做真实联调。

### 3.1 相似分组检索

`POST /api/v1/audio/speaker-directory/similar`

```json
{
  "schema_version": 1,
  "detail_ref": {"type": "candidate", "id": "candidate-example", "expected_version": "optional-source-version"},
  "limit": 20,
  "cursor": "",
  "version": ""
}
```

- detail_ref 沿用目录身份，支持 candidate 和 speaker。插件传入前解封账号绑定引用；后端仍需验证账号、资源归属及版本。
- 首页 cursor/version 为空，后续页绑定第一页的 version。页面最多 20 个候选；后端按稳定距离顺序返回，距离相同用稳定身份键排序。
- 候选第一期只返回未标记组，允许基准为已标记人物，用于“找更多属于此人的声音”。合并多个已标记正式人物不是本期自动行为。
- 仅搜索当前账号可访问且模型兼容的声音。不要把新旧不兼容向量直接放进同一个近邻空间。

响应示意：

```json
{
  "supported": true,
  "schema_version": 1,
  "state": "ready",
  "version": "similarity-snapshot-example",
  "metric": "cosine_distance",
  "model_version": "embedding-model-example",
  "aggregation": "robust-multi-reference-v1",
  "score_definition": "cohesion-calibrated-v1",
  "searched_count": 9000,
  "total_count": 10000,
  "anchor": {
    "person_key": "anchor-example", "type": "unmarked", "display_name": "说话人 A",
    "display_number": 1, "is_self": false, "day_count": 12, "last_seen_at": 1791907200000,
    "detail_ref": {"type": "candidate", "id": "candidate-example"}
  },
  "anchor_consistency": {"state": "ready", "score": 93, "analyzed_count": 120, "total_count": 120, "review_count": 0},
  "items": [{
    "person": {
      "person_key": "other-example", "type": "unmarked", "display_name": "说话人 B",
      "display_number": 2, "is_self": false, "day_count": 8, "last_seen_at": 1791907200000,
      "detail_ref": {"type": "candidate", "id": "other-candidate-example"}
    },
    "distance": 0.12,
    "consistency": {"state": "partial", "score": 91, "analyzed_count": 60, "total_count": 80, "review_count": 2},
    "reason": "多段清晰声音接近，仍有 2 段需复核"
  }],
  "has_more": false,
  "next_cursor": ""
}
```

字段约束：

- state 为 ready / building / insufficient。后两者返回空 items、has_more=false；不以空列表伪装检索完成。
- searched_count 为当前索引中已覆盖、可参与该查询的候选身份数；total_count 为此次检索目标范围内的候选身份总数。这里是索引覆盖度，不是 ANN 实际逐一比较次数，也不是最终相似结果数。不得把目录已加载 50 条当成整个账号已搜索。
- 同一候选不重复，不返回基准自身。anchor.detail_ref 必须与请求一致。
- distance 是按明确 aggregation 算出的有限余弦距离 0–2，越小越近；没有可解释数值时为 null。不得返回百分比相似度却标为距离。
- 一致性规则复用此前协议：有限 0–100；ready 覆盖全部且至少 2 段，partial 明确局部；building/insufficient 时 score=null。review_count=null 表示未知，不等于 0。
- **这里的一致性是该目录身份全部成员范围，不能拿单日一致性冒充。** 即使基准是已标记的人物，也应检查其内部是否混入声音。
- model_version、aggregation、score_definition 和 version 必须可解释且版本化；跨页必须同一证据快照。归属／排除／模型变化时使旧快照过期，要求重新查找。
- 404/501 或 `{ "supported": false }` 才表示能力未开放。网络、鉴权、数据冲突和格式错误正常报错，不能吞成“没有相似人”。
- 只读请求不应触发无限量历史分析。索引构建在后台有预算、有进度、可恢复，查询可先返回 building 或部分覆盖。

### 3.2 基准与候选试听片段

`POST /api/v1/audio/speaker-directory/voice-samples`

请求：`{ "schema_version": 1, "detail_ref": { "type": "candidate", "id": "candidate-example" }, "limit": 3 }`。

响应示意：

```json
{
  "supported": true,
  "schema_version": 1,
  "detail_ref": {"type": "candidate", "id": "candidate-example"},
  "items": [{
    "sample_key": "sample-example", "time_label": "2026-10-14 12:00:00", "transcript": "合成示例",
    "locator": {"session_id": "session-example", "child_id": "child-example", "start_at": 1000, "end_at": 5000, "num": 7}
  }]
}
```

- 最多 3 个当前真实存在、归属可核验的切片。start_at/end_at/num 是既有播放切片文件定位口径，不是任意剪辑范围或 Unix 时间；范围必须精确存在。需要重新切片时，先完成有授权的后台处理，不能拼一个不存在的 OSS 文件名。
- 优先不同日期／设备条件下的清晰片段，避免全取同一录音的重复切片。必要时取一条边界样本帮助发现混入，不能仅挑最像的片段掩盖问题。
- 插件通过已有账号限定媒体签名器发放短时 mediaRef，不接受响应里的任意 URL，也不向前端返回 OSS 凭据或原始向量。
- 新接口未开放时，未标记候选可复用既有 `/unmarked-speakers/detail` + `/segments` 的前 3 条试听；**这些是已有片段，不宣称后端已做代表性筛选**。正式人物没有此回退时明确暂不可用。
- 短时播放引用过期或播放失败可重新读取；切换人物、账号或收起对比会停止播放。

## 4. 归并、排除与统计的后端要求

### 4.1 先预览再提交，保留来源

建议统一提供 preview / commit / operation-status / undo；最终路由待后端确认。优先复用既有 batch-mark 的候选解析、版本检查和冲突处理，不重复造一套无关联归属。

预览绑定基准、选定候选及各自版本、可选片段子集、目标身份、证据版本、过期时间。返回准确的去重片段数、日期范围、原始声音组数、目标目录身份、冲突和混合声音风险。前端不能把各组 day_count 或 segment_count 直接相加作为去重总数。

提交时再次验证范围和人工标记优先级，用同一幂等键关联写入／状态查询／撤销；超时后先核对结果，不换键盲重试。归并、目录映射、样本更新、负证据、审计及后续投影失效需要可靠一致性机制，避免只完成前半段。

当前前端预览最多勾选 100 个候选，尚无提交。既有 batch-mark 限制为 20 个；正式联调必须以后台能力返回的 max_candidates 收紧前端或扩展后端，**不能前端切成多个请求伪装一次原子操作**。

### 4.2 三种目标

- 已有人物：同一个稳定身份，支持本人、联系人和手工人物的一致口径；不得按同名合并。
- 新人物：仅创建一次，提交失败不能遗留重复人物；名称长度与后端限制统一（既有批量接口 40 字）。当前预览最多输入 40 字。
- 暂不知姓名：创建／复用一个稳定匿名身份，目录只呈现一条，可后续命名，不要求伪造昵称。不删除原 DaySpeaker/InnerSpeaker/片段来源。

混合组只允许确认的子集进入目标。选择多个未知声音不能自动证明它们互相同人；先解决各组内不一致，再谈整组归并。

### 4.3 明确不是同一个人

保存有版本、有来源、可撤销的 cannot-link：基准与各个选定对象之间的否定关系。勾选 B、C 排除于 A，**不意味着 B 与 C 也不同**。支持片段级范围，避免把混合组全部作为某个人的负证据。

后续推荐、归并和历史重算遵守有效人工否定；撤销／拆分后迁移约束必须可追溯。不因单次否定全局降低阈值。曾明确排除的候选不能刷新后反复推荐。

### 4.4 目录数量与长期学习

- 100 个未标记身份统一成一个新人物／匿名身份，目录结果应为 1 个身份，总数减少 99；全部归入一个已存在且已计数的人物，总数减少 100。录音片段数和来源分组不因此丢失。
- 使用同一版本的服务端 summary/list 更新；前端可以即时呈现待同步效果，但不能把请求已发出当作权威计数。失败回滚、结果不明时保留核对入口。
- 清晰且明确确认的多种声音样本才进入人物库；自动候选和用户仅浏览的记录不得充当训练标签。改绑／撤销样本必须退出原人物库，参见持续学习交接。

## 5. 检索与排序建议

先复用兼容模型的已有向量和索引。按账号组织增量近邻检索，必要时近邻召回后用多段样本重新核对；不要每次页面打开就扫描／下载全账号向量。是否使用近似索引由实际规模、延迟和召回评估决定，不预设必须新增某个库。

组间距离要利用多个可靠样本及组内结构，避免一个受污染中心决定整个分组。A 接近 B、B 接近 C 不意味着 A、B、C 可以自动整体归并；预览需验证整体兼容性和人工否定约束。同人换麦／远近距离与异人相似声音都要纳入评估。

候选按可核验的相似证据排序；经常出现、明确现场交流可用于展示优先级，但不能替代声纹证据。手机播放来源、噪声、重叠及证据不足要注明，不能把播放内容的所有声音归为一个人。

## 6. 验收

- 同一个人跨日期、跨文件、同一天多个分组都能进入候选；有真实距离、模型和覆盖说明。
- 两个很像的人不被自动合并；组内混入第三人的候选能进入此前一致性审查／片段拆分流程。
- 只选 B 时，C 不随之归并；排除 A-B 不影响 B-C；未知姓名归并保持稳定匿名身份。
- 旧版向量缺失／不兼容时显示证据不足；索引只覆盖部分历史时不能显示已检查全账号。
- 分页同版本，不重不漏；版本变化清空旧选择并要求重新核对；跨账号取消请求和试听。
- 提交超时、并发标记、重复请求、撤销冲突都有可核对结果，不能返回假成功。
- 目录数量收敛而原始录音来源保留；刷新与其他端一致；未来识别改善必须单独验证，不能由本轮 UI 测试代替。
