# 对话输入框截屏（桌面原生与浏览器）

## 范围

- 发给自己、私聊、群聊（含自己的主题）工具栏，表情右侧新增“截屏”。
- Arkme 桌面运行环境保留 macOS 原生区域框选；普通浏览器改为“浏览器选择屏幕/窗口 → 静态截图裁剪 → 加入草稿”。
- 不自动发送、不覆盖文字和既有附件，恢复原光标位置。
- Esc 取消静默处理。切换会话、退出输入场景、切换账号或关闭页面时取消，不向新会话添加截图。
- 无标注、马赛克、全局快捷键、自动隐藏应用；浏览器不提供跨桌面的原生框选覆盖层。Windows 原生截屏暂不支持，但支持选屏的浏览器可使用网页流程。
- 未改已安装的 Arkme 客户端、宿主原生代码或权限配置。macOS 屏幕录制授权由系统决定，不绕过授权。

## 浏览器流程与边界

1. 只有用户点击剪刀后才调用 `getDisplayMedia({ video: true, audio: false })`；同一点击调用栈内发起，不在前面等待宿主能力请求。
2. 用户在浏览器中选择屏幕、窗口或标签页。得到第一帧后立即停止所有轨道，再显示裁剪弹窗；不会在编辑时持续共享，也不采集音频。
3. 截图弹窗支持拖动选区（含反向拖动）、取消、使用整张、完成裁剪；同时适配明暗主题、窄窗口和键盘关闭。
4. 只有确认后才复用附件暂存。截图不会自动发送，不替换原文字和已有附件，完成或取消后恢复原输入位置。
5. 会话、账号、页面可见状态变化或组件卸载时取消；浏览器选屏窗口无法由网页强制关闭，但后续即使授权返回，也立即停止流，不添加到新会话。
6. 等待选屏超过 120 秒取消本次操作，读取画面超过 10 秒释放共享；裁剪静态画面不设操作限时。
7. 不安全地址、缺少选屏能力、拒绝授权、系统权限或读取失败均显示提示，并提供“兼容浏览器/系统截屏后粘贴”的替代路径。

原实现只有本机 `desktop.screenshot.capture` 路径，并不能证明普通浏览器拥有原生框选能力。现在以现有 `arkmeDesktop.appVersion / harnessVersion` 桥接标识识别 Arkme 客户端；不把所有 Electron 内嵌浏览器都当成 Arkme 原生客户端。

浏览器安全限制不能绕过：每次都需要用户主动操作并选择共享来源；某些内嵌浏览器即使暴露 API，也需要宿主实现选屏支持。参见 [W3C Screen Capture](https://www.w3.org/TR/screen-capture/) 和 [Electron desktopCapturer](https://www.electronjs.org/docs/latest/api/desktop-capturer)。本次不改 Arkme 或其他应用的宿主权限配置。

## macOS 原生路径约束

只在明确点击按钮后启动 `/usr/sbin/screencapture -i -s -x -t png`，不执行 shell、不接受调用方路径、不读取剪贴板。接口要求本机连接、当前同源页面和有效登录账号，截屏前后核对账号；不注册为 MCP 工具。默认 120 秒超时，仅允许一个截屏进程；页面取消和账号退出会终止进程。

PNG 先写入独立的私有临时目录，校验大小及签名后只返回图片内容，不返回本机路径。成功、取消、出错均清理该临时目录。图片加入草稿时沿用已有文件数量和大小限制，只有用户点发送才进入消息发送流程。

## 真实环境验收

1. 已登录 3098 后，分别进入发给自己、私聊、群聊；保留文字及一个已有附件。
2. 将光标置于文字中间，点击表情右侧的剪刀。浏览器先选择共享来源，再在网页弹窗框选并确认；Arkme 桌面原生路径直接框选。确认新增缩略图、文字未改、光标恢复，消息未自动发送。
3. 再次截屏按 Esc，确认原草稿不变。重复点击只能打开一个截屏流程。
4. 拒绝系统屏幕录制权限时应出现明确提示，不生成空附件。允许权限后重试。
5. 切换会话或账号后，迟到的图片不得出现在新会话；已完成的草稿附件仍由原有草稿规则保留。

系统权限通常属于实际启动插件的运行环境；请以 macOS 权限面板显示的应用名称为准，不修改或清空其他客户端权限。
