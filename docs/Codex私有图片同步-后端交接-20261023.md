# Codex 私有图片同步：后端交接

日期：2026-10-23。状态：插件本机采集、持久保存和预览已实现；本文件的云端接口为待确认提案，尚未调用、未宣称已上线。

## 用户要求

Codex 用户输入的图片、回答实际展示的图片，都应跟随对应消息同步到即我。图片只允许所属用户本人查看，团队其他成员及团队管理员不能查看。本人另一台设备登录后也应能看到。

现有团队文字共享规则继续适用。图片不能直接沿用团队文字的读取权限，也不能只通过前端隐藏实现隔离。

## 当前插件完成的边界

- 在已经绑定当前即我账号的 Codex 来源中，按原始 session/turn 关联图片；不按标题猜测、不扫描其他人的目录。
- 支持原始用户消息的图片数据、回答 Markdown 中的本地图片，以及明确生成并展示的图片输出。远端图片 URL 暂不下载；缺失、格式不支持或超过限制时显示“原图片不可用”。
- 图片独立保存在插件 Host 的稳定私有账号目录中的 SQLite 表，包含账号、原始 session、turn、消息类型及序号；不会进入团队同步事件。重启和临时原文件删除后仍可读已保存图片。
- 原图经解码后保存为 PNG，缩略图为 WebP，移除原图附带的元数据；当前按单张 20 MiB、40M 像素、每条消息最多 32 张设置处理上限。GIF 仅静态首帧。
- 页面展示“仅本人可见 · 尚未同步到云端”，点击放大、加载失败重试。Host 的 `team.codex.image` 再次验证账号、来源、任务、轮次及图片引用。
- 分享/转发文本和团队同步正文清理实际图片链接、base64 和附件路径，不携带图片字节或本机图片引用。
- 本机仅补齐有可靠原始记录的历史图片；已丢失的数据不伪造恢复。

## 后端最小协议

以下路由名可按现有服务调整，但权限语义不能省略。可复用 `/api/v1/files/prepare-upload` 的分片、上传凭据及完成机制，前提是文件服务支持不可转为团队可见的私有资源用途，并与 Codex 消息绑定。

1. **准备上传**：建议 `POST /api/v1/team-codex/images/prepare-upload`。
   输入 `source_id/task_id/event_id/event_version/image_ordinal/client_image_id/size/mime_type/sha256`。所有 ID 沿用已确认的云端事件 ID，禁止传原始本机路径。服务端从登录身份确定 owner，验证 source/task/event 的真实归属，不接受客户端自行指定 owner。
2. **完成上传**：建议 `POST /api/v1/team-codex/images/complete-upload`。
   校验实际文件类型、大小、内容摘要及上传归属，生成不可猜测的 `image_id`，返回 `width/height/state/version`。绑定消息与附件应幂等；重试不能生成多份。同账号相同内容可复用，跨账号去重不得透露他人的图片是否存在。
3. **读取清单**：扩展现有 `events/list`。
   本人可得到 `private_images: [{image_id, ordinal, width, height, state, version}]`；同团队其他成员只能得到通用私有图片占位，不返回 ID、URL、文件名、尺寸、摘要、OCR、EXIF、本机路径或图片内容。
4. **读取图片**：建议 `POST /api/v1/team-codex/images/read`，输入 `image_id` 和 `variant=thumbnail/original`。
   每次验证当前登录用户等于图片 owner。优先认证读取/代理流；不要把无登录即可打开的永久地址当成私有读取。若底层使用短时签名 URL，须评估转发 URL 后他人能否直接读取，不能宣称满足严格本人权限。
5. **失败/删除/更新**：返回可区分的本人状态 `pending/ready/failed/deleted`。读取别人图片统一不可访问，不泄露是否存在。消息更新后的附件版本不能重新复活旧图片；已完成上传但未绑定消息的对象需要清理。删除事件时需要明确图片保留、恢复及最终删除周期。

图片所属账号不随加入、退出、解散团队或角色变化迁移。退出团队后本人历史图片如何从个人入口读取，请后端明确；不得通过保留团队访问权限解决。

## 共享路径与历史兼容

- 团队工作台、搜索结果、通知预览、日志、导出、复制链接、公开分享页、转发快照都不能把私有图片带给其他用户。
- 同一图片的缩略图和原图使用相同权限；猜 ID、换 event_id、换 owner、换团队、旧缓存命中均不能绕过。
- 本人“发给自己”若未来支持引用图片，应保存同一私有图片的引用，并继续按本人身份读取，不能生成公开副本。
- 旧客户端可能已把 Markdown 图片 URL 作为正文同步。新版插件会在重新同步及展示时清理图片地址；后端仍需排查已存旧事件、搜索索引、旧版本及分享快照，清理可访问图片地址，避免只修新版 UI。
- 当前本机 `ref` 是本地随机 ID，不能直接当作跨设备 `image_id`。云端 ACK 返回后建立本机 ref 到云端 image_id 的映射；未收到 ACK 必须继续显示未同步。
- 不从任意正文 URL 自动抓图，以免访问带凭据的地址或引入服务端任意地址访问风险。

## 验收矩阵

| 场景 | 预期 |
| --- | --- |
| 用户 A 上传截图并收到生成图片 | A 的原对话按顺序出现两侧对应图片 |
| A 另一台设备登录 | 图片从云端恢复，实际完成后才显示同步完成 |
| 同团队 B 查看 A 的任务 | 仅通用占位，响应中不含私有图片引用及地址 |
| 团队管理员查看 A 的任务 | 与 B 相同，不因管理员权限获准读取 |
| B 获取 A 的 image_id，直接调用原图或缩略图接口 | 拒绝，不能返回图片字节或可读 URL |
| A 上传中切换到 B | 停止原账号任务，B 无缓存图片、无跨账号上传 |
| 上传完成响应丢失后重试 | 幂等恢复，不产生重复图片 |
| A 退出团队 / B 加入团队 / 团队解散 | 不扩大任何人的图片读取权限 |
| 团队转发、导出或公开链接 | 无原图、缩略图、图片地址和私有元数据 |
| 原始临时图片删除、插件重启 | 已入库的图片仍可恢复；确实丢失的显示不可用 |

## 对接代码

- `src/team-codex-private-images.ts`：本机后台索引、持久保存与按账号读取。
- `src/team-codex-service.ts`：权限校验及消息投影。
- `src/team-codex-image-text.ts`：共享文本中的图片地址清理。
- `src/team-codex-cloud-journal.ts`：现有文字同步，刻意不发送 privateImages。
- `src/client/redesign/contacts/CodexPrivateImages.tsx`：缩略图和预览。

后端返回真实字段、错误码、权限验证结果和部署环境后，再接入上传与跨设备读取；不要直接开放团队图片权限作为过渡。
