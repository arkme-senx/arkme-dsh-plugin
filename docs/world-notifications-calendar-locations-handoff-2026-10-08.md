# 世界回复通知与日历位置交接

日期：2026-10-08。分支：`codex/ts1008-04-通知回复与日历位置`，基于 `origin/dev` 的 `03d07a6e`。

本次补齐桌面插件遗漏的评论回复通知，移除个人日历中的原版日历入口，并增加位置名称和当天位置地图。实现包含插件 UI 与调用现有接口的 Host 适配，没有新增或部署云端后端。后端同事需要确认收件人通知列表、批量位置读取和正式地图服务方案。

## 已完成的行为

- 世界通知覆盖自己发布的世界及自己在他人世界下的评论，排除自己回复自己，按互动引用去重、按互动时间排序。
- 点击通知读取当前仍公开可见的原文，展开评论并翻页定位目标回复；删除、撤回、审核不通过或不可访问的内容显示不可查看。返回对话仍选中通知。
- 点击一条世界通知不会把全部世界互动标为已读；现有「全部已读」继续调用原有汇总已读接口。
- 个人日历不再显示「原版日历」入口或切换到旧界面。其他地方复用的月历组件保留。
- 时间条目优先显示已有地址或地点名，可见条目懒加载设备位置详情；没有地址时显示「地址暂不可用」，不编造地点。
- 「当天位置」独立分页读取所选日期的原始个人记录，不受时间线分组、来源筛选或当前已展开条目数量限制。地图点位与时间列表联动，同坐标聚合，保留每次记录，不连接成推测路线。
- 加载中可停止；部分失败保留已读取的点并明确提示尚未完整。关闭、切换日期或账号取消请求；受限及加密记录不显示位置。

## 通知遗漏根因

`1026f46f`（2026-10-02，`feat: unify Arkme notifications`）引入的统一通知中心调用 `world.mine` 取最近 10 条原始世界，再为每条读取前 50 条互动。`WorldService.listMyWorldFeed` 会过滤评论，因此在他人世界下发表的自己的评论不在扫描来源中；对这些评论的回复无法进入桌面通知。较旧原文的新回复、后续分页的互动也可能遗漏。手机收到通知不代表桌面所读列表完整。

此前点击世界通知统一跳转「我的世界」，无法定位他人的原文。本次增加仅供插件使用的 `world.notification-sources` 和 `world.notification-target` 操作，复用已有 HTTP 接口，不要求部署同名云端接口。

## 当前调用的已有接口

| 用途 | 已有接口及读取方式 |
| --- | --- |
| 我发布的原文与评论 | `POST /api/v1/public-record/my-list`，每页 20，按原始列表条数推进 offset，保留归属当前账号的可见评论 |
| 评论及回复 | `POST /api/v1/public-record/extend-list`，经 `world.interactions.list` 每页 50，读取后续分页；评论作者只接收对自己评论的直接回复，原文作者接收原文下的回复 |
| 原文定位 | `POST /api/public/v1/public-record/detail`，按父记录链向上查找原文，检查公开状态及审核状态，防循环，最多 64 层 |
| 未读汇总与全部已读 | `POST /api/v1/world-interaction/summary`、`POST /api/v1/world-interaction/mark-viewed`，保持服务端序列语义 |
| 当日原始记录 | 现有 `calendar.activity` 的 record/details，`bucket_date`、`timezone`、个人范围，每页 50，按接口返回游标推进 |
| 记录位置与权限 | 现有 `calendar.record-location`，复用 records detail 与 location context get，校验账号归属和当前访问权限 |

兼容通知读取每批最多并发 2 个评论树，最多 100 页来源、每个来源最多 100 页回复；达到上限或任一来源失败会提示未完整，保留上次完整列表。账号首次扫描量较大时，通知完成加载会较慢。窗口重新获得焦点会刷新；当前不承诺实时推送到列表。

当天位置读取最多 200 页原始记录，每批最多并发 2 个位置详情；达到上限、游标异常或请求失败会提示未完整。点位为当天记录附带的设备观测，不等于连续 GPS 轨迹，也不涵盖没有挂到记录上的独立定位数据。

## 后端需要对接的能力

### 收件人通知列表

已检查的 `jotmo-world` master、develop 及相关发布分支只有互动 summary 和 mark-viewed，没有可直接供桌面使用的收件人互动列表。请先核对实际部署和 App 所用服务；已有等价接口时优先提供正式合同。

建议由服务端提供按收件人过滤、按互动发生时间倒序的列表，返回稳定事件 ID、互动序列、原文 ID、父评论 ID、回复 ID、作者与摘要、时间、是否可查看及分页游标。需要同时覆盖原文作者与直接被回复评论作者，排除操作者自身并去重。这样可替换当前全量扫描自己历史内容的兼容实现。

明确单条已读与汇总已读的序列含义，以及 IM 或 Push 的增量失效事件。当前接口只有未读汇总，不能可靠推断每一行的已读状态；前端不使用时间戳伪造序列，也不因打开一条而清空全部世界未读。

### 当天位置批量读取

当前功能已能使用已有记录与位置接口。为减少逐条请求，建议在日索引中批量返回位置，或提供带日期与时区范围的日位置接口。Flutter 现有位置视口查询包含边界、主题与游标，未确认日期合同，不能直接代替当天查询。

需要明确：个人记录归属和权限过滤、日界线依据（记录时间或采集时间）、采集时间及精度、稳定观测 ID、地址或 POI、坐标系、来源设备、分页和完整性、无位置与读取失败的区别。撤回、加密和权限变化必须使旧位置失效。

### 地图服务

当前地图使用 OpenStreetMap 标准栅格底图，无新增依赖，只请求当前视口瓦片；保留版权链接、浏览器 Referer 和缓存行为，不下载离线地图。点位及文字标签在插件中绘制；底图提供方可以从瓦片请求推断浏览区域。

正式发布前需确认地图提供方在目标地区的可用性、容量、坐标系及配置方式。当前投影按 WGS84 使用经纬度，不会静默猜测并转换 GCJ02 或 BD09。OpenStreetMap 公共瓦片没有服务保证，较大规模使用应选择合适的服务或自有部署。参见 [OSM 官方瓦片使用政策](https://operations.osmfoundation.org/policies/tiles/)。
