# DSH 人工文本归档

## 来源约定

DSH Agent Input 只归档受信 Web 输入框确认提交的文本。不根据消息内容、user 角色或 RPC 标识推断人工来源，不归档模型回复、程序提示词或父 agent 派发。

配套 DSH 的 Session/子会话 `submitText` 接口复用普通提示词准入，在接纳的 `agent/inbox/spliced` 消息来源中保留 `submission`：`schemaVersion=1`、`origin=web-composer`、接收会话的 `sessionId` 和引用展开前的 `text`。`source.rpcId` 是既有请求标识。归档消费方不读取展开后的模型输入；只有附件的提交不产生文本归档。

这是可信客户端归因，不是物理真人认证，也不提供额外授权。具有调用权限的恶意客户端仍可显式调用该接口。普通程序提交入口不会附加标记。

## 归档与账号

归档 writer 在获取凭据前绑定已经确认的账号身份；初次异步取号和每次写入均检查账号。重复事件和队列移动不会重新绑定账号，终止失败后也不会把旧提交写到后来登录的账号。网络失败最多重试三次；不可重试的账号和输入策略错误立即终止。卸载后不再启动写入，并清除等待中的重试。

归档标识由 `dsh-agent-input-submission-v1` 命名空间和会话/请求标识派生。事件序号不参与新标识，因此队列移动不产生新快记。旧记录标识保持不变；不根据旧日志补档、不删除已有记录。fork 继承的来源会话标识与当前会话不同，不能重复归档。

归档失败日志只包含固定诊断，不输出原文、上游异常正文或凭据。终止失败不保留新的持久待办队列；用户消息在 DSH 内的发送不受归档失败影响。

## 兼容与发布边界

插件检查 `sessionController.submitText`，并逐事件校验来源版本。缺少接口的宿主会记录兼容警告，不会退回旧的 user-role 猜测。DSH Host 与 Web Client 必须配套交付；仅更新插件到旧宿主会停止归档，不能作为完整修复发布。

当前实现以 DSH 0.1.3-alpha.1 基线开发；不为尚未发布的开发形态添加兼容参数。专用 record 请求只有 record_uid、text_content、send_at，服务端固定纯文本模板和记录来源。没有增加文件或多模态归档逻辑。

认证刷新沿账号 owner 的既有串行入口提交，只有 userId 与 refreshToken 仍属于原登录会话时才更新或失效凭据。晚返回成功和失败、同账号重新登录、不同账号切换已有回归覆盖。不可变包安装和服务端配套联调仍是发布前验收，不以单测代替。

## 消费面

| 消费面 | 本次作用 | 验证 |
| --- | --- | --- |
| DSH Web UI | 可信 Enter/发送按钮提交原文；合成事件不标记 | 正式组合、真实 Chrome、无密钥模型回放三条路径通过 |
| Host owner | 共用提示词准入；插件仅消费接纳来源并调用原有固定来源写入接口 | 主/子会话、原文展开、去重、账号、失败和卸载测试 |
| Tools / 外部 Arkme SDK | 不新增伪造人工归因的入口；原有程序写入能力不变 | 本次不是新增 UI 业务 API；人工来源不是程序写入能力 |

真实 Chrome 验证使用独立临时配置；没有操作用户常驻 DSH。完整安装和跨仓验收通过前不得发布。

## 可发现系统主题与消费面矩阵

topic.kind=3 表示 DSH 输入系统主题；kind=2 是原内部 Agent 容器，仍不列出。record.creation_source=3 仅表示记录来源，不决定主题能力，不依据标题或 UID 猜主题类型。普通同名主题不受限制。

复用既有主题目录、详情和首页策略 owner。DSH 主题可阅读，主题树、面包屑、输入区及转发选择器不提供被禁止的主题写入操作；详情仅显示首页开关。新主题默认关闭首页，重复归档保留用户开关。旧主题不批量改默认值，不清理历史误收录；用户可以自行关闭。首页复用 home/feed 查询；默认分类仍是 uncategorized 查询，两者不是同一业务列表。

| 消费面 | 首页策略能力 | 权限与失败边界 |
| --- | --- | --- |
| UI | 系统主题详情读取与切换 | 失败保留确认值；切换主题/卸载取消旧请求 |
| SDK | topicHomeVisibility(sourceRef, showInHome?, signal?) | 可通过 features.topicHomeVisibility 探测；绑定账号的 opaque ref |
| Tools | arkme_topic_home_visibility | 读取不确认；设置沿现有 explicit-user-write 确认机制 |
| Host | topic.home-visibility → SourceService | 仅传 show_in_home，不回放名称、隐私等默认字段；record owner 最终校验 |

人工提交来源与首页策略是不同能力：前者不提供 Tools/SDK 伪造标记入口，后者三消费面共享同一业务 owner。类型、来源、账号 owner 各司其职，不建立第二套能力状态机。
