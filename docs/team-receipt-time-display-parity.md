# 团队回执时间沿用线上插件口径

恢复 `team.app.receipts` 对已有 `read_at` → `TeamReceiptMember.readAt` 的映射，与线上 `v3.0.24` 保持一致。撤回此前因“不是单条消息首次阅读时间”而丢弃该字段的额外取舍。服务端字段仍表示会话阅读游标更新时间，界面没有新增首次阅读语义。

客户端继续使用原有 `ArkmeReadReceiptMember`：未读显示圆点；已读且有正数时间时按 `readAtLabel` 格式化；已读但没有有效时间显示“已读”。外部联系人没有阅读时间，只有阅读布尔值，因此已读时显示“已读”。日期优先级为：今天、昨天、前天、本周、上周、本月、上月、今年更早、去年、前年、更早；周一为一周起点。保留现有严格 `>` 的零点边界。

能力范围：仅恢复现有 UI 返回结构中的可选字段，Host 权限与成员隐私仍由原 `TeamAppService` 控制。没有新增 Host/Tools/SDK 能力或路由，其他消费面不需要新入口；客户端原控件与格式化代码不变。

验证：`team-app-service`、`team-read-receipt-ui`、`team-read-receipts` 共 125 项通过，1 项既有跳过。Host 测试确认原 `read_at=123` 可传出；外部视图仍不暴露内部成员。Flutter 已用线上实际日期函数生成的 40 项输入/输出对照，上海和纽约时区均一致，包括本地日历跨夏令时边界。
