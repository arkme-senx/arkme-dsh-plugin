# 录音转写对比菜单

工具栏的“转写对比”悬停或点击打开选择面板，打开和选择方案均只读。对比窗口中通过明确的“使用此策略处理”或“开始豆包转写”按钮提交处理。日历工具栏默认查看所选日期的全部录音，不要求选择小时或文件。默认版与测试版v1聚合展示当天各源件的独立结果；豆包保留已有的当天转写增强范围，不冒充完整的分人转写策略。文件列表仍保留单文件对比入口。

## 行为与数据来源

- 按当前日历范围分页读取录音元数据，每页最多50条。只列出当前账号上传的录音，内存归属其他人的可读正文不等于拥有其原件。
- 打开菜单不查询正文，也不提交处理；选择策略后分页发现当天录音及其源件。源件元数据补充服务端已确认的结束时间，跨午夜录音保留当天相交内容，排除同一长会话中的其他日期文件。结束时间尚未确认的历史源件可读取，但无法确认属于当天时不纳入批量处理。
- 长文件名按控件宽度省略显示，悬停显示完整名称；原始文件名和源件引用不变。菜单网格限制最小列宽，避免文件名把策略与状态撑出可见区域。
- 左侧按时间连续显示当天正式结果，右侧显示所选策略；每个音频标注真实的 `officialStrategy`，不读取账号偏好推断旧结果。当日混用过不同策略时也不改写历史事实。
- 没有结果时，只有服务端确认正式处理成功、原件仍存在且在保留期内，才在对比窗口提供“处理当天未生成部分”按钮。明确点击后逐文件提交既有幂等命令，执行前重新核验条件，已有结果和已使用该策略的正式录音不重复处理。部分失败保留成功提交，可再提交剩余部分。客户端在截止时禁用新处理入口，服务端继续负责最终校验。
- 已有、处理中、部分失败的独立结果均可打开，不重新启动；原件过期不影响读取已有结果。
- 豆包仍使用已有增强入口（可使用压缩播放音频），独立于完整策略原件的两天有效期；选择豆包只读取结果，只有点击“开始豆包转写”才发起当天处理。
- 选择对比不会更改账号默认策略、正式结果、已绑定说话人、总结或后续 AI 数据。
- 元数据请求最多并发 3 个；每列正文按可见区域逐页续读，每次仅一个请求。某文件处理中不阻塞后续文件，恢复后继续读取而不重复其他正文。日期/账号切换与关闭取消读取及未提交任务，已受理任务继续由服务端恢复。支持键盘打开、Escape、外部点击和加载失败重试。

## 统一对比视图

- 策略对比与豆包对比共用 `RecordingComparisonView` 的全屏框架、列标题、发言行和时间联动滚动。视图通过 portal 放在页面顶层，避免工具栏的局部层级使时间轴穿透。
- 正式结果在左，对比结果在右。策略列仍显示真实策略名称；豆包左列保留“系统转写”，因为当天可能包含不同策略生成的正式录音，不能用账号当前设置替代历史事实。
- 标题区区分“单个音频”和“当天录音”；文件名超宽省略并保留全名提示。完整策略各列的说话人编号保持独立；联动滚动只按时间寻找邻近发言，不对应说话人编号。
- 两种视图均支持双击发言或回车/空格播放、当前播放列暂停、关闭取消播放请求。短于一秒的正时长显示 `<1秒`，不把它误显示为零秒；正文和时间数据不变。
- 共享层只负责呈现与交互。策略原件有效期、源件与结果分页、豆包当天增强、各自的播放授权及处理提交保持独立；打开对比不会提交任务。

统一视图回归：全仓 14,308 项测试通过、24 项跳过；portal 层级修正后重跑 55 项相关测试通过，包含键盘焦点、按时间同步滚动、防止单击误播放、正式策略列顺序、过期结果可读、取消播放及处理提交边界。类型检查和最终 tgz 构建通过。纯 UI 变更，不新增 Host/SDK/Tools 能力或配置项。

最终安装包在隔离的官方 DSH 实例完成实际浏览器验收：策略与豆包均为正式结果在左、对比结果在右；仅打开两种对比页不提交处理，明确点击处理按钮后结果更新。两种页面均无时间轴穿透。另复现并修复处理完成移除按钮后焦点落到 body 导致 Esc 失效的问题；补充回归先失败后通过，48 项相关测试、类型检查及重新打包通过，重新安装后实际验证该场景的 Esc 关闭正常。最终浏览器验收使用 macOS 内置浏览器与本地协议夹具，不代表模型质量或生产端到端验收。

## 能力覆盖

| 消费面 | 实现 | 验证 |
