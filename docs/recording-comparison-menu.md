# 录音转写对比菜单

工具栏的“转写对比”悬停或点击打开选择面板，打开和选择方案均只读。对比窗口中通过明确的“使用此策略处理”或“开始豆包转写”按钮提交处理。默认版与测试版v1针对选中的物理音频源件；豆包保留已有的当天转写增强范围，不冒充完整的分人转写策略。

## 行为与数据来源

- 按当前日历范围分页读取录音元数据，每页最多50条。只列出当前账号上传的录音，内存归属其他人的可读正文不等于拥有其原件。
- 按已有源件查询列出该录音的音频文件，不扫描全部上传历史，也不为打开菜单读取整天正文。
- “此音频正式结果”来自源件的 `officialStrategy`，不读取账号偏好推断旧结果。当日有多个录音时可切换查看。
- 没有结果时，只有服务端确认正式处理成功、原件仍存在且在保留期内，才在对比窗口提供处理按钮。菜单中的“未生成”只打开空结果视图，不提交任务。客户端同时在截止时禁用新处理入口；服务端继续负责提交时的最终校验。
- 已有、处理中、部分失败的独立结果均可打开，不重新启动；原件过期不影响读取已有结果。
- 豆包仍使用已有增强入口（可使用压缩播放音频），独立于完整策略原件的两天有效期；选择豆包只读取结果，只有点击“开始豆包转写”才发起当天处理。
- 选择对比不会更改账号默认策略、正式结果、已绑定说话人、总结或后续 AI 数据。
- 日期/账号切换与关闭会取消读取；源件切换后忽略旧响应。支持键盘打开、Escape、外部点击和加载失败重试。

## 能力覆盖

| 消费面 | 实现 | 验证 |
| --- | --- | --- |
| UI | `RecordingComparisonMenu` 组合已有策略比较与豆包入口；复用双列结果组件 | 单测及不可变 tgz 在未修改官方 DSH 0.2.1-rc.2 的 Chrome 页面验收 |
| Host | `RecordingService.recordingStrategies` 的 `recordings` 只读动作，复用 Audio 录音查询 | 账号校验、分页引用的账号/日期绑定、空页继续、缺失归属、异常范围测试 |
| SDK | `recordingStrategies({action:'recordings',startAtMillis,endAtMillis,cursor?})`；能力 `recordingStrategyRecordingsV1` | 独立仓外 TypeScript Consumer 编译并调用已安装插件；旧 Provider 显式拒绝 |
| Tool | `arkme_recording_strategies` 增加 `recordings` 动作及日期范围参数，沿用只读权限 | 官方 DSH 真实 Agent 会话发现工具、调用并读取不透明引用结果；未触发处理 |

三端共用 Host 权限和分页处理，不暴露上游凭据或数据库ID。不新增后端接口、集合、索引、配置或原件保留成本。
