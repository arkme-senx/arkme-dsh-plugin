## 依据与边界

- 插件原始基线：`1a9b86bc243097ff9d37d6a30634893b7fdbb20b`；本任务此前实现：`390500aa`、`57ee8c90`。
- 产品目的：个人已在普通群内时可明确选择代表自己的团队发言；真实作者仍是本人；团队徽标打开既有公开名片，联系时进入既有团队通道或成员收件箱。
- 不扩展团队正式入群、代理读群、群归集，也不向同事授予原群权限。
- 原始交接中的临时预览和 `backend_pending` 需要接成真实业务；它们不要求保留成第二套交互。

## 保留的必要闭环

- 原临时预览接为受控身份选择；发送携带服务端验证的团队引用、成员版本和入群时间。个人、团队分别保留草稿，失败不降级为个人。
- 原任务未接通的消息徽标接真实关系归属，点击复用公开名片。团队描述和不可用状态来自真实公开查询。
- 原“联系团队”按钮对本团队成员进入既有收件箱，对外部用户进入既有 open 流程；不再显示后端未接通占位提示。
- 原转发弹窗内按目标群复用同一身份选择器。目标身份必须由用户明确选择，不能继承来源消息的团队。
- 未另建名片、创建团队、身份菜单、长文编辑器、转发弹窗或设计体系。

## 原生窗口的实际合同

只读核对 `arkme-dsh-client` 的 `188db7fd90f7bc6173bde2a29ef82160e031e02c` 中 `src/long-article-windows.ts`、`src/long-article-window-ipc.ts`、`src/preload.cts`：原生层只保留目标的白名单字段；同账号、同 `sourceKey`、同编辑模式复用既有窗口，并冻结首次上下文。

因此适配集中在现有 `long-article-window.ts` 边界：原生不解析的窗口键携带稳定草稿作用域，原生不解析的会话引用携带冻结身份。返回插件时，适配器先恢复原始会话键/引用，再交给界面、发送 API 与主窗口回执。身份不完整或作用域不一致时显式失败，绝不改按个人发送。此封装不产生业务权限；后端仍验证原有密封引用和当前成员/群关系。

稳定窗口键不包含每次核验会轮换的密封引用，因此同一团队刷新身份不会打开重复窗口；个人和不同团队的窗口及草稿分别隔离。未修改客户端源码、原生权限规则或 DSH 运行时，未增加配置和存储结构。

## 2026-11-02：按交接边界收敛消息展示

- 个人消息头像继续使用交接时的 `MessageAvatar/ArkmeUserAvatar`，不改变个人头像、姓名或资料交互。
- 移除本会话额外添加的“代表 · 团队名”消息头、自己的消息头展示、连续消息分组及五分钟/跨天等展示规则。
- 消息只补齐交接中明确缺失的真实团队标识：复用身份菜单的 Users、14px 圆标及蓝色配色，直接打开原 `TeamPublicCardDialog`；未把角标改成装饰后另造入口。正常消息和延伸消息都保留实际发言人的头像与该标识。
- 无头像的共享录音卡片复用其原标题信息行显示同一团队链接，避免产生空头像叠层或丢失名片入口；转发内容的来源团队仍放在既有作者信息行，不新增来源面板。
- 真实发送、身份草稿隔离、原生长文窗口和原转发选择器的接入保留。已接受回执、消息合并、附件投影及扩展响应中的服务端快照修复保留；不从当前输入区选择或 originRepresentation 推断当前消息身份。

## 2026-11-03：原转发交互的后端事实闭环

原右键“转发”、原“转发给”目标选择器、“发给自己”和发送后附言提示均保持原交互。普通群消息转存个人/话题时，ChatService 改为仅提交来源定位，Record 经 Chat 的当前权限与审核版本读取真实原文，再保存独立副本；不再将签名 actionRef 中的缓存正文上传为事实。长文继续使用既有长文能力协商，群目标继续使用既有 Chat 转发接口。

已接受的当前 representation 从服务端回执读取，个人外层不会继承来源团队；原作者信息行消费副本内仅含 name/jotmo_id 的来源展示值。个人附言用副本 ID 派生有效稳定 UUID，原发送 owner 和失败提示继续负责恢复。没有新菜单、署名、分组、资料面板、普通转发 Tool 或运行时补丁。

正式 tgz 安装到全新官方 DSH Profile，通过原 UI、仓外 SDK Consumer、官方 Tools 对隔离真实三服务验收；SDK 转存精确重放及附言恰好一条均有真实读回断言。本轮证据目录为交接包 `开发证据/final-prelaunch-review-20261103-r2/`。
