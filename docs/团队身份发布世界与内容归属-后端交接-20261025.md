# 团队身份发布世界与内容归属：后端交接

日期：2026-10-25

## 产品约定

团队成员可代表团队向世界发布公开内容，例如运营成员发布产品更新。内容所有者是团队，实际发布/编辑者是操作成员的个人账号。外部以团队名称、头像为主，成员小头像及发布人信息为辅；个人活动中可查“我代表团队发布”的记录，关联同一份团队原内容。

团队世界使用独立身份空间，不把团队 ID 当个人 user_id；成员退出、被移除后，既有内容仍属于团队，原发布事实保持不变。团队所属内容不得自动变成原发布人的个人私有内容。

## 本轮插件完成范围

- 世界发布窗口复用头像角色选择器，默认“我”，展示真实已加入团队的身份候选。选择团队后显示团队归属与实际发布人预览；保留当前正文、选中图片，可切回个人。
- 共享团队资料卡（群聊团队标识、团队通道）与联系人团队详情增加“团队的世界”。所有入口进入同一个团队页面；从联系人进入可返回原团队。
- 团队页面读取真实团队资料和当前成员关系，明确展示接口开发中，不调用个人世界列表、不展示伪造空列表、计数或样例动态。当前成员可打开预选该团队的发布窗口。
- 点击团队发布仅调用本地 Host `team.app.world.prepare`，重新核验账号及当前团队成员关系，返回 `backend_pending`。不会上传图片、创建个人快记、提交公开内容或产生个人活动事件。
- `team.app.world.view` 也是本地适配边界，返回 `backend_pending` 和已核验资料；不是已上线的团队公开列表 API。外部查看者只使用公开发现资料，不访问团队成员专用资料接口。
- 旧 `world.publish-text` / `world.publish-file-assets` 收到团队身份字段时明确拒绝，不能丢弃身份后按个人发布。
- 请求取消、切账号、身份失效、失败重试均保留边界：不能静默降级成个人；切换账号清除旧账号编辑状态；同次团队核验使用原请求 ID。没有新增后台轮询。

**真实团队发布、团队内容列表、团队公开互动、个人活动归档和跨设备草稿均尚未接通。** 本轮身份候选只表示真实成员关系，不表示已经获得发布授权。

## 正式协议需要补齐

### 1. 内容主体和真实操作者

建议采用以下语义，最终路由/字段由后端确定：

| 语义 | 要求 |
| --- | --- |
| owner/principal | `user` / `team`；团队内容的稳定 team ID、公开团队标识 |
| publication | 独立稳定公开内容 ID、底层内容 ID、版本与公开生命周期 |
| actual_actor | 从认证态写入的真实发布成员；客户端不能指定他人作为发布人 |
| created_by / edited_by | 首次发布人、每次编辑人、时间；变更历史保留原事实 |
| actor presentation | 可公开的成员昵称/头像或经服务端裁剪后的展示快照；不暴露私人备注、设备位置或内部成员目录 |
| public author ref | 绑定团队主体的公开引用，不能复用个人 authorRef 进行私聊、声纹或个人资料查询 |
| permissions | 当前查看者可执行的发布/编辑/撤公开等能力及版本；成员身份不等于授权 |

团队正文只有一份。个人活动引用团队内容，并带“代表哪个团队”的操作语义；不得创建两份可独立编辑的个人/团队正文。团队内容取消公开或用户退出团队后，个人活动仍可记录发生过该操作，但摘要和跳转必须按现有权限裁剪，不保留绕过团队权限的完整正文副本。

### 2. 发布身份候选及授权

- 返回当前账号真实所属团队、可否发布及不能发布原因。建议负责人、管理员和获授权成员可发布，授权策略由后端持有；客户端不根据 role 自行扩权。
- 发布时重新验证成员状态、授权、团队状态和权限版本；团队被解散/停用、成员被移除、权限被收回时明确拒绝并保留本地草稿，禁止改为个人发布。
- 个人与团队、多个团队之间切换后必须生成新的提交身份；同一幂等 ID 的主体或内容变更返回冲突。网络超时后提供按原请求 ID 查询真实结果，区分未执行、审核中、已发布、被拒绝和结果未知。
- 是否延用个人手机号限制、团队认证/额度限制、内容发布审核等策略，请明确返回能力与原因。首版不引入未确认的审批工作流。

### 3. 创建、附件及公开生命周期

- 原子建立团队内容归属、真实操作者、公开投稿和个人活动关联；不能先调用个人 create-record，再仅替换公开昵称。
- 附件有团队授权上下文。准备上传、完成上传、重试和取消均校验当前成员权限；团队内容不能长期依赖离职成员的个人附件读取权限。不得把私人原始内容自动公开或迁移给团队。
- 团队文字、图片复用世界原有格式、敏感审查、审核状态及发布结果语义；不跳过通用检查。
- 支持有版本条件的编辑、取消公开、删除/恢复及团队内部管理读取。取消公开后公开列表、详情、分享链接及时撤销访问；内部原件和审计仍按团队策略处理。
- 原发布者退出团队不自动取消公开；团队解散时的公开留存/撤销政策需明确并由后端执行。

### 4. 团队世界读取、互动和导航

- 独立团队公开列表、详情及稳定分享链接；世界总流应同时包含个人和团队主体，按真实发布时间排序，分页不得用成员个人列表拼装。
- 可按公开团队引用读取，不要求外部用户加入团队或先建立团队私聊；返回公开资料、当前可访问内容、分页和可选数量。接口未支持与真正为空必须区分。
- 团队主页和世界总流的同一帖子保持同一公开内容身份，表态、评论和分享均归这条团队公开内容；不导入成员个人/私聊/群聊的表态和评论。
- 团队作者点击进入共享团队资料卡，可“团队的世界”“联系团队”。操作者若可公开展示，单独提供个人动作引用；不能把团队作者当作某个成员跳到个人世界。
- 通知归团队公开内容，团队授权成员可以共同查看并接续处理；个人可按操作记录看自己发布的反馈，但不得产生多份内容或重复未读。评论回复的个人/团队身份、权限和归属需明确。
- 所有列表/详情/媒体/分享/转发重新校验公开状态；不因旧缓存、签名引用或个人活动事件绕过撤公开与团队权限。

### 5. 个人记录与统计

- 个人活动支持团队发布/编辑/撤公开等操作类型，返回所属团队、操作时间、操作人、内容引用与按权限裁剪的摘要。
- 个人“我的世界”默认仍只显示个人归属的公开内容；代表团队发布的内容在个人工作活动中查看，团队主页集中查看团队归属内容。是否增加“我参与的团队发布”筛选可后续补，不混成个人内容。
- 个人发布次数、团队内容数量和个人参与次数是不同口径，同一帖子不应被统计成多份独立内容。

## 联调验收

1. 运营甲为团队发布：总流和团队页显示团队主体、小头像对应甲；乙能按权限管理；甲的活动精确关联原件。
2. 同名团队、多个团队、个人/团队反复切换、发起后切账号，不串归属；未确认身份不得按个人发送。
3. 发布前/上传中/超时后撤销成员权限：查询真实结果、草稿和重试行为明确；无越权补发或重复内容。
4. 甲离职后帖子/附件留在团队；甲不能继续编辑或通过个人活动绕过权限读内部原件。
5. 审核中、拒绝、取消公开、再次公开、删除恢复：公开总流、团队页、旧链接及缓存的可见性一致。
6. 外部用户无需入团可看公开团队内容；不会读到内部资料、私人备注或人员目录。
7. 团队内容评论/表态/通知与个人及私聊群聊互动隔离，团队同事可以按权限共同处理。
8. 图片上传、公开内容创建和个人活动关联保持幂等；没有创建团队帖却留下个人公开帖的半成功状态。

交付请附部署环境/版本、真实脱敏请求响应、角色授权矩阵、幂等状态查询、审核/撤公开/附件策略及可供联调的账号场景。插件需按正式合同接入，不能只把 `backend_pending` 改成已发布。

## 2026-10-26 补充：共用输入框与个人快记右键发布

用户已确认将世界发布改成“发给自己”的简约输入框效果。插件提取共享输入外壳，个人对话和世界发布使用同一个外壳、富文本输入、附件条、表情和发送按钮；世界保留自己的内容限制，Ctrl/Cmd+Enter 发布、Enter 换行。去掉原大表单和独立图片专区。

个人快记整条右键增加“发到世界”，进入同一个编辑器，默认个人身份，有真实团队时可切团队。`world.source-draft` 通过当前账号、加密来源、本人创建/拥有、来源归属、记录状态及隐私锁检查，读取已提交正文、标题、附件和版本；不恢复、不提交重新编辑草稿。后台环境录音不会附带公开；语音、视频、文件、动态照片和不可用附件不能静默丢弃，而是显示并阻止提交，直到用户显式从发布副本移除。原快记不受编辑或移除操作影响。

个人发布继续使用现有世界新建公开稿流程，不更改原个人快记的归属或可见性；原快记后续修改不自动覆盖已发公开稿。团队发布仍未接云端，仅核验成员关系并保留发布副本。**不能把个人原快记直接改成团队所有者。**

后端接通团队投稿时需补：

1. 接收经服务端验证的个人来源引用、来源版本和“派生发布副本”关系；发布稿内容允许用户在编辑器内调整，应分别记录来源版本及最终稿版本。
2. 服务端确认来源仍属于当前操作人且可用于派生发布；团队拥有新内容，个人保留原件和操作关联，禁止信任客户端任意 origin/actor ID。
3. 当前本地 `team.app.world.prepare` 可携带 origin 供后续适配，但仍只返回 pending、不会建立来源关系。正式写入须在一次幂等操作中保存团队归属、实际操作者、来源关联和发布状态。
4. 原个人来源引用只用于经授权的内部追溯，不能随公开详情/分享链接暴露私人原快记、所在主题或完整历史。
5. 附件须经过授权的团队复制/归属迁移策略，不能因个人已上传就默认团队有长期读取权限；普通个人稿可复用本人既有图片资产，不重复上传。
6. 对个人/团队、不同团队切换后创建不同投稿身份；重试保留相同稿件请求 ID，已上传的同一附件不重复上传，结果未知不能直接重复发新帖。

这一补充不代表来源关联已在云端持久化。个人活动归档、团队长期附件归属和跨设备引用关系仍按正式后端合同联调。

## 2026-10-26 补充：已有内容统一发到世界

- 世界和团队世界的「发布」改为引导，说明发给自己、私聊、群聊、Arko 等对话中本人已发内容都可从消息菜单进入「发到世界」。「去记录」仅导航并聚焦发给自己的输入框，不创建内容、不覆盖草稿、不自动公开。
- 发给自己、私聊与群聊使用已有 Record detail，核验当前账号同时为 owner 和 creator，且原始会话绑定匹配。Arko 使用已有 messages/details，仅接受本人历史 user 消息且状态为已发送，完整载入文字及图片；Bot 使用账号、会话绑定的签名操作引用，仅接受 user 消息。源内容只读，公开副本使用现有发布审核流程。
- DSH 和本人 Codex 的用户提问可进入同一确认页。这些是本地可见输入的正文快照，不能当作后端验证过的来源关系；同事任务及 AI 回答不展示此操作。DSH/Codex 附件与 Bot 附件尚无统一可复用的公开资产协议，本轮显示阻断占位，明确移除后才可仅发布正文，不能静默遗漏附件或自动上传。
- 团队世界的引导会把目标团队作为下一次公开确认的初选建议，按账号隔离。团队成员关系在发布确认时重新核验；团队实际发布继续等待本文原协议，不退回个人发布。
- 后端继续建设派生公开内容时，来源需支持 Record、Arko 消息、Bot 消息和本地会话输入等不同命名空间，并逐项验证读权限、作者、当前可用性及附件授权；本地正文快照不能作为云端来源、所有权或授权证据。个人原记录不变，团队副本归团队并记录实际操作者。
