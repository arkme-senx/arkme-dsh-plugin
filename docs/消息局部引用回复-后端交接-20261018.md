# 消息局部引用回复：后端交接

日期：2026-10-18。范围：私聊、群聊；复用消息延展，不新增一套回复树。

## 目标与当前状态

用户在一条消息中选中某句话，点击“回复”，新消息只展示被引用的片段，能返回原消息并高亮该片段。引用、正文、附件一起作为会话草稿保存；取消或更换引用不删除正文。

本分支实现了插件端选区、草稿、展示、定位及协议适配；没有修改、发布任何服务端。下面的能力接口和字段是本次拟定的 v1 合同，必须由服务端实现并完成端到端验收后启用。不能只返回 enabled=true、忽略引用字段。

目前既有 `/api/v1/chats/extensions/children/create` 仅有 parent/child 关系。Flutter 远端 master `d1959c14b0` 的请求模型有通用 metadata，但没有局部引用的专用收发合同。是否能通过现有扩展字段落盘可由后端评估，插件不依赖未经验证的透传行为。

## 1. 能力查询（新增，只读）

POST `/api/v1/chats/extensions/capabilities`

请求：`{ "chat_session_uid": "当前会话" }`。

成功 data：

```json
{
  "quote_reply": {
    "enabled": true,
    "protocol_version": 1,
    "projection": "arkme-text-v1",
    "max_quote_length": 2000
  }
}
```

必须验证会话访问权限。只有创建、持久化、历史查询、实时推送、撤回撤权清理及兼容显示全部就绪后才声明支持。

404/405/501、明确不支持、未知协议版本均不允许局部回复发送；网络和鉴权错误独立提示并支持重试。插件保留草稿，绝不降级成整条延展或普通消息。支持检查在附件云端上传之前完成。

## 2. 创建：沿用既有接口，增加可选字段

既有 parent/child、会话、正文、附件、mention 等字段不变，增加：

```json
{
  "quote_reply": {
    "version": 1,
    "projection": "arkme-text-v1",
    "sourceDigest": "64位小写SHA256十六进制",
    "recordVersion": 12,
    "start": 7,
    "end": 9,
    "text": "可以",
    "prefix": "可以，先检查。",
    "suffix": "，再处理。"
  },
  "quote_reply_source": {
    "relation_uid": "原消息在当前会话中的关系ID",
    "sequence": 123
  }
}
```

`recordVersion` 仅在前端拿到真实版本时传入，不填假版本。`sourceDigest` 必须存在。

- `start/end` 是规范展示文字的 UTF-16 偏移，左闭右开，不是 UTF-8 字节数，不是 Markdown 源码偏移。
- `text` 保存用户所见的片段及内部换行；长度上限按 UTF-16 计算。展示可折叠，保存不能静默截断。
- `prefix/suffix` 是规范展示文字中选区前后最多各 32 个 UTF-16 单元。结合 offset 区分重复句子，禁止直接 indexOf 取第一次命中。
- `sourceDigest = SHA256(UTF8(JSON.stringify([body, format])))`。body 为消息 textContent，空时取 title；format 为 plain/markdown。JSON 必须使用与 JSON.stringify 一致的无额外空格序列化。不是仅对选区文字求散列。
- `arkme-text-v1`：plain 原文或 Markdown 可见文字 → Arkme 表情 token 转 Unicode → 连续空白合并为 ASCII 空格并去首尾空白。Markdown 使用现有 `arkmeMarkdownPlainText` 规则；具体参考 `src/message-quote.ts`，并使用测试用例作跨语言对照。消息附件、读回执、按钮不属于正文。折叠显示不会截短规范文字。
- 当前对无法与原文可靠映射的显示（例如被改写的链接预览标题）会要求用户在详情选择原文，不能猜测位置。

### 服务端必须校验

1. 会话可访问、可发送，parent owner、record、relation、sequence 真实属于同一次消息出现位置。
2. 引用来自用户有权查看的原文版本，hash、选区及前后文一致。不能信任客户端提供的作者或文本。
3. 发送前原文变化：若无法验证目标版本，返回明确冲突，不能把新原文强行套到旧选区。插件保留回复正文供重新选择。
4. 引用和回复消息在同一幂等提交中保存；同一 child record/relation ID 重试不得重复创建，变更内容的同 ID 请求不能覆盖先前成功提交。
5. 当前会话/成员状态、撤回、原文访问权限最终由服务端裁决。插件签名快照校验仅为额外约束，不能代替服务端权限校验。
6. quoted text 中的 @、链接、Markdown 均为引用数据，不生成 mention 或 Bot 调用。新回复正文的显式 mention 沿用既有行为，避免重复提醒。

创建成功回执必须原样返回已验证的 `data.quote_reply`。能力宣称支持但回执缺少/改变引用，插件按“提交结果待核对”处理，保留稳定发送身份，不声称成功。

## 3. 历史、实时、单条与延展树读取

统一在消息的 extension_edge 中返回 `quote_reply` 和 `quote_reply_state`，或在 timeline item 顶层返回同名字段（插件优先读取 edge）。

状态：

- `available`：已验证且仍可展示引用；提供引用快照和原消息定位预览。
- `edited`：发送后原文发生编辑；保留发送时引文，提示原消息已编辑。禁止把快照替换成新文本。
- `unavailable`：撤回、删除或权限变化导致不可展示；不下发引文正文。插件也会清空该预览正文及附件。

没有引用字段的旧消息沿用整条延展。存在引用字段但状态未知、字段损坏时不回退成整条内容，按不可查看处理。

必须覆盖：发送回执、统一时间线分页/around、实时事件、单条详情、延展树、搜索及恢复后的缓存。原消息被编辑/撤回后，要更新所有相关投影并发出版本事件，防止旧缓存复活引文。消息正文编辑不能意外删除其既有 quote 元数据。

区分本地隐藏、全局删除、撤回及权限收回。撤回/撤权不可通过引用、搜索、导出或转发绕过；回复正文按既有规则保留。

## 4. 移动端与旧客户端

保留 parent-child 延展关系兼容已有导航和计数。新客户端展示作者＋所选片段；旧客户端若不能消费结构化引用，需要有明确的兼容投影，不能悄悄显示整条原文而让双方理解不同。

推荐移动端至少先补读取/展示支持，再升级选择交互。若采用旧端文本回退，应由协议层明确区分“引文”和“回复正文”，禁止把引文复制进可编辑的新正文或当作原作者新发了一条消息。兼容方式需后端和移动端共同确认。

## 5. 插件实现与验收边界

- 入口：选中文字的即时工具栏/右键，复制、全选、回复；私聊群聊正文和当前消息详情共用。
- 默认一个连续片段；跨消息选区只复制。长文卡片、合并转发、录音分享、通话复合卡片暂不作为局部引用来源，避免假造原文身份。
- 回复使用原会话草稿、发送队列、延展树及历史定位，未新增后台轮询。
- 首期整体撤回后的引用不可见规则需要服务端提供可靠状态；前端测试不能证明生产端已经满足。
- 精确定位复用现有消息 around 能力。相同 Record 在同一会话多次出现时，服务端需支持 relation/sequence 精确查找；目前插件既有导航仍主要按 record＋owner，需要后续联合补齐出现位置定位。已提供 sequence/owner 与实际定位行不一致时，插件明确提示并拒绝高亮，不能宣称此项已完全覆盖。
- 关联消息详情中的“延展子消息列表”目前缺少每个子项独立签名操作引用，首期不在这里提供局部回复，打开该条真实消息后可使用。

建议联调：私聊/群聊各一组，重复短语、超 2000 字原文后半段、Markdown/表情/跨段、文字＋图片、发送前编辑冲突、发送后编辑、撤回撤权、弱网重试、账号切换、刷新恢复、旧端接收。只用明确授权的测试消息，不使用真实消息做删除测试。

## 6. 新增：发给自己局部延展（2026-10-18）

用户已确认同一选区能力覆盖发给自己的全部、默认分类、已选主题及当前消息详情。工具栏叫“延展”，聊天仍叫“回复”。不会清空已有正文、附件或切换选中的主题。

新增只读能力：POST `/api/v1/records/extensions/capabilities`，个人全部/默认分类请求 `{}`，主题请求 `{topic_uid}`；返回与聊天一致的 `data.quote_reply` 能力结构。必须分别确认两种创建路径已实现，而不是只给全局开关。

- `/api/v1/records/extensions/create`：增加可选 `quote_reply`。
- `/api/v1/topics/records/extensions/create`：增加可选 `quote_reply`，原 `topic_uid` 保留。
- 成功回执均必须返回已保存的完整 `data.quote_reply`；不一致按结果未知处理，禁止普通消息回退。
- 个人原文身份用 account + record_uid，仍沿用现有主题归属和延展边；创建子记录不能移动原记录到另一个主题。
- 个人时间线/主题列表/单条详情：在 extension_edge 上返回 `quote_reply`、`quote_reply_state`。
- `/api/v1/records/extensions/tree`：在对应 child_record_uid 的边上返回引用字段，不能错用树根的引用。若用顶层字段，则必须只代表本次 opened record 的 parent 边。
- 原记录锁定、删除、权限变化：不下发引文，插件隐藏引文和原文预览。`available/edited/unavailable` 规则与聊天一致。

插件已补齐能力查询、两条创建路径、个人来源投影及边读取。后端仍需实现本节协议；测试中的模拟回包不代表线上已经支持。

个人入口实测补充：2026-10-18 13:22—13:24，3102 已验证全部视图、主题视图和消息详情的“延展”入口，切换会话、刷新后引用草稿保留，取消引用保留正文，主题不跳回全部。当前个人能力接口未支持，局部延展发送仍禁用；测试草稿已清理，未发送真实消息。
