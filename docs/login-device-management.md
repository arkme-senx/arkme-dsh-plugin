# 登录设备管理

头像入口打开设备管理弹窗，展示已登录设备、常用设备和登录日志。保持已确认的信息层级，不增加常见问题、状态解释或平台副标题。无法识别名称和平台的历史记录不展示；缺少在线状态时显示“未知”，不将其解释为离线。

## 权限与操作

UI、Tools 和 SDK 共用 `LoginDevicesService`。Host 操作 `account.devices` 只接受本机且 Origin 与当前 Host 一致的请求。SDK 从公开入口 `@senguoyun/dsh-arkme/sdk` 导入 `createArkmeSdk`，握手确认 `loginDevicesV1` 后调用 `loginDevices`。Node 消费者须提供指向已验证本机 Origin 的 fetch 适配器，不将接口代理到公网。

查询 action：`list`、`trusted`、`events`、`notifications`。退出和移除先用 `prepare` 获取短效 ticket，用户确认后调用 `confirm`；结果不明时使用同一 ticket 调用 `operation`。通知写入使用 `set-notifications`，携带原 revision 和稳定 requestId。Tools 写入口依赖宿主真人确认上下文，不接受模型提交的 confirmed 标记。

移除常用设备会同时撤销该设备的登录凭据，再次登录需要额外验证；云端聊天记录保留。当前操作设备受保护，不能从此远程管理入口退出或移除。首次密码登录保持原规则；仅曾被移除信任的设备要求验证码、扫码或授权验证。

device ref、cursor、ticket 均绑定账号和登录会话。device ref 和 cursor 有效期 15 分钟，ticket 5 分钟；过期 ticket 只能核实已有操作，不能提交新写入。同一账号重新登录也会使旧写引用失效。

后端登录会话是权限依据，原生控制只负责本地清理及在线状态。成功回执必须明确确认凭据撤销；目标离线或本地清理尚未完成时，不提前显示“设备已退出登录”。服务端流式授权排空可能使确认多等待约两秒，界面继续显示操作中。

## 数据和资源边界

每页 50 条。设备列表保留当前页；日志按点击“加载更多”追加并按事件 ID 去重，最多保留 500 条，返回第一页可以重新读取，关闭即释放。没有新增后台轮询或 WebSocket。

读取复用 Host 请求协调器，按账号、登录会话、路由和参数合并并发请求，不缓存完成结果；单个调用方取消不影响其他调用方。写入前后使该会话的读取失效，回执丢失时也不接受旧响应。其他设备的变更通过刷新或重新打开读取。

旧有效凭据由服务端在合法请求时自动登记，不要求退出重登。无法完整统计时入口显示“登录设备管理”，不展示不完整总数。日志有覆盖起点，不补造历史。

手机只有声明完整通知协议后才开放消息、通话两个开关；旧客户端保持既有提醒行为。消息开关仅影响聊天提醒，日程和 AI 来信不受影响。设置失败或结果未知时不显示成功。模拟协议支持不代表真实手机已支持完整离线来电控制。

明确凭据失效后沿用现有刷新和退出流程；普通业务拒绝或临时服务故障不清理凭据，迟到请求不能清除后来登录的会话。

## 样式与验证边界

设备管理 CSS 经 `installArkmeRedesignStyles` 的既有插件生命周期内联安装；弹窗 portal 自身持有字体和 border-box 规则，不依赖预览页全局样式。

Host、同源 HTTP、SDK、Tools 和 UI 均有自动化合同测试。自动化、类型检查和构建不替代真实桌面交互、Tools 真人确认、完整深色/小窗口及跨平台验收。原生离线来电链路仍须单独验收，未声明完整能力的手机保持开关禁用。
