# Codex 每轮处理时长：云端字段交接

日期：2026-10-23

## 目标与当前交付

即我插件的 Codex 对话在每轮回答上方显示处理时长：进行中“已处理 …”，完成后“用时 …”，中断“已中断 · 用时 …”。按 `turnId` 归属，不能以提问和回答的上传时间相减。

本次已实现本机真实时间事件读取、稳定账号/任务缓存、前端展示，以及云端返回可选 `timing` 的解析。即使当前界面展示的是云端消息，只要能通过本机已配置的采集源核对 owner/team/source/task 与原始 turn 的映射，也能补充本机时长。

**跨设备时长上传尚未接通。** 现行 `/api/v1/team-codex/sync` 上传包没有时间字段；本次继续发送原协议，避免未协商字段造成正文同步失败。另一台设备没有本机原始记录时，仍需以下后端支持。前端没有将本机补充显示称为云端已同步。

## 真实来源与边界

- Codex `task_started`：`turn_id`、`root_turn_id`、`started_at`。
- `task_complete` / `turn_aborted`：另有 `completed_at`、`duration_ms`。
- 原始 `started_at` / `completed_at` 单位为秒；插件转换为毫秒。原始时长是毫秒，可能与两个整秒时间之差有不到两秒的精度差。
- 仅接受根轮次事件，排除子代理。只读取已授权、已捕获任务对应的原始记录；不扫描会话目录，不上传工具输出或推理正文。
- 本机格式属于兼容读取，未来 Codex 格式变化时缺省不显示时长，不能补成 0。不修改 Hook 命令或信任设置。
- 读取是按需、异步、有大小限制的；长历史记录分批补齐，缓存完成值后重开仍能显示。

## 建议新增的可选事件字段

`sync.tasks[].events[].timing` 和 `events/list.items[].timing` 使用同一对象：

```json
{
  "startedAt": 1792748662000,
  "completedAt": 1792748790000,
  "durationMs": 128012,
  "state": "finished",
  "observedAt": 1792748790000
}
```

| 字段 | 说明 |
| --- | --- |
| startedAt | 来源执行开始时间，Unix 毫秒 |
| completedAt | 完成/中断时必填，进行中不填 |
| durationMs | 完成/中断的原始耗时，非负整数；进行中不填 |
| state | working / finished / interrupted |
| observedAt | 来源最后核验时间，Unix 毫秒；进行中作为新鲜度依据 |
| live | 进行中可选布尔值：来源在 observedAt 时是否在线；不能用数天前保存的 working 状态替代在线证据 |

`UserPromptSubmit` 可携带该轮已知状态；`Stop` 只接受 finished；`Interrupt` 只接受 interrupted。事件与时间对象必须归属同一 source/task/turn，禁止按标题、相邻消息或成员名称配对。

## 保存、版本与兼容要求

1. 对现有记录做可空扩展，老客户端不传字段也不报错；缺省更新不能清空已保存的时间。
2. 时间后补沿用相同 event_id，版本递增。正常的 ACK、重试和去重规则继续适用。
3. completedAt >= startedAt，durationMs >= 0，observedAt >= completedAt；时长与起止时间差允许 2000 ms 的原始精度容差。拒绝负数、非有限值和跨轮次关联。
4. 终态不能被迟到的 working 覆盖。若有合法历史修正，以更高事件版本更新完整对象。
5. 写入与读取沿用现有 owner/team/source/task 权限校验；删除任务时清理对应时间数据。
6. 提供能力协商（建议 `turn_timing_v1`）。能力未开时插件继续原上传格式；后端上线并确认能力后再接通上传。
7. 进行中更新时间不能依赖“每秒上传”。来源可以低频刷新 observedAt，接收端本地展示秒数；来源证据超过 30 秒时冻结并标“等待同步”，完成后以 durationMs 固定下来。

## 后端完成后仍需插件补齐

- 将已核验的本机时间缓存并入云端同步账本，包含用户没有打开过的活跃任务（有界后台采集）。
- 根据能力标识附加 timing，时间后补触发事件版本更新；旧服务继续兼容。
- 跨设备分别核验进行中、完成、中断、断网重连、乱序及重复 ACK；不能仅凭本机界面有数值就验收云端完成。

## 验收

- 128012 ms 显示“用时 2分钟 8秒”，即使正文晚同步十分钟也不改变。
- 完成值重开保持；两台设备同一 source/task/turn 的最终数值相同。
- 等待确认、工具执行、最终回答输出等均遵循 Codex 原始轮次计时，不自行扣除。
- 缺失时长、子代理、历史中断、排队未开始、切账号、暂停采集均不显示虚假的实时计时。
- 计时每秒更新不会导致正文重绘、滚动跳动或不断提示“有新内容”。
