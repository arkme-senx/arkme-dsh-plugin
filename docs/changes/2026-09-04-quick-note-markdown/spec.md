# 合同与验收

- 创建：新编辑器发送 `text_format: markdown`；未传字段按 plain 阅读。历史含 `#` 或 `*` 的快记不自动转 Markdown。
- 更新：未传 text_format 时保留既有格式；显式 plain 表示退回纯文本；非法枚举由 Record 拒绝。JSON、BSON、clone、详情、历史版本和编辑结果都保留格式。
- 跨端：CommonMark + GFM 的标题、粗斜体、删除线、列表、任务、引用、链接、代码、表格及软换行。任务在阅读态不可勾改。移动端原文编辑保留 Markdown 缩进及标记。
- 入口：快记主列表、个人/主题/私聊/群聊、延展、原消息详情、转发明细和分享快照使用同一格式识别。会话摘要取可读文本，完整正文保留源文。
- 发送：没有用户可见的编辑/预览切换。文件上传、发送失败恢复、重启恢复按账号和会话隔离草稿，Markdown 与已有附件一起保留。
- mention：UTF-16 范围指向最终源文；发送校验拒绝位于代码或 URL 的 mention。旧客户端省略格式字段的更新不得把已标记快记退回 plain。

## 发布与回滚

1. 先发布 jotmo-record 的字段持久化与更新兼容；再发布 jotmo-chat 的转发、公开快照白名单。
2. 发布桌面及移动端读能力，完成真实账号上个人/主题/私聊/群聊、延展、转发、重编辑与重启草稿联调。
3. 插件随包发布的 `cordis.patch.yml` 显式启用 `markdownQuickNotesEnabled: true`，用户更新对应正式运行环境后自动获得实时 Markdown 编辑能力。这是内部部署配置，不是发送框的用户开关；配置 Schema 的缺省值仍为 false，独立宿主可自行选择启用时机。正式启用前需完成前两步的生产兼容性确认。
4. 回滚时在本地或部署覆盖层显式设置 `markdownQuickNotesEnabled: false`，隐藏新建 Markdown 编辑能力并拒绝新的 Markdown 写入，保留已发布读能力及后端字段。不要把旧服务覆盖回去清除标记，不做批量历史正文转换。

当前交付仅修改代码与本地构建验证；未提交、部署或修改运行中 Harness 配置。真实服务与设备的发布联调由发布流程执行。
