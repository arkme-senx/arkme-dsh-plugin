# 后端 Markdown 转发与媒体载荷修复（2026-09-07）

## 范围与基线

- `jotmo-chat`：`zp/v143`，HEAD `4356ccf`，审核基线 `origin/master` `8660563`。
- `jotmo-record`：`zp/v143`，HEAD `95537f1`，审核基线 `origin/master` `dd017f0`；保留之前未提交的 UTF-16 标签修复。
- 插件补齐个人快记、主题转发请求的子项格式字段。没有界面布局改动。
- 本轮没有切换或合并分支，没有提交、推送、部署。

## 根因与修复

1. Chat 的媒体载荷白名单缺少 `text_format`，普通发送和 extension child 在重建 Record 请求时均丢失字段。现在白名单声明和归一化复制均保留该字段，正文不被裁剪。
2. 转发卡片转换公开链接快照时，没有读取子项格式，且对正文直接执行 `TrimSpace`。现在普通叶子只恢复 `plain` 或 `markdown`；Markdown 保留原始正文，普通文本保持既有裁剪行为。长录音与通话仍使用独立结构化快照。
3. Record 转发子项缺少输入、存储、输出字段。现在 `text_format` 贯通 DTO、domain、Clone、BSON `tf` 和受控输出，包含嵌套转发；只有 Markdown 输出保留首尾空白。非法格式被递归校验拒绝。
4. 插件转发到个人快记和主题时，操作引用已有 `textFormat`，但构造转发子项时漏发。现在将其写入 `text_format`，缺省沿用 plain。

嵌套子项的缺省格式与显式 plain 在内容语义比较中等价；Markdown 参与内容身份判断。比较只操作副本。

- Record：DTO → 校验 → Clone → BSON → 输出完整链路，涵盖一层与嵌套转发、非法格式、未知字段隔离及格式语义比较；同时回归既有转发、修订和 UTF-16 标签测试。
