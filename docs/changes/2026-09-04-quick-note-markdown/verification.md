# 2026-09-04 实时编辑问题复测

## 复现与根因

在连接测试环境的 v143 dev 客户端及其同一 Host 页面中逐字输入，发现三个问题：

1. 空输入框输入 `# `、`- `、`> ` 等前缀后，刚生成的格式消失。编辑器输入规则已生成 heading/list/blockquote，但可见正文暂时为空。`ArkmeComposerDraftStore.storeOrDelete` 只检查正文和附件等字段，将草稿删除；组件收到空草稿后执行 `clearContent`，恢复成普通段落。部分空结构的 Markdown 序列化结果也是空字符串，因此修复必须检查编辑器文档结构。
2. `[链接](https://example.com)` 输入完成后仍显示源码。Tiptap Link 默认未开启 `markdownLinks` 输入规则；`autolink` 只负责普通 URL。
3. 输入代码围栏后按 Shift+Enter 仍是普通段落。插件捕获该快捷键并执行段落分割，而默认 CodeBlock 输入规则只在文本输入的空白字符上触发。

## 排查与修复流程

1. 在运行中的页面逐字输入，读取实际编辑区 DOM，区分语法没有识别和 CSS 显示异常。
2. 跟踪编辑器更新、草稿保存和 React 外部值同步，检查已安装 Tiptap 的 Link/CodeBlock 实现。
3. 将组件测试从简化的 `useState` 草稿改为真实 `ArkmeComposerDraftStore` + `useSyncExternalStore`，按实际 Sidebar 回调写入。修复前可重现标题、列表、待办、链接及围栏问题。
4. 保存非默认 Markdown 文档结构，开启 `markdownLinks`，在 Shift+Enter 时处理完整的代码围栏；重新构建插件并刷新测试页面和桌面客户端。
