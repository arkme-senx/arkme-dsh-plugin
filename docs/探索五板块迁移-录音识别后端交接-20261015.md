# 探索五板块迁移与录音识别：后端交接

更新日期：2026-10-15（北京时间）。本轮仅修改 Arkme 插件，未修改、发布后端或 Flutter，未合入 dev。

## 目标与交付边界

桌面插件左侧第一栏用一个「探索」入口收纳：个人档案、关系、事件、目标、纪念日、世界。桌面先形成可核对、可纠正、可追溯的日常使用闭环，再将稳定协议与交互迁回移动端。

本次复用现有服务，不建立另一套识别数据库，不把浏览器本地数据冒充后端保存结果。用户仍需能够判断「谁说的、是现实交流还是播放内容、为什么识别到这里、原文在哪里、纠正是否生效」。

**本文件是接口与验收交接，不附个人数据导出包。** 示例采用泛化描述；生产排查样本由数据所有者按需提供。

## 已完成的插件能力

| 板块 | 已接入 | 当前边界 |
| --- | --- | --- |
| 个人档案 | 八个分类、快照分页、事实详情、依据、纠正/删除、启动/暂停/继续整理、模型与分析来源设置 | 当前验证账号八类均暂无结果，owner 返回历史暂停任务；没有自动恢复大批量任务 |
| 关系 | 识别实体、类型筛选、名称/别名/关联联系人备注搜索、详情、来源记录连续加载、删除实体 | 识别实体名与关联联系人单独呈现；不按同名/近音自动合并，不擅自修正后端身份绑定 |
| 事件 | 历史事件流、类别详情、原始记录定位、关注/取消关注、补充、创建、调整分类、分析模型与整理入口 | 调整分类读取完整 event/plaza 分类目录，不局限于已加载的事件记录 |
| 目标 | 目标列表、分析、时间线、原始记录定位、重新分析/停止、模型选择 | 当前协议未提供统一人工修改目标/确认否定反馈接口；未伪造此能力 |
| 纪念日 | 已确认/待确认、依据、日期与倒计时、公历/农历/闰月确认和修改、忽略、模型选择、原文定位 | owner-ref 为 audio 时回查原始转写版本；找不到精确原文会明确报错，不跳到相似内容 |
| 世界 | 原有世界界面通过探索进入 | 世界业务保持原有实现 |

宽窗口列表与详情并排，窄窗口切换列表/详情；来源保留在详情抽屉中。切换板块短时间返回保留筛选、选中项与滚动位置。后台分析仅轮询状态，不自动重新启动任务；分页和保存失败可重试，不能先显示保存成功或先移除原结果。

## 已核对的服务协议

Flutter 参考：`jotmo-frontend` 的 `origin/master`，2026-10-15 拉取到 `5f5b6de27d`。下表均为现有路径，新增协议建议在下一节单独列出。

### 个人档案：memory-core + intelligent

- memory-core：`POST /api/v1/personal-profile/v3/experience/home`。
- `POST /api/v1/personal-profile/v3/section/get`：`snapshot_id, section_id, page, page_size`。分页必须维持快照，不混入另一次运行的事实。
- `POST /api/v1/personal-profile/v3/fact/override`：`fact_key, action=correct|delete, value`。
- `/experience/activate`、`/experience/refresh`、`/experience/rebuild/pause`、`/experience/rebuild/resume`；暂停/继续使用当前 `run_id` 和能力状态。
- `/experience/sources/set`：`sources`。
- intelligent：`/api/v1/personal-profile/v3/model/list`、`/model/activate`。
- 本次 home 的来源目录只有 `personal_record / native_chat / wechat_import / ai_call`，**未提供独立录音来源选项**。不要仅凭「即我数据」文案推断已覆盖全部音频。
- 验证账号 home：`phase=paused`、`processed_units=58`、`total_units=140409`，更新时间为 2026-08-10。这里只说明服务返回状态，不认定暂停原因。

### 关系：relation

- `GET /api/v1/relation/list?limit=10000&offset=0`。
- `POST /api/v1/entity/detail-full`：`entity_id`。
- `POST /api/v1/entity/records/list`：`entity_id, limit, offset`；返回 `records / total / has_more / next_offset`。
- `POST /api/v1/entity/delete`：`entity_id`。
- 生产 list 在传 `limit=100` 时仍返回了 7146 个实体，未提供清晰分页游标。插件暂时在 host 端按 50 条投影分页，缓存 30 秒，并检查分页期间的集合变化。
- 类型枚举以 Relation/Flutter 为准：1 人物、2 组织、3 地点、4 宠物、5 事件、6 项目、7 作品、8 品牌、9 其他。
- `linked_user_id / entity_kind / can_start_private_chat` 不等于「人工已确认正确关联」。当前数据存在实体名称、别名、关联联系人不一致的案例。插件不替后台修复或合并。

### 事件：data + intelligent

- data：`POST /api/v1/event/stream`：`filter=all, scope=all, limit=50, offset`，生产验证返回总计 1201 条。
- `POST /api/v1/event/detail`：`event_id, anchor_event_record_id, range_key=all, limit=30, include_aggregate, cursor`。
- `POST /api/v1/event/plaza`：本次返回 `has_data / subscribed / cancelled / all` 数组，`all` 为 45 个分类。
- `/event/create`、`/event/detail/supplement`、`/event/record/reclassify`、`/event/subscribe`、`/event/unsubscribe`、`/event/process/trigger`。
- 调整分类使用 `event_record_id, source_event_id, target_event_id`。人工补充传 `event_id, content, text, supplement`；创建类别传 `event_name, name, is_subscribed, subscribed`，与现有移动端首选路径对齐。
- intelligent：`/api/v1/event-model/list`、`/event-model/activate`。
- 未照搬移动端「任何失败都换路径再次提交」的写入兜底；服务失败直接报告，避免一次人工操作重复提交。

### 目标与纪念日：intelligent

- 目标：`/api/v1/insight/goal/list`（`view=full, limit, offset, result_version`）、`/goal/detail`、`/goal/refresh`、`/goal/model/list`、`/goal/model/activate`。
- 目标刷新当前使用 `source_type=0`。生产目标任务验证期间仍在运行，数量发生变化，不能把某次列表长度当固定总数。
- 纪念日：`/api/v1/insight/anniversary/home`（`source_type=0, result_version`）、`/anniversary/follow`、`/anniversary/dismiss`、`/anniversary/refresh`、`/anniversary/evidence/open`、`/anniversary/model/activate`。
- 纪念日模型目录：`/api/v1/insight/model-panel/get`（`section_type=4, source_type=0, history_limit=20`）。当前 UI 使用现行版本；历史版本选择未在本轮展开。
- 纪念日确认参数：`candidate_id, title, calendar_type, origin_year, origin_month, origin_day, is_lunar_leap_month`；未知年份保留 0，不强行补今年。
- 任务状态：`/api/v1/insight/section-summary`，目标 type=3，纪念日 type=4；停止 `/api/v1/insight/terminate`。
- 本次纪念日返回已确认 1、待确认 16；`material_coverage` 显示 audio_ready 2429、audio_unavailable 429。未可用不能等同于「不存在有价值内容」。

## 后端优先配合项

### P0：识别结果能证明来自哪里、属于谁

五个板块统一返回稳定的 evidence/source owner 定位信息。建议公共语义如下（是建议，不是已上线字段声明）：

- 结果：稳定业务 ID、canonical identity ID、result/snapshot version、task/run ID。
- 来源：provider、owner/source ID、原始发生时间与时区、可见性/可用状态。
- 录音：session/container ID、child ID、ASR source（system/doubao）、ASR item index 或稳定 segment ID、start/end、transcript version/hash、原文及有限上下文。
- 参与者：稳定 speaker/identity ID、是否本人、人工确认状态、关联联系人的依据和确认状态。
- 用途区分：`personal_statement / direct_conversation / playback / background / unknown` 等由 owner 输出的状态，并附置信度/证据；未知不能默认是本人或现实交流。
- 提供统一的 evidence/open：重新验证当前账号权限、当前来源是否存在、版本是否匹配；不要只给模型改写摘要或临时 URL。

纪念日已经有 `evidence/open + owner_ref(provider=audio, container_id, child_id, transcript_source, item_ordinal, start_at)`，可作为协议参考。其余板块多只给 record_uid，不能由前端猜出音频时间轴位置。

### P0：排除播放/环境内容，保留本人优先且不丢其他人的提及

现场已见播放内容中的人物生日被作为待确认纪念日。文本里「今天是某某生日」不能单独证明它与用户生活有关。

- 按实体/事实汇总，不先按说话人切成多份独立结果。
- 本人明确提过的优先；同一实体保留其他人的提及与关系证据。
- 区分现实交流、手机视频、电视、环境音。播放内容不能自动形成用户家人、用户目标或真实关系。
- 对 ASR 错误采用原音/上下文复核、候选纠错与置信度；姓名近音只能产生候选，不能自动绑定联系人。
- 短期无法判断时保留待确认和原文，不输出强结论。

### P0：人工纠正具有持续效力

- 统一支持纠正内容、不是这个人、播放内容、与我无关、忽略/撤销等反馈；明确作用于单次提及、实体、事实还是未来识别。
- 用户确认过的日期、名称、身份和排除项，重新分析后不应被旧模型结果覆盖或重新推荐。
- 反馈需幂等（request_id/feedback_id）、版本冲突检查、返回持久化状态与受影响对象；提供重新读取与撤销路径。
- 关系需解除/重新绑定错误联系人、可靠合并/拆分，不能只提供删除整个实体。
- 目标需补齐可持久化的纠正/完成/放弃/忽略协议；前端当前未提供虚假的编辑入口。

### P1：录音来源覆盖与增量任务

请分别确认 profile、relations、events、goals 对独立录音、录音转写、录音总结的实际消费链路；不是只接纪念日。各模块暴露来源能力和有效覆盖日期/数量，不把尚未接入录音显示成「暂无结果」。

- 提供录音新增/转写完成/说话人纠正后的增量识别；不要每次全量扫描。
- 声纹标记变化、ASR 修订、手工负反馈应使相关派生结果失效并可重算，保留人工修订。
- 任务明确 queued/running/paused/recovering/partial/failed/completed、心跳、进度分母、可重试/继续/停止能力和简要错误，不永久显示恢复中。
- 已产出内容可读；模型切换、失败重试、停止不会静默清空旧结果；按快照保证分页一致性。
- 关系 list 需要真正的 owner 分页、搜索、总数和快照版本，避免每次传输几千实体。

## 验收清单

1. 同一人当天多段录音、多人提及同一实体，最终为同一可靠身份的汇总视图；不能仅凭文字名字相似合并。
2. 播放视频中出现的生日/目标/人际关系，不自动算作用户本人事实。
3. system/doubao 都能从识别结果回到精确原文；旧版本变化时明确报错，不落到相似句。
4. 本人/他人标记错误可纠正，重新读取、刷新与重新识别后保持有效。
5. 日期支持公历/农历/闰月/未知年份；人工纠正后重算不覆盖。
6. 原记录或录音删除、权限变化后证据不可越权读取。
7. 连续分页、后台生成新版本、切换账号、失败重试均不混入错误结果，不把失败显示为保存成功。
8. 生产确认/删除/重新分析等写入验收应使用用户选定的真实事项；本轮自动验证未随意修改用户事实，也没有重启 14 万条档案整理。
