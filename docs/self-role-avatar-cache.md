# 角色头像本地优先

角色与历史消息保存稳定 `file_asset://` 引用。MediaService 现在先读进程内缓存与既有 SQLite 头像缓存，再按上传回执查找本机原图；只有本地不存在或文件不可用时才解析资产并下载。缓存身份包含环境、账号和资产 ID，签名 URL 过期不会淘汰文件；既有容量淘汰规则仍适用。

同资产的磁盘查找、解析及下载共用一个在途请求。不同缺失资产在 8 毫秒窗口内合并，按最多 50 个 UID 调用既有文件查询接口。上传回执继续负责原图与资产 ID 的对应关系，角色删除后仍可供冻结消息读取。缓存写失败不阻断展示；查询失败清除在途状态以便重试；切换账号或销毁服务后不返回旧账号结果。

| 消费面 | 路径与范围 |
|---|---|
| UI | 消息和角色选择器继续通过 `image.read` 读取，继承持久缓存；没有新增设置或加载操作 |
| SDK | 现有 `readImage` 使用同一 Host owner，签名、返回数据和能力版本不变 |
| Tools | 现有 `arkme_image_read` 使用同一 `MediaService.readImage`，不新增工具或授权 |
| Host | 缓存属于既有图片读取能力；复用头像表、角色上传回执与文件查询接口，无新业务 endpoint 或表 |

回归覆盖 SQLite 关闭/重开后的离线读取、上传原图复用、删除角色后的历史头像、同资产合并、不同资产分批、查询失败重试、环境/账号隔离、账号切换和损坏缓存恢复。头像资产沿用 8 MiB 头像上限，调用者指定的更小上限仍生效。
