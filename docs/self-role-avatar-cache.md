# 角色头像本地优先

角色与历史消息保存稳定 `file_asset://` 引用。MediaService 现在先读进程内缓存与既有 SQLite 头像缓存，再按上传回执查找本机原图；只有本地不存在或文件不可用时才解析资产并下载。缓存身份包含环境、账号和资产 ID，签名 URL 过期不会淘汰文件；既有容量淘汰规则仍适用。

同资产的磁盘查找、解析及下载共用一个在途请求。不同缺失资产在 8 毫秒窗口内合并，按最多 50 个 UID 调用既有文件查询接口。上传回执继续负责原图与资产 ID 的对应关系，角色删除后仍可供冻结消息读取。缓存写失败不阻断展示；查询失败清除在途状态以便重试；切换账号或销毁服务后不返回旧账号结果。

| 消费面 | 路径与范围 |
|---|---|
| UI | 消息和角色选择器继续通过 `image.read` 读取，继承持久缓存；没有新增设置或加载操作 |
| SDK | 现有 `readImage` 使用同一 Host owner，签名、返回数据和能力版本不变 |
| Tools | 现有 `arkme_image_read` 使用同一 `MediaService.readImage`，不新增工具或授权 |
| Host | 缓存属于既有图片读取能力；复用头像表、角色上传回执与文件查询接口，无新业务 endpoint 或表 |

回归覆盖 SQLite 关闭/重开后的离线读取、上传原图复用、删除角色后的历史头像、同资产合并、不同资产分批、查询失败重试、环境/账号隔离、账号切换和损坏缓存恢复。头像资产沿用 8 MiB 头像上限，调用者指定的更小上限仍生效。

## 最终审核修复：本地探测与损坏图片

- 浏览器持久缓存未命中时，先使用独立配额调用 `image.read { imageRef, cacheOnly: true }`。只探测当前账号的 Host 内存、SQLite 和上传原图，不加入正在下载的请求，也不发起资产查询；未命中才进入原有下载队列。不同头像的两个慢下载不再挡住 Host 已缓存的第三张头像。
- Host 对持久缓存、上传原图和新下载内容执行实际图片解码，拒绝只有文件头的截断图片。继续使用现有 8 MiB 字节上限，解码首帧额外限制为 64 MP；损坏缓存按未命中处理，下载成功后覆盖，损坏下载不持久化。
- 浏览器 CacheStorage 的读写也执行解码校验；旧的合法 base64、非法图片内容会被删除并回源。不可变文件仍无时间过期，容量淘汰、清理站点数据和损坏内容均视为缓存未命中。
- 保持现有账号、环境、生命周期隔离和同图在途去重。无需数据库迁移、后端部署、新增配置或依赖升级。

| 消费面 | 新增合同 |
|---|---|
| UI | 浏览器缓存 → 独立 Host 本地探测 → 原有下载；默认头像、角色选择与刷新继续使用原有界面 |
| SDK | `features.imageCacheRead` 能力探测；公开 `readCachedImage`，本地未命中返回 `undefined`，不支持的 Host 明确报错 |
| Tools | 既有 `arkme_image_read` 增加可选 `cache_only`，沿用原 grant；未命中返回 `image-cache-miss`，不偷偷下载 |
| Host | `MediaService.readImage({ cacheOnly: true })` 是共同 owner，探测仅支持稳定 `file_asset://`，普通读取的默认行为不变 |
