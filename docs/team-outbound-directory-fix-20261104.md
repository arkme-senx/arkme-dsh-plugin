# 主动团队联系后立即进入会话目录

代码版本：`a736f44013f1538e0f5f1a747ea8b1459f54b61a`，基于 `dev` 的现有团队选人修复分支。以下是本地新代码验收，不代表安装客户端或线上发布已更新。

## 原因和范围

从群成员名片或选人弹窗发起团队联系后，Host 已返回有权限访问的会话，但原前端只刷新目录并打开右侧窗口。Team 的列表查询过滤 `last_seq > 0`，因此未发送首条消息的关系不会返回；重复刷新无法补齐这一行。

后端证据：本地只读检查 `jotmo-team` 提交 `55d8d32c9ff51c5281a6b3016271cfb5f38a0bd9` 的 `internal/teammessaging/reception.go:OpenByMember` 和 `repository.go:MongoStore.Conversations`。这次未修改、部署后端。

## 最终行为

- 两个主动联系入口统一使用 `openConfirmedTeamContact`：验证当前账号、团队和会话标识，立即保留 Host 返回的会话，再导航到相应团队和右侧窗口。
- 共享目录包含主动发起的会话，即使普通列表尚在等待或不含该行；按稳定会话 key 合并首条消息、重复发起与后台刷新。
- 新行选中并滚动到可见范围，保留已有置顶和活动时间排序。没有可用预览的空会话显示“尚未发送消息”，已有语音、附件、正文和表情预览继续使用原展示。
- 不制造消息、活动序号、未读或通知。普通空窗挂载、公开链接预览、云端置顶不激活空关系。
- 保留项参与已读更新、撤回摘要清理、偏好权限判定和通道撤权。账号变更（包含 A→B→A）取消发起请求，退出账号、Provider 更换或目录生命周期结束清空保留项。
- 保留项为当前窗口内存，每账号最多 100 项，容器最多 8 个账号；不持久保存凭据或会话引用。

后端仍过滤空关系，因此页面/Provider 重启及跨设备恢复不在本次前端修复保证范围。需要后端持久记录“成员明确发起”的事实，并配套列表、索引和分页，见 [后端交接](team-outbound-directory-backend-handoff-20261104.md)。

## 实际点击验收

隔离浏览器 `127.0.0.1:3185` 使用原名片、选人弹窗、共享目录、导航和右侧组件，仅替换 API 为明确标注的双团队数据。实际点击确认：

1. 名片切换到产品团队并发起；列表请求保持等待时，新行已出现且选中，右侧同步打开。
2. 返回不含该人的旧列表、再次刷新，行仍保留。
3. 通过选人弹窗再次发起同一目标，仍为一行；模拟首条消息后摘要更新同一行。
4. 模拟权限撤销后新增行被移除；模拟发送接口调用数始终为 0。
