# 桌面表态交付说明

## 最终范围

私聊、群聊、发给自己的消息可添加和取消表态，支持表情、手势与短语组合、自定义颜色、短语保存/排序/删除。同词不同颜色分别保存，完全相同的短语提示重复。世界页面不提供表态入口。

表态显示参与者姓名，优先采用查看者的备注，再使用个人名称；群昵称单独补充。姓名可打开名片。

侧边栏显示别人对自己消息的未查看表态，点击橙色预览定位原消息并强调新表态。查看会话本身不清除提醒。没有新增聊天内提醒按钮，原回到底部按钮保持既有行为。

“我的一天”记录自己的添加与取消操作，沿用原时间轴、头像、发送者、时间和展开结构。前往原始来源定位消息并强调对应表态；已取消且不再存在的表态只强调原消息。高亮在进入视野、滚动停稳后开始。

## 能力与数据边界

- Record 后端持有当前表态、操作历史、短语及隐私策略，Chat 提供消息可读性。客户端不新增消息持久字段。
- Host ReactionService 是权限、幂等和错误语义的单一入口；UI、公开 SDK reactions 能力和读写 Tools 共用该 owner。
- 读取、写入及缓存均按账号作用域隔离。历史失去原消息访问权限时隐藏来源和原文，隐私锁保护历史。
- SDK consumer 和正式 ToolRuntime 合同已测试；未完成已安装桌面中的真实模型会话验收，不将合同测试视为该验收。
- 客户端反应查询有目标数、批大小、并发及缓存容量边界；前后台切换/卸载清理订阅和计时器。没有新增桌面原生桥或修改 DSH 源码。

## 测试环境及依赖

后端功能已部署测试环境：Chat #728、World 权限支持 #131、Record 后续原消息上下文 #522 均成功。生产部署须先具备这些后端合同。World 权限适配不代表本次增加世界页面表态入口。

插件沿用 0.1.79 版本字段，通过不可变 tgz 和官方 DSH 安装流程装配到三个专用 Windows 测试 Profile。未发布生产渠道，未修改插件版本或客户端源码。

用户已用多个账号逐项复测此前反馈的交互问题，最后确认取消表态的来源跳转灰色提示通过。最近一次局部修复 26 项检查及类型、构建、打包通过。

全仓测试存在 Windows/运行环境及其他模块失败，历史全量结果并非全绿。提交前的最新测试结果以 PR 验证部分为准；不得把表态局部通过写成全仓通过。

## 回滚

先恢复上一插件制品，再按后端发布流程回滚对应服务；不删除表态历史集合，不改用户测试账号或已有数据。
